# Preview 长执行修复验证记录（2026-09-09）

## 结论与范围

本轮实现已完成，最终 3 分钟真实流程验证通过。30 分钟验证按要求取消，不计为通过。修改尚未提交 Git，未替换正在使用的生产发行目录。

原问题包含两层：Preview 请求直接执行同步重任务，阻塞 FastAPI 事件循环；启动器将短暂 Degraded 状态映射为不可用，提前隐藏工作台。本轮将 Preview 放入独立常驻进程，并区分健康检查中的 Checking 与确认不可用状态。

## 实现与核对

- Preview 采用有容量上限的独立进程池，复用模型会话，每个应用最多一个活动预览；不占用正式 Workflow Runtime 执行槽位。
- 前端异步提交、查询真实终态、取消和刷新恢复查询；取消及 timeout 保留协作停止与强制退出边界。
- 上传文件归执行器所有，确认执行结束或进程退出后再回收；记录包含 owner 和 worker 的 PID、创建时间，避免把正常长任务当成遗留失败任务。
- 子进程事件转发到既有 WebSocket，保留 JSONL 重放；完整展示结果按需读取，默认查询保持摘要行为，旧同步接口保持兼容。
- 启动器 Checking 保留已经打开的工作台，首次启动仍需要就绪，明确故障仍显示不可用状态。
- 浏览器验证中出现大型结果页面异常，结果面板增加 12,000 字符摘录上限，保留完整对象查看。后续成功与取消场景复测未再次出现崩溃；未将该现象认定为单一原因已被完全证明。

未修改模型文件、前后处理算法、业务判断阈值或正式 Runtime / Trigger 的 ZeroMQ、共享内存数据面。Preview 与正式运行仍共享机器资源，不能据此断言资源竞争不存在。

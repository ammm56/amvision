## 范围与结论

基线为合并提交 `a80ff1bb`（合入远程 `01587765`），使用本机 conda amvision、真实开发数据库、5600 后端、5601 前端、现有已部署分类模型和仓库合成连接器资源。验证使用真实 HTTP、WebSocket、独立 Runtime、ZeroMQ、LocalSharedMemory 和 Windows x64 .NET Framework SDK，没有替换节点处理器或模型结果。

## 已修复和配置变更

1. 本机缺少不纳入 Git 的 `config/backend-service.local.json`，三维 Preview 文件上传返回 `preview_file_policy_unconfigured`。经确认，采用 `custom_nodes/metrology3d_nodes/workstation.example.json` 补齐配置：活跃数组预算 1 GiB、算法工作内存预算 4 GiB。重启后实际点云上传、预览和 SDK 调用通过。这是每台开发机需要显式提供的配置，Git 拉取不会同步此文件。
2. Backend 占用者识别只接受 `python -m uvicorn`，没有识别标准 Windows 开发入口 `backend.service.infrastructure.http.reload_server`，导致 Broker 无法记录完整服务归属，新启动接管失败。补齐入口识别，保留 app target、内核进程身份、目录、解释器、锁句柄和进程组校验。已有不完整记录先通过已核对的项目进程组停止；未删除锁文件。修复后再次执行标准启动命令，实际成功接管旧服务，旧 HTTP、reloader、Broker PID 均确认退出。
3. 连接器示例生成脚本仍配置 `passed_count`，当前 Check Limits 返回 `required_ok_count`；原状态颜色也缺少 `invalid`。更新生成脚本，并在完整图测试中核对实际结果进入 Value Display 后的数值和状态颜色。

首轮没有覆盖业务草稿、切换旧 Runtime 版本或修改真实生产统计；后续经授权更新了两个连接器应用的草稿和发布版本。整个验证过程没有改模型权重、公差、Runtime/Trigger 数据面、公开 API、数据库结构或真实生产统计。

### 发布身份不再匹配

以下两个旧发布引用的 `core.rule.check-limits` 实现已改变，显式启动返回 409，并要求审核草稿和重新发布：

- `workflow-app-connector-single10` / `workflow-runtime-c39f989f90874c8e8e6f8cc2003893f7`

首轮结束时两者为 `desired_state=stopped`、`observed_state=failed`，因此不在当时的 8 个预期运行实例中。启动拦截是版本保护；不能把当时状态接口的 `ready=true` 理解为这两个历史发布已恢复。

首次检查还观察到自动恢复路径反复尝试旧发布，并记录通用的“worker 在启动完成前退出”，而显式启动接口能够返回具体的节点身份冲突。自动恢复错误传递和停止重试边界仍需单独修正，当前实例停止状态不能视为该逻辑已经修复。

### 配方与显示字段需要整体迁移

旧草稿仍使用 `passed_count`，并且未配置 `invalid` 状态颜色。仓库生成脚本已修正，但不会自动覆盖已有草稿或发布快照。

旧 single10 配方对 `width_on_limit` 原图测得 R1P05 宽度约 `0.692435 mm`，上限 `0.69 mm`，输出 NG。仅把旧配方的 `image_encoding` 改为 `srgb` 时，该宽度变为约 `0.686576 mm`，但其他项出现 invalid；因此单独改编码不能解决整份配方的一致性问题。仓库当前 `build_example` 生成的完整配方对两组临界图测试均通过。

处理顺序应为：对照当前模板审核图像编码、采样与阈值、标定资源、PIN 布局及显示字段；用参考、缺 PIN、界内、界限、界外原图完成回归；确认后重新发布并选择新版本。不得通过放宽公差或直接重发旧草稿掩盖差异。

### 自动恢复修复

根因：worker 在完成启动前抛出异常，原响应协议未向父进程返回结构化启动错误。父进程仅得到“提前退出”，恢复控制面又对失败持续退避重试。

修复后通过带身份校验的 `startup-failed` 消息保留原始错误码、原因、路径、节点和是否需要重新发布。明确的配置、文件、权限错误暂停恢复；其他启动错误在同一发布代最多 3 次。次数与暂停状态保存到现有 `health_summary.recovery`，服务重启不重置。修复后显式启动或选择新版本可继续。同步 Runtime/Trigger 调用不增加队列、自动重试或数据面数据库写入。

真实独立进程回归测试先启动隔离 Runtime，再移走其发布 application 文件模拟路径丢失：一次恢复后记录具体文件原因并暂停，后续扫描不再启动；恢复文件后通过正式启动接口成功运行。测试仅操作隔离目录，不移动实际应用文件。

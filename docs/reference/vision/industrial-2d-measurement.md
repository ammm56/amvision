## 三种“通用”需要区分

以下划分是 AMVision 的架构选择，不是对上述产品内部模块的推断。

| 层次 | 示例 | 设计判断 |
| --- | --- | --- |
| 跨行业基础能力 | 图像边缘、几何距离、平面标定、数值范围判断、文件追加 | 输入不需要知道连接器、PIN 或治具；应留在 Core 或对应通用技术包。 |
| 行业内可复用能力 | PIN 名义排列、端子身份关联、按 PIN 定义的间距/偏位 | 需要连接器语义，但能跨产品型号使用；进入连接器自定义节点包。 |
| 具体产品配置 | 料号、24/80 个位置、A/B 类定义、公差、NG 标签、存储路径 | 是 Workflow、模板或受版本管理的资源，不形成新的节点类型。 |

判断一个能力是否行业专用，不能只看最初由哪个项目提出。连接器提出的“点到线距离”仍是通用几何；所有行业都能使用的批量上下限判断也不是“连接器判定”。相反，PIN 留空表、同类邻接顺序和端子编号不能偷偷加入通用 Line Measure。

## 行业检查项目与二维可见性

| 工艺问题 | 二维检测的可用证据 | 配置与边界 |
| --- | --- | --- |
| PIN 缺失、多余、设计留空 | 可见候选与名义位置的对应关系 | 未观察到与物理缺失分开；遮挡/视野外需给出无效原因。 |
| PIN 间距、宽度、偏位 | 定义特征、截面、方向及有效测量平面 | 名义基准固定；不能拟合被检阵列的尺度来消除误差。 |
| 端子弯曲、毛刺、缺损 | 可见轮廓偏差、局部边缘和区域 | 不能把稳健拟合剔除的缺陷点全部丢弃；轮廓结果与几何拟合质量分开。 |
| 壳体异物、缺口、混料 | 已配准区域、形状或外观特征 | 优先使用现有通用检查/已部署模型；标签和最终规则来自产品配置。 |
| 可见装配位置 | 对应视图中端子、壳体与基准的关系 | 看不见的卡扣、接触区及高度不得输出“已验证”；需要其他视图/测量手段时明确留给外部系统。 |
| 导通、接触电阻、插拔力、内部结合质量 | 单幅二维图通常不能提供所需直接测量 | 不加入视觉节点的保证范围；外部检测结果可以经既有协议进入通用规则。 |

二维检查的通过结果仅覆盖启用并有效完成的视觉检查项，不表示整件产品全部电气和机械性能合格。

## 对功能设计的新增约束

1. 定位、图像坐标、物理标定是不同职责；工件随动不意味着重新求解每张图的标定。
2. 名义配置和本次检测状态分开；参考资源不可被一次定位结果覆盖。
3. 通用工具的诊断保持一致：采样位置、被采用/排除的点、有效性、残差和坐标单位。连接器 UI 增加 PIN 表与行业配对，不复制图像编辑器和颜色系统。
4. 端子量测、壳体外观和最终工艺判定不合并为一个不透明节点。
5. 改善旧通用节点应使用独立回归证明；只用连接器图测试不足以确认其他场景不受影响。
6. 样本标注需记录“看得见且有真值”“可见但无独立真值”“不可见/不适用”；不能混为统一 OK/NG 训练或验收集。

## 后续资料重点

收集顺序为：首个产品图纸与原图 → 视图/特征对应表 → 独立参考测量 → 临界/缺陷样本 → 成像与节拍变化 → 官方完整软件操作资料。优先填补会改变测量定义和节点职责的信息，不继续堆叠厂商功能名。

每条待实现检查至少登记：检查 ID、产品视图、对象/特征、量或缺陷的定义、所属通用/行业能力、配置来源、有效性条件、放行规则、证据和验证方法。具体格式与实施门禁统一维护在[实施基线](../../development/connector-inspection-2d.md)。

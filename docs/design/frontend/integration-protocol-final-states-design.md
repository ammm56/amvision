## 2. 实现事实与目标契约

- 创建支持调用方提供trigger_source_id，并能按ID读取；重复ID被拒绝。回执丢失应复用原ID查询并比对项目、实例和配置。单次404、同名资源或断线不能证明原请求未提交；“已确认未创建”必须有服务端明确终态/提交完成屏障，此终态能力仍需实现。ID与原配置在客户端当前草稿保留，不增加数据面幂等或业务重试。
- 已删除实例与无权限/暂时不可达必须区分。只有明确不存在且权限允许才显示删除态；不自动绑定同名实例。停止实例去应用分类处理，集成不复制Runtime管理。
- 当前未注册Webhook/MQTT适配器；图稿描述未来已安装且受信任的扩展能力。接收路径由服务生成，鉴权使用凭据引用；不在图中承诺不存在的API/SDK方法。扩展选择按实际发现能力，安装/授权在节点/扩展管理，不在触发配置页隐式执行。
- 本机共享内存只适合同机64-bit调用，不出现网络端口、手写池槽位或Base64降级；目录监听由后端执行，无SDK调用配置。该说明用普通文本，不当异常。
- 目录轮询health已有last_scan_at/last_visible_count/last_new_candidate_count/last_batch_file_count/known_identity_count/sequence_id等。这些是扫描/提交信息，不能算物料产量或完成率；当前没有精确扫描百分比/ETA，不伪造。示意扫描中需要未来活动阶段字段。
- 当前目录轮询失败/超时时不会把候选写入known_identity_keys，后续轮询可能再次提交。此前“不自动重跑失败记录”的泛化表述不适用于这个现状；同步Trigger容量拒绝无新增队列/重试仍保持。该差距写入设计记录，本轮不修改执行代码。
- 现有checkpoint不存在时从空进度开始；文件存在但无法读取、JSON/格式/入口ID等不匹配时抛ServiceConfigurationError，已会阻止正常启动。写入使用write_text，失败会更新last_error；新界面需要区分“文件缺失”和“文件损坏”，不能将缺失解释为已安全迁移。配置修订/规则迁移确认、缺失进度的人工处理仍属目标能力，须另行实现与测试。
- 规则变更不能默认迁移已知身份或清空；停用后人工确认重新扫描，有重复触发可能。取消保留原配置/进度；失败仍停用，状态未知先核对；不主动执行业务测试。

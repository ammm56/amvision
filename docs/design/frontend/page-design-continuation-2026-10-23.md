## 1. 固定的共同规则

当前执行顺序：先完善[全部页面中文设计与提示词](prompts/README.md)，核对覆盖和来源后，从数据集主页面亮暗配对继续出图。下文 A 批三组图是已否决的历史批次；保留其功能字段和行为约束供复核，不作为当前布局或直接出图请求。

- 使用[已确认母版](master-review-2026-10-23.md)：项目、任务、数据集、模型、部署、推理、图编辑、应用、集成、节点、设置，共 11 项平级导航。
- 无独立全局顶栏；搜索、筛选、创建放在各页内容区。页面不恢复重复大标题和空标题高度。
- 品牌 `#00D992`，亮暗主题主色不变。主要按钮白字；普通 hover、输入 focus 为中性色；选中与主要动作使用品牌色。精确值以[设计系统](design-system.md)为准。
- 右侧资源详情是可关闭的覆盖式抽屉，主页面不因展开缩成固定分栏。管理数据集、部署导入使用居中对话框；长时间样本浏览使用完整工作区；图编辑器保持画布与节点属性交互。
- 所有亮暗配对使用相同数据、内容顺序和布局。时间、ID、计数是说明交互的设计样例，不作为运行结果或能力验收。
- 不重复建设异常、连接器或 3D 的全局业务页面；能力通过 Workflow、节点包、专属 UI 和共享查看器提供。

## 3. A 批：数据集管理（D02）

入口保留在数据集页面右上角“管理数据集”。主体导入/导出表单与记录保留，不把版本列表重新放到主页面。

居中宽对话框包含标题、关闭、检索、任务类型筛选、版本表格、分页。表格优先名称、版本、任务、样本数、类别数和操作；长 ID 收进详情及复制入口，不让多行 ID 撑坏每一行。显示名没有配置时以 ID 回退，不能凭空推断名称。版本列是单个不可变版本的名称/标识，不默认存在“当前版本”或 v1/v2 顺序。

“打开”进入该版本的完整样本工作区；“详情”在同一对话框正文切换为版本摘要/来源/引用，提供返回列表，避免叠加抽屉套弹窗。“删除版本”先检查外部引用，再显示删除对象和范围；有引用时说明具体引用，禁止删除。没有“删除整个数据集”。

| 操作 | 保留 | 删除 / 打开范围 |
| --- | --- | --- |
| 主页面删除导入记录 | 数据集版本、图片、标注 | 导入记录、关联任务、上传 zip、导入暂存文件 |
| 管理中删除版本 | 外部引用不允许被破坏 | 版本、图片、标注及关联导入/导出记录；存在引用时阻止 |
| 打开版本 | 不修改数据 | 进入只读样本浏览；编辑/派生属于后续单独能力 |

**能力状态：** 当前已有对话框、按 ID 搜索、任务/样本/类别显示和引用保护删除。显示名、任务筛选、服务端分页、详情整合和“打开版本”属于目标扩展，依赖版本/样本 API；静态图不证明这些功能已存在。类目和样本计数不从旧稿虚构为真实数据。

必要状态：空列表、无匹配、加载失败可重试、部分计数不可用、长名称/ID、无权限、被引用禁止删除、删除成功后总数与页码修正。删除过程中避免重复提交；对话框关闭不伪造任务取消。

## 4. A 批：部署实例导入（R01）

入口为部署页“导入部署实例”。未选择文件时使用文件选择；分析得到计划后打开居中宽对话框。布局按“包摘要 → 实例配置 → 运行配置 → 资源映射 → 问题 → 底部操作”。

- 包摘要紧凑显示文件、模型、任务、后端/精度、输入尺寸、类别数，不铺满大卡片。
- 展示名称、设备、实例数对齐，标签在控件上方，统一高度；范围与设备选项来自契约。
- 运行配置按 execution、lifecycle、backend_options 分组。后端字段按实际后端显示，不混画 TensorRT 与 OpenVINO 参数。
- 采用真实字段示例：OpenVINO `performance_hint`、`inference_num_threads`、`num_streams`。保留包内配置与“推荐配置”动作；只读字段明确，不通过外观暗示可编辑。
- 资源映射使用“资源 / 包内来源 / 导入目标 / 处理方式”表格，分别说明 model、version、build、deployment 的新建或复用。名称优先，ID 可以复制和展开，不用颜色独自传达复用。
- 参数变化后导入按钮变为“检查配置”，重新分析通过后才恢复“导入”；不能继续使用过期计划。
- ID 冲突才出现副本创建选项；普通配置状态不常驻一整套冲突提示。
- 历史失败逐条提供清除按钮；清除提示不是删除部署或重试任务。CRC、设备不支持、映射冲突和任务失败给出对应恢复动作。

**能力状态：** 上述导入字段、分析/再检查、映射、推荐配置和清除失败记录已有基础实现；本稿整理信息层级和表单。没有为取图上传包或执行真实导入。长列表滚动、分析中关闭、取消和任务恢复应按服务实际状态验证。

## 5. A 批：触发入口详情（X01）

触发主列表仅名称、类型、状态、触发时间、操作；不恢复长 ID、原始健康 JSON 或最近错误列。详情从操作列打开右侧覆盖式抽屉，列表的列位置不因打开而重排。

抽屉顺序：名称与当前状态 → 关联运行实例 → 最近触发/创建/更新时间 → 请求/成功/错误/超时/满载等关键计数 → 最近错误 → 技术标识/原始诊断。优先显示名称，完整触发 ID、Runtime ID 可换行和复制；完整诊断使用明确展开入口，不直接占据默认视图大半高度。

列表的“未触发”是正常状态；已启用且正在监听也可以是未触发。满载是独立容量信息，不一概渲染为故障，不增加排队或重试。诊断数据缺失显示“暂无数据”，不可伪造 0 或正常。目录监听无需 SDK 调用配置，普通说明按需要展示，不作为异常。

**能力状态：** 抽屉、名称/ID/运行实例/状态/时间及健康 JSON 已存在；将已有计数结构化、折叠原始诊断、提供更清楚关联入口属于 UI 优化。设计样例的正常状态不代表当前所有 Runtime 已启动。

必要状态：运行/停用/错误、未触发、计数不可用、长 ID、错误长堆栈、原始诊断展开、断线旧数据、权限受限。关闭抽屉恢复原列表滚动与焦点，不改变触发启停状态。

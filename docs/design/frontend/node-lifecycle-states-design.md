## 当前契约与未来设计
[路由](../../../backend/service/api/rest/v1/routes/workflows/node_pack_admin.py)已区分workflows:read与workflows:write。查看状态、版本、日志、审计以及单包校验使用读权限；安装、启用、禁用、回滚、整体重载使用写权限。只读账号仍可校验，不能把校验按钮误禁用。
安装是同步提交接口。图中的阶段进度、操作结果查询、静态预校验、变更前的引用检查与版本并发校验属于待实现契约，不假定现接口已具备。后续实现需单独设计、验证，不新增业务推理队列。
包“enabled”与实际加载成功分开；响应返回不等于节点全部可执行。状态必须来自服务端快照。
操作中关闭抽屉只隐藏面板，不取消动作。再次打开显示同一操作。无确定进度时只显示当前阶段，不编造百分比。
网络中断不判定失败。保留上次版本、状态与确认时间；查询状态后才能允许新的写操作。
恢复成功仅在服务确认后显示；恢复失败则显示暂不可用、上次可用版本和下一步，不展示虚假的当前已加载。
“启停”在此指节点包启用/禁用，不代表停止模型或Runtime。运行引用阻止包含间接包依赖；不隐式停机。
未来并发检查需要包身份、版本及内容摘要，过时页面不得覆盖新状态。错误内容允许复制，技术信息默认收起。
回滚示例0.1.10→0.1.8只表示已登记版本的设计场景，不保证现场存在该历史包；旧版本节点数不凭当前Catalog推断。
已禁用不是错误；操作成功用短反馈，禁用后的可用性用中性状态，依赖影响用警告。
Core节点沿服务版本发布，本批节点包管理均为扩展包。

## 交互验收与边界
- 确认框只在副作用发生前出现；写动作提交后禁止重复提交，关闭不回滚。
- 运行中阻止没有强制继续按钮；跳转查看实例不代替停止确认。
- 只读保留查看、复制、校验；无读权限不显示资源数据，不能用“0个节点”代替403。
- 使用说明保留必要步骤与真实端口关系。参数配置回到图编辑，不产生第二套参数保存面。
- 短屏采用1366×768布局目标。Logo承担展开入口，正文独立滚动、页头页脚固定，参数不丢失。
- 亮暗严格同内容、同布局、同操作，遮罩覆盖整片底层。正常文字精简，错误原因与恢复动作完整。
- 静态图片仅验收信息与布局。键盘、焦点、回到原行、权限变更、并发和恢复必须在Vue原型及后端实现验证。

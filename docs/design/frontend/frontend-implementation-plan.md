## 2. 设计依据与冲突处理

优先级如下：

1. 已明确的用户要求和分类最新修订；图编辑以[当前实现基准](graph-editor-current-baseline.md)为准，设置以[细节优化](settings-detail-refinement.md)为准。
2. 分类最新页面规格、状态定义和中文提示词，以及[设计系统](design-system.md)。
3. 当前生成清单指向的有效图片，用于空间、层级和风格对照。
4. 当前产品行为与公开契约，用于识别功能差距和回归约束。
5. `bak1` 与早期过程文档，只用于理解来源，不恢复已经否决的方案。

生成图中的数字、ID、文字溢出、错误控件或偶然色差不是规范。实际模型类型、版本、资源名称、运行状态来自接口；缺失数据展示未知或不可用，不使用设计稿中的成功值补位。

已有接口不限制未来目标，但决定实施依赖：先定义缺少的业务契约，再实现对应页面。公开接口变更遵守项目版本规则；增量能力使用现有 v1 命名体系，不为 UI 换皮另建整套 v2 API，也不静默破坏现有 v1 和 .NET SDK。

## 3. 固定的产品与视觉边界

### 3.1 工作台与主题

- 保留 11 个平级导航入口及当前权限过滤：项目、任务、数据集、模型、部署、推理、图编辑、应用、集成、节点、设置。不新增全局顶栏、常驻第三级导航或全站项目选择栏。
- 保留导航展开/折叠行为。短屏折叠后点击 Logo 展开，不添加额外展开图标。图编辑导航、顶部操作组、图标、尺寸和间距不因其他分类改造而变化。
- 品牌色继续来自 `--am-brand-primary: #00d992`，主按钮及选中控件标记使用白色。选中使用品牌色，普通悬停和输入框焦点使用中性色；危险、警告、未知、禁用各有独立语义。
- 亮暗使用同一 DOM、间距和组件结构，只切换语义 Token。背景为纯色，不加入纹理、暗角或渐变。图编辑保留白色/暗色网格、金色直接连线与中点手柄。
- 保留原有字体层级，普通参数、只读数值不全加粗。正常状态少解释，错误保留短原因和直接操作；长 ID、路径、堆栈进入详情或技术信息，支持完整复制。
- 图片框、mask、热图、坐标轴、测量与点云的颜色表达独立于主题选中色，不把所有可视化都改成绿色。
- 不重新加入全局路由缓存、整页切换动画或业务页面强制等待。现有品牌词缀和必要局部面板动效遵循减少动态效果设置。

### 3.2 页面、抽屉与查看器

| 类型 | 实现规则 | 典型内容 |
| --- | --- | --- |
| 普通页面/多步页面 | 页面内部工具栏、页签和正文；浏览器返回与深链接可用 | 项目概览、数据集工作区、训练/导入向导 |
| 模态抽屉 | 覆盖、不挤压底层；整屏遮罩同时覆盖导航和正文；焦点限制在当前最上层，关闭后归还 | 项目信息/编辑、实例详情、配置 |
| 非模态检查面板 | 覆盖、不重排图像；允许继续选对象和操作画布，不伪装成 `aria-modal` | 样本对象、推理对象信息 |
| 确认对话框 | 明确影响、当前动作和取消；短屏操作区可见；允许从抽屉内打开但只激活最上层 | 删除、停止、放弃修改 |
| 图编辑浮动面板 | 沿用现有画布层级与位置，不强行套模态抽屉 | 属性、节点组、节点专属编辑器 |
| 专用大图/大视图 | 同一次结果、同一对象身份；返回恢复原位置与选择 | 图片、标注、生产数据叠加、点云 |

不把所有右侧面板变成一种固定三栏布局。打开抽屉不得改变底层图片比例、节点坐标或滚动位置。只读结果使用标签/值、表格或代码视图，不用可编辑输入框装饰。

### 3.3 执行与数据面

- 编辑态 Preview 继续由独立 Worker 执行、WebSocket 逐节点反馈；Runtime 监视/App Mode 继续接收实际运行的完成结果，不为了界面引入逐节点生产广播。
- Runtime、Trigger 和 .NET 同步调用不因页面改造增加排队、自动重试或二次模型加载。满载是正常容量拒绝，忙碌不等于服务未就绪。
- WebSocket `permessage-deflate` 保持关闭。图片预览沿用 JPEG 等既定显示编码；原始输入与模型处理数据不因显示缩放而改变。
- 页面显示、接口成功和业务 OK/NG 是不同状态。UI 不补算生产判定、不用检测框个数替代物料数、不为临时预览增加数据库或磁盘归档。
- 浏览器不直接访问磁盘、数据库、ZeroMQ 或共享内存。所有资源通过现有受控 API/显示通道取得，正式数据引用及生命周期保持不变。
- 关闭页面不停止生产执行；断线重连只恢复观察，不补发业务请求。图片、值、表格和三维结果按 run ID、节点/端口及实际版本关联，旧结果不能覆盖新结果。

## 4. 当前工程与实现差距

### 4.1 代码组织

现有产品代码位于 `frontend/web-ui/`，保持下列依赖方向，不建立第二个应用或通用页面搭建系统：

```text
app/router、shells、modules、workflows
                 ↓
shared/contracts、shared/api、shared/ui、platform
                 ↓
          现有 lib 与 Vue 生态
```

| 现有位置 | 后续职责 |
| --- | --- |
| `src/config/navigation.config.ts`、`src/shells/` | 原导航、权限与工作台外壳；只做必要细节一致性修正 |
| `src/shared/styles/tokens/`、`src/shared/styles/index.css` | 语义色、表格密度、尺寸、边框、层级和响应式规则 |
| `src/shared/ui/components/` | 复用 Button、Select、MultiSelect、SideDrawer、ConfirmDialog、ImageViewer、FilePicker、PaginationControls、资源删除/清理组件 |
| `src/shared/contracts/`、`src/shared/api/` | 正式类型、请求、错误解析；不在页面内散写 URL 或猜测字段 |
| `src/modules/<分类>/pages、components、services` | 路由页面、业务组件、对应 service；操作状态按业务拆分 |
| `src/workflows/workflow-editor/` | 编辑器、专业节点 UI、Preview、Runtime/App Mode；共享显示适配而不是复制执行逻辑 |
| `src/platform/i18n/` | 中文与英文同步；专业名称保持统一，错误码转换为可操作的提示 |
| `tests/frontend/`、`frontend/web-ui/e2e/` | 状态/契约单元测试和浏览器真实交互回归 |

`DeploymentOperationsPage.vue`、`TriggerSourcePage.vue`、`CustomNodeCatalogPage.vue` 和训练详情等已有较大的页面文件。按操作块提取组件/composable 后逐块替换布局，不在一个提交内同时改完数据生命周期、全部 API 和视觉外壳。

设置原型 `docs/design/frontend/prototypes/settings/` 是设计证据，不是产品模块。迁移有用的布局和组件规则，不搬入模拟账号、假数据、第二套路由或鉴权。

| 分类 | 当前可复用 | 需要补齐/重点核对 |

| 图编辑 | 草稿/发布/历史、组与多选、专业编辑器、App Mode、三维查看器 | 节点库局部改进、配置/查看效果、专业节点交互缺口；不重建整页布局 |
| 应用 | 应用/版本/Runtime/调用/观察组件 | 多实例摘要、详情页签、配置变更、诊断、记录与未知结果恢复；不能用首个实例代表整应用 |

| 节点 | Catalog、包状态、校验、安装、启停、版本/审计/回退 | 目录/包/诊断的完整 UI、说明与依赖、权限；与节点库共用同一 Catalog |
| 设置 | 偏好、启动、服务、系统/Python/设备、会话/用户 | 细节规范、整体就绪摘要、异常与长内容；维护能力另行定义受控契约 |
| 任务/全局状态 | 任务列表/详情、Startup、登录、错误页面、路由门禁 | 新风格下的完整状态、返回业务入口、会话过期与权限变化、当前设计覆盖补充 |

具体已识别的接口问题：

- `project.service.ts` 的 `listProjects` 当前固定 `offset=0, limit=100`；后端项目列表已有分页参数，但当前读取后再分页。新增大规模检索时同时核对读取成本，不能只加前端翻页按钮。
- 项目路由已有 detail/summary，当前前端没有独立概览路由和编辑元数据 service；编辑不能借 bootstrap 覆盖身份或目录。
- `dataset.service.ts` 没有目标样本工作区所需的分页样本、标注和树结构契约。先复用已有导入结构/版本索引，不在浏览器扫描整个目录。
- 检测、分类、分割、Pose、OBB 等已有评估路由。报告字段、逐样本输出和可比较条件需逐类核对；模型页没有对应完整 evaluation service/界面，不等于后端没有评估功能。
- 当前 TriggerSource 路由有创建、查询、启停、删除、健康，缺少通用更新操作。实现编辑时补停止条件、版本校验和原子更新；更新失败保留原配置。
- 目录监听无需 SDK 调用配置，仍按普通说明省略。三维输入/结果的协议能力以最新代码为准，不沿用旧集成文档只列 image/value/text 的假设，也不推定所有协议都已支持点云。

新增持久化字段或索引须提供迁移、旧数据回填及失败处理；已有 dataset version、model artifact、application version 和 runtime ID 保持稳定。业务通过 Repository/Unit of Work 实现，不为页面直接拼 SQL。

## 6. 分阶段代码实施步骤

每阶段顺序固定为：**核对契约和当前行为 → 实现一条完整操作路径 → 自动检查 → 开发环境真实数据验证 → 亮暗/短屏核对 → 更新完成记录**。未通过的问题在本阶段修复，不带着数据错乱或生命周期问题进入下一分类。

### P0：冻结有效依据与回归基线

1. 记录开始实施时的 Git 提交、前后端/节点包版本、Catalog 和能力列表；检查工作区变更，保留已有用户修改。
2. 为首批项目页面建立场景映射，绑定设计文件及哈希、目标路由、组件、API、权限、关键状态与验证数据。后续分类开始时用同一格式补充，不提前编造全部 API。
3. 保存同主题、同视口、同数据的原页面参考，图编辑另固定流程、缩放和平移；记录现有用户流程和只读页面的请求数。
4. 跑当前相关测试，登记已有失败；核对准备好的连接器/标定/点云资源可读取，不改生产 Workflow 或部署配置。

完成条件：有效图、当前代码和未实现目标区分明确；首批页面每项操作有真实来源，受保护的 Runtime/Trigger/SDK 回归清单确定。

### P1：统一共享样式与交互容器

| 项目 | `/projects` | 新增 `/projects/:projectId` 概览；抽屉状态不另建孤立主页面 |
| 数据集 | `/datasets`、导入/导出详情 | 新增 `/datasets/:datasetId/versions/:datasetVersionId` 工作区，样本/筛选使用可恢复参数；保留旧记录深链接 |
| 模型 | `/models`、训练/转换详情 | 页签/筛选可回放，向导和评估详情按最终数据身份注册，不在 URL 放长 JSON |
| 部署/推理/应用/集成/节点 | 既有模块路径 | 页面重组保持资源 ID 和深链接，必要新增详情路由而非重命名全部入口 |
| 图编辑/Runtime | 当前 `/workflows/...` | 保留草稿、应用、运行实例身份；监视和 App Mode 不指向最新未发布草稿 |
| 设置 | `/settings?category=...&section=...` | 保留原分类定位与启动回跳 |

新增路径是实施建议，进入对应阶段先检查路由排序及冲突。浏览器后退应恢复有界的筛选/页码/选择，不使用无限期 KeepAlive 保存大图或全部响应。

### 8.2 状态职责

- 查询状态包含首次加载、已有数据刷新、空数据、无匹配、局部失败、无权和资源失效；后台刷新失败可以保留上次值，但标明时间/过期状态。
- 写入包含可提交、提交中、已成功、已失败、结果未知和冲突。请求超时不能直接认定服务端未执行；支持操作 ID 的查询原操作，不支持的先核对目标资源，禁止无条件重复提交。
- 多页编辑使用明确草稿；关闭提示取决于实际修改，不因打开过面板就确认。成功写入后更新对应资源快照，不只改本地标签。
- 页面/项目/资源变化时取消旧读取，用请求身份拦截迟到结果；不能取消已经受理的生产任务来清理页面。
- 所有列表明确分页范围、总数含义和选择范围；不能用当前页数量充当全量总数，也不能只筛当前 100 项却声称全局搜索。
- 大图、标注、JSON、点云按视图有界加载；避免把完整二进制深度响应式化或复制到多个 store。关闭/替换时释放 Object URL、监听、定时器、解码任务和 WebGL 资源，保留现有服务端租约/ACK 语义。

## 9. 验证方式与完成记录

### 9.1 自动检查

前端从 `frontend/web-ui/` 执行，先跑变更对应测试，再在阶段交付时完成构建；不因为修改一个颜色就重跑全套长任务。

```powershell
npm run typecheck
npm run test:unit -- <相关测试文件>
npm run build
npm run test:e2e -- <相关浏览器用例>
```

后端接口或结构变化从仓库根目录执行：

```powershell
conda activate amvision
python -m pytest <相关测试文件>
python -m ruff check <变更的Python目录或文件>
```

pytest 临时目录继续使用仓库约定的 `.tmp/pytest`，需要隔离时使用 `.tmp/<本阶段名称>`。确认本任务进程不再使用后清理临时产物；设计资产、验收结论不保存在 `.tmp/`。

优先复用现有测试：`tests/frontend/resources`、`models`、`deployments`、`auth`、`workflows`，以及 `frontend/web-ui/e2e`。点云保留 `test_cloud_preview.ts`、`test_cloud_viewer_lifecycle.ts` 等回归；API/Runtime/Trigger 使用对应已有测试，SDK 修改或协议影响时补仓库 .NET 测试。测试命令是后续步骤，不表示本轮重新执行过这些测试。

### 9.2 浏览器与业务检查

| 维度 | 必须验证 |
| --- | --- |
| 视觉 | 同数据亮暗、1920×1080、1366×768、短屏/缩放；导航与控件无裁切，抽屉底层零位移 |
| 操作 | 键盘、Tab/Esc、焦点归还、滚动、下拉层级、双击大图、路由前进后退、复制/下载 |
| 状态 | 正常、空态、无匹配、长内容、只读/无权、首次失败、刷新失败、提交失败/未知、冲突、取消竞态 |
| 数据 | 真实 ID/版本/单位/项目，图像与结果对应，缺失数据不补 0，删除/引用保护正确 |
| 性能 | 页面请求有界、无高频重复订阅；记录首屏/交互/大资源解码耗时，重复开关后资源回落 |
| 执行隔离 | Preview 与 Runtime/Trigger 同时使用；UI 打开/关闭不改变业务调用次数、模型实例数、结果或 ACK |
| 发行 | 本地构建资源、离线可用、深链接、CPU/NVIDIA 能力与错误可解释，无 CDN 和额外客户端 Node 依赖 |

首次建立相同工作流、数据、硬件、观察客户端数的性能基线，之后比较中位数及尾延迟、内存/租约趋势；有超出基线波动范围的变化先定位，再进入下一阶段。不凭设计图承诺固定毫秒值，也不把多客户端大图广播等既有边界写成已消失。

只读核对可使用现有资源；导入、删除、取消、回退、清理和安装等写入测试使用独立测试项目/实例/目录。对真实生产资源的回归保持可恢复，不能因验收界面而删改生产 JSONL、图片或运行配置。

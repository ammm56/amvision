# 图编辑中的应用模式 UI 设计

更新：2026-10-29。状态：规划与静态设计；没有修改产品代码、草稿或已发布Runtime。延续[当前图编辑基准](graph-editor-current-baseline.md)和已确认的亮暗配色。图编辑导航、顶部操作组、节点大小与连线保持当前实现。

## 1. 使用目的与边界

应用模式把Workflow已有输入和显示输出组合为现场操作界面。工程师在图编辑中配置，操作人员在Runtime应用模式中查看结果、必要时手动调用。不是另一套页面搭建器，也不在页面中重新实现计数、判定、图像处理或模型推理。

| 层次 | 提供的内容 | 不承担的工作 |
| --- | --- | --- |
| Workflow节点与连线 | 图片、表格、值、业务结论、统计、显示数据关联 | 不知道页面栏目位置 |
| 应用模式配置 | 页面标题、独立栏目选择、栏目标题、宽度、顺序 | 不改OK/NG规则、不增加另一套图片数据绑定 |
| 应用模式界面 | 显示结果、输入校验、手动调用入口、查看大图与详情 | 不根据图片数量累加产量、不在浏览器计算生产统计 |
| Runtime/Trigger | 执行已发布流程、返回结果、独立运行 | 不依赖页面开启或结果刷新速度 |
| 编辑器Preview | 草稿调试、异步逐节点结果 | 不能被运行页默认调用，也不自动更新生产Runtime |

## 3. 现场使用步骤

1. 在Workflow中连接图像、业务结果与显示节点。需要图片内数据时显式连接Value Display → Image Preview的Display Data；仅图片不连接。
2. 点击现有顶部“应用模式”，选择要显示的栏目，设置业务标题、宽度和顺序。需要额外数据面板时选择“单独显示”。
3. 点击“查看效果”检查排版。此为拟新增的只读效果预览，只使用当前配置草稿和已取得的预览结果；没有结果显示占位，不执行Workflow、不读取新增文件、不生成虚假结果。返回时保留表单。
4. “应用”只更新编辑草稿；按现有“保存 → 发布 → 显式更新Runtime”流程投入运行。不得将“应用”误标为生产生效。
5. 打开Runtime应用模式，接收该Runtime显示结果。外部Trigger照常工作；打开、刷新、重连、全屏和关闭页面都不会触发业务执行。
6. 需要人工运行时使用“手动运行”。有输入则打开输入面板，校验后执行；无输入直接单次调用。不添加前端排队、重复点击排队或自动重试。
7. 双击图片进入大图，保留对应图片及其显示数据；返回恢复栏目位置。

## 4. 应用模式配置

保留现有中心对话框，不迁移到右侧长抽屉，不修改图编辑工具栏。使用现有宽对话框尺度，最大高度视口减32px。标题与底部操作固定，正文独立滚动；遮罩统一覆盖导航和画布，不挤压或平移底图。

### 布局

- 顶部：应用模式配置、关闭。
- 页面标题：默认应用名，可修改。
- 显示栏目：每项一个紧凑配置行，正常字段不附长说明。
- 底部：左侧“移除配置”次级危险动作；右侧“查看效果”“取消”“应用”。移除仅移除应用模式配置，不删除节点或Runtime；确认后仍是草稿改动。
- “查看效果”不是执行按钮。表单无有效栏目时不可用；失效引用在对应行提示并阻止应用。

### 栏目行

| 内容 | 设计 |
| --- | --- |
| 显示开关 | 图片/表格/普通值使用“显示”；Value Display明确写“单独显示” |
| 名称 | 业务标题优先，不反复显示Image Preview、Body、内部ID |
| 标题输入 | 保留可编辑栏目标题；不重复绘制同样的大标题和输入 |
| 宽度 | 将“小/中/大”显示为“1/3行 / 1/2行 / 整行”，仍映射现有small/medium/large |
| 顺序 | 紧凑上/下移按钮，首尾禁用；同时提供可访问名称，不仅靠图标 |
| 图片内数据 | 显示“图片内数据：治具检测 · 定位”；纯图片显示“仅图片”；不提供第二套关联下拉 |
| 数据用途 | Value Display行只显示“随图显示：治具结果图”，另需独立栏目才勾选；关联很多时展开用途详情，不把所有ID塞进主行 |
| 定位节点 | 对话框有未应用改动时保留内部草稿，定位后返回不丢失；不能将定位操作变成隐式应用或丢弃 |
| 缺失/禁用 | “来源已删除”“关联节点已禁用”就地显示，提供定位/取消选择；不能静默过滤已配置栏目 |

同名输出优先使用业务标题；必须区分时提供次级来源详情，不永久显示技术标识。来源列表按Catalog和图连接生成，不硬编码Image Preview/Value Display之外的类型。

所有已选择栏目共享同一顺序，不能按图片/数据类型分开排序后再隐式拼接。未选择的独立数据面板集中在下方；勾选后该项加入上方已选栏目，提供同样的标题、宽度、上/下移操作，可放在任意两张图片之间。取消独立显示则返回下方候选区，图片中的关联数据不受影响。移动后焦点保留在同一业务项；禁用的是未选择栏目的标题/宽度输入，不是Workflow节点。此为目标交互，需原型验证。

### 显示规则真值表

| 图节点与关系 | 独立栏目选择 | 页面结果 |
| --- | --- | --- |
| Image Preview启用，未接Display Data | 图片选择 | 只有图片 |
| Image Preview启用，接启用Value Display | 图片选择，数据未选择独立显示 | 图片内数据正常显示，无重复数据栏 |
| 同上 | 图片与数据都选择 | 图片内数据 + 额外独立数据栏 |
| 图片未选择，Value Display启用 | 只选数据独立显示 | 只有独立数据栏 |
| 已配置图片的关联Value Display被禁用/删除 | 任意 | 配置标明失效，不能误当成正常纯图；已发布运行页局部报显示异常 |
| Value Display未连接图片 | 未选独立显示 | 不在该应用页面显示 |
| 一个Value Display连接多个图片 | 选择其中部分图片 | 只随选中的关联图片显示，数据来源/上下文仍由节点保障 |

“不勾选独立面板”不是关闭节点。图片是否带数据由显式连线决定，页面不提供含义相同的第二个开关。Results对象/测量结果绑定与Display Data文字叠加分别保留，不把对象检测列表当成产量统计。

## 5. 应用模式使用界面

### 常态布局

沿用现有导航组件。应用内容中一条紧凑局部操作行：业务名称、连接状态、最近显示更新时间，右侧为手动运行（有权限）、全屏、更多。没有新的全局顶栏、KPI仪表盘、状态说明横幅或固定参数侧栏。

更多中保留“刷新显示、运行监视、应用详情”；受原有权限控制。刷新只刷新显示连接，不运行流程。正常显示短状态词，详细错误才展开说明。全屏为拟新增的显示行为，不改权限或持久化页面配置。

主体按配置排列栏目：
- 宽屏12列：1/3行占4列、1/2行占6列、整行占12列；顺序不自动改变。
- 2张常用图片可并列；3张图片可由工程师配置为3列，也可保留2+1。不能把现有3个medium配置静默改成small。
- 栏目标题使用业务名；图片保持contain比例，不能裁掉边缘检测区。查看大图按钮与双击均可到达。
- 图片内数据在左上角，默认半透明垂直排列：OK/NG、生产总数、良品数量、不良数量、良品率。字段并非写死；连接器可显示测量值/公差，其他场景按Value Display字段配置。
- 字色、字号、状态字号、面板尺寸、背景与透明度沿用Value Display。亮暗切换不改用户明确指定的检测颜色；未指定时继承主题。
- 未关联图片不生成统计面板。数据面板不是写入图片的像素，也不影响模型输入、坐标或计量值。
- 表格/JSON/文本/图库各自使用已有渲染器；大数据有界预览与滚动，长JSON进入详情，不占满主页面。

### 结果身份

界面至少区分“连接正常”“正在执行”“执行结果”“显示更新时间”。NG是业务结果，不表示服务故障；实例满载是本次调用容量拒绝，不是未就绪。

图片与数据按同一结果身份组合。大图打开后固定当前结果，新结果到达提示“有新结果”，不在缩放测量时自动换图；显式查看最新后整体更新。此行为为目标设计，需实现验证。

显示Workflow可能从磁盘读取不同生产流程的最近记录。显示Workflow运行时间不等于原始拍摄/生产记录时间；若业务数据未提供来源时间或条码，就不能编造“刚检测”。跨来源栏目不宣称是同一工件，查看详情时保留各自来源标识。

新结果的图片解码未完成时，旧结果保持“上一结果”标识或局部等待；不能把新数值配上旧图。缺测显示“—/无结果”，实际0正常显示，未判定不显示OK。

### 手动调用

- 无公开输入：按钮发起一次调用，不保留“此Workflow没有输入”的独立占位区。
- 有公开输入：右侧打开可关闭的“手动运行”输入抽屉，底层结果不重排；正文滚动，执行按钮固定。
- 输入顺序、必填、格式、大小及传输方式遵循公开契约；常用值字段优先友好控件，复杂对象仍可JSON输入，不能自行改变payload。
- 文件上传不等于服务端路径；默认显示业务输入名，技术引用方式放入明确选项。
- 当前手动请求提交后按钮防重复；关闭面板、页面或刷新不等于取消已提交的运行。超时且执行状态不明时标明“结果未确认”，不自动重试。
- 有权限才显示调用入口。只读用户不出现伪禁用执行表单；UI隐藏不能代替后端权限校验。

## 6. 必需页面与状态

| 画面 | 必需状态 | 设计/验证重点 |
| --- | --- | --- |
| 配置对话框 | 首次、已有、多栏目、无候选、无选择、同名、长标题 | 固定底部、不堆技术文本、返回草稿不丢失 |
| 关联配置 | 纯图、随图、另加独立、多目标、失效/禁用 | 由连线决定，无双重开关 |
| 查看效果 | 有已有预览、无结果、旧结果、返回配置 | 不执行、不假造、不写生产记录 |
| 结果主界面 | 单图、多图、纯数据、图库、图片+表格 | 图像比例、业务字段、独立更新时间 |
| 手动运行 | 有/无输入、校验错误、执行中、满载、超时 | 立即调用、无队列、无自动重试 |
| 结果大图 | 普通、缩放、叠加收起、新结果到达 | 同一图片数据、返回位置、键盘与显式按钮 |
| 运行与显示异常 | 未配置、等待、服务停止、连接中断、局部图片失败、结果过期、权限不足 | 不将慢执行判定离线、不用NG代表服务失败 |
| 短屏/长内容 | 1280×720、1366×768、125%/150%、长JSON、多字段、多图 | 不整体缩小字号、滚动不遮操作 |
| 专业扩展 | 测量表与几何叠加、瑕疵热图、未来3D/点云 | 复用栏目和显示契约；不把未来节点画成已可用 |

## 7. 字体、颜色、尺寸

复用当前tokens与组件：品牌主色#00D992，亮色白/浅中性表面，暗色深中性表面；普通hover和输入焦点使用中性灰。主体文字常规字重，标题与重要结果适当强调，不全部加粗。主按钮白字；危险动作红色，正常状态不展示大段解释。

配置行控件约32–36px，正文14px，辅助12–13px。触控屏需要保证按钮命中区域；桌面图标可紧凑但不能以小命中区假装触控支持。正文独立滚动，Esc/关闭/Tab焦点恢复列入验证。主题色和透明叠加在亮暗图片上的对比仍需实际素材核对，不能仅凭图稿宣布可访问性达标。

## 8. 实现与验收顺序

1. 固定配置语义：现有displays选择/顺序/size及显式Display Data关系。先以真值表核对现有测试，不扩大后端执行范围。
2. 配置UI：紧凑行、业务标题、固定底部、宽度直观文案、失效就地反馈。复用ConfirmDialog/Select；查看效果作为只读会话，不增加默认执行。
3. 运行UI：结果区优先，手动输入按需打开，全屏与更多入口；保留权限和公开契约。
4. 统一结果与大图：同次结果组合、更新提示、无结果/过期/局部错误区分；分离服务健康、执行状态和业务OK/NG。
5. 专业结果：复用现有图像/表格/几何显示，扩展节点能力按版本契约加入；不能由App Mode加载模型或复制算法。
6. 实测：真实配置只读核对 → 隔离草稿验证配置 → 合成数据确认纯图/关联/独立 → Preview与Runtime分别验证 → 短屏/亮暗/键盘 → 前后性能与资源释放比较。

现有metadata.app_mode配置本轮不新增持久化字段，small/medium/large只改显示名称；查看效果、输入抽屉、全屏为页面临时状态。若后续新增公开配置字段，必须明确契约与迁移，不静默改变已发布版本。

UI显示订阅继续沿用现有结果通道。连接重试只重建显示订阅，不重放业务调用；Runtime/Trigger同步高性能数据面、模型容量拒绝和资源生命周期不由本设计改造。显示图维持既定JPEG策略及关闭WebSocket压缩要求，不把显示图用于计量。

## 9. 出图顺序与当前状态

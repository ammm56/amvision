# 前端设计图生成准备

状态（2026-10-23）：原项目四图确认结论见[历史检查记录](master-review-2026-10-23.md)，当前参考见[设计总览](generated/项目/设计总览.html)，新版待审阅。数据集管理、部署导入、触发详情此前新稿已被否决，见[记录](resource-pages-review-2026-10-23.md)。保持简洁平级导航、无独立顶栏；图片清理状态见[最新检查](project-complete-design-review.md)。

## 1. 目标和依据

最新进度：中文提示词已覆盖全部 45 个规划场景，D01 数据集主页面亮暗稿已生成并完成内部检查，尚待用户审阅；见[恢复与检查记录](prompt-restoration-review-2026-10-23.md)。不将内部检查等同于用户确认。

旧提示词已整理恢复为[中文页面提示词](prompts/README.md)，历史来源与编号对应见[恢复记录](prompts/历史来源.md)。每次实际发送“通用要求＋本页提示词＋主题与状态”，正文全部中文，专有名称英文；先核对对应旧图和页面规格，再生成图片。原英文请求仅作生成历史，不是当前规范。

目标是一套可由现有 Vue 3 工作台实现、跨页面一致的工业界面，不是为 59 张旧图各自换皮。需要保持信息密度、图像可读性、操作确定性和亮暗一致；简化重复标题、ID、解释文字和不必要装饰。

依据顺序：最新用户要求 → `bak1` 合理页面设计与真实功能核对 → 外壳及局部错误修订 → 统一风格母版 → 具体页面图。当前页面主要用于核对功能和参考简洁导航；不能忽略旧图中正确的内容结构。已否决的新批次和历史 archive 不作为风格来源。

功能缺失或不明确时，先记录“规划/待核对”，依据目标规格设计交互；正式节点名、接口、模型组合和执行状态须有契约来源，不能编造可执行性。外观修订与功能新增分开记录。

## 2. 保留约束与重新设计范围

| 项目 | 本轮统一规则 |
| --- | --- |
| 外壳 | 左侧导航 + 页面内容，无独立全局顶栏；保留旧稿合理主体；右侧详情/配置是抽屉，补关闭/展开状态 |
| 导航 | 参考当前简洁平级形式，无分类标题；撤销五入口合并及新增项目选择，不按行业增加入口 |
| 品牌 | 展开 AMVAR+动态词缀，静态图固定 Vision；收起 AM 图标。关于页才使用小写、普通字重、无词缀底色 |
| 标题 | 不恢复普通页 h1、空标题高度和设置二级导航顶部“设置”；保留资源/对话框/节点必要名称 |
| 主题 | 同页亮暗成对；只替换 token，不重新排列布局或更换数据；画布和属性面板同时适配 |
| 色彩 | 品牌 #00D992；主按钮白字；普通 hover 中性灰；selected 品牌软底；输入 focus 中性灰。完整数值见设计系统及 tokens |
| 字体 | 使用可离线分发的统一字体系统；字体、字号和字重按新视觉方案设计，保持工控机可读性，不引入 CDN 依赖 |
| 密度 | 4px 间距体系，常用 8/12/16/20/24/32；控件约 36–40px，常规行 44px，两行信息 56px，长内容重排不缩成小字 |
| 形状 | 4/6/8px 圆角，轻边框；阴影只用于浮层。避免给每段文字套大卡片 |
| 图标 | 复用 Lucide 线性图标；同一操作同一图标，不使用随机模型商标、彩色立体图标 |
| 图像 | 工业图像占主要空间，尺寸/比例不变形；叠加与用户配置色独立，不全染成主题绿 |
| 动效 | 静态图表达终态；保留已有品牌/局部面板规则，不增加页面过渡或持续状态闪烁 |

以上密度数值是统一出图目标，不宣称所有现有组件已经一致。若母版检查要求改变某项，全批更新同一规则，不能只修单张图。品牌白字对比度风险单独记录，不私自改回旧暗绿。

## 3. 母版与出图顺序

| 阶段 | 产出 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：准备 | 旧图保留内容、风格差异、功能错误、导航与顶栏修正、样例数据 | 明确哪些保留、哪些修正，不推翻全部旧图 |
| B：母版 | 修订后的普通工作台亮暗图，分别含抽屉关闭/展开；随后编辑器和控件状态板 | 无独立顶栏、无导航分类，右侧不是常驻详情列；亮暗与各页风格一致 |
| C：代表场景 | 数据集管理与样本工作区、部署导入、触发详情、专业节点配置、App Mode 大图/3D | 同一表单/抽屉/结果显示语言可复用；窄屏不截操作、不溢出 |
| D：页面覆盖 | 按下表扩展页面与必要状态 | 每张图有明确场景和原型依据；同类结构复用已确认母版 |
| E：复核 | 图像清单、逐图检查记录、修订对照 | 文案/字段/操作/连线可核对；不以设计完成代替前端验收 |

不一次性批量生成几十张。母版和代表场景检查通过后再扩大范围，避免风格误差被复制到全部页面。状态板可并列多个控件；业务图一张只展示一个明确页面状态，不拼成难读的海报。

## 4. 页面与状态清单

完整 ID 与逐页内容统一维护在[设计覆盖清单](frontend-design-roadmap.md)，不再并行维护另一套编号。该清单覆盖当前导航功能及子页、数据集标准管理、异常/连接器/3D 专属 UI 和共用结果展示；功能域分类不直接出现在侧栏。

本轮先完成全部页面文档和中文提示词的覆盖核对；出图从 D01 数据集主页面的亮色、暗色配对开始，先核对旧稿合理结构与最新版本管理边界。原项目四图的历史确认状态不变；当前中文重生成稿尚待审阅，见[重生成记录](project-regeneration-review-2026-10-23.md)；其后逐页推进 D02/D04、R01、X01、G02/G03、V02、W06/W07，再补其余场景，不复用已否决批次。

保留现有对话框/抽屉的职责；明确新增的长时间工作区可作为目标页面出图，例如 D04 样本工作区，不假称已有路由。权限不足、无项目、无记录、筛选无结果、加载、断线、部分失败按适用场景覆盖，不机械复制到每页。

## 5. 重点场景的内容规则

### 表单和结果展示

- 标签、控件、帮助/错误分别对齐，字段间距由组件统一；长路径可展开或复制，不能撑破对话框。
- 下拉同时检查收起值、展开菜单、hover、selected、键盘 focus、disabled；多选标签中性，勾选使用品牌色。菜单不能被节点或抽屉裁切。
- JSONL 汇总的单批记录数、MB、整数秒使用当前字段与单位；不是整个日志大小上限。Source Path 保持字段提取语义，不解释成文件路径。
- App Mode 统计面板左上垂直排列、半透明；字段颜色/字号/面板大小由 Value Display 配置。独立面板选择不等于禁用节点，图片关联只由连线决定。
- 检测结果 OK/NG 与服务健康分开；次数、物料数、检查项数分开，不能把多个尺寸失败当作同数量物料 NG。

### 图编辑与计量

- 使用当前 Catalog 的实际节点名和端口；需要出图的连线先核对 Workflow 文档，不根据视觉布局编造可执行图。
- 参考图用于建立配方，待检图用于本次观测；标定单位、坐标和资源版本有明确入口。标定失败/过期不能显示可保存或可测量。
- 表格当前行与图片几何使用同次结果；缺失值为缺测，预期位置不冒充实测边缘；无图/无结果不能补旧帧。
- JPEG 为展示图，原始图用于算法。界面例子的耗时、准确率或测量数值必须来自指定样例，不能生成好看的性能结论。

## 6. 资源与文案准备

通用记录使用固定、已脱敏的同一组项目/应用名称和状态；亮暗/宽窄版本保持数据一致。真实工作流优先只读截图或导出副本，不为了构图触发生产保存、发布或磁盘清理。

连接器开发图、标定图和资源说明见[开发资源](../../development/connector-development-assets.md)与[工程示例](../../examples/workflows/connector-inspection.md)，本地目录为 `data/development/connector-inspection/synthetic-v1/`。下一轮生成前确认实际文件与版本，明确标注为合成开发样例，不把渲染真值称为独立实物参考量值。

已有产品文案从当前 i18n 和节点 schema 摘取；新增页面文案先在目标规格固定。普通动作随语言切换，模型名、协议、必要技术词不生硬翻译。第一批用简体中文，节点名/参数保留现有约定；代表表单追加英文长文案检查。不在图片里随意混写半中文半英文句子。

异常检查需准备正常/异常/未知及缺少 mask 的开发样例；3D 需准备带明确单位/坐标的点云、已知几何与异常样例。未就绪时只能绘制结构性规划图，不能虚构正式节点名、测量值或验收状态。参考图、合成真值与实物量值在素材清单分开登记。

## 7. 分辨率、文件与记录

- 主要工作站设计以 1920×1080、100% UI 尺度为参照；1366×768 为窄屏检查，连接器关键对话框追加 1280×720。每张图注明导航展开/收起和打开的浮层。
- 区分设计视口与输出图片实际像素。工具无法精确输出时如实记录两者，不能改文件名冒充分辨率；目标像素的真实截图在可运行实现阶段完成。
- 新图按直观页面类型保存，例如 `generated/项目/项目列表-亮色.png`、`generated/项目/新建项目-暗色.png`；其他页面使用数据集、模型、部署、集成等名称。日期、内部编号、实际尺寸与修订放入清单，不用抽象批次名替代页面类型。不得覆盖 `bak1`。
- 批次清单记录 ID、所属页面/组件、当前/扩展/规划属性、状态、主题、设计视口、实际尺寸、母版版本、源码或目标规格参考、样例来源、文件 SHA-256、审核结论和已知偏差。清单不写密钥或个人数据。
- 文件状态区分“待审/需修订/视觉确认”；视觉确认不等同于功能、性能或实物计量通过。Git 忽略的本地图片如需团队交付，应另行纳入明确资产备份流程。

## 8. 每张图的检查清单

1. 当前图核对路由/容器；目标图注明规划属性和规格来源。模型、字段、操作、节点和状态不被误表述为已交付。
2. 与母版导航、品牌、字形、间距、行高、圆角和主题一致；不混入旧深绿色。
3. 页面没有被隐藏的大标题/空标题高度；没有重复 ID、无意义拓扑说明或装饰 KPI。
4. hover、selected、focus、disabled 可以区分；失败不与容量拒绝混淆，颜色不是唯一提示。
5. 目标尺寸下文字可读、图片不拉伸、控件与列表不重叠；长内容滚动位置合理，底部操作可到达。
6. 危险操作说明准确，记录删除与资产删除分开；错误提示清除不冒充资源清除或重试。
7. Preview、Runtime、Trigger 的功能边界保持一致；无隐式保存、重复模型加载、业务队列或自动重跑暗示。
8. 合成图、示例数值与真实验收数据清楚区分；测量项、NG 数和产量不混算。
9. 与同一页面的另一主题和窄屏版本并排核对；不只检查单张图是否好看。

图片生成常见的错字、错误图标、错连线和缩小字体需要单独修订。需要精确文本、数据或可交互检查时，使用后续 Vue 原型与浏览器截图，不能把生成图片当作像素级实现契约。

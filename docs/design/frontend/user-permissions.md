# 用户权限与启动页面设计

状态：已实现并完成开发页面验收。边界见[通用权限设计](../../development/user-access.md)，执行证据和未验收项见[实现与验收](../../development/user-access-implementation.md)。复用现有 Vue 页面、控件和应用模式。

## 1. 使用流程

管理员在用户管理创建账号，填写账号并勾选页面、操作和项目范围。用户登录后进入现有“设置 → 启动页面”，自行选择项目和 Runtime，保存启动目标，以后打开原应用模式。

没有权限预设、管理员代选启动应用、专用应用选择页或按应用数量自动跳转。页面许可、业务操作和个人启动选择分别生效。

## 2. 用户管理和共用表单

保留当前列表、详情、创建对话框。详情显示页面、操作、项目摘要，增加“编辑权限”，auth:write 才能提交。

创建框顺序：

1. 用户名、展示名称、密码。
2. 页面权限：按原导航分组复选框；设置展开到启动页面等子页；Workflow 分列图编辑、应用管理、Runtime 监视、应用模式。
3. 操作权限：按业务分组，Workflow 列“查看工作流”“执行工作流”“管理工作流”。管理包含原保存/发布/删除及 Runtime/Trigger 管理；项目组增加“查看项目文件”，短说明明确包括授权项目的公开输入、结果、数据集版本及导出文件；其他模块按真实查看/管理能力显示。
4. 项目范围：指定/全部项目，可搜索选择，重名补短 ID。
5. 原长期 Token 可选项，默认不勾选，管理员需要时明确开启。
6. 取消、创建用户。

新建不默认授予业务权限。页面/操作使用折叠分组，长内容内部滚动，不加预设选择器或多步向导。主要标签用业务名称，原始 scope 放技术详情；旧未知值保留并标明未登记，不自动扩大权限。

页面勾选不自动增加管理权限。缺少页面最低读取权限时就地提示，管理员明确补齐后才能提交矛盾组合；无页面但有 API 能力合法。执行依赖查看时明确提示最终需勾选的内容。指定项目为空禁止提交，加载失败不能误提交全部项目。

编辑权限复用表单，仅页面、操作、项目，无密码/状态/Token/启动应用配置。防重复保存，失败保留输入，并发冲突提示重新载入；取消/Esc 不写入、不备份。最后管理员保护由后端执行。

## 3. 导航和设置

显示已授予且满足最低读取能力的页面。设置父入口按有权子页派生，URL、查询参数、别名和页内跳转使用同一策略。只授予启动页时，设置中只显示启动页面，不额外请求用户、Token、诊断或系统配置。

应用模式保持原页面和工作台入口，不新增侧栏业务模块。保留有权的设置入口，用户可以返回修改自己的启动选择。初始化不闪现全菜单，账号切换清理旧身份内容，登录/退出/无可用页面始终可用。

## 4. 原启动页面

保持 `/settings?category=startup`，复用启动方式、项目、Runtime、保存和恢复默认控件。

- 只显示有权的启动类型和目标；没有项目首页权限不提供该首页选项，但可在授权项目内选择 Runtime。
- 未选择时进入本页（有权时），由用户自行选择，不自动选唯一应用。
- 保存只修改当前账号的 localStorage JSON，不修改工作流或 Runtime，不要求 workflows:write。
- 恢复默认回到有权默认入口，不固定 /projects。删除/失权提示重选，短暂故障保留原选择并重试。
- 无候选和加载失败分别显示；停止的已配置 Runtime 沿用原行为，不自动启动。

## 5. 原应用模式

保留现有工具栏、输入、结果布局、图片/JSON/表格/图库和显示流。页面与 workflows:read 控制查看，workflows:invoke 或原 write 控制运行；隐藏无权管理入口和跳转。

无执行权限隐藏运行，输入按原布局作必要只读处理；有执行权限的输入只属于本次检测，不写回节点参数。运行依据授权、Runtime 状态和输入有效性，不新增显示 WS 连接前提。

断线标注实时结果暂不可用，保留上次结果，恢复不重发检测。外部 Trigger 最新结果和本次调用状态分别处理。Runtime 停止只显示状态，账号退出、页面关闭或权限刷新不停止后台服务与已接受任务。

## 6. 登录、样式与验收

仅有 amvar 沿用原自动登录，有其他用户则手动登录；正常手动 Session 仍恢复。默认全权限永久 Token 与第三方/.NET SDK 调用不变。

沿用原创建框最大 760px、间距、圆角和主题 token，复用输入、下拉、复选框、按钮。长内容滚动、页脚可见，不另建视觉系统；亮暗切换不重建表单，保留焦点、键盘和减少动画能力。

验收覆盖手动勾选创建/编辑、摘要/取消、导航/直达、用户自行保存和恢复启动目标、跨账号偏好、目标失效、查看/执行/管理分离、真实输入显示和断线。检查亮暗主题、1024×768/1366×768/1920×1080、125%/150% 缩放，无裁切、闪烁或遮挡。

上述流程已落地；追加自动化、九组浏览器等效视口、亮暗主题及日语/韩语结果见[专项验收记录](../../development/user-access-acceptance.md)。最小视口的 App Mode 保留输入/结果最小高度并滚动显示。实际 Windows 125%/150% 系统缩放与浏览器等效视口分别记录，不能用后者替代前者。

## 7. 本次页面核对与细节补充

已在内置浏览器使用受限开发账号，完成启动目标选择与真实 24 工位模型检测。左侧仅显示有权设置入口，应用模式保留刷新、运行、输入和结果，无 Runtime 管理或应用管理跳转。图片按区域等比显示，JSON 独立滚动，避免大图占用相邻结果区域。

创建/编辑表单包含页面与操作两个折叠区域，分别提供全选/清空按钮和逐项复选框；全选只选当前登记项，不自动合并成 *。已有 * 账号保留明确“全部操作”状态，改变授权由管理员明确勾选。内容区域滚动，标题、取消和提交按钮固定可见；项目提供指定/全部切换与搜索。

“查看项目文件”未勾选时，不阻止纯 JSON 或内联图显示；请求项目图片/文件失败时在对应区域提示缺少读取权限，不提示工作流执行失败。文件读取能力独立于模型查看和页面可见性，说明不得声称仅能读当前 Runtime 图片。

启动设置恢复默认采用当前账号有权的默认落点；未配置时显示待选择，而不是预填无权的项目首页。已有 v1 启动 JSON 迁移到账号隔离的 v2 后保持已授权的用户选择；不替用户自动选唯一应用。输入与下拉缺权限、无候选、加载失败、保存中分别使用既有状态样式。

# 前端完整页面内容规划

更新：2026-10-22。性质：目标设计，尚未实施导航重排或新页面。当前页面事实见[信息架构](information-architecture.md)和[当前页面规格](page-specifications.md)。本次扩大设计范围，允许规划尚未实现的标准功能；不能把目标图当作当前功能截图。

**导航和布局以[修订方案](frontend-redesign-plan.md)为准：参考当前简洁平级导航，无独立顶栏；以 `bak1` 中合理页面为基础，右侧详情按抽屉理解。本文保留完整功能清单，表中的功能域不出现在侧栏。**

## 2. 功能覆盖与导航重设计

下面按功能域整理能力，不代表侧栏分组。上一轮五项主导航的合并方案已撤销，本轮参考当前平级导航。旧图大部分合理页面设计继续保留，主要统一风格并修正明确错误，不将全部内容强制重排。

| 功能域（文档分类） | 当前入口 | 当前入口路径 | 页内类别 / 子导航目标 |
| --- | --- | --- | --- |
| 工作空间 | 项目 | `/projects` | 项目列表；“查看”进入项目概览（目标 `/projects/:projectId`）；SDK 配置包 |
| 工作空间 | 任务 | `/tasks` | 全部任务；按类型/状态筛选；任务详情 |
| 数据与模型 | 数据集 | `/datasets` | 数据集/版本列表；导入/导出记录；查看 → 样本、标注、数据结构 |
| 数据与模型 | 模型 | `/models` | 模型与训练；转换与导入；验证与评估 |
| 工作流 | 图编辑 | `/workflows/graph` | 画布；节点目录；属性；预览；应用模式配置；版本历史 |
| 工作流 | 应用 | `/workflows/apps` | 应用列表 → 应用版本、运行实例、运行记录；实例 → 监视 / 应用模式 |
| 工作流 | 节点 | `/custom-nodes` | 节点目录；节点包；问题诊断 |
| 运行与集成 | 部署 | `/deployments` | 部署实例；创建/导入；实例详情与控制 |
| 运行与集成 | 推理 | `/inference` | 单次调试；异步任务及结果；输入/可视化/结构化结果 |
| 运行与集成 | 集成 | `/integrations/trigger-sources` | 触发入口；输入映射；结果绑定；入口详情 |
| 系统 | 设置 | `/settings` | 偏好；启动页面；运行状态；系统环境；访问控制 |

表中的类别不是全部新增路由。分类筛选、短参数表、详情抽屉保持页内组织；长时间样本审阅、复杂结果查看才使用独立工作区。模型的三个页内类别为目标重组，当前 `/models` 仍是原工作台。

### 导航交互与尺寸

- 不显示此前五个分组标题；常用任务尽量单击可达，避免过多嵌套和重复入口。
- 导航展开/收起参照当前简洁形式，使用真实字体和窄屏核对，不沿用被否决图的宽度比例。
- 品牌、折叠与底部用户区固定，中间导航独立滚动。720/768 高度容纳不足时滚动，不压缩字号或遮挡末尾入口。
- 当前项品牌选中色，普通 hover 中性灰，输入 focus 中性灰；不重新引入页面切换动画。
- 按权限过滤入口，整合后的导航不扩大权限；直接 URL 仍由路由和后端授权。
- 导航 active 继续按当前路由归属：图草稿属于图编辑，App/Runtime 属于应用，推理和节点保留对应入口，训练/转换/评估属于模型。同一时刻只激活一个入口。
- 保留 URL、权限和公开资源 ID；不新增全局顶栏、项目选择栏或 KPI 首页。

## 3. 每个页面的内容与职责

下表和各节定义完整目标内容。“已有入口”不表示其全部目标动作已实现。规划动作只有在对应服务契约、权限和错误处理具备后才出现在产品中，不摆放无法使用的占位按钮。

### 3.1 项目

**已有列表入口，新增独立项目概览。** 列表保留简洁资源摘要和“查看”；查看进入目标 `/projects/:projectId`，包含项目名称、数据集/模型/应用/部署入口、最近更新、当前运行和继续工作。不增加左侧导航项，也不强制成为启动页。创建、编辑、补充信息与 SDK 配置使用各自短表单、抽屉或对话框；完整概览不挤入列表抽屉。详见[项目查看页面设计](project-overview-design.md)。

当前代码仅有 `/projects`，行点击为选择项目，没有上述独立路由；模型实体计数、最近更新清单、元数据更新和项目深链接均需按专题补齐。项目列表设计中的更新时间也需要可靠来源，不能用摘要生成时间替代。

项目操作统一为：新建/项目信息/编辑使用右侧覆盖抽屉，SDK 配置包/删除使用居中对话框；各状态和契约差异见[项目分类完整设计](project-pages-design.md)。删除的 `cleanup_pending` 与文件清理完成分开显示；两字段新建表单必须先补稳定 ID 分配，不能直接调用仍要求 ID 的当前接口。

项目分类已复核 14 张现行稿，见[审查与补全](project-design-audit.md)。完整范围为 2 个主页面、3 类抽屉、2 类对话框；不新增项目子导航。当前项目识别、菜单、空态、权限、保存/删除结果不明及短屏等按[状态清单](project-pages-design.md#11-完整状态覆盖清单)设计，不能把图像齐全等同于操作链路齐全。

- 数据集、模型、应用等入口携带明确项目范围；项目没有资源时显示创建/导入入口，不展示假统计。
- SDK 配置包显示支持的部署、Runtime 和调用型 Trigger；目录监听由后端执行，省略配置是普通说明。
- 删除预检展示真实依赖和影响；生成配置包失败与运行服务失败分开。
- 项目选择用于业务范围，不改变资源所属项目。只读用户不能看到可写操作；跨项目切换不得混用上一项目的缓存、参数草稿或结果。

### 3.2 任务

**已有列表与详情，统一任务类型入口。** 列表包含名称/所属业务、类型、项目、状态、阶段、时间和详情。筛选项来自注册任务类型，按真实服务分页。

- 类型包含已注册的导入、导出、训练、评估、转换和异步推理；以后新增数据检查或离线处理任务时复用同一结构。
- 详情分“概况、进度与指标、产物、事件/日志”；不同任务只显示实际有的数据。训练详图仍返回模型页，避免两套控制逻辑。
- 显示取消能力、取消中和真实终态；未知总量显示阶段，不伪造百分比或 ETA。
- Deployment、Runtime、Trigger 是常驻实例，不放入有限任务队列。同步调用失败不自动变成重试任务。

### 3.3 数据集

**当前已有导入/导出和部分版本管理；完整目标重新设计。** 默认主页面是数据集列表，局部标签为数据集、数据集版本、导入记录、导出记录。管理直接在主页面完成，“查看”进入指定版本工作区；不把现有对话框作为未来管理入口的限制。

目标版本工作区分“样本、数据结构、类别与划分、质量检查、版本与来源”。缩略图与大图直接叠加标注，对象表与图像联动；目录和文件可定位关联样本，提供筛选、问题定位及外部标注交接。页面与容器见[最新数据集方案](dataset-pages-design.md)。数据格式、不可变版本、删除边界与新增页面契约见[数据集完整设计](dataset-management-plan.md)。

### 3.4 模型

**已有训练/转换工作台与详情，目标页内三个类别。** 不为每一种算法新增导航；类别、系列、尺寸、运行时等由能力矩阵约束。

| 类别 | 内容与操作 | 状态 |
| --- | --- | --- |
| 模型与训练 | 可用预训练引用、项目模型/版本、训练创建与任务列表；版本详情显示数据来源、参数、指标和文件 | 已有，整理层级 |
| 转换与导入 | 选择模型版本及转换目标、转换任务列表；下方为模型导入区域和记录；构建文件详情 | 已有，整理层级 |
| 验证与评估 | 选择模型版本、数据版本/划分和评估配置；评估记录、指标、按类结果、错误样本 | 页面规划，依任务类型核对已有 API |

- 模型版本、转换产物和部署实例互相链接，不能把 ONNX/TensorRT 文件当作新训练版本。
- 训练详情保留曲线、设备、日志和 checkpoint；评估工作区显示任务特定指标，不能把 AP、异常分数、重复性统一叫“准确率”。
- 版本比较仅比较兼容任务、指标定义、数据与配置；不支持的比较说明原因。
- 异常检测若需要训练，由注册的训练后端和模型运行时提供入口；现有参考差分/统计变化节点不伪装成已接入的异常学习模型。
- 预训练文件仍按平台资产管理；不因模型导入页面而新增任意预训练模型上传体系。

### 3.5 图编辑

**已有主工作台，扩展专业节点 UI 与结果类型。** 中间画布、左侧节点选择、右侧属性、节点内预览和专属编辑器保持一致结构。节点库按能力筛选，保留 Core / 节点包来源。

- 页面工具：应用名称、保存、预览、发布、应用模式配置、节点组与历史入口；保持实际支持的操作，不补不存在的全局撤销栈。
- 属性：输入来源、参数、资源选择、配置校验；短参数直接显示，复杂 ROI/阵列/尺寸/点云区域进入节点专属编辑器。
- 预览：公开输入、本次执行进度、逐节点结果、错误定位；临时结果和已保存配方分开。
- 资源：参考图、标定、模板、规则/配方、点云参考的项目内选择、版本与依赖；资源编辑从节点进入，目标为共享资源选择器/管理区域，不新增行业资源中心。
- 发布：列出节点包、资源和公开输入输出依赖；区分草稿、发布快照、当前 Runtime。缺少包、标定、模板或资源失效时在对应节点定位问题。
- 异常检测、连接器、3D 的具体操作与组件边界见[视觉工作流扩展设计](workflow-vision-ui-plan.md)。

### 3.6 应用

**已有列表、详情、运行监视和应用模式。** 列表显示名称、发布与运行摘要、更新时间，完整 ID 在详情。旧图右侧的详情/配置按抽屉展开状态设计，不强制常驻分栏；编辑仍进入完整画布，已有独立应用详情路由继续保留。

| 区域 | 目标内容 | 关键边界 |
| --- | --- | --- |
| 应用详情 | 草稿入口、发布版本、来源、版本比较、运行实例、关联触发入口 | 草稿修改不自动切换运行版本 |
| 版本 | 不可变版本及依赖、载入历史、归档与允许的发布动作 | 历史载入进入草稿，不直接覆盖运行实例 |
| 运行实例 | 版本、状态、设备/依赖、启动/停止、自动启动、详情、监视/App Mode | 忙碌与满载不是未就绪 |
| 运行记录 | 本次结果摘要、时间、耗时、错误、来源和可用产物 | 不承诺永久保存未显式保存的图片/点云 |
| 运行监视 | 发布画布只读观察和结果定位 | 不复用编辑 Preview 的逐节点状态语义 |
| 应用模式 | 公开输入和配置的图片、值、表格、图库，以及未来 3D 栏目 | 同一发布配置；不建立独立页面设计器 |

图片/3D 与数据叠加必须显式绑定，独立显示栏目选择与节点执行开关分开命名。双击扩大保持同一结果与绑定数据。生产记录仍由保存节点写入明确磁盘路径，统计读取/计算/展示由节点组合；本页面不引入通用 MES 或生产数据库。

### 3.7 节点

**已有节点目录、节点包、问题诊断三个标签。** 目录显示名称、类别、来源、输入输出摘要、版本、详情；内部 type id 可搜索/复制，在详情展示。

- 能力分类采用输入输出、图像、几何计量、规则数据、模型、文件、协议、3D 等功能维度；包来源是另一筛选维度，不能把某一行业标签当作全局算法类别。
- 节点详情包含用途、端口/单位、参数、示例、包来源与限制。图编辑内插入入口直接回到同一目录定义，不维护两套节点说明。
- 包页包含版本、依赖、启用、能力和引用；诊断显示加载失败、缺依赖、schema 不兼容及具体修复入口。
- 连接器专用节点在对应扩展包；通用算法、采样、测量、文件、显示组件不带固定 PIN、托盘或产品规则。

### 3.8 部署

**已有实例列表、导入、配置与详情。** 首屏聚焦模型、运行时、设备、实例数、实际状态及操作。导入配置与资源映射使用统一字段网格，错误逐条可清除。

- 详情分来源与文件、运行配置、可用状态、接口契约、最近错误/诊断。长 ID 和进程信息放详情。
- 配置预算、容量与实际并发分开；启动和停止反馈真实阶段，不因后台推理而误报服务故障。
- 导出说明资源范围与本次生成状态；导入先校验包与映射，再创建实例；坏包、缺文件、不兼容设备有定位信息。
- 节点包能力不自动成为可部署模型，只有已实现 ModelRuntime 的模型进入该列表。

### 3.9 推理

**已有同步与异步入口，扩展共享结果查看器。** 左/上侧选择部署、输入、参数与调用方式；主区展示图片/结构化结果及耗时。异步任务从明确入口进入任务结果，不能让单次同步按钮隐式排队。

- 输入选项匹配后端契约；浏览器上传、本机服务文件、远程 URI 和本机共享内存引用不是同一种路径。
- 图片支持检测、分类、分割、关键点、OBB 等已注册类型；异常热图、几何或 3D 结果按实际部署能力扩展。
- 结果查看器中的显示阈值/显隐不改变本次计算或生产判定。重新推理必须显式提交。
- 大图解码或 3D 渲染失败仅影响显示面板，业务响应状态仍按服务结果展示。

### 3.10 集成

**已有触发入口与详情，保持单一工作台。** 列表为名称、类型、状态、触发时间、操作；诊断 ID、健康计数、最近错误放右侧详情。

- 创建/编辑按“绑定 Runtime → 协议配置 → 输入映射 → 结果绑定”组织；简单配置同一表单，复杂映射才分步。
- 协议类型来自注册 adapter。目录监听是后台自动执行；SDK 主动调用是另一类入口，不混用按钮和状态。
- 发布版本改变导致契约不匹配时显示字段差异与修复入口，不自动重写映射。
- API/SDK 使用说明入口复用项目配置包和契约，不另建一套 SDK 资源管理。连接测试仅验证明确范围，不把一次本机模拟当作现场设备通信验收。
- 核心集成不增加相机/PLC 驱动控制中心；直连硬件仍由受信任扩展节点承担。

### 3.11 设置

保持当前二级分类，不增加独立运维首页。

| 分类 | 子项和内容 | 目标状态 |
| --- | --- | --- |
| 偏好 | 语言、外观和已支持的界面偏好 | 已有；新增项依实际配置能力 |
| 启动页面 | 根路径落点、Runtime App Mode 选择、失效目标提示 | 已有，本地浏览器偏好，不等于服务自动启动 |
| 运行状态 | Backend Worker、部署/Runtime/Trigger 启动完成情况、组件状态与诊断 | 已有基础；统一状态表达、权限内资源链接 |
| 系统环境 / 关于 | 应用名称、Community Edition、版本、构建、许可和链接 | 已有 |
| 系统环境 / 系统信息 | OS、服务地址、路径与资源信息 | 已有基础；不伪造监测历史 |
| 系统环境 / Python 运行时 | 解释器、发行 profile、依赖诊断 | 已有基础 |
| 系统环境 / 设备信息 | CPU、GPU/NPU、驱动与可用运行时 | 已有基础，不负责安装系统驱动 |
| 系统环境 / 存储与诊断 | 资产位置、占用、诊断导出及维护入口 | 规划；先定义后端能力，不新增自动全盘清理 |
| 访问控制 / 会话与权限 | 当前账号、项目范围、允许的页面/操作 | 已有 |
| 访问控制 / 用户管理 | 本地账号与授权范围 | 已有；不扩展云租户、SSO 等新体系 |

备份/恢复、发行 profile 更新、存储迁移应有操作说明和相应维护能力后再开放 UI；本轮列为后续运维需求，不能用设置开关模拟。日志保留与默认凭据遵循既有项目决定，不借设计工作擅自改策略。

### 3.12 无导航的系统页面

启动检查、登录、离线、无权限、未找到、会话失效、资源已删除和版本不兼容都纳入出图与交互覆盖。失败内容必须区分“无法连接”“正在启动”“缺少依赖”“无权访问”，提供可执行的恢复动作，不统一显示无限加载。

## 4. 跨页面规则与补漏

| 问题 | 统一设计规则 |
| --- | --- |
| 项目范围不明 | 页内操作区显示必要的项目名称；模型/版本/Runtime 等固定所属对象不可随意换项目；筛选和草稿按项目隔离 |
| 数据资产与生产记录混用 | 数据集用于样本与版本；生产文件由保存/汇总/清理节点管理；日志、缓存、预览临时数据不是数据集版本 |
| 已有、开发中与规划混淆 | 设计资产标记阶段；产品按可用能力显示；缺包/无权/无数据/未实现分别处理 |
| 查看、修改、执行混淆 | 查看与试算不自动提交配方；应用参数、保存草稿、发布、切版是不同动作 |
| 旧结果被当成本次结果 | 显示执行来源与时间，过期/断连明确标识；缺测不补零、不保留旧 OK 冒充新结果 |
| 删除边界不清 | 删除记录、删除资产、停止实例、禁用包分别说明影响；关联预检由服务端兜底 |
| 前端失效影响生产 | 页面关闭、预览解码失败、WebGL 丢失不终止常驻 Runtime；取消仅作用于契约支持的指定执行 |
| 外部连接依赖 | Vue 与所有 UI 资产本地分发；设计不以 CDN、云服务或设备直连为默认条件 |
| 国际化/可达性 | 普通按钮与字段走 i18n；专业名可保留英文；长名称、单位、键盘、焦点、触控与高 DPI 同批验证 |
| 现场角色混用 | 操作员主要进入已发布 App Mode；工程师配置与管理员维护按权限开放，结果界面不默认暴露配方写操作 |

所有页面覆盖首次加载、无数据、筛选无结果、部分失败、权限不足、断连和恢复的适用状态。后台任务、常驻服务、业务 OK/NG、标定有效性四类状态分别表达；忙碌和容量拒绝不能被描绘成系统未启动。

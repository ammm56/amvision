# 应用分类页面设计

更新：2026-10-30。目标为完整工业视觉工作站，当前代码只用于确认边界，不限制未来功能。本文是设计规格，不表示功能已实现或生产验收通过。

## 1. 设计结论

应用分类负责应用查找、发布版本、运行实例、触发入口关联、调用调试和运行记录。图编辑负责草稿编排及发布，应用模式负责输入和结果使用，三者复用同一 Workflow，不建立另一套业务页面系统。

当前累计65组130张亮暗配对。本轮新增编辑实例配置、实例诊断、失败记录详情和准备新调用确认4组8张，见[收尾规格](application-final-states-design.md)。此前的35组70张异常/管理图及26组52张基础图保留。详见[异常与管理状态设计](application-exceptions-management-design.md)及[调用与执行记录设计](application-invocation-records-design.md)。本轮要求的独立场景已出图，重复的成功反馈、字段错误等采用明确的共用状态规则，不为每条文案复制整页。

## 2. 现有证据与保留项

- [应用列表实景](references/应用/01-当前应用列表.jpg)、[应用详情实景](references/应用/02-当前应用详情.jpg)、[实例抽屉实景](references/应用/03-当前运行实例详情.jpg)来自开发环境，只做读取和导航。
- 当前列表有草稿应用、打开图编辑、删除、运行状态；详情有发布历史、归档/恢复、输入输出、多个 Runtime、启停、版本切换、调用和 Trigger 关联。
- 保留 bak1 的应用—版本—实例—触发关系；取消旧图独立顶栏、复杂分组导航、固定右分栏和长 ID 列表。
- 当前单个 primaryRuntime 状态不能代表全部实例；目标设计显示“运行 2 · 停止 1”等组合，存在异常时明确显示异常数。
- 当前应用详情纵向堆叠且业务名称不突出；目标采用清楚的业务名称和页内栏目，不把所有接口和 JSON 同屏展开。
- 当前运行实例抽屉的覆盖行为可保留，技术字段转入技术信息与诊断，常用状态优先。
- 多实例选择仅确定本页操作对象，不称主实例/备用实例，不暗示自动故障转移。

## 3. 统一外壳和视觉

沿用项目、数据集、模型和推理母版。标准图目标 1672×941，页面空间按比例适配，不拉伸截图。导航约占 17%，11 项平级：项目、任务、数据集、模型、部署、推理、图编辑、应用、集成、节点、设置。应用选中，无分类标题、独立全局顶部栏和统计大横幅。

品牌绿 #00D992；亮色白色表面、浅灰背景，暗色中性炭黑表面。主按钮白字，普通文字中性灰，选中行浅品牌底，悬停和输入焦点中性灰。绿色不覆盖所有名称/字段，红色只用于异常/危险动作。正文普通字重，标题适度加重。

抽屉覆盖页面，不挤压底图；遮罩覆盖导航和主体的整个可交互背景，同一颜色和透明度。抽屉内滚动，标题/关闭固定，必要操作底部固定。短屏导航折叠后只有 AM Logo，点击 Logo 展开，不添加独立展开图标。

## 4. 主流程与页面

### 应用列表

局部工具栏：搜索名称、发布状态和运行状态筛选；刷新、新建应用为清楚入口，文档导入为次要操作。可按现有项目上下文过滤，不额外发明全局项目顶栏。

表格：应用名称、最新发布、运行实例状态汇总、触发入口数量、更新时间、查看/图编辑/更多。未发布显示“未发布”，没有实例显示“未创建”。不显示长 ID、节点总数、重复的大统计卡或没有范围说明的总量。列表不显示“ready=true”等调试字符串。

新建进入图编辑；导入打开 Workflow 文档载入流程，明确仅含图和配置，不包含部署模型、Runtime、Trigger 或二进制文件。缺失节点包/资源必须提示，不自动安装或启动。复制创建新应用身份，不复制运行状态和正在工作的 Trigger。

### 应用详情

左上返回与业务名称，旁边最新发布版本。右上编辑流程、应用信息、更多。页内栏目：
1. 运行实例（默认）
2. 发布版本
3. 输入输出
4. 调用调试
5. 执行记录

运行实例表格：名称、实际版本、状态、关联触发数、最近心跳、操作。选中行用软绿色，并明确“当前实例：名称”；应用模式、运行监视和调试入口作用于该实例。无选中实例时相关动作不可用。最新发布版本与实际运行版本分开，旧版正常运行不标红。

实例行常用操作为详情及当前合法的启动/停止，重启、切版、删除放更多菜单。创建实例单独主按钮。下方关联触发列表只显示当前实例的触发入口，提供新增和详情；真正的协议配置复用集成页面，返回保留应用和实例选择。

发布版本表：版本、状态、说明、时间、引用数、查看/与草稿比较/更多。载入图编辑放版本详情，避免与运行切版混淆。输入输出用名称、类型、必填和简短说明，不默认显示完整 schema。调用调试区按实际契约展示 image-ref、Base64、值等输入，明确目标实例和同步/异步能力。执行记录按实际记录策略显示，不能将本页最后回执当成所有生产调用历史。

### 运行实例详情抽屉

概览/诊断两页内选项。概览显示业务名、状态、所属应用、实际/目标版本、关联触发数、请求超时、记录策略、诊断开关只读值、最近心跳及最近错误。技术信息按需展开显示完整 Runtime ID、generation、创建更新时间和复制按钮。诊断可显示原始 health JSON，原始字段保留但不成为默认主视觉。

“请求超时”不冒充启动预算。字段不可取得时显示“暂无”，不能写 0 或“正常”。正常概览不铺解释段落。故障状态给出短原因、发生时间、相关日志/诊断入口与合法恢复动作，不建议无条件自动重试。

## 6. 必须明确的业务边界

- 保存草稿、发布版本、切换 Runtime 是三个动作；发布不自动更新生产。
- AppVersion 是不可变发布快照；Runtime ID 稳定，切版/回退形成新的 generation。
- 版本切换以服务端校验为准：实例停止、无活动执行、无启用 Trigger、目标版本可用、依赖与契约满足。generation 冲突刷新并重新确认，不自动覆盖。
- 切版成功只设置目标版本；下一次启动验证并激活。未启动时并列展示“最近成功版本”和“目标版本”，不声称新版本已运行。
- failed 实例先复位；失败 revision 必须重新选择版本。停止不自动停用 Trigger，可能中断执行，不承诺排空后停止。
- archived 版本不能用于新选择；已引用实例可继续运行。恢复归档需校验。删除引用版本必须阻止。
- 删除应用必须检查 Runtime 和活动 Preview；共享模板、部署模型不是连带删除对象。删除实例必须检查活动执行和 Trigger。
- 模型满载、工作流长时间执行是容量/执行状态，不等于服务不可用。业务 NG 不等于调用失败。
- Runtime/Trigger 高性能同步链路不增加队列、等待列表、自动重投或隐藏重试。明确用户提交的异步 Run 采用既有受支持机制，不能混同。
- 记录策略与诊断开关读取实际实例；不能把创建表单选项当作全平台缺省。none 显示“不保存执行记录”，不能显示“从未执行”；minimal 不能假装有完整输入输出。异步提交必须满足记录策略。
- Preview 逐节点进度与 Runtime 执行完成结果观察不同；运行监视不伪造逐节点进度。
- 页面重载、筛选、进入详情、重连仅重新读取状态，不再次运行工作流。
- 检测、分类、分割、测量、异常/瑕疵及未来点云均通过 Workflow/节点资源和结果查看器扩展，不新建行业专用应用管理系统。
- 应用模式生产计数由实际显式节点数据提供；列表中的实例数/记录数不是产量。

## 7. 当前实现与所需服务配合

已有路由和模型是实现依据；UI 目标增加的聚合筛选、可读版本信息、信息编辑入口和记录检索须逐项核对 API，不能靠前端猜测。

- 列表需分页查询及批量状态汇总，避免每行单独拉取 Runtime/Trigger、加载整个节点 Catalog；“总数”明确全筛选结果还是当前页。
- 服务返回实际/目标状态、更新时间和可执行操作或稳定拒绝码，前端不通过字符串猜运行健康。
- 状态更新采用现有低成本机制，不在页面频繁做真实推理探测。页面隐藏时收敛订阅，退出释放资源。
- 调用调试必须保留取消/超时与最终回执语义，不将浏览器等待结束直接等同后端已停止。
- 权限由服务端执行；只读可查看可复制，不能以隐藏按钮替代授权。
- 所有设计适配 Vue 3、TypeScript、现有路由和组件；离线静态资源分发，不引入云依赖。

## 8. 验收与下一步

累计65对130张，4项复核缺口已补齐8张亮暗图。实例配置入口作用域、停止后保存与下次启动生效、诊断查看、失败记录及准备新调用确认见[收尾规格](application-final-states-design.md)。当前已登记的应用管理静态范围已覆盖，待用户审阅；可以开始集成分类。图编辑、应用模式共享专题和真实交互验收另计。

交互原型应验证：返回保留筛选和滚动；切换实例后的所有按钮指向一致；抽屉 Escape/焦点返回；请求过期响应不能覆盖新选择；长名/键盘/缩放200%；断线不显示假正常；危险动作确认只执行一次。静态图只能验证视觉结构，不能替代上述行为验收。

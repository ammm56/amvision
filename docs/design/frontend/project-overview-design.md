更新：2026-10-23。状态：目标设计，未新增产品路由或 API。入口为项目列表操作栏的“查看”，建议页面名称“项目概览”，目标路由 `/projects/:projectId`。

实现更新（2026-11-04）：上述日期描述设计阶段状态；当前路由和 v1 概览 API 已实现，并完成本轮缺口修复。现状与测试依据见[收尾验收记录](../../development/project-workspace-completion-validation.md)，下文保留目标设计和原始调研依据。

后续操作已补充到[项目分类页面与操作设计](project-pages-design.md)：项目信息/编辑的右侧抽屉、SDK/删除的居中对话框，以及空态、失败、权限与未保存处理。本文继续负责概览主页面。最新逐图核对和修订项见[项目分类 UI 审查](project-design-audit.md)。

## 1. 为什么单独设计

项目列表用于查找和选择项目；查看页用于了解项目内有哪些资源、哪些任务正在执行、哪些服务正在运行，并继续具体工作。这些内容需要完整主区与稳定深链接，不适合全部挤入项目列表的右侧抽屉。

本设计修正此前“项目详情均采用抽屉”的规划。新建、编辑和补充信息仍可使用抽屉或对话框；从列表“查看”进入的资源概览使用独立页面。它不增加左侧导航入口，也不成为强制启动首页。

## 4. 页面布局

### 4.1 项目标题区

主区左侧为返回按钮、项目名称及一行说明。右侧为“项目信息”“编辑项目”“生成 SDK 配置包”，均为次按钮；进入 SDK 对话框后“生成并下载”才是主动作。名称长时允许最多两行，不缩成小字，不增加“项目概览”重复大标题。现有概览 PNG 仍将 SDK 画为绿色，列为下一轮局部修订项。

项目名称是必要的资源身份，不属于已移除的普通页面 h1。完整 ID、来源、存储位置等放入“项目信息”抽屉，可复制；不在标题处连续堆叠 ID 和状态。

“编辑项目”为目标能力，必须补齐合法更新契约、授权与冲突处理后接入；不得借创建接口隐式覆盖既有项目。默认概览不放删除按钮，删除继续走项目列表的依赖预检。

### 4.2 资源入口

同一条浅边框区域内四个等宽入口：数据集、模型、应用、部署。名称、适度字号的计数和进入箭头即可，不加大图标或趋势图。

| 名称 | 统计对象 | 不可替代的数据 |
| --- | --- | --- |
| 数据集 | 本项目数据集目录/逻辑实体数量，与目录契约一致 | 导入记录数、版本数、样本数 |
| 模型 | 本项目登记的模型实体数量，具体类型由模型目录统一 | 训练次数、模型版本/构建总数、全局预训练模型数 |
| 应用 | FlowApplication 数量 | 模板数量、发布版本数、Runtime 数量 |
| 部署 | DeploymentInstance 总数 | 已加载推理槽位数、模型数量、“健康”数量 |

无法取得准确值时显示“—”及局部失败/未提供提示，不能以 0 冒充。设计样例延续项目列表第一行：12、8、5、4；这些是示例数据，不是当前运行环境统计。

### 4.3 主体内容

宽屏主区采用两个相邻正文模块，以细分隔和标题建立层级，不层层套卡片。初始提示词约 58:42；实际待审阅稿为近似等宽，能同时容纳日期列与训练进度。实现时按可用宽度调整，优先保证文字可读。它们不是“列表＋固定详情”。

**最近更新**：默认最多 5 条，字段为名称/类型、状态、更新时间和打开入口。仅显示本项目真实资源的更新；同一资源按稳定键去重，以更新时间排序。点选跳转对应业务详情；“查看全部”展开本页的有界分页列表，不新增全局资源导航。没有服务端全局排序时不能声称是跨所有资源的最近 5 条。

**当前运行**分为两个小节：

- 正在执行的任务：显示名称、类型和真实阶段；有明确分母才显示百分比。无任务时显示“暂无执行中的任务”。
- 常驻服务：显示部署实例和应用 Runtime，名称、类型、观察状态及详情入口。运行时间只有可靠启动时间时才显示；本轮静态稿不填写无依据的长时间运行数字。

当前运行最多显示少量代表条目：任务小节的“任务”进入项目任务列表；常驻服务小节的“部署”“应用”分别进入相应模块。当前运行不设置将三类对象混合的“查看全部”。Trigger 从相关 Runtime 或“集成”入口查看，不重复堆叠所有触发器配置。

最近更新“查看全部”的完整状态：保留项目标题和资源入口，下面切换成全宽分页列表，暂不显示当前运行和继续工作；提供“返回概览”、资源类型筛选及搜索。仍在同一概览，不新增导航或固定详情列。返回时恢复摘要位置。此状态尚未出图，详见[补充提示词](prompts/项目补充状态.md#7-最近更新展开列表)。

### 4.4 继续工作

底部一行轻量入口：“导入数据集”“创建训练”“创建部署”“新建工作流”。打开对应模块的创建流程，继承当前项目；不自动选择“最新模型”或自动执行任务。

尚不满足数据、模型或权限条件时保留合理引导，不静默使用其他项目的资源。新建工作流打开现有图编辑器，不新建行业专用页面。

## 5. 交互、范围与异常

1. **查看**：校验目标项目存在且可访问后进入目标路由，URL 的 projectId 与当前业务项目范围同步。背景刷新不得切换项目；同页所有请求固定捕获同一 projectId。
2. **返回列表**：恢复搜索、页码和滚动位置；选中状态与当前项目一致。浏览器前进/后退重新按路由恢复范围。
3. **进入资源**：显式携带项目范围，到目标模块后先显示该范围，再加载资源；不能先展示其他项目缓存。与旧项目有关的迟到响应必须丢弃。
4. **打开详情**：优先复用现有业务详情路由。无独立详情页的资源使用所属模块的明确选中/抽屉入口；不存在的查询参数只作实现计划，不能冒充现有深链接。
5. **权限**：按资源类别分别检查权限。单个模块无权限不使整个项目消失，也不泄露该模块的计数/名称。写动作按权限处理。
6. **加载与部分失败**：项目身份必须先确认；各内容区独立加载和报错。有旧结果时保留并标记更新时间/已过期，不假装刷新成功。
7. **不存在、删除和断线**：不存在或失权提供返回；资源被删除给出原资源不可用提示；断线不伪造离线完整数据。
8. **刷新与生命周期**：页面可见时低频刷新或消费已有摘要变更事件；不逐次订阅推理结果。离开页面取消请求、定时器和订阅，事件密集时合并 UI 刷新。

服务“正在推理、忙碌、容量已满”不等于服务异常；不根据业务 OK/NG 判断部署健康。项目页不聚合产量、良品率或图像结果，这些继续由 Workflow 的记录、计算与显示节点定义。

## 6. 数据与性能边界

- 先复用现有元数据、摘要和按项目筛选的有限查询，缺少准确总数或跨资源排序时补服务端有界查询；不从前端拉全量资源再计数、排序。
- 可以在同一项目模块增加概览读取服务与明确响应契约，无需新微服务、执行 Worker 或独立任务队列。新增公开接口继续使用 v1 并同步类型与文档。
- 当前 summary 包含目录/资源枚举，不宜直接用于高频轮询。概览首屏请求有总量上限，资源列表有分页，后端避免 N+1 扫描；实时观测时间与资源更新时间分别表达。
- 概览只读取控制面元数据，不执行推理、不加载模型、不访问图像 mmap、不扫描生产 JSONL/清理目录。同步 Runtime/Trigger 路径不改动。
- 不为概览建立伪造的统一健康布尔值。SDK 配置省略目录监听触发源仍是普通说明，不显示运行警告。

| 步骤 | 实现/设计内容 | 验证要求 |

| 3 | 盘点并补齐读取/编辑契约和权限 | 任意合法项目深链接、准确计数、最近更新排序、局部无权与失败 |
| 4 | Vue 3 项目详情页与现有模块深链接 | 刷新/返回/跨项目切换正确，旧请求不污染新项目，已有列表行为不退化 |

# 应用分类收尾页面设计

更新：2026-10-30。对应[完整性复核](application-completeness-audit.md)的4项缺口。本文件是目标设计和后续实现约束，不表示现有服务已新增配置更新接口。4组8张亮暗图已完成生成和逐张静态核对，进入集成分类首批；交互原型另行验证。

## 实例配置：入口、保存与生效

- 运行实例行“更多 → 编辑配置”、实例详情以及调试页的“查看实例配置”均锁定同一个Runtime。只读权限仍可查看，不提供保存。记录列表筛选“全部实例”时不显示无目标的配置修改按钮；选择具体实例后显示在实例上下文栏。
- 打开使用实例当前保存值；表单字段为名称、请求超时、执行记录、返回诊断。Runtime身份、所属应用、发布版本只读；版本修改复用切版流程。
- 为保持执行边界简单，配置更新仅允许实例已停止、无活动执行、关联Trigger已停用时提交。运行中/控制待确认/失败待复位时显示只读配置及对应短原因，不自动停机。
- 目标更新契约必须支持配置修订比较与原子保存；页面拿到的修订只用于并发检查，不以心跳更新时间判断冲突。服务端再次检查权限、实例状态、Trigger、字段合法性和配置修订，拒绝覆盖并发修改。接口路径与模型在实现阶段按现有v1模块正式定义，不用前端直接改数据库或metadata。
- 请求超时为整数秒且遵守执行策略实际范围；记录方式为不保存/摘要/完整，诊断为关闭/开启，读取实际策略，不能从示例值推断全平台默认。保存不改版本、不新建实例、不启动服务，下次启动使用新配置。历史记录不追溯改写。
- 保存成功关闭表单并刷新该实例配置；失败保留输入。请求回执丢失先重新读取修订与值，不盲目再次提交。冲突复用现有“读取最新”规则；关闭未保存复用既有确认组件。均不另生成大量重复图。

## 诊断与执行失败

- 实例诊断显示实例状态与检查时间，相关资源和短原因优先；原始诊断收起，长内容内部滚动。不存在的指标写暂无，满载/长执行不能冒充健康故障。
- 执行记录详情固定执行时的实例、版本与记录策略。错误节点只在记录提供证据时显示；无证据显示失败阶段或暂无，不从最新图结构猜节点。失败不能被显示为业务NG。
- 完整记录只展示实际保存的输入、输出和诊断；摘要/未保存/已清理/无权限用已有规则。部分结果明确标记，不用于伪造完整判断或计数。复制诊断与错误仅含允许显示的字段，不泄露认证信息。
- 示例失败是Load Local Image输入文件不存在，结束时间晚于开始时间；相关Runtime仍可能正常运行。诊断页面和历史记录不得产生新的执行副作用。

## 准备新调用确认

- 仅用于没有可查询run_id、且上次同步结果未知的场景；正常新调用不增加确认步骤。
- 目标实例固定，提示重复保存/计数风险。确认只解锁输入准备，仍需用户随后点击“调用一次”；后台不重发旧请求。
- 旧回执保持结果未知，不能因准备新输入而改为成功、失败或已取消；选择其他实例也不能错误转移旧回执。服务是否可调用仍由最新状态与真实调用校验决定。

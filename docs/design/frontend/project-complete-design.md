# 项目分类完整产品设计

更新：2026-10-23。依据最新要求，UI 以项目未来完整能力为目标，不以当前 API、字段或路由是否存在决定设计范围。现有实现用于记录差距，不用于删减合理的用户操作。本文件优先于此前按当前接口限制出图的条款；产品定位、权限、工业使用与高性能边界保持有效。

## 1. 固定方向

- 继续采用 2 个主页面、3 类抽屉、2 类对话框，不新增项目子导航。
- 项目列表与概览完整设计；新建、信息、编辑是右侧覆盖抽屉；SDK 和删除使用对话框。
- 11 个简洁平级导航、无独立顶栏、亮暗同一品牌绿 #00D992、白字主按钮、中性 hover/focus。
- 界面呈现完成后的正常能力，不放“API 未实现”等开发说明；生成清单区分目标设计与当前产品。
- 当前有效图片直接保存在 `generated/项目/`，使用直观页面类型和状态命名；总览与清单各一份，中文请求统一放在 `prompts/项目完整设计请求/`。

## 2. 完整功能与实现要求

| 页面能力 | 目标用户体验 | 对实现的要求 |
| --- | --- | --- |
| 项目列表 | 可靠计数、项目搜索、分页、当前项目标识、查看/更多菜单 | 可查询、按权限过滤的目录与摘要；更新时间为项目元数据修改时间 |
| 项目概览 | 资源入口、最近更新、有限任务与常驻服务、继续工作 | 有界聚合和稳定深链接，不逐次全盘扫描，不将生产 OK/NG 当服务健康 |
| 项目信息 | 名称、说明、ID、来源、存储位置、创建时间、更新时间 | 元数据来源和时间语义明确；不能以当前 schema 缺字段为理由删掉时间 |
| 新建/编辑 | 简洁名称/说明表单、自动稳定 ID、校验、保存与冲突核对 | 创建结果可核对、条件更新、权限、草稿保护；不借 bootstrap 覆盖已有项目 |
| SDK 配置包 | 默认全部可调用资源，可调整资源范围；预览派生文件再生成下载 | 范围选择与必要依赖联动，文件由选择推导；预览版本核对，资源变化明确提示 |
| 删除预检 | 保护原因、活动资源阻止、非活动数据影响、ID 确认 | 执行前复核，真实影响类别及计数，不把无活动资源等同于空项目 |
| 删除结果 | 区分项目移除和文件清理完成，可检查结果、复制操作标识 | 提供经过授权的删除操作状态查询，不能以列表消失证明磁盘已清空 |

SDK 的资源选择不是任意挑选 ZIP 内文件。默认使用全部范围；“调整范围”在同一个对话框中切换到资源选择视图，应用后返回文件预览。Runtime 与 Trigger 依赖同步检查，不导出孤立或失效引用。SDK 配置方式继续尊重同步高性能调用，不设计自动排队或自动重试。

## 3. 本轮出图与检查

顺序为：修订正常主图与操作容器 → 补关键状态 → 配对亮暗 → 短屏。每一张使用中文请求，记录实际参考图和输出尺寸；同场景配对数据相同。每个页面只表现一个清楚状态。

关键状态包括列表空态与无匹配、最近更新展开、空项目、编辑失败/退出、SDK 空配置与范围调整、非空删除确认与清理待完成。加载、复制、轻提示等复用公共组件规格；40 项检查不等于强制生成 40 个独立页面。

短屏稿按 1366×768 设计重排，不将宽屏整体缩小。它仅证明该静态方案的布局；125%/150% 缩放、键盘、焦点、请求状态仍需在后续产品或交互原型验证。

本轮不实现业务代码、不修改真实项目、不执行 SDK 下载或删除。最终图数量和核对结果以本机生成清单为准，全部新稿待用户审阅。

## 4. 范围选择与状态查询的完整行为

- SDK 默认全部可调用资源；调整范围在原对话框内替换正文，不弹第二层选择窗口。搜索仅过滤显示，不改变已选集合。
- 长资源列表使用一个独立滚动区；标题、项目、搜索、已选摘要和底部动作固定。每组标明已选/总数，顶部总计包含屏幕外及被搜索隐藏的选择。长名称允许换行，复选框、锁标识与首行对齐；不为每组增加嵌套滚动条，不把整页文字缩小。搜索无匹配时保留已选摘要和清除搜索入口，不显示“无资源”；真正空分组显示“暂无可调用资源”。依赖锁定配合文字原因，不能仅靠颜色。大清单读取采用有界加载，选择状态独立于当前可见行，加载失败不清空已选或伪造全部加载完成。
- 手动选择和依赖带入分别记录。选中 Trigger 时包含其 Runtime；尚有已选 Trigger 依赖时，Runtime 不允许直接取消，并展示关联原因。取消 Trigger 后仅移除该依赖，不能丢弃原本主动选择的 Runtime。用户主动选择过的资源继续保留。
- “返回预览”放弃本次范围草稿，“应用选择”校验后应用并返回；关闭整个对话框不发起生成。空选择允许回到无配置状态，生成禁用并说明原因。
- 文件清单由已选资源和同步调用配置派生。生成时检查预览对应的资源版本；资源已变更则更新预览并明确提示，不静默使用旧配置。列表和检查为控制面功能，不添加 Runtime/Trigger 执行排队或自动重试。
- 删除结果显示项目身份、操作标识和真实状态。关闭后须能从项目列表的临时结果提示重新打开；页面重载仍可按已保存的操作标识查询。该标识只定位操作，不代表授权，服务端按账号和项目访问权限验证。
- “检查结果”是一次状态查询，不重新执行删除。仍待清理、清理失败、清理完成分别显示；查询失败保留最后已知状态及“本次检查失败”，不能改成全部完成。完成后明确项目与文件清理均已完成；不凭目录列表消失作出此判断。

## 5. 短屏与可访问性实现约束

- 对话框最大高度为视口减去上下安全边距，标题和动作区固定；正文使用独立滚动，避免嵌套横向滚动。短屏可缩减空白，不整体缩小文本。
- 抽屉目标宽度统一为 520 CSS px，窄窗不超过视口宽度；全高覆盖，不改变背景网格宽度。图片中的近似像素位置不能当作 CSS 定值。
- 长名称、路径、文件名允许换行；必要的 ID 和复制操作保持可达。当前页面选中、普通 hover、字段 focus、禁用状态分别使用既定语义，不能只依赖颜色区分。
- 所有覆盖层阻止背景交互并限制焦点；打开后焦点进入容器，关闭返回原触发项。Esc 关闭遵循草稿保护；危险确认不默认聚焦删除动作。
- 1366×768、125%/150% 缩放、键盘遍历、长列表和离线失败需在可交互实现阶段验证。本轮静态短屏稿只核对布局表达，不声明这些交互已经通过。

## 6. 下一步实现顺序

1. 先完成共用页面、抽屉、对话框及亮暗 Token；以长内容和短视口检查固定操作区。
2. 补项目元数据、有限资源聚合、时间语义、权限与修改版本契约；实现列表及概览、创建与编辑。读取失败用未知值，不能伪装成零。
3. 实现 SDK 资源范围、依赖选择和预览版本核对；验证无配置、资源变更及下载失败。
4. 完成删除预检、执行前复核和授权结果查询；验证活动资源阻止、非空影响、文件占用与查询失败。
5. 将 40 项状态矩阵用于组件与端到端验收；上线前再用真实数据核对业务计数、权限和调用边界。

异常/瑕疵、连接器二维、3D/点云项目仍复用上述项目与资源页面。专业设置、标定、测量和结果交互继续位于 Workflow Node App 及相应节点 UI，不为每种行业场景复制项目分类页面。

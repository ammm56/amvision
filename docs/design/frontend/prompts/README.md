# UI 设计提示词

更新：2026-10-24。这里恢复并修订旧设计提示词，供下一轮逐页生成使用。**提示词正文统一中文，专有名称保持英文。** 这不是新一轮导航改版，也不表示规划功能已经实现。

## 使用顺序

模型最新要求：使用[模型提示词](模型.md)、[完整页面规划](../model-pages-design.md)和[复核记录](../model-design-review.md)。首批12组亮暗、24张静态稿，配套24份合并修订后的中文规格，见[设计总览](../generated/模型/设计总览.html)；当前图片与规格哈希记录在清单。未出图状态另列，不能用首批代表页面代替完整交互验收。

数据集最新要求：使用[数据集提示词](数据集.md)、[工作区规格](../dataset-workspace-completion-design.md)、[向导规格](../dataset-wizard-states-design.md)及[管理规格](../dataset-management-states-design.md)。截至2026-10-25，56组亮暗、112张静态稿，对应112份中文规格，位于 `数据集完整设计请求/`。本轮48份规格先写后生成，逐图修订已合并；末次实际请求另存在清单。见[设计总览](../generated/数据集/设计总览.html)和[逐图检查](../dataset-design-review.md)。

最新项目稿按[完整产品目标](../project-complete-design.md)生成，见[项目图检查](../project-complete-design-review.md)。[项目完整设计请求](项目完整设计请求/项目列表-亮色.txt) 目录现为 30 份当前有效中文规格，与 15 组亮暗、30 张图一一对应；已合并历次局部修订，不重复保留被替代的请求文件。这些规格用于复用最新设计，不声称是未经整理的逐次工具请求。本次新增删除确认/依赖阻止暗色规格及 SDK 长列表亮暗规格。

1. 查阅本页规格、[旧图保留与修正清单](../bak1-review-2026-10-23.md)和对应 `bak1` 图片，确认主体结构。
2. 读取[通用要求](通用要求.md)，选定主题、页面状态、导航和抽屉状态。
3. 从下表选单页提示词，组合为“通用要求＋本页提示词＋主题/状态补充”。一次只生成一个业务场景。
4. 直接附上对应旧图作为内容结构参考；附已确认项目图作为导航、主题和组件参考。两类参考职责不能交换。
5. 保存实际发送的完整中文提示词、参考文件、实际图片尺寸和检查结论；亮暗图采用同一组数据。
6. 有布局、业务或文字错误时先修正本页，不能把未确认新图作为其他页面参考。

所有提示词的页面 ID 沿用[覆盖清单](../frontend-design-roadmap.md)，**与旧稿的同名编号不一定相同**。旧编号对应关系见[历史来源](历史来源.md)。面向用户的文件名按页面类型命名，不使用这些内部编号。

## 本轮恢复边界

项目查看补充：旧 P02 的合理主体用于新增 P03，见[项目概览](../project-overview-design.md)。随后 P04–P06 及状态补齐为[项目完整流程](../project-pages-design.md)。该阶段曾统计 49 个场景、88 段提示词、15 份 Markdown 文档；数据集重写后不沿用该数字作为当前总量。此前 45/61、46/62 和 49/70 也均为阶段记录。18 段状态提示词中部分场景已生成，准确覆盖见[本轮检查](../project-complete-design-review.md)，不能把计划数当作图片数。

旧 OpenAI Image 2 的页面内容和状态提示已按类型整理恢复；旧 Google Stitch 提示词改为中文结构化要求，并引用同一套逐页规格，避免维护两套布局。历史原文及版本仍可通过 Git 精确恢复，来源与修改项已列明；这里的文件是修订版，不冒称生成 `bak1` 时逐张实际发送的原始请求。

`generated/bak1/` 保持原图不变。原已确认项目四图已归档；按用户要求重新生成的中文提示词版本见[重生成记录](../project-regeneration-review-2026-10-23.md)，尚待审阅。项目表格不改为所有业务页的模板。已否决的 `20261023-resource-pages` 不作为参考。本轮新增图先标“待用户审阅”，内部检查不替代用户确认。

每个场景的“已有/扩展/规划”说明写在文档和图片清单，不把架构术语、设计编号或规划说明塞进操作员的主界面；需要对外展示尚未实现功能时，应在图注明确说明。

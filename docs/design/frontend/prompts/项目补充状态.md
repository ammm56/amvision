# 项目分类：修订与补充状态提示词

依据：[完整产品目标](../project-complete-design.md)、[项目分类完整设计](../project-pages-design.md)、[14 张稿审查](../project-design-audit.md)、[通用要求](通用要求.md)。本文件是状态出图规格；已生成场景以 `generated/项目/生成清单.json` 为准。专有名称保持英文，其余提示词使用中文。

每次组合“通用要求＋以下一个场景＋明确的亮色或暗色要求”。附上对应现有稿，不能把多个状态拼成一张普通业务页面。文件按场景名和亮/暗主题命名；实际输出尺寸、完整请求、参考图及检查结论另存生成清单。日期锚点 2026-10-23。

## 18. 共用状态组件

此项仅用于明确标注的组件状态板，不伪装成一个同时报多种错误的业务页面。

```text
制作项目分类共用组件状态板，使用同一套亮色或暗色主题，清楚标注各个独立状态：名称必填错误、创建中、保存中、结果暂时无法确认、复制成功、无权限、已开始下载、读取失败重试、分页边界禁用。组件保持与项目页面相同的字号、按钮、间距和中性焦点样式。
每块只展示必要文案和动作，不展示业务计数。结果不明只给核对/关闭或返回列表，不出现自动重试倒计时；复制成功使用短反馈；已开始下载不写磁盘保存完成。状态板是组件说明，不添加一套导航或营销展示效果，不把所有错误放进一个项目概览。
```

## 检查与保存

1. 核对本次指定主题、对象和状态；未给真实来源的数量必须在清单中标为样例。
2. 检查导航次序、无独立顶栏、抽屉覆盖、品牌色、选中/hover/focus 区别。
3. 检查每个按钮在当前状态是否有意义；一个页面不要同时显示互相矛盾的成功与失败。
4. 配对主题后逐项核对文字、数字、启用状态和坐标结构；不能只凭配色相似接受。
5. 当前图按页面和状态直接保存，历史英文版、被替代的旧版与过程图按本次要求清理；`bak1` 不修改。清理执行状态以最新检查记录为准。

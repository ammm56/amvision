# 设置与系统：页面设计与提示词

继承[通用要求](通用要求.md)。系统入口可不展示业务导航；设置沿用一层页内分类，不把旧三列导航照搬。后台繁忙不等于未就绪。

## S01 启动与登录

- 来源：[启动检查](../generated/bak1/00-foundation/S01_startup-check_light_checking_v01.png)、[登录](../generated/bak1/00-foundation/S02_login_light_manual_v01.png)。
- 保留：直接步骤与表单、本地服务状态。
- 修正：只显示实际检查项，不伪造迁移进度；不硬编码旧端口/版本。
- 状态：连接中、启动未完成、可进入、凭据错误、会话失效、版本不兼容。

### 启动检查

```text
设计 AMVAR 启动检查页面，简洁品牌与居中检查区域，不用完整业务导航，也没有独立全局顶栏。显示本地服务连接、会话和实际报告的启动情况，完成、进行中和失败配文字与图标；没有数据不伪造百分比或五步全绿。
服务地址和版本来自配置，本例地址为 http://127.0.0.1:5600；浏览器不执行数据库迁移。失败给出原因、重试和诊断入口，不用无限 spinner。检查成功遵从用户启动页面或显式回跳，可进入 Runtime App Mode，不固定跳项目页。
```

### 登录

```text
设计本地账号登录页，保留旧稿清楚的品牌区和登录表单比例，使用同一亮暗主题与品牌绿。普通文字中文，账号、密码、显示密码和登录动作明确；服务地址与连接状态简洁展示。
没有注册、社交登录或云协作。凭据错误保留用户名和回跳目标，服务不可用与密码错误分开显示，不让错误内容推动整个表单反复跳动。关于和许可入口按实际功能提供。
```

## S02 离线、无权限、未找到

- 来源：[离线](../generated/bak1/00-foundation/S03_system-state_light_offline_v01.png)、[无权](../generated/bak1/00-foundation/S03_system-state_light_forbidden_v01.png)、[未找到](../generated/bak1/00-foundation/S03_system-state_light_not-found_v01.png)。
- 容器：系统状态页/局部状态，单次出图只选一种。
- 修正：不承诺未实现离线缓存；资源无权不泄露名称；归档不等于不存在。

```text
设计单一系统异常状态页面，沿用简洁品牌和主题。离线时显示无法连接的服务、最近更新时间、重新连接与诊断入口；已呈现旧数据要标明过期，没有完整缓存能力时不放进入只读缓存按钮。
无权限时只显示允许披露的信息、缺少权限说明和安全返回；未找到时说明对象不可用并返回实际存在的入口。会话失效有重新登录和保留回跳，版本不兼容给明确原因。不要把所有情况都画成同一红色故障页，也不添加工单、在线申请权限和重复顶栏。
```

## C01 偏好与启动页面

- 来源：当前设置功能；旧 C01 仅参考紧凑字段，不保留三层常驻导航。
- 状态：外观/语言选择、目标有效/失效、未设置、保存反馈。

```text
设计设置的偏好与启动页面。全局设置选中；内容内一列简洁设置导航，顶部不重复显示设置标题，不再加第三层固定导航。主区是统一字段网格，语言、亮色/暗色/系统外观和启动页面选择清楚。
根路径可选择普通工作台或指定 Runtime App Mode；该偏好存于浏览器本地，不冒充后端用户数据库或服务自动启动配置。目标失效时说明并提供重新选择，不能把 Runtime 启停动作混成启动页面开关。单多选品牌绿，输入焦点中性。
```

## C02 运行状态

- 来源：[旧正确诊断图](../generated/bak1/06-settings-system/C01_settings-diagnostics_light_devices_v02.png)，不是历史外部数据库队列错误图。
- 状态：启动中、就绪、组件失败、正在工作、满载、状态过期。

```text
设计设置运行状态页。主体显示视觉服务、部署、Workflow Runtime、Trigger 的实际启动/健康摘要与诊断入口；Backend Worker 使用简洁名称，不附长篇 Topology/epoch 说明。只列当前激活配置。
正在推理、长时间执行和实例满载不显示为未就绪。进程、接口和业务成功分开，未检查写暂无，不伪造健康。异常首先显示具体组件、原因和允许操作，再展开技术信息。有限任务进度不冒充服务整体启动进度，图表只在真实数据存在时显示。
```

## C03 系统环境与关于

- 来源：旧 C01 环境表与当前关于、Python、设备信息。
- 容器：设置内局部切换；关于是信息页，不做营销品牌页。

```text
设计设置的系统环境页面，局部选择关于、系统信息、Python 运行时、设备。设备页按 CPU、CUDA、OpenVINO、TensorRT 等实际探测信息列版本、状态和原因；没有探测不能因设备名写可用。conda 开发环境与随包 Python 发布环境分清，不提供未实现的驱动安装按钮。
关于页按简洁字段排列：应用名称为小写 amvar 加动态词缀的静态代表 vision，无词缀背景，字体与 Community Edition 普通文字一致；版本类型显示 Community Edition，版本取当前值，许可证保持正式名称。全局导航品牌仍使用 AMVAR 和带品牌底色的 Vision，不被关于页样式改变。链接悬停清晰稳定，不闪烁。
```

## C04 会话、权限与用户

- 来源：当前[权限与启动设计](../user-permissions.md)。
- 状态：管理员/普通/只读、无项目、授权变更、会话失效、拒绝访问。

```text
设计设置访问控制页面。会话与权限使用当前账号、可访问项目、账号来源等清楚中文，不中英混写 Project/Provider。项目和允许操作使用对齐表格，长列表可搜索，当前身份与权限来源可查。
用户管理仅按管理员权限开放，编辑有明确保存与错误反馈，不能把默认允许和显式授权混淆。普通账号能查看自己的范围，不暴露未授权资源详情。不要加入云租户、SSO、订阅方案或未实现的权限审批工作流。
```

## C05 存储、诊断与维护

- 来源：现有维护与节点文件处理边界；目标规划，不是新增自动清理执行器。
- 状态：容量未知、只读、预检查、有引用、处理中、部分失败、完成。

```text
设计设置中规划的存储与诊断页面。按数据资产、模型文件、日志和临时数据显示明确路径范围与可获得的占用，未知数据不写0。诊断导出与数据清理是不同操作，选定维护范围后先显示影响和引用检查，再确认执行。
不提供默认全盘扫描删除、不偷偷改日志保留策略、不把 JSONL 生产记录当作可任意清除的缓存。维护失败保留具体文件范围和原因，前端关闭不假装后台已取消。规划能力在交付说明标记，界面不伪装成已验收的运维系统。
```

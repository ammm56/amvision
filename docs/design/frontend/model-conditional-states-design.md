## 1. 边界与技术核对

- ONNX 的 Opset 必须与目标执行环境兼容；动态维度由模型和导出能力决定；external data 是模型伴随资产，不是另一个模型版本。参考[PyTorch ONNX 文档](https://docs.pytorch.org/docs/stable/onnx.html)。
- OpenVINO IR 保存的 FP16 权重压缩与设备执行精度分开；CPU/GPU/NPU、线程、streams 属于部署。INT8 校准与数值校验、任务精度评估分别定义。参考[OpenVINO IR 转换](https://docs.openvino.ai/2026/openvino-workflow/model-preparation/convert-model-to-ir.html)。
- CoreML 必须选择兼容的转换、校验环境和最低目标系统；ML Program 的最低系统示例是 macOS 12，不代表所有模型在此系统可运行。参考[Core ML 格式](https://apple.github.io/coremltools/docs-guides/source/target-conversion-formats.html)。ARM NPU 必须先明确厂商适配器、芯片和工具链，不提供假通用参数。
- 模型、数据版本和历史执行快照不可由编辑展示信息或重试操作暗中修改。重新执行产生新任务；不为 Runtime/Trigger 引入等待或重试。

## 6. 完整性结论

本轮明确列出的24组条件分支均有亮暗图稿，上一轮五类静态缺口已有对应场景。该轮按状态族判断可进入原型；下一轮按按钮去向发现导出记录入口和输出差异等缺口，已在[操作去向规格](model-flow-closure-design.md)补齐。相同结构的全失败、导出取消等状态按第3节复用并更换数据和动作，未冒称已单独出图。模型分类可进入Vue 3交互原型阶段。

该结论限定于已定义的完整产品体验范围。适配器新增字段、不同任务的数据契约以实际能力注册为准，不能靠通用表单假装全部支持。精确色值、同一原图像素保真、键盘焦点、短屏/200%缩放、状态恢复、真实长日志和运行性能仍需实现后验证。图片与示例指标不构成算法验证证据。

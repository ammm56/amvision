# 集成分类收尾设计

日期：2026-10-30。以44组既有设计为基础，新增两组、修订七组；不改变分类导航，不删除必要配置。

## 范围

- 新增：目录轮询扫描进度恢复、技术信息展开，均为亮暗配对。
- 同名修订：进度不可用、ZeroMQ接入、长内容、短屏长错误、共享内存接入、规则变更确认、启停待确认。
- 背景表格不因抽屉打开而缩窄；遮罩覆盖导航、Logo、头像和内容。主按钮统一品牌绿与白字，普通悬停、输入焦点中性灰。

## 进度恢复

| 情况 | 展示与动作 | 完成结果 |
|---|---|---|
| 首次启用，从未保存进度 | 按已确认配置扫描，无额外恢复确认 | 采用新进度 |
| 曾有进度但文件丢失/损坏 | 已停用，短原因，选择恢复方式 | 不自动清空或启用 |
| 恢复原进度 | 放回有效文件后检查；校验对象与规则，不仅校验JSON语法 | 检查通过后仍停用，可单独启用 |
| 重新扫描 | 明确提示已有文件可能再次触发；确认后准备新进度 | 仍停用，不执行检测 |
| 恢复失败 | 保留选择、原进度和错误；允许检查或取消 | 不谎报成功 |
| 恢复结果未知 | 暂停重复提交，只查询状态 | 依据服务事实更新 |
| 运行时进度写入失败 | 显示进度未保存及服务实际状态，提供停用/检查 | 不把仍运行的入口显示为停用 |
| 扫描规则变化 | 默认保留原配置，可直接确认返回；显式选择新规则才重建 | 不自动启用 |

源码目前无法区分从未保存和历史进度被删除；写入失败也不自动停止。恢复状态、修订校验、操作结果查询属于后续实现契约。本任务只完成设计，不声称后端已具备上述行为。确认恢复仅准备进度；实际扫描发生在之后显式启用。

## 信息层级和交互

ZeroMQ与共享内存配置默认展示常用接入参数；映射、返回结果、其他配置、技术信息按需展开。展开内容保留真实字段和完整复制。编辑映射界面仍完整可操作，不套用只读详情的收起策略。

技术信息的ID来自服务，设计样例遵循现有默认格式；不根据显示名生成。完整值自然换行，复制取得未截断值；原始错误允许正文滚动，底部操作固定。

断线时，受本次操作影响的行显示结果待确认；其他行分别保留运行中、已停用或异常并标记“上次”，附更新时间；没有缓存才为未知。刷新只查询，不重发命令。恢复连接后按最新事实更新。

抽屉支持Esc、关闭后焦点返回触发按钮、焦点限制在最上层、关闭后恢复筛选与滚动位置。长内容不缩小文字硬塞；短屏AM Logo为唯一导航展开入口。权限不足禁用变更操作但不改变只读信息。

# 应用输入输出、调用调试与执行记录

更新：2026-10-30。本批为目标 UI 设计规格，不表示生产功能已经实现；不更改实际应用、Runtime、Trigger 或记录策略。

## 1. 现场界面与代码核对

参考：[输入输出与调用](references/应用/07-当前输入输出与调用.jpg)、[调用与回执](references/应用/08-当前HTTP调用与回执.jpg)、[请求示例](references/应用/09-当前请求示例抽屉.jpg)。

开发环境塑盒应用当前为 v3，具有 image-ref、image-base64、value 三个输入和一个 value 输出。设计沿用已确认的 v5 示例，不改现场版本。设计中的 inspection_result 是可读示例 binding_id，不是现场已改名的声明。

核对 WorkflowAppDetailPage.vue、workflow-runtime.service.ts、workflow_runtime/runs.py、runtime/policies.py 和 completion.py：已有同步调用、异步创建、单条记录、事件和取消接口；当前详情只展示本页最后一次回执。批量历史检索/分页列表仍需服务端能力，不得把前端本页数组冒充历史。

## 2. 输入与版本

- 输入输出页显示所选不可变发布版本。切换查询版本不切换运行实例。
- 调试锁定所选实例及其实际运行版本契约；调用中修改选择不得把旧回执写入新实例。
- 名称和 binding_id 分开；图片引用与 Base64 至少一项是示例流程条件，不是全平台所有图像参数规则。
- 表单与 JSON 编辑使用同一 bindings；切换不静默丢值，JSON 非法时定位字段并禁止提交。
- HTTP 根据契约提供 image-ref、image-base64、value、text、file-ref、file-refs；ZeroMQ/mmap 不宣称支持所有 HTTP 文件类型。
- 浏览器文件先使用实际上传结果形成引用。服务端路径必须是执行进程可访问路径，不能采用浏览器伪路径。
- 上传与 JSON 同一 binding 不重复发送。file-refs 保持顺序；示例占位符不允许直接作为有效输入提交。

## 3. 调用和结果

- 同步一次调用直接获得回执，不增加队列、隐式等待名单或自动重试。
- 异步提交要求支持持久查询的记录策略；none 时异步不可用，同步保留。仅显式进入配置修改流程才改变策略。
- 已提交只认定服务接收，状态 running 没有总量时用不定进度，不伪造逐节点进度、百分比、预计时间。
- HTTP 成功、执行成功、业务 OK/NG 分层显示。NG 是业务输出，不能映射为执行失败。
- 满载是明确容量拒绝，没有完整业务结果；前置节点可能已经执行，界面不得断言整个工作流未执行；仍允许手动新的独立调用，不自动排队。
- 取消仅向服务提交取消请求，取消中锁定重复提交，终态以返回为准；已经成功不能再渲染为已取消。
- 浏览器等待超时、断线与服务端 timed_out 分开。有持久记录/run_id时查询原执行；同步none没有记录时显示结果待确认，不能凭空恢复。准备新调用必须确认可能重复副作用，不自动重发。
- 请求示例抽屉沿用现有 JSON/multipart/curl/.NET SDK 能力，仅复制不调用；生成示例不等于创建有效文件。
- 新增的表单、结构树、业务结果映射是目标能力，字段显示由契约/显式绑定配置决定，不能硬编码塑盒业务。

## 4. 记录模式与资源生命周期

- 不写全平台默认 none：读取实际实例配置；当前创建界面的选项默认值与后端缺省策略不是同一概念。
- none：当前同步回执可显示；不生成可持久查询记录。历史已保存记录不随当前策略变化消失。
- minimal：保留公共结果及执行信息；不声称有输入、模板或节点明细。图像引用按清理/脱敏策略处理。
- full：仅展示确实保留的输入、输出、trace。完整记录也不保证图片永久保存。
- 图片只能读取仍然存在并有权限访问的文件；禁止重用过期 mmap/image_handle。未保存、已清理、无权限、加载失败分别显示。
- 历史详情使用执行时 version/revision/generation/worker_epoch，不能用当前实例版本补写。
- 列表按应用/实例/版本/状态/时间分页查询；记录数不是生产总量。刷新、筛选、返回和重新连接均只读。
- 权限区分查看与调用/取消；服务端最终校验。实例状态和权限变化时重新确认，不能仅靠隐藏按钮。

## 6. 后续分支与复用

第三批12组为主要调用与记录页面；第四批已补请求示例长内容、字段错误、取消确认/处理中/已取消/完成竞态、异步断线与同步无记录回执待确认、服务端超时、记录空态/无结果/加载失败和权限状态。完整清单及共用规则见[异常与管理状态设计](application-exceptions-management-design.md)。取消请求完成不能覆盖先到的成功终态；同步none回执丢失时无可查询run_id，不允许自动重投。

交互实现验证：重复点击只提交一次；回执归属实例固定；返回保留筛选；取消与完成竞态；资源清理不会抹掉业务结果；权限改变与错误重试；200%缩放/键盘焦点/Escape回焦；短屏滚动与固定动作。静态图片不证明这些行为已验收。
## 7. 请求示例契约核对

对照HTTP请求模型及.NET WorkflowRequestBuilder：示例使用input_bindings包装，不与顶层公开输入混用；value输入为`{"value":{"barcode":"a1b2c3d4e5"}}`，storage图像引用含transport_kind、object_key、media_type。文档图中的object_key只是占位示例，真实调用采用上传返回的合法引用和当前版本契约。抽屉只复制/关闭，不发起执行。

## 当前补充验收

- **场景 36–39。** 真实模型和 COCO 导出核对创建、类别映射、评估规则和预检。隔离 Worker 实际处理 117 张图像并生成报告。运行详情用 Worker 保存的样本进度和日志复放，验证两种短屏亮暗和失败后重试。[详细记录](../../../design-qa.md)

- **场景 56。** 模型目录刷新只保留相同账号、项目、筛选和页码的快照；断线标注最后更新时间，重连只读取。开发库模型用于两种短屏亮暗场景；注入读取失败和只读权限，并验证训练读取失败不影响转换记录。[详细记录](../../../design-qa.md)

- **场景 8、30–33、72–73。** 开发库真实 OpenVINO 文件用于隔离导入、CRC 错误、类别索引对照、登记和记录清理。1024×768、1366×768 亮暗均核对了检查、冲突、独立登记与记录详情，短屏避免横向溢出。详见[验收记录](../../../design-qa.md)。

- **场景 74–76、84。** 导出记录保留生成终态，另判定 ZIP 可用性。以真实 OpenVINO XML 和 BIN 在隔离服务验证下载、清理、源文件缺失和按原选项重新生成。开发前端用隔离 API 回执验证筛选、禁用下载和过期恢复；覆盖 1024×768、1366×768 亮暗主题。[详细记录](../../../design-qa.md)

- **场景 83、90。** 开发环境读取 `task-f866f7152e47` 的 61 张评估图像和 39 张问题图像，验证类别、文件名、漏检筛选、仅显示未匹配标注框、零结果和图片重试；误检筛选在该报告中正确返回零结果，非空误检的匹配与分类由隔离 API 测试覆盖。真实旧报告 `task-ba41a14002ee` 无样本级错误记录，保留原图并提示无标注框和预测框；样本列表读取失败可重试。两份报告均覆盖 1024×768、1366×768 和亮暗主题。

## 首轮验收证据（历史）

- **场景 54 与导航。** 实际 OpenVINO 记录核对了 1024×768、1366×768 的亮暗删除确认，真实项目只打开并取消确认。隔离测试删除记录后收到 404，专属报告和临时文件被清理，登记产物仍可下载且原部署引用仍能读取。训练、转换标签与任务类型、搜索、状态和分页同步到 URL，实际浏览器验证返回与刷新恢复搜索条件。[场景 54](generated/模型/设计总览.html#scene-54) · [转换删除测试](../../../tests/test_yolox_conversion_tasks_api.py)
- **场景 3、17、21、57。** 实际 YOLO11-s 与 COCO 导出核对双列参数、百分数、检查页及返回后的高级区状态，覆盖两种短屏和亮暗主题。服务端预检检查输出同名系列、导出清单和初始化文件。隔离 API 测试覆盖清单错误阻止和恢复检查；使用同一真实导出副本的 YOLO11 训练跑完 1 轮 CPU，登记模型并生成最佳、最新检查点和验证指标。[训练参数和恢复](../../../tests/test_yolox_training_api.py)
- **场景 6、25、26。** 以真实 YOLOX 核对固定输入和 Opset 选择，以真实 YOLO11 记录核对动态批次和服务端检查，覆盖亮暗及两种短屏。隔离 Worker 生成 Opset 19 ONNX，模型图具有符号批次轴，转换报告的批次 1、2 数值校验通过。动态宽高及 INT8 校准由预检和创建拒绝，现有模型登记只接受现有适配器声明的精度。[转换 API](../../api/platform-base-models.md)
- **TensorRT INT8 隔离试验。** TensorRT 10.16.1.11 在固定 128×128 输入下用 5 张真实 train 样本校准并生成引擎，另用 1 张 val 图像执行 TensorRT 与 ONNX 对照，最大绝对差约 0.00195。该结果只覆盖固定输入的单模型试验。场景 26 还需要动态空间 min/opt/max、校准与独立验证数据契约，以及 Worker、产物登记和部署的 INT8 能力接入。
- **全量状态。** 90 个场景和 180 张亮暗图仍作为逐图验收清单。模型前端 22 个文件、170 项测试通过，前端类型检查通过。独立模型包和评估页面仍待实现。

## 实施顺序与交付检查

1. **转换删除和页面导航。** 为仅删除任务记录明确独立操作及服务端边界，保留已登记产物、文件和部署引用。先按文件归属核对清理范围，覆盖登记产物存放在任务目录中的情况。隔离测试需证明记录及专属临时文件被清理，原产物仍能下载且部署引用仍能解析。同时同步 URL、标签、筛选及详情返回，覆盖刷新和浏览器前进后退。
2. **训练创建与恢复。** 先对齐场景 3、57、63 的双列、字段单位、组距、高级区和页脚。高级区状态及参数随同一草稿保留，短屏能快速到达高级参数。随后对齐场景 14–17、21 的模型与数据选择、划分、初始化、检查及恢复。训练预检与创建共用校验，检查重名与系列匹配、数据导出及必需划分、初始化权重、恢复检查点和可确认的 Worker 能力。用真实可用来源及错误分支验证，再提交一项隔离的短训练。
3. **转换高级参数。** 先验证场景 6、23–26、29 所需的适配器能力和可用环境，再将可选 Opset、动态尺寸和 INT8 校准逐项接到 Worker。页面按来源、目标格式和执行环境展示可选范围及禁用原因。用真实 ONNX/OpenVINO 产物验证配置和数值报告，TensorRT 依可用的实际环境完成验证。
4. **版本差异与独立模型包。** 先补能由历史记录确定的版本编号及来源。定义模型包 manifest、文件完整性、模型契约和兼容版本，再实现预检查、冲突处理、登记新版本、导出记录及重试。跨项目用隔离数据往返，核对原有版本、文件和类别索引。部署实例继续使用既有迁移流程。
5. **评估。** 以真实目标检测样本完成创建、列表、详情、按类别指标、误检漏检样本、部分失败和取消，再按各类型的真实报告能力扩展。比较按相同数据版本、划分和规则验证，部分失败结果展示实际参与计算的样本数量。
6. **逐场景验收。** 每组流程通过后才进入下一组。在 1024×768 和 1366×768 核对亮暗主题、焦点和滚动，优先验证正常、空数据、加载失败、权限阻止与可重试状态。每个场景记录设计图、路由、真实数据、浏览器结果及剩余差异，复用状态和数据仍一致的现有证据。

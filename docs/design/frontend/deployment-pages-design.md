# 部署分类页面设计

更新：2026-10-26。设计目标为完整的本地工业视觉服务产品；不以当前功能、路由和接口进度限制合理页面规划。当前阶段交付中文规格和静态图，不修改部署进程、模型、数据库或高性能数据面。

继承[通用要求](prompts/通用要求.md)与[模型交接边界](model-design-review.md#14-收尾复核与部署分类衔接)。入口为左导航“部署”，页内为部署实例、导入记录、导出记录。设备能力是次级入口，不增加第四个常驻栏目。无独立全局顶栏，无重复大标题。

## 1. 对象、页面与边界

| 对象 | 页面职责 | 不包含 |
| --- | --- | --- |
| 部署实例 | 固定模型版本/产物、运行设备和配置，管理服务启停与容量 | 训练、模型转换、数据集管理 |
| 推理运行单元 | 就绪数、执行中数、实际生效配置 | 独立进程数量的隐含承诺 |
| 导入记录 | 包分析、配置/映射、检查、登记与结果 | 导入成功等同服务启动成功 |
| 导出记录 | 当前资源生成的新包及文件有效性 | 复用旧包冒充本次结果、进程或在途请求快照 |
| 来源模型/产物 | 只读来源和契约、跳回模型管理 | 在部署页面修改原模型版本 |
| Workflow Runtime / Trigger引用 | 显示使用关系、受影响范围及跳转 | 在部署分类复制应用、集成管理体系 |

默认全宽列表；名称、模型版本、运行后端/设备、调用模式、实例容量、状态和操作是首屏重点。ID、PID、generation、完整错误放详情。列表“详情”打开模态覆盖抽屉；抽屉局部为概览、运行配置、接口、诊断、引用。日志长列表和复杂诊断允许转完整工作区，不在窄抽屉同时放所有图表。

创建为完整三步页面；导入为四步宽对话框，正文滚动、步骤与底部动作可达。短编辑、资源详情用抽屉；停止、删除等影响确认用对话框。叠加确认替换焦点层，整个底层共用一层遮罩，关闭回到原抽屉/列表焦点。

## 2. 主流程

1. 从模型详情、单项产物、转换完成或部署列表进入创建；传入项目、模型、版本及已选产物。未选择产物时明确选择，不猜后端。
2. 创建三步：选择来源 → 运行配置 → 检查。创建后启动和随服务自动启动分别配置。
3. 静态检查完成后提交一次，创建记录与加载服务分别反馈。创建成功但启动失败保留实例，进入诊断，不重复创建。
4. 运行正常时查看可用性和容量，进入推理分类测试；操作员不能把正在推理、满载或长调用理解为未就绪。
5. 修改运行配置、切换版本或回退，先检查兼容性和引用影响，再明确是否需要停止/重启。默认不承诺零停机切换；失败保留已确认配置与诊断，禁止隐式切后端。
6. 导入：文件 → 配置与映射 → 检查 → 结果。分析只读包内容；新建/复用须核对身份、摘要与契约。同名不代表同一资源。变更映射或设备使之前检查失效。
7. 导出：确认固定内容 → 生成/校验 → 下载。每次显式导出重新生成；记录完成与文件仍存在分开。不能在本次失败时提供旧包冒充结果。
8. 停止、删除、删除记录均检查影响。删除部署不连带删除模型版本；删除导入记录不隐式删除部署；清理下载包不抹除操作历史。存在不允许解除的引用时阻止删除，并提供查看引用。

## 3. 完整页面与状态矩阵

累计74组148张亮暗配对，覆盖启停异常、导入冲突/回滚、记录清理、后端参数、长内容以及本轮交互收尾状态。主流程和主要恢复路径可连续审阅；通用状态按下表复用。真实交互尚未验收。详见[操作与状态补全](deployment-flow-states-design.md)、[异常恢复与后端参数](deployment-closure-states-design.md)和[交互收尾](deployment-interaction-completion-design.md)。

| 页面族 | 已有独立图稿 | 复用及实现核对 |
| --- | --- | --- |
| 入口 | 部署实例、首次为空、导入记录、导出记录 | 加载、筛选无匹配、只读权限复用公共规范 |
| 创建 | 来源、运行配置、参数错误、检查、提交结果待确认、检查阻止短屏 | 其他必填/范围错误复用行内校验，创建离开复用未保存确认；配置更改使旧检查失效 |
| 启动与停止 | 运行正常、启动中、已停止、启动失败、启动超时、停止引用影响、停止中、停止失败 | 停止未确认时只查询，不能重启或假定资源释放 |
| 运行配置 | 请求/实际值、编辑、离开确认、变更确认、修改冲突 | 已停止编辑复用同表单；离开确认不绕过检查保存 |
| 接口 | 输入输出契约、HTTP/.NET直接部署调用、共享内存/ZeroMQ关联Trigger入口 | 按实际关联显示，浏览器不直接访问mmap；真实调用留实现阶段 |
| 诊断与引用 | 接口异常但进程存活、观测中断、引用关系、长日志、长引用列表 | 有界加载/分页、断连与长文本交互待原型验证 |
| 导入 | 文件、包类型不符、配置映射、检查失败/通过、进行中、完成、完成但启动失败、失败详情、资源冲突、回滚待清理、记录删除确认 | 取消可用性按阶段；登记中不可直接删除或伪装取消。附属文件随所属版本，不单独映射 |
| 导出 | 范围确认、记录列表、生成中/取消中/可下载/失败/已取消/文件失效详情、取消确认、文件清理、记录删除与占用阻止、部分清理失败 | 完成与取消竞态按事实显示；已清理保留历史结果但禁用下载 |
| 版本与删除 | 选择来源、切换确认、回退确认、变更失败、显式恢复完成、删除确认、依赖阻止 | 其他版本变更完成复用恢复完成布局并替换操作名；未知结果先查询 |
| 手动维护 | 重置确认、执行中阻止 | 预热沿诊断入口和阶段反馈，完成禁用；查询不执行重置，详情见交互收尾 |
| 后端能力 | TensorRT；OpenVINO CPU/GPU/NPU/AUTO；ONNX Runtime CPU/CUDA；PyTorch；CoreML；ARM NPU；设备能力 | 厂商和设备实际字段由适配器能力决定，不声称支持所有硬件组合 |
| 适配 | 详情短屏、导入长映射短屏、创建检查阻止短屏 | 真实1366×768、125%/150%缩放、键盘与滚动仍需Vue原型核对 |

静态范围中的主要操作、异常恢复和后端代表分支已补齐。通用复用状态在文档明确，不用数量替代交互完整性，也不为每种错误文本重复生成相同布局。

## 4. 状态与防误操作

| 状态 | 文字和操作要求 |
| --- | --- |
| 运行正常 / 正在执行 / 满载 | 服务状态正常，容量单独列；满载是拒绝，不是故障，不出现同步等待队列或自动重试 |
| 启动中 / 预热中 | 显示实际阶段与就绪单元，未知总工作量不画假百分比；尚未就绪不能调用 |
| 启动失败 | 明确阶段、实际原因、保留配置与诊断；复查后由用户重新启动，不自动改设备或后端 |
| 停止中 | 已提交操作不等于已停止；新调用与在途调用按实际服务契约处理，不提前释放使用中的资源 |
| 观测中断 | 显示最后更新时间、状态待确认；不把旧的绿色“运行正常”当实时结论，不用零数据填曲线 |
| 提交结果未知 | 保留只读摘要；先查询现有操作，只有明确未创建才开放再次提交；查询不重新执行 |
| 配置过期 | 保留用户输入、重新检查，不能提交旧检查结论 |
| 导入历史错误 | 每条可清除；当前阻止原因不能清除后绕过验证，清除不删除资源或重试 |
| 删除/停止 | 说明范围、引用、在途调用与超时影响；危险按钮统一实红，普通取消中性 |

所有统计标注区间和计数口径。示例已结束请求120=成功118+失败2，容量拒绝3和在途1另列。满载2/2不改为不可用。进程存活不能代替模型加载及服务可用性检查；不为状态查询触发额外推理。

## 5. 后端参数与目标能力

依据[模型发布运行时配置](../../architecture/models/deployment-runtime.md)固定语义，不把现有字段作为未来设计上限：

- 执行、生命周期与后端专属选项分组；实例数是可占用的推理单元数，不冒充独立进程数。
- TensorRT运行期显示产物已有Optimization Profile；构建精度、动态输入范围、workspace与INT8校准回到模型转换，不在部署假装可编辑。
- OpenVINO区分权重存储精度与实际计算精度，CPU线程、Streams与性能目标分别表达。设备专属可写性按能力；NPU只读属性不能画成可编辑。
- 请求配置与实际生效值分列，裁剪原因可见；CPU线程样例16核心/2实例，每实例8，保存配置16保持不变。
- ONNX Runtime、PyTorch、CoreML及ARM NPU使用对应运行后端/设备能力；未安装、工具链不兼容有明确原因，不因规划支持就列出虚构可用组合。
- 不增加同步队列、隐式合批、自动后端回退；资源协调不放进逐次推理热路径。UI只表达实际状态与可控配置。

## 6. 数据、主题和验证

设计日期2026-10-26；前两批业务样例2026-10-23，第三批2026-10-26，各组事件保持内部时间一致。来源延续模型设计：零件检测YOLO11-s v4、连接器分类YOLO11-s v2、包装瑕疵YOLO26-n v1。设备和数值均为设计样例，不是性能或现场验收证据。

亮暗必须同数据、同布局、同控件状态。主题沿用#00D992及已确认母版，主按钮白字；普通悬停/焦点与图标中性；危险#DC2626。单遮罩覆盖全部底层含品牌导航账户。实际生成尺寸与1920×1080/1366×768目标分开记录，不拉伸图稿。

逐张先检查亮色，再以该亮色图生成暗色并核对，错误修订合并进中文规格。只把最终稿复制到`generated/部署/`；过程图不进入该目录，bak1不改。哈希、实际尺寸、引用和逐图结论在[设计复核](deployment-design-review.md)与生成清单维护。真实交互、可访问性、性能、离线运行及生产链路验收必须另行完成。

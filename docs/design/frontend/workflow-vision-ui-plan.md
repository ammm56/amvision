# 视觉工作流、专业节点与结果界面扩展设计

更新：2026-10-22。包含异常/瑕疵检查、连接器二维定位计量、3D/点云测量检查。三者沿用 Workflow Node App、Runtime、Trigger、节点包及应用模式；不创建三套行业导航、执行系统或页面设计器。

| 学习型异常检测 | 不因存在 Variation Inspect 就视为训练/部署已接入 | 按实际模型后端能力扩展数据、模型及节点 UI |

## 2. 层级与职责

```text
现有工作台外壳 / 项目与权限
  Workflow 编辑器 / 发布版本 / Runtime / Trigger
    通用 UI：参数表单、资源选择、几何编辑、结果表格、查看器
      通用能力节点与算法库
      专用扩展节点包及节点专属 UI
    同一结果模型 → 节点内预览 / 专属编辑器 / Runtime 观察 / App Mode / 大图
```

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 核心平台 | 生命周期、端口契约、权限、资源引用、发布和执行 | 固定产品尺寸、PIN 类别、托盘规则 |
| 通用算法/节点 | 图像、几何、坐标、统计、逻辑、文件、显示等可复用能力 | 某一连接器产品的流程硬编码 |
| 专用节点包 | 连接器 PIN 阵列/行业测量、特定协议/设备适配、特化检查 | 复制调度器、另建任务系统或调用时重复加载已部署模型 |
| 节点 UI | 参数与资源编辑、ROI/阵列/测量项配置和本次结果定位 | 浏览器执行权威测量、隐式保存或切换生产版本 |
| 结果查看器 | 呈现图像/点云/几何/表格及数据绑定 | 推断业务判定、自动配对其他节点、篡改原始输入 |

通用二维/三维数学和显示可复用库；是否作为核心节点或通用扩展包由稳定性、依赖体积与已有归属决定，不因为“可复用”就把 Open3D 等重依赖塞入核心启动链路。专用检查放对应包，包仍声明 manifest、版本、capabilities、schema、timeout 和禁用规则。

## 3. 节点目录分类目标

分类是检索维度，不要求重命名现有公开 node type id。节点来源另列 Core / 包名 / 版本；无包时不能把所有能力显示为可执行。

| 能力类别 | 子类 / 常见用途 | 行业边界 |
| --- | --- | --- |
| 输入与输出 | App 输入、文件读取、图像/值/表格/未来点云预览、显式保存 | 不含行业固定字段 |
| 图像处理 | 灰度、滤波、阈值、形态学、区域、变换、绘制 | 复用已有 Core/OpenCV，不重复造节点 |
| 定位与坐标 | 模板/特征定位、标定、坐标框架、映射有效性 | 物理单位与像素空间分明 |
| 几何与测量 | 边缘、直线/圆、距离/角度、公差、测量结果 | 通用数学与定义，不绑定连接器尺寸命名 |
| 异常与瑕疵 | 参考差分、统计变化、区域筛选、已注册模型调用 | 具体产品排除区/缺陷规则是配置 |
| 模型 | 已部署模型调用及通用前后处理 | 不在 Workflow 节点重新加载已部署模型 |
| 数据与规则 | 提取/组装、比较、条件、循环、汇总、显示数据 | NG/OK 分类、产量和记录格式由图配置 |
| 文件与维护 | JSONL 追加/汇总、图像保存、保留期清理 | 只处理明确路径和类型，不默认保存 Preview |
| 3D 与点云 | 读取、滤波、配准、几何拟合、测量、偏差与显示 | 依实际 3D 包实现登记；不冒充完整 GD&T |
| 专用扩展 | 连接器 PIN 阵列、行业检查、设备/协议桥接 | 保留对应包和专属 UI，不混入通用节点 |

节点选择器支持用途关键词、端口类型、包来源筛选；详细技术类别路径在详情，不要求用户理解内部模块目录才能添加节点。

## 4. 三类用户工作路径

### 4.1 异常与瑕疵检查

1. 选择输入和检查方法：参考差分、正常样本统计或已部署异常模型，不能以一个“AI 开关”混淆。
2. 准备参考/正常样本资源和必要对齐：定义检查区、排除区、采集条件；模板保存与当前待检图分开。
3. 配置检查：差异/异常阈值、面积等筛选、公差与业务判定；参数范围按节点 schema。
4. 预览：原图、对齐参考、差异/热图、区域和结果表联动；选中表格项定位缺陷区域。
5. 验证与发布：用正常、明显异常、边界、光照/位置变化样例核对；保存资源、草稿、发布，再启动既有 Runtime。

异常分数与概率不同；图像级与像素级阈值需分别定义，归一化/阈值处理取决于模型实现，不能仅根据热图颜色判 OK/NG。该设计依据 [Anomalib 后处理说明](https://anomalib.readthedocs.io/en/latest/markdown/guides/how_to/models/post_processor.html)。

**节点专属编辑器**：上方为输入/参考来源；中心图像和叠加层；侧边 ROI、阈值与筛选；下方缺陷列表。显示调色板/透明度不会改计算阈值；调整算法参数后需显式执行预览，生产生效仍需发布/切版。

### 4.2 连接器二维定位、检测与计量

工程准备与每次检测分开，标定和模板制作不是每个工件重复执行的步骤。

```text
工程准备：检查目标/图纸与公差 → 成像样例 → 标定验证 → 定位参考
          → PIN/区域与测量项配置 → 多样例验证 → 保存/发布
单次运行：待检原图 → 定位/坐标基准 → PIN/边缘提取 → 尺寸计算
          → 公差/规则判定 → 结果汇总 → 显示 / 显式保存 / 返回
```

- 标定编辑：图像来源、方法、物理尺寸和单位、点对应、残差与适用范围；已有标定可直接选择，不能为流程形式要求重新标定。
- 定位编辑：参考图、搜索区域、参考原点和方向、定位有效性；只进行像素检查时明确输出像素，不伪造物理单位。
- PIN 配置：阵列/编号、预期空位、搜索带、几何方法；预计位置与真实找到的位置使用不同线型。
- 测量编辑：测量对象、定义、名义值、上下限、单位、补正来源；结果显示实测、偏差、状态和失败原因。
- 结果：图片几何与 Results 表格联动，缺 PIN、缺边缘、标定无效、超差分别标记；缺测不是 0，也不能用名义值顶替。
- 数值判断使用后台原始数值，显示精度仅影响格式。临界值的包含关系与误差/不确定度政策必须来自测量规则，不在前端四舍五入后重新判断。
- 合成图用于算法回归、配方与 UI 开发；亚像素小数、拟合残差、重复性均不等于实物测量准确度。

### 4.3 3D / 点云测量与检测

```text
工程准备：来源与单位/坐标 → 参考几何/标定 → 配准基准
          → 检查体积/测量项 → 偏差与公差规则 → 样例验证/发布
单次运行：受控点云或深度输入 → 无效点处理/必要变换 → 配准
          → 几何与尺寸/偏差计算 → 判定 → 3D + 表格/数值显示
```

- 输入允许按实际实现选择文件、协议或扩展节点；核心不直接接相机。PCD/PLY 等格式须明确变体、字段与大小限制后才开放。
- 标定、坐标变换、配准和查看器视角是不同操作。点云坐标必须声明单位、轴方向/手性和 frame；单位或变换缺失时不能显示可信 mm 测量。
- 3D 专属编辑器提供点/线/面/体积选择、基准、配准前后叠加和测量项表；有序深度与非结构化点云使用不同输入解释。
- 显示 RGB、强度、法向、偏差或分类着色只在字段存在时开放。无效点、遮挡、点数不足、配准失败和模型不适用有独立状态。
- 距离、角度、拟合误差、形状偏差等定义在算法契约中；共面度、平面度等不能用含糊“拟合距离”命名冒充图纸评价方法。
- 默认有适配、重置、方向视图、坐标轴/单位、点大小和图例；首次进入不自动旋转。触控、鼠标、键盘操作提示简短且可查。
- 结果表选择某项时高亮本次几何；改变相机视角不触发后台测量、不改变生产参数。

点云除点位置外可能具有颜色、法向等不同属性，字段按真实数据呈现；设计参考 [Open3D 点云说明](https://www.open3d.org/docs/latest/tutorial/t_geometry/pointcloud.html)，不据此宣称本项目已支持该库的全部功能。

## 5. 通用节点 UI 与资源配置

| 组件 | 必需内容 | 保存/执行语义 |
| --- | --- | --- |
| 资源选择器 | 名称、类型、版本、来源、有效性和预览；新建/编辑入口 | 选中引用，不自动改发布版 |
| 图像几何编辑器 | 图像缩放/平移、ROI/掩膜/坐标、当前选择 | 几何修改先留编辑状态，应用后进入节点草稿 |
| 测量/规则表 | 对象、字段、计算或比较规则、单位、阈值、启用 | 行级校验；错误定位，不默默跳过错误规则 |
| 3D 几何编辑器 | 视图、选区、frame/单位、基准与测量表 | 编辑的是配方参数，视角偏好不混入几何变换 |
| 结果表 | 实测值、单位、限值、状态、原因、几何链接 | 展示本次结果，不能直接修改测量真值 |
| 显示数据编辑器 | 字段、格式、颜色、大小和布局 | 仅展示配置，判定由上游业务数据提供 |

普通 Apply / Cancel / Reset 等操作继续随界面语言切换。短配置如 File Summary 批次限制和 Load Local Image 限制保持直观单位，不为了统一新 UI 把这些字段重新藏入折叠面板。

资源须在发布时绑定确定版本和依赖。未来统一资源库需要持久化/API 设计，首期优先复用已有连接器资源能力，避免同时维护新的不兼容模板格式。跨项目资源引用、共享/复制、删除依赖必须由后台验证。

## 6. 结果查看与应用模式

统一查看器“外壳”，按媒体选渲染器：二维图像、热图/区域叠加、深度数值图、3D 点云/几何、表格和值。并非把所有数据都转成 JPEG。

| 使用位置 | 显示方式 |
| --- | --- |
| 节点内 | 小型静态/轻量预览和摘要；复杂内容点击展开，不在每个节点持续创建 WebGL 场景 |
| 专属编辑器 | 当前输入、配方和本次结果联动；配置与结果状态明确 |
| Runtime 监视 | 发布图只读结果；遵循执行完成后的观察边界 |
| 应用模式 | 在原应用模式配置中选择栏目；图片/3D/表格按已声明类型布局 |
| 专用大图 / 大视图 | 保留同次结果、显式绑定的显示数据与选择状态；退出返回原位置 |

Display Data 关联必须由明确连线/已定义映射产生。独立 Value Display 栏目未勾选不等于禁用该节点；图片的数据叠加由该图片绑定决定，配置需要用简短明确名称区分。未来 3D 栏目复用这一规则，不能按相邻位置或名字自动配对。

图片统计仍在左上角、垂直、半透明，按节点配置显示颜色/字号/大小。3D 统计占用同样位置但不遮挡必要轴标和操作；关闭数据层不影响计算。OK/NG、物料总数、检查项数、点数、运行次数分别展示，字段由 Workflow 决定。

## 7. 数据契约与高性能边界

新的结果类型需先明确以下信息，再做端口或查看器实现；名称为语义要求，不是已存在的 API 字段声明：

- 数据种类、有效性、同次执行/观察与源样本身份、对应节点输出。
- 原始资源引用、展示资源引用、尺寸/点数/字段、单位、坐标框架、标定/变换版本。
- 几何与表格项的稳定关联；缺失/失败原因；显示数据的明确来源。
- 版本化 payload、能力发现、大小限制、所有者、接收确认、释放、超时和取消边界。

原图/原始深度/全精度点云供后台算法，JPEG/热图伪彩/显示抽样只供浏览器展示。显示抽样不回流测量；像素级数值探查从原始数据或正式测量结果读取，不从 JPEG 反推精度。

沿用当前 Preview Worker → 已部署模型服务 → 节点结果 → WebSocket 页面路径。Preview 临时数据不隐式落盘；显式保存节点保持原语义。Runtime / Trigger 同步数据面不因新 UI 增加队列、等待或业务自动重试。WebSocket 不启用 permessage-deflate。

3D 大数据采用有界展示分辨率/点数、必要分块和按需加载，具体传输协议与原始引用按已有架构评审后确定。浏览器放大并不无条件要求发送整片百万/千万点数据；参数上限来自设备预算与测试。显示面可以合并更新，执行结果和生产响应不能因此被丢弃或延迟到浏览器渲染完成。

## 8. 查看器稳定性与离线边界

- 同时激活的 3D 场景有上限；非活动页停止绘制，关闭时释放几何、纹理、Worker、事件监听和对象 URL。帧缓存、缩略图及场景缓存都必须有容量界限。
- 渲染按变化更新，静止画面不持续满速耗 GPU；切换视角、主题、窗口尺寸后正确更新。
- 检查 WebGL 能力与资源分配失败；context lost 显示局部提示，恢复时重建显示资源。不能把浏览器 GPU 故障解释成后端检测服务异常。事件处理依据 [WebGL 1.0 规范](https://registry.khronos.org/webgl/specs/1.0.3/)。
- 无 3D 能力时保留表格、诊断和明确标注的二维快照入口；不能用快照假装可交互或可进行三维测量。
- Vue 3 主栈不变，渲染器模块按需加载并随发行包本地分发；不依赖 CDN、外部字体或目标机 Node。前端渲染库选择在可运行原型后确定，不提前把某个库写成已有依赖。
- 单帧跨页面结果、长时间反复打开/关闭、多个查看器并用及后端执行中的断连都需要测内存与延迟；静态图不构成稳定性结论。

## 9. 首批完整设计场景

1. 异常检查：正常/明显异常/未知、对齐失败、热图/区域/表格、显示阈值与判定阈值的区别。
2. 连接器：已准备合成图、标定图、位置变化、缺 PIN、临界尺寸、缺测；明确合成开发资源标签。
3. 3D：带单位的简单已知几何点云、噪声/缺点、单位缺失、配准失败；准备数值基准后再绘制测量值。
4. 共用：未执行、执行中、错误、旧结果、图像解码失败、点云超限、只读权限和断线。
5. App Mode 与扩大视图：纯图片/纯 3D、显式数据绑定、无数据绑定、结果表联动；亮暗与窄屏成对。

当前可以开始统一界面母版与专业编辑器设计。3D 的可执行节点名称、端口与数值示例必须先与开发实现核对；不能为生成好看的流程图而编造正式节点或连线。

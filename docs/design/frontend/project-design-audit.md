现有主要页面和容器划分合理，可以保留。项目分类只需要 **2 个主页面、3 类抽屉、2 类对话框**；不足主要是状态覆盖和操作边界，不需要增加左侧子导航、项目设置中心或行业专用项目页。

## 4. 优先修正的设计问题

### 4.1 选中项目与查看项目

保留行选中。绿色行表示当前业务项目，不是多选、悬停或正在运行。项目名称旁加低干扰“当前项目”标识，不能只靠底色辨认。点击行选择；“查看”选择同一目标并进入概览；更多菜单打开信息/编辑时锁定该行对象，不隐式切换全局项目。

列表上方 SDK 按钮作用于当前项目，打开对话框后必须显示发起时的项目名称；无当前项目时禁用。搜索、分页不改变当前项目，过滤后选中行不可见时在列表工具区显示“当前项目：名称”及“定位”，清除搜索并定位所在页；不重新引入全局项目选择栏。键盘操作需提供可聚焦的项目选择入口和独立查看链接。

### 4.2 文案与数据口径

新建和编辑统一“项目名称”“项目说明”，列表列名使用“说明”。标题统一“新建项目”，不混用“创建新项目”。同名项目可以存在时，只在需要区分的选项/对话框中显示短 ID；详情始终可复制完整 ID。

列表“更新时间”定义为**项目元数据（名称/说明等）最近修改时间**，不是训练进度变化、资源最近活动、文件系统扫描时间或摘要生成时间。若目标接口未提供则显示“—”，不能填生成时间。最近更新模块中每条时间属于对应资源，两者不混用。样例日期只用于设计稿。

模型实体数、应用数、Runtime 数及部署实例数分别定义；不能把训练次数当模型数或模板数当应用数。四项计数的来源继续以[概览规格](project-overview-design.md)为准。

### 4.3 重要性与浮层

列表“新建项目”为绿色主动作。概览顶端信息、编辑、SDK 都是次动作，不额外突出 SDK；真正打开 SDK 对话框后，“生成并下载”才是该容器的主动作。

新建、信息、编辑统一建议宽 520 CSS px，允许 480–560px 的受控适配。锁定底图，开启时不得移动背景内容。亮暗均使用覆盖遮罩，暗色用可见边界和遮罩清楚地区分前景；不能用绿色光晕、磨砂或改变品牌色代替。正文滚动，标题和操作区固定。

### 4.4 删除影响不能只画空项目

“无活动资源”不等于“没有数据”。确认前展示服务端真实 `resource_counts` 对应的影响列表及项目目录说明；多个类别逐行列出，不将不同层级的数量相加成不明的“资源总数”。范围未知时明确未知，不显示 0。默认项目、配置项目保护与缺权限分别说明；不提供强制停止或强制删除。

现有服务端已经在删除执行阶段复核活动资源；应保留该行为。前端目前忽略删除返回状态，统一提示删除成功，后续实现必须区分 `deleted` 和 `cleanup_pending`。本轮仅记录设计/实现缺口，没有执行删除测试或修改代码。

### 4.5 异常不能伪装为正常空态

无项目、搜索无匹配、无访问权、尚在加载、读取失败、旧数据过期分别呈现。部分模块失败只影响本模块。保存失败保留草稿；提交结果不明先核对，禁止自动重发写操作。分页前后边界必须禁用；只有一页可隐藏分页按钮，保留总数。

## 5. 还缺哪些设计

详细清单已补入[项目分类设计第 11 节](project-pages-design.md#11-完整状态覆盖清单)，每项有对应显示、动作和出图方式。缺少的不是更多功能页，而是以下 8 组：

1. 列表：当前项目/操作菜单、无项目、无匹配、读取失败、长名称/分页。
2. 新建：初始空表单、必填/服务校验、提交中、失败或结果不明、创建后返回。
3. 概览：空项目、最近更新展开、部分失败、只读、无权/不存在。
4. 信息：长 ID/路径、无说明、复制反馈、加载失败、配置项目只读。
5. 编辑：字段错误、保留草稿的失败、并发冲突、未保存退出、保存完成。
6. SDK：空配置、失败、生成中/已开始下载、预览后配置变化。
7. 删除：暗色配对、受保护、非空影响确认、清理待完成/结果不明。
8. 共用：短屏、缩放、焦点、关闭后恢复位置、断线重连。

不新增项目导入/导出、迁移、克隆、独立备份、成员管理或项目回收站。这些没有当前需求和完整契约，不能为“设计齐全”而随意加入。异常检测、连接器测量和 3D/点云项目仍进入相同 Workflow/应用页面，项目分类不新增行业分支。

## 6. 下一轮出图与实施顺序

1. **先修现有主图**：当前项目标识、分页边界、文案、概览动作层级、统一抽屉和暗色遮罩。先亮色，检查后再配暗色；不批量传播未修正母版。
2. **补正常使用缺口**：列表操作菜单、空列表/无匹配、空概览、最近更新展开。一个状态一张页面，不做拼接海报。
3. **补操作关键状态**：保留草稿的保存失败、未保存退出、SDK 空配置、非空删除影响确认、清理待完成；补删除暗色图。
4. **公共状态复用**：加载、禁用、复制成功等使用公共组件状态规范；不为每个组合生成一张全屏图。需另外核对最密集页面的短屏和长内容。
5. **再进入代码实现**：先稳定项目读取/创建/编辑及摘要契约，再实现列表/概览、共享抽屉、SDK 和删除反馈。每步验证后推进，不把静态画面的缺省值写死进代码。

当前 14 张 PNG 均保留，本轮补齐规格与中文提示词，不将尚未生成的状态登记为已出图。后续使用[项目补充状态提示词](prompts/项目补充状态.md)，避免重新猜测状态或增加功能。

## 7. 验收要求与范围

- 每个入口有明确对象、返回位置、成功/失败/权限/结果不明行为。
- 同一场景亮暗数据相同，关闭抽屉后底图位置不变；普通 hover 与当前选择可区分。
- 1920×1080、1366×768，125%/150% 缩放下主要操作可到达；不以整体缩小字号解决溢出。
- 同名项目、长中文名称、长 ID/路径、仅一页和跨页选择均有处理。
- Tab 顺序、Escape、焦点恢复、屏幕阅读名称和错误关联在可运行原型中验证；截图不等于无障碍验收。
- 品牌绿配白字/浅底绿色小字的对比度风险沿用[设计系统](design-system.md)已记录取舍，保留用户要求的品牌色，不能宣称对比度已达标。
- 概览读取不启动模型、不扫描生产图片目录、不订阅逐帧推理结果、不新增执行队列。SDK 不增加自动调用或自动重试；设计阶段不影响 Runtime/Trigger 数据面。

# 设置分类页面规划

更新：2026-11-02。以实际九页布局为基础，本轮完成28组56张，修订母版并补关键操作、异常与短屏。本轮10项细节交互已验证，前轮19项基线检查另行保留；[修订记录](settings-revision-and-states.md)与[QA](prototypes/settings/design-qa.md)为最新依据。

## 1. 固定边界

详细依据见[现有实现核对](settings-current-baseline.md)。已确认的其他分类设计用于统一颜色、状态和组件表现，不用于替换设置页布局。

- 全局导航展开220px、折叠64px；设置导航220px，不沿用旧生成图的284px侧栏。
- 偏好、启动页面、运行状态分别独立。系统环境子项为关于、系统信息、Python运行时、设备信息；访问控制子项为会话与权限、用户管理，仍在同一列分组缩进。
- 无独立全局顶栏，不恢复隐藏的设置重复标题；保留界面偏好、启动页面、服务信息等局部标题。
- 保留字段网格、诊断表、独立滚动和用户目录+详情工作区；不把现有确认弹窗一律换成抽屉。
- 正常状态减少说明，错误保留原因与下一步。品牌绿#00D992，主按钮白字；选中软绿、普通hover及输入focus中性。
- 优化顺序不是新导航分类。禁止再以“偏好与启动→运行状态→环境关于……”为由合并现有页面。

## 2. 页面与状态矩阵

下表九页已有源码实现。九页均已完成实际亮暗截图和主图视觉核对；补充状态当前覆盖见[范围矩阵](settings-state-coverage.md)，本表保留完整目标。

| 页面 | 路由查询 | 保留内容 | 补充状态 |
|---|---|---|---|
| 界面偏好 | category=preferences | 语言下拉、Sun/Moon亮暗选择、即时生效 | 长语言、键盘焦点、存储失败 |
| 启动页面 | category=startup | 项目页面/应用模式、项目、Runtime选择与状态、恢复默认/保存 | 未修改/已修改、加载/校验、无实例、目标失效、无应用模式、保存失败 |
| 运行状态 | category=services | 六项服务、Worker元数据/七列表、接口配置、平台能力 | 初次加载、健康、心跳异常、断线旧值、刷新、长ID |
| 关于 | category=system&section=about | 小写普通字重动态品牌、Community Edition、版本/构建/许可/链接 | 未知版本、长文本、链接focus |
| 系统信息 | category=system&section=host | OS/CPU/内存/路径、磁盘表 | 长路径、不可读、容量未知 |
| Python运行时 | category=system&section=python | 环境网格、依赖表 | conda/随包Python、缺失/导入异常、长路径 |
| 设备信息 | category=system&section=devices | CUDA/OpenVINO/TensorRT/ONNX Runtime/NPU状态、GPU表 | CPU-only、未探测、驱动异常、安装与可用差别 |
| 会话与权限 | category=security&section=session | 身份、凭据、可访问项目、账号来源 | 无项目、权限收窄、会话失效、长ID/Scopes |
| 用户管理 | category=security&section=accounts | 用户目录、访问权限、Token、密码重置、创建/确认弹窗 | 只读、空列表、提交错误/未知、受保护用户、过期Token、长内容 |

## 3. 必要细节优化

| 项目 | 设计处理 | 与当前代码的区别 |
|---|---|---|
| 数据新鲜度 | 服务标题区紧凑检查时间和刷新，旧值注明时间 | 当前没有持续刷新；不能画成实时仪表盘 |
| 加载与失败 | 原位保留空间，未获取不显示假离线/0/0 | 当前空数据有默认值，需要实现时补判断 |
| 长内容 | ID/路径完整可查、复制；错误短原因+按需详情 | 保留字段顺序；是否进一步折叠Topology字段需截图后确认，不先删字段 |
| 日常标签 | Workflow / Runtime→运行实例，Frontend build→前端版本，Backend version→后端版本，Project可见范围→项目范围，Auth mode→认证方式 | 只改显示文案，专有名、API字段不改 |
| 保存反馈 | 启动草稿离开保护、存储失败保留内容，保存完成与未完成明确 | 已有isDirty/禁用；未见离开保护及存储失败专用提示 |
| 排版 | 保留64px偏好行、40px按钮、6/8px圆角和现有表格密度 | 不整体放大；仅处理换行、溢出、控件对齐 |
| 状态语义 | 已安装、可用、未探测、运行中、过期、撤销分别表达 | 繁忙/满载不等于未就绪；未撤销Token不必然有效 |

本轮已由实际截图确认表格列宽、Token状态截断、长路径与普通标签混写问题并完成静态稿，不改上述代码。刷新/检查时间等已在本地样稿验证，不代表生产代码已实现。

## 4. 操作边界

- 语言/外观在当前浏览器localStorage即时保存；启动配置按principalId隔离，不新增后端数据库偏好。
- 启动页面只决定浏览器打开位置，不启动Backend/部署/Runtime/Trigger。实例已停止与目标不存在分开。
- 保留未修改禁用、加载禁用、目标身份/app_mode校验，以及快速切换项目防旧请求覆盖。
- 用户创建、权限、Token、密码重置是不同动作；ConfirmDialog保持。权限取真实服务结果。
- 当前保护包含删除自身、系统默认用户、唯一amvar等条件，不扩大为已验证的通用最后管理员保护。
- 真实Token/密码不进入设计资产。结果未知先查状态，不能重复创建或撤销。

## 5. 后续完整目标

保留演进范围，但不把未来能力塞入基线母版。

| 扩展 | 位置 | 开始前条件 |
|---|---|---|
| 部署/Runtime/Trigger整体就绪摘要 | 运行状态内增量信息区或诊断入口，保留原六项服务和Worker表 | 对齐/system/status范围/时间/权限；繁忙健康不变 |
| 跟随系统 | 偏好原行第三选项，另做扩展状态 | 当前ThemeMode仅light/dark；先定义系统变化和手动选择规则 |
| 存储与维护 | 系统环境分组的后续入口，沿用原主区 | 明确受管理目录、容量、引用、权限、任务和恢复契约 |
| 诊断导出、维护记录 | 对应信息页局部操作 | 明确脱敏、导出范围、执行方式和文件生命周期 |

不全盘清理，不把生产JSONL当缓存，不修改既有日志策略，不增加常驻第三层导航或全局顶栏。

## 6. 出图顺序与后续步骤

1. 已取得九页同视口亮暗截图，校准导航、字体、间距、滚动。
2. 运行状态优先作为母版：保持六项摘要→Worker→接口→平台能力顺序；允许滚动，不缩字塞满。
3. 亮色逐项通过后生成暗色配对；尺寸取实际截图，不沿用上一版生成尺寸。
4. 九页母版、启动目标失效、断线/Worker异常、用户权限/Token、依赖异常及短屏已完成。
5. 主图后补状态。同结构空态/失败用明确文案规则复用；创建用户、编辑权限、Token明文、撤销和删除确认分别设计。
6. 核对窄容器、短屏、亮暗、键盘、长内容和权限变化。静态图不替代交互及生产验收。

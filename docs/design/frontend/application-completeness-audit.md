## 3. 收尾清单

### A. 现有实例配置修改路径——必须补齐

证据：[异步不可用](generated/应用/调用调试-异步不可用-亮色.png)已有“查看实例配置”，[记录空态](generated/应用/执行记录-空态-亮色.png)已有“实例配置”，但只有[只读详情](generated/应用/运行实例详情抽屉-亮色.png)和[创建表单](generated/应用/创建运行实例-亮色.png)。当前不能从这些设计完整走通修改记录策略的操作。

补一组“编辑运行实例配置”亮暗图，复用创建表单的字段样式，明确实例名称、超时、记录方式和诊断选项。实例身份和版本只读，切版仍走原流程。提交失败保留输入、并发冲突读取最新且不强制覆盖；共用已有错误组件，不再为每个字段生成整页图。

出图前先确定更新接口、配置修订和生效时点；在此之前不得承诺运行中热修改。执行相关配置采用停止后修改、无活动执行且相关触发停用的目标边界，服务端最终校验；不由UI自动停止或重启。当前产品未实现该更新能力，设计与实现状态分开。

同时修正入口作用域：配置入口放在明确的当前实例上下文中；执行记录选择“全部实例”时不提供无目标的修改动作。配置返回后保留原筛选、输入和实例选择。

### B. 实例诊断页——已有方向，缺少代表界面

证据：[实例详情](generated/应用/运行实例详情抽屉-亮色.png)有“诊断”标签，[启动失败](generated/应用/运行实例-启动失败-亮色.png)有“查看诊断”，现有图片未展示诊断标签选中后的布局。

补一组“运行实例诊断”亮暗图：实例、状态、检查时间；短错误摘要；相关资源；按需展开原始诊断并允许复制。正常时不堆说明和JSON，数据不可用显示“暂无”，断线显示最后确认时间，不给假正常或0计数。长内容在抽屉内部滚动，错误复制注意凭据脱敏。性能数据只显示服务实际提供的字段。

### C. 通用执行失败记录——补齐错误定位

证据：[完整记录详情](generated/应用/执行记录详情-完整-暗色.png)展示成功结果，背景记录列表有失败行；超时已有独立图，但通用节点/执行异常的详情未完整呈现。不能用业务NG详情或超时图代替所有执行失败。

补一组“执行记录详情-失败”亮暗图：执行编号、固定的实例/版本、失败阶段或节点（仅有证据时）、短原因、时间、复制错误和查看诊断。部分输出只能展示已保存且可访问的数据，明确为部分结果，不计为业务OK或伪造完整结果。摘要记录没有完整输入输出时使用现有不可用状态。输入输出/诊断标签复用现有结果查看器与上述诊断组件，不新增另一套页面体系。

### D. 结果未知后准备新调用——确认规则需具体化

证据：[同步回执待确认](generated/应用/同步回执-待确认-亮色.png)允许“准备新调用”，原文只有“须后续确认”，未明确确认界面和动作结果。

补一组小型确认框“准备新的调用？”，列出目标实例；短提示“上次调用可能已执行，再次调用可能重复保存或计数。”按钮“返回检查”和“准备新调用”。确认只解锁新的输入表单，不发送请求；后续必须再点“调用一次”。旧回执保留为结果未知，不改成失败或成功。无run_id不提供虚假的查询结果。正常调用不增加这层确认。

## 4. 已修正的文档与视觉约束

- 创建表单中的“不保存、诊断关闭”是该图的示例选择，不是全平台缺省；实例页面读取实际配置。
- 亮色图个别文字/图标略偏蓝黑，字号与短屏侧栏比例有生成误差。实现按已确认中性色与尺寸Token；不把蓝色当普通操作链接，不按位图采样替代CSS。
- 右侧抽屉覆盖底图，导航和正文同层遮罩；主按钮品牌绿白字、危险动作实色红、悬停与输入焦点中性灰。正常说明短，错误保留必要处理信息。
- 4组补图已完成，属于有限收尾范围，不扩张成每项字段错误的独立页面；目录不放占位图。

## 5. 与集成分类的边界和顺序

可以开始集成分类的信息架构、中文提示词和母版。正式生成共享配置/诊断页面前，应先落实上面的实例配置与诊断边界。

| 分类 | 负责 | 不重复建设 |
|---|---|---|
| 应用 | 应用/发布版本/Runtime、实例调用调试、执行记录 | 不在应用详情另做协议配置表单 |
| 集成 | TriggerSource、协议参数、输入映射、结果绑定、启停及通信诊断 | 不管理模型部署，不修改Workflow内部节点 |
| 图编辑/App Mode | 草稿编排、Preview、发布、配置与使用结果界面 | 不把Preview WebSocket作为通用Trigger协议 |
| 项目/节点 | SDK配置包入口、受信任扩展能力和依赖管理 | 不把硬件驱动塞入集成核心 |

下一阶段顺序：

1. 触发入口列表与详情亮暗母版：名称、类型、目标实例、状态、触发时间、操作；长ID、错误和原始计数进详情。
2. 新建/编辑：目标实例 → 协议参数 → 输入映射 → 结果绑定。优先核对ZeroMQ、本机共享内存、目录监听；后续协议按Adapter能力注册扩展，不虚构内建硬件控制。
3. 启用/停用、修改生效、删除确认、实例未运行、接口变化、端口占用、文件权限及资源失效；保存与启用条件分别定义。
4. 诊断与验证：配置检查不执行Workflow；真实试调用必须明确为一次执行，可能产生记录/文件等副作用。目录监听由后台自动执行，无SDK调用配置。
5. 空态/权限、断线待确认、长映射、短屏、返回应用后保留目标。满载正常拒绝，不加排队、自动重试或自动重投。

参考[已有集成提示词](prompts/集成与节点.md)中的X01/X02与bak1资源；节点目录N01/N02属于“节点”分类，后续详细集成规划应单独成文。保持当前简洁平级导航，无独立全局顶部栏，正常操作不增加说明墙。

## 6. 验收界限

审查当时为61组122张；本次收尾后为65组130张、130份中文完整规格。4组图和交互规则已完成静态核对。原有图继续有效，不重复创建版本目录。链接、哈希和目录检查结果追加至[逐图复核](application-design-review.md)。

静态覆盖不证明焦点返回、权限撤销、并发回执顺序、取消竞态、短屏真实尺寸和性能已通过。下一步交互原型仍应针对这些行为验证；图编辑/App Mode专题的未完成状态单独登记。

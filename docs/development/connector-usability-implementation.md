## 节点与显示契约

现有 v1 API 不增设 v2 或双轨实现。本轮公开内容是向现有节点增加可选输入/输出及显式参数；既有调用不填写时保留原行为，数据库无需迁移。应用使用新端口时须重新保存并发布，既有冻结发布版本不自动更换资源。

- `Check Limits.summary` 的每个条目增加 `lower`、`upper`、`include_lower`、`include_upper`。值来自本次实际执行规则；前端不拿另一个草稿的公差拼接结果。缺测保持 null，原始未舍入值用于判断。
- `Value Preview.display_mode` 为 `json`（默认）或 `table`。表格取 Path 对应的对象数组，最多 8192 行、32 列；`columns` 是唯一的 `{key,label,format?}` 列定义。`format` 为第二轮新增可选显示语义，详见下文。缺少路径显示空结果，不沿用旧结果。原有 JSON/ROI 路径保持原行为。
- `Value Preview.geometry` 可选，使用 `value.v1` 携带 `{observation_id,image,items}`。每个图形含唯一 `item_id`、`kind`、`points`。`line` 必须有两个点，`point` 和 `expected-point` 必须有一个点，坐标均为当前原图坐标。只在 Table 模式接受，同次观察和表格行 ID 必须一致。
- `Connector Measure.result_geometry` 提供上述显示数据，不重复读图或重新检测。缺针位置以 `expected-point` 表示名义位置；不能当作测得边缘或数值。Core 不认识 PIN 或产品类型，只校验通用身份、边界和位置。
- `Image Preview.results` 可选，接 `Value Preview.body`。后端核对 `observation_id`、执行 run ID 和原图引用摘要；绑定另一张处理图或另一帧会明确拒绝。未连接时不创建结果表或改变原有显示数据叠加。
- 小图和大图共享本次表格与选中 ID。新 observation 清空旧选择；仅不通过过滤不修改完整原始结果。预览分页内容在原有内存接收/确认/释放链路完整读取后显示，表格 JSON 读取上限 16 MiB。
- `Planar Calibrate.debug_preview` 仅在编辑预览启用时包含 `calibration_resource` 和 `parameter_snapshot`。前端检查当前参数与该次成功输出相同后才能保存；取消、迟到、失效结果或参数改变不允许保存。保存不自动修改测量节点引用，Runtime/Trigger 不增加这一份调试配置复制。

显示 JPEG 不参与测量，测量仍用原始图。WebSocket permessage-deflate 保持关闭。结果几何和表格传输是显式增加的应用输出开销，不应把它宣称为零成本；原图没有绑定 Results 时不承担图形身份校验。

## 临界量值分解

复现命令：

```powershell
conda activate amvision
python -m scripts.connector_assets.analyze_boundaries --assets data/development/connector-inspection/synthetic-v1 --scratch .tmp/connector-usability-boundaries --report data/development/connector-inspection/usability-implementation-20261008/boundary-analysis.json
```

验证脚本单独使用合成真值作比较；生产节点只接收原图、固定参考配方和已保存标定。两类物料各 9 个工况，共 18 张图片，并增加 16 个理想积分边缘控制实验。

| 临界样本 | 标注宽度 mm | 实测 mm | 实测像素宽度 / 投影几何宽度 px |
| --- | --- | --- | --- |
| single10_front / width_on_limit | 0.69 | 0.692435152893 | 23.324131466 / 23.242111206 |
| dual08_top / width_on_limit | 0.69 | 0.698787673130 | 23.538111095 / 23.242111206 |
| dual08_top / width_inside_limit | 0.68 | 0.690063368439 | 23.244239779 / 22.905273438 |

三项仍按既定 0.69 mm 上限判定 NG，保留失败结论。对这三张静止样本，固定单位位姿与实际定位的宽度相同到浮点误差，排除其刚性位姿为主要来源。18 张样本中，物理宽度与像素宽度按保存比例映射的差异最大约 `4.89e-15 mm`，没有发现单位转换或比例映射错误。

采样步距 0.25/0.5/1 px、灰度增益及模糊实验显示：非裁剪线性灰度变化几乎不改位置；更小步距或模糊并不保证所有边界样本更准确。理想积分边缘的四个像素相位、两种分辨率仍出现约 0.00447 mm 的最大误差。当前证据把主要偏差收敛到图像光度边缘与采样/边缘估计，而不是界面、公差抄写、资源引用或标定单位。

这些实验不足以把 Blender 光照/栅格化与估计器各自误差精确分离，也不能证明提高分辨率必然解决所有相位误差。本轮不通过改公差、舍入后判断或真值补测掩盖问题。当前配方可用于流程开发和明确裕量样本，不能承诺上述临界区分能力；现场需要原图、独立参考件及重复拍摄数据确定误差预算。

**资源稳定性不能按调用成功直接判通过：** HTTP 工作集由约 287 MiB 上升，在后段约 809 MiB 附近波动，末次降到约 682 MiB；Preview Worker 工作集末次约 129 MiB，但句柄由 337 增至 384。只读句柄检查发现后段增加主要反映在 Semaphore 数量，未观察到未关闭图片文件或 `psm_` 映射；单独重复 JPEG/resize/拟合的短实验没有复现同样增长。

后续已定位并复现句柄根因：`WorkflowModelSessionManager._scope_locks` 为每个 Preview session 永久持有 `RLock`，无模型的空 scope 也保留锁和 LRU 时间项，`close_all()` 只遍历模型 lease，不能释放这些空 scope。隔离复现 100 个空会话使 Windows 句柄从 215 增为 315，关闭后仍为 315。

### 计量与耗时

已确认生成资源使用 Blender Standard/sRGB 输出。编码后的强度不等价于线性光度剖面；在 sRGB 数据上直接计算梯度会改变亚像素峰位。Pin Array Locate 新增显式 `Image Encoding`，默认 native 不变；合成配方设置 srgb，先按已知传递函数还原再采样。没有更改公差、取整后判定、读取测试真值补结果或按样本名切换算法。

还原强度后，低曝光下固定绝对门限会漏检，过低门限又会引入背景候选。采样类型增加默认关闭的相对门限，实际阈值为绝对底线与每条扫描线峰值比例的较大值。开发配方使用比例 0.2，PIN/行搜索绝对底线 0.005，外侧候选带 0.01；类型、候选带和参数均显式保存在图中。诊断图显示本次实际阈值范围。

| 样本 | 原实测 mm | 修复后实测 mm | 原上限 mm | 当前结果 |
| --- | ---: | ---: | ---: | --- |
| single10_front / width_on_limit | 0.692435152893 | 0.686575515262 | 0.69 | OK |
| dual08_top / width_on_limit | 0.698787673130 | 0.686812902975 | 0.69 | OK |
| dual08_top / width_inside_limit | 0.690063368439 | 0.676634419841 | 0.69 | OK |

0.70 mm 外侧样本分别得到 0.699369639713 与 0.700976995935 mm，仍判 NG。两种产品族的临界、平移、旋转、亮暗、缺针、多针、空图和多工件等 40 个场景使用真实节点回归。残余误差仍存在：例如平移双排某 PIN 的宽度误差约 0.01133 mm；这些固定样本通过不等于任意像素相位均有 0.01 mm 区分能力，更不等于实物计量准确度。

定位采用二值掩膜零均值归一化相关的等价计算，复用源图平方和，不缩小搜索角度、金字塔比例或候选数量。与独立 OpenCV 通用 masked NCC 的随机旋转对照通过；常量搜索区仍不生成可信高分。20 次完整 Runtime HTTP 调用中位数 1.569 s，范围 1.091–2.877 s；单排中位数 1.447 s、双排 1.845 s。前次 2.170 s 为另一轮现场样本序列，不能把全部差异归为算法提升，也未达到普遍小于 1 秒。

### Broker 与内存

旧周期回收是 HTTP Supervisor 线程通过 router 请求 Broker，存在控制往返超时的独立失败路径；撤销扫描仅在请求空闲时执行，持续控制请求可使回收延后。现在 Broker owner 在请求之间和空闲期间按单调期限推进清理，保留既有 reader guard、epoch 和 lease 身份校验。空 arena 依据 owner 已恢复的 buddy 占用跳过全 descriptor 扫描；不增加业务排队、模型重试或强制回收。

清理异常按动作分别保留并对 health 可见，同一动作成功后清除当前错误，同时保留最近错误。另行修复已超时控制回复污染下一次调用的问题：有界保存超时 identity，下一次调用仅丢弃已知迟到回复，使用本次原有超时预算，不重发原请求。未知 identity 继续报错。历史那一次超过 5 秒的操作系统调度现场无法从原日志重建，因此不声称已经确定具体是哪次系统调用阻塞；本次移除了这条周期清理 RPC 依赖，并通过忙碌、空闲、借用保护、故障注入和恢复测试验证。

隔离真实 HTTP 100 次 Runtime 调用的诊断中，显式 GC 后 Python 跟踪存量约 0.39–1.82 MiB，工作集 291–296 MiB，句柄 817→806；用于区分活对象与工作集，未把 GC 加入产品。三分钟开发服务混合运行完成 Runtime 49、ZeroMQ Trigger 67、Preview 21 次，错误为空；HTTP 工作集约 291–296 MiB，Preview Worker 收尾约 134 MiB/326 句柄，所有预览完成 ACK 后释放及会话清理。当前没有复现原 HTTP 数百 MiB 的持续增长，但短测不能精确解释旧进程每一段工作集变化。

### 表格显示契约 v1 的增补

`Value Preview.columns[].format` 为可选枚举：`value`（默认）、`unit`、`result`、`validity`、`reason`。后端拒绝未声明的格式，原始 rows 保持不变。`result` 仅把布尔值显示成 OK/NG；`validity` 显示有效/无效；`unit` 显示 mm/px/° 等符号，未知单位保留原值。任意普通布尔字段不会被隐式解释为合格。通用原因由共享层解释，连接器原因文本由 Connector 包在前端组合入口登记，未知代码仍保留可诊断原值。

这是现有 v1 表格节点的可选字段增补，不增加 v2 API、不修改数据库结构；旧配置省略字段仍按 value 显示。需要统一表格格式的应用应显式添加字段后保存并发布。旧冻结发布版本和不可变资源不自动改写。显示舍入只影响文本，判定始终比较原始量值；完整 JSON 可核对 0.6900000000000001 等临界原值。

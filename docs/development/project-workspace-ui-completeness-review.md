## 修复前确认的问题

### 1. P1：连续请求失败会误清除删除待确认记录

位置：[ProjectDeleteDialog.vue](../../frontend/web-ui/src/modules/projects/components/ProjectDeleteDialog.vue:39)、[ProjectDialogs.vue](../../frontend/web-ui/src/modules/projects/components/ProjectDialogs.vue:35)。

触发顺序：预检成功 → 删除响应丢失 → 查询最新结果失败 → 再次预检也失败。`load()` 捕获错误后没有清空旧 `preview`，外层仍因旧对象存在而发出 `unaccepted`，父组件因此删除本地待确认标识。此时服务端删除是否成功仍未知。问题是前端丢失恢复入口，不代表服务端回执被删除，也不能把它解释为删除未受理。

本轮用真实组件和模拟服务拒绝复现：删除调用一次、结果查询一次、预检两次，最终确实触发 `unaccepted`，没有收到任何成功结果。该测试专门确认缺陷存在，其通过不表示正确行为通过。

修复要求：请求失败与服务端明确未受理分别处理；查询失败保留操作身份和最后已知状态，不根据旧预检数据清除提示，不自动再次发起删除。

### 2. P2：删除恢复只保存一个操作，结果界面未完整对齐设计

位置：[ProjectDialogs.vue](../../frontend/web-ui/src/modules/projects/components/ProjectDialogs.vue:39)、[ProjectDeleteDialog.vue](../../frontend/web-ui/src/modules/projects/components/ProjectDeleteDialog.vue:5)。

待确认信息存放于一个账号级 localStorage 键。项目 A 尚待清理时删除项目 B，会覆盖 A；B 完成时也可能清除 A 的恢复入口。服务端记录仍在，页面没有按操作枚举恢复。

视觉证据：[目标设计](../design/frontend/generated/项目/删除项目-清理待完成-亮色.png)、[实际截图](../design/frontend/verification/projects-20261104/delete-receipt-light.jpg)。结果正文没有项目名称/身份；`cleanup_pending` 只显示警告图标，没有单独表达“项目已移除”的成功状态；查询按钮是正文中的次按钮，未对齐设计的底部品牌色主动作。

修复要求：按项目与操作保存多个未完成结果；明确区分项目移除和文件清理两层状态，保留项目身份；检查结果只查询，不重发删除。

### 3. P2：草稿保护没有覆盖离开路由和刷新

位置：[ProjectMetadataDrawer.vue](../../frontend/web-ui/src/modules/projects/components/ProjectMetadataDrawer.vue:49)。

已有保护只在抽屉关闭、取消和 Esc 路径中执行；项目页面及公共路由守卫没有对应的离页保护，也没有该表单的 beforeunload 或恢复草稿。浏览器返回、刷新会直接卸载表单。创建请求身份也仅存在组件内，不能把同一次打开内的重试保护外推为刷新后仍可核对。

修复要求：脏表单的内部导航统一确认；刷新/关闭采用浏览器支持的离页提示；创建结果未知时保留必要请求身份供查询或显式恢复。保存成功后解除保护，不增加自动写入或自动创建。

### 4. P2：概览与最近更新尚未按完整规格实现

位置：[ProjectOverviewPage.vue](../../frontend/web-ui/src/modules/projects/pages/ProjectOverviewPage.vue:66)、[project_summary_repository.py](../../backend/service/infrastructure/persistence/project_summary_repository.py:95)。

- “展开最近更新”只将查询条数从 6 增加至 20，仍是原来的半宽面板。缺少设计中的全宽列表、分页、搜索、类型筛选和返回概览恢复位置。
- 最近更新来源为任务、Runtime 和部署，未覆盖数据集版本、模型版本、应用发布等实际资源更新。当前接口限制为最多 20 项，没有下一页契约。真实运行状态更新也会挤占资源更新位置。
- 当前运行没有页面可见期间的刷新或摘要事件接入，没有观察时间；停留页面不会自动反映服务已经停止等变化。
- 任务真实阶段/可计算进度以及任务、部署、应用分组入口尚未补齐。

修复要求：通过现有资源元数据提供有界查询，不建设独立审计系统；补分页及真实更新时间语义。可见时低频刷新或复用已有变更通知，离开后释放；不订阅生产图像或改变 Runtime/Trigger 执行方式。

### 5. P2：请求失败与空数据混用，返回状态恢复不完整

位置：[ProjectListPage.vue](../../frontend/web-ui/src/modules/projects/pages/ProjectListPage.vue:46)、[ProjectOverviewPage.vue](../../frontend/web-ui/src/modules/projects/pages/ProjectOverviewPage.vue:73)。

列表读取失败会清空已有项目，同时出现无项目/无匹配提示。概览活动读取失败会清空旧活动，下面显示“暂无记录”；元数据刷新失败则清空整个概览。虽然显示错误提示，仍没有按设计保留最后成功数据及过期时间。首次加载活动时也可能短暂呈现空数据。

列表只在组件初始化读取 URL 的搜索和页码；同一组件中的路由查询变化没有独立同步，浏览器历史恢复与滚动位置尚未形成完整闭环。

修复要求：区分初始加载、真实为空、局部失败、保留旧数据但已过期。跨账号/项目或权限撤销时清除旧数据，不能为了保留结果暴露失权数据。补搜索/分页/返回的路由状态和滚动恢复测试。

### 6. P2：资源级权限设计未完整落地

位置：[项目 overview 路由](../../backend/service/api/rest/v1/routes/projects/router.py:296)、[ProjectOverviewPage.vue](../../frontend/web-ui/src/modules/projects/pages/ProjectOverviewPage.vue:63)。

概览接口要求同时具有 `workflows:read` 和 `models:read`，但聚合结果没有按数据集、任务等类别分别裁剪；前端四类指标固定展示，继续工作仅检查部分写 scope，没有统一检查现有 `allowed_pages`。这与设计中“无权模块不暴露名称/计数，也不导致整个项目消失”不一致。管理员真实联调不能证明受限账号的行为正确。

本轮为契约与代码差距确认，未创建受限账号做新的真实越权实验。修复需同时统一服务端字段范围、项目入口权限和前端可达动作；不能只隐藏按钮。

### 7. P2：SDK 长列表只有滚动容器，没有有界加载

位置：[ProjectSdkDialog.vue](../../frontend/web-ui/src/modules/projects/components/ProjectSdkDialog.vue:76)、[配置包资源读取](../../backend/service/application/sdk_config_packages/sdk_config_package_service.py:229)。

前端一次取得全部资源并渲染；后端 Runtime/Trigger 全量枚举，部署只读取前 10,000 项，没有继续分页或超限反馈。这与默认“全部资源”及大清单有界加载要求不一致。超过边界时可能遗漏部署；37 项资源的真实测试不能证明大清单完整性。

修复要求：资源查询提供分页/明确上限，选择集合独立于当前页；默认全部必须有服务端准确语义。达到导出容量时明确提示，不能悄悄截断。搜索无匹配的清除入口已经存在，不列为缺项。

## 适合一并优化的细节

- 保留已实现的简洁导航、整体布局和品牌样式，不重新设计外壳，也不照搬生成图中的蓝色文字、纹理或不合理比例。
- 概览当前服务条目过多时，保留少量代表项和直接跳转入口，减少两侧大滚动区与重复 Runtime 条目对“继续工作”的挤占。
- 将通用“暂无记录”按语境改为“暂无执行中的任务”“暂无运行服务”，正常页面不增加大段说明。
- SDK 真正为空的资源分组与被搜索过滤的分组区别呈现；项目信息复制按钮明确对应字段。
- 继续工作目前能进入现有含创建表单的业务页面，不属于无效按钮；仍应完善空项目缺数据/模型时的前置引导及权限处理。
- 当前多个 Vue 模板和样式压成很长的单行，补齐行为时按现有工程风格拆开，提高异常分支可读性，不引入新框架或通用页面引擎。

## 下一步实施顺序与验收门槛

1. 先修删除待确认和多操作恢复、离页草稿保护。分别验证单步/连续断线、项目 A/B 同时待清理、刷新恢复和不重复 DELETE；失败不得误报成功或未受理。
2. 再补资源级权限、加载/失败/空态、返回历史和局部刷新。使用管理员及受限账号、同项目刷新与跨项目切换验证；迟到请求不得污染新范围。
3. 补最近更新完整来源、分页展开、当前运行观察时间与低频刷新；任务无可靠分母时不显示百分比。
4. 完成 SDK 有界查询/完整导出边界及空项目引导，核对隐藏选择与依赖在分页/刷新后保持正确。
5. 调整清理结果视觉层级、概览密度与细节；重拍同数据亮暗图，检查短屏、键盘、原生 125%/150% 缩放。
6. 使用真实开发数据重走创建、查看、编辑、SDK 下载、删除隔离项目；补共享覆盖层在已有业务模块的回归。关闭本任务服务并清理临时产物后，再将项目分类标记完整、推进下一分类。

以上为修复前的实施计划；执行结果与未覆盖的设备验证边界以最新验收记录为准。

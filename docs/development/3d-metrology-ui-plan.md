# 3D 测量节点操作与结果显示计划

日期：2026-10-30。源码核对基点：`f7c11fa0`。承接 [F4 实施与限制](3d-metrology-r5-f4-implementation.md)和[实施基线](3d-metrology.md)。本轮是三维节点的源码核对与交互设计，不是已经完成的页面改造或全流程视觉验收。

## 1. 范围与证据

仅优化 `metrology3d.nodes` 已实现节点的参数编辑、点云显示、测量证据，以及十二钢片和 S1/S2 配方的使用过程。不修改应用列表、节点分类、节点管理、平台导航或其他业务应用，不创建另一套 Workflow、发布、资源或运行系统。

本轮直接核对节点注册、Vue 编辑器、三维显示/证据读取方和既有回归源码。此前页面检查被当前业务服务的三维节点包加载失败阻断，未取得可用于本轮结论的完整三维操作截图。以下缺口依据源码和 F4 记录，不声称已在当前业务页面复现全部视觉问题。正式实施的第一步需要在隔离环境取得真实节点页面；不为此重启、保存或修改现有业务应用。

工业软件参考仅采用官方文档，属于设计研究，不等同于本机 CloudCompare 操作验收或本项目实测：

- [CloudCompare Cross Section](https://www.cloudcompare.org/doc/wiki/index.php/Cross_Section)：数值尺寸与三维框面拖动并存，可对齐裁剪框视角；包络和截线明确区分。参考其空间编辑反馈，不改变本项目的测量定义。
- [CloudCompare Rasterize](https://www.cloudcompare.org/doc/wiki/index.php/Rasterize)：运行前显示格网尺寸，参数变更后显式更新，空格保留为空。参考参数与计算状态的对应关系，不引入自动补点。
- [ZEISS INSPECT](https://www.zeiss.com/metrology/en/software/zeiss-inspect.html)：测量步骤可追溯、重复和编辑。参考按测量对象组织查看的方式，本项目继续使用现有节点图与发布记录，不复制其软件架构。

## 4. 目标操作方式

### 4.1 工程师配置节点

仍从 Workflow 节点参数打开三维编辑器，不新增业务路由。采用同一对话框内的布局：顶部为节点名、输入来源、单位/坐标系与预览状态；左侧为当前方法的参数；中间为已有三维视口；右侧或下方为当前目标及证据。窄屏切换参数/三维/证据页签，不能把视口挤成不可用的小块。

参数按“来源、几何/方法、质量、高级数值条件”组织。不是给所有节点展示四套空表单，只呈现当前方法需要的项。已存在的质量规则编辑器、字段验证器和表单转换函数继续使用。

输入关联仍以现有连线和当前 Run 身份为准。显示名在前、稳定 ID 可查看；同名来源用节点/端口区分。缺少可确认来源时显式待选择，不取第一项，不按名称推测。其他显示可以作为只读背景，但不能作为跨观测/跨坐标系的拾取来源。

编辑操作仅更新草稿。应用参数后沿现有 Preview 重算完整支持，不在拖动中自动提交计算。上次结果与待应用草稿并列时明确标识“参数已修改，结果未更新”；既有 stale/Run 校验继续生效。点选显示点只产生候选位置，不把采样点计算作为正式测量。

### 4.2 操作员查看工件结果

使用原 App Mode 的三维显示和数值表，不改应用列表、面板系统或通用表格。当前工件通过现有配方输出组织十二钢片各 L/W/H/Z 与 S1/S2 直径，稳定 item_id 不改。不能把 `A_top_L` 等业务对象写死到通用节点组件。

在同一三维证据组件中，点测量行高亮对应尺寸与支持；点边界段高亮对应证据行。可聚焦到选中对象，再恢复全工件视图。跨通用 App Mode 面板的自动联动不作为本批前置要求，不为此新建全局选择总线。

结果至少区分：量值和单位、测量方法、几何有效性及原因、实测/模型估计性质、质量指标。无效值不显示 0。未经产品限值评价不显示产品合格或不合格。报告数值只能用于独立对照，不能回填结果。

S2 方法明确为“部分实测圆弧估计直径”。F4 删除角块的稳定性诊断未通过，保留在本工件配方说明和验收记录中；该诊断不是每次 Run 的证据，不向当前结果伪造“已执行稳定性检查”字段。只有将来真正产生同输入、同配方的验证证据，才显示相应验收状态。无相应数据时不推断“稳定”。

## 5. 按节点分批实施

### U0：真实页面基线

1. 隔离启动已有后端/前端及必要执行器，加载当前正式节点包；先处理该隔离环境的明确启动错误，不绕过 manifest/发布准入。不改业务环境配置或管理界面设计。
2. 使用既有完整 PLY 与 F4 配方建立本轮真实输入和当前 Run，不用 297 点等合成工件替代视觉验收。小型独立真值仍用于组件/算法测试。
3. 截图记录 ROI、拟面/坐标系、H/Z、包络 L/W、S1、S2、结果详情七个操作点。每个页面记录当前输入、参数、结果来源；没有显示成功的步骤记为阻断，不记为通过。
4. 核对 1366×768 与 1920×1080，并检查 125% 系统缩放、键盘焦点、弹窗关闭及长 ID。这个步骤只建立 UI 基线，不重跑长稳或 P99。

### U1：结果含义、来源和参数防错

- 修改三维 Summary 与节点表单：几何状态明确命名；原始 reason 保留并提供直白中文；选中高亮不使用“成功”语义。
- 为有长度/面积/角度意义的参数显示实际单位；向量显示 X/Y/Z 或 U/V，矩阵放高级区域。角度读写如提供度数视图，仍保存现有弧度契约，未经编辑不反复转换/舍入。
- 来源选择展示现有节点/端口与 frame/unit，不改变显式选择规则；无 Preview、计算中、失败、过期、无可用来源分别呈现。
- 沿现有配方检查定位到字段；局部草稿问题、连线引用问题、运行时动态输入问题分别呈现。禁止在浏览器另写几何可用性或公差算法。
- 量值显示格式复用项目现有格式约定；若无法满足三维量值，先确认显示小数策略。保留原始精度用于导出/证据，不把显示位数当作质量阈值。
- 验证：中英文/单位/空值，两个同名来源，换节点/Run 的失效引用，模式切换清理非活动字段，部分弧显示与孔径参数一致；所有数值/算法配置往返不变。

### U2：ROI、基准和 H/Z 同屏配置

- 在原 RoiEditor 中复用 ROI 图与并集依赖，提供成员列表、高亮、显示开关和聚焦。并集不是可直接拖动的包围盒，编辑实际成员，不改五窗联合支持。
- 在原 TransformControls/overlay 中增加盒面、圆柱半径/长度的显式尺寸编辑；直接写入既有 center/size/radius/length/rotation 等字段。不能保留 Three.js 临时 scale 作为另一份测量参数，禁止反转或非正尺寸。
- fit-plane/build-frame 复用 CloudViewer 显示输入支持、正法向、基准轴和当前拟面证据；已存在的支持/剔除和残差着色保留。平面外框是显示范围，不冒充连续实测支持区域。
- height-query/measure-step 内嵌已有拟面表单，显示本次 pose/U/V、方向、两交点、真实支持及基准延伸距离/上限。切换来源清除候选，不自动延长被测面。
- 验证：拖动与数字输入等价；旋转盒/倾斜平面独立真值；并集改名/删除依赖；取消不改参数；修改草稿不显示为已重算；显式 Preview 后数值与冻结配方一致。

### U3：包络、拟线/拟圆和尺寸证据

- visible-envelope：沿当前评价面显示有限栅格范围、种子窗、前景归属、真实观测/空格、四侧剖面、插值点与格边估计；显示格距、格数和覆盖/缺口指标。编辑格距不能自动改变目标分区距离或闭运算参数。
- fit-line/measure-edge-pair：真实有限段、缺口、正方向和查询线同屏；区分模型延长线与实际支持，域外无效不变。
- extract-boundary/fit-circle：为既有环带、起始角、扫角提供可视手柄；未选候选、选中片段、残差内外点、缺弧、拟合曲线分别表示。环带选择使用配方参考中心，拟合覆盖使用拟合圆心，两者不能混画为同一角域。
- 补实际稳健权重及径向残差的有界显示，连到角区计数与缺口表。禁止从屏幕采样重新计算权重、残差或全部覆盖率；只消费后端同观测的真实证据。现有证据不足时在原预览契约内明确补充并同批更新读取方，不新建点云服务。
- measure-extents/measure-hole：直接消费已有特征，方法、统计端点、支持来源、圆心和直径线联动。拟合补全用虚线，缺弧不连成实测线。
- 验证：有界显示点与原始/生成来源映射，组/段选择，跨 0 角域、反向和缺弧，估计/实测线型，保存读取、导出和当前 Run 一致。全部结果仍由原算法产生，显示层不能“修好”S2。

### U4：全工件与真实发布验收

1. 先走 A_top_L 的 ROI → 基准 → H/Z → 动态等高 → 包络 → L/W，再走 S1 完整弧和 S2 部分弧；逐步截图和核对参数，不只导入后运行一次。
2. 用当前 F4 全对象配方核对全部 50 项、测量 ID、方法和单位；无效/失败用独立案例验证，不覆盖真实工件结果为“方便显示”的假值。
3. 保存、读取、正式发布、WorkflowAppRuntime、App Mode 查看采用现有链路。历史结果只读，没有保存原云时不能假装可以重新测量。
4. Windows 与 WSL Ubuntu 原生数据目录分别检查服务端证据和保存恢复；浏览器在支持的前端环境验收，不把 WSL 服务通过算作 Ubuntu 桌面 GUI 已验收。
5. 检查快速切节点、换 Run、关闭弹窗、取消下载、请求晚返回、WebGL 丢失、重开及停止后的资源释放。沿现有预算，不任意增加展示点数；隐藏图层是否释放由既有 owner/缓存边界控制，不扩大常驻资源。
6. 只停止本轮测试服务，删除本轮临时文件；保留必要截图与精简验收矩阵到文档资产。业务 5600/5601 和原始文件不动。

## 7. 不被界面任务掩盖的剩余项

- F4 的 50 项几何有效，不等于 50 项精度/工件合格已验收。
- S2 角块删除直径最大变化 0.078548 mm、圆心 0.053682 mm，超过既定 0.03 mm 诊断线；本批不得改变门禁、隐藏失败或宣称稳定性通过。
- 秒级检测计算节拍尚未最终验收，UI 优化不作为性能达标证据。后端热点和冻结节拍属于 F4 后续计算任务，本轮不反复跑性能/长稳。
- M3.4 产品三态及其全平台消费者尚未完成，本批只正确显示现有几何结果，不私自补一套三态判定系统。
- 本计划已开始实施，当前进度、实际截图和回归范围见 [界面实施与验收](3d-metrology-ui-validation.md)。U1/U2 的主要链路与 U3 权重/残差显示已接通，但角域手柄、完整包络调试显示及全部操作点的最终页面验收尚未完成，不将本批通过项等同于 U0–U4 全部完成。

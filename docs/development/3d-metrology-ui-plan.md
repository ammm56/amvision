## 4. 目标操作方式

### 4.1 工程师配置节点

仍从 Workflow 节点参数打开三维编辑器，不新增业务路由。采用同一对话框内的布局：顶部为节点名、输入来源、单位/坐标系与预览状态；左侧为当前方法的参数；中间为已有三维视口；右侧或下方为当前目标及证据。窄屏切换参数/三维/证据页签，不能把视口挤成不可用的小块。

参数按“来源、几何/方法、质量、高级数值条件”组织。不是给所有节点展示四套空表单，只呈现当前方法需要的项。已存在的质量规则编辑器、字段验证器和表单转换函数继续使用。

输入关联仍以现有连线和当前 Run 身份为准。显示名在前、稳定 ID 可查看；同名来源用节点/端口区分。缺少可确认来源时显式待选择，不取第一项，不按名称推测。其他显示可以作为只读背景，但不能作为跨观测/跨坐标系的拾取来源。

编辑操作仅更新草稿。应用参数后沿现有 Preview 重算完整支持，不在拖动中自动提交计算。上次结果与待应用草稿并列时明确标识“参数已修改，结果未更新”；既有 stale/Run 校验继续生效。点选显示点只产生候选位置，不把采样点计算作为正式测量。

### 4.2 操作员查看工件结果

使用原 App Mode 的三维显示和数值表，不改应用列表、面板系统或通用表格。当前工件通过现有配方输出组织十二钢片各 L/W/H/Z 与 S1/S2 直径，稳定 item_id 不改。不能把 `A_top_L` 等业务对象写死到通用节点组件。

在同一三维证据组件中，点测量行高亮对应尺寸与支持；点边界段高亮对应证据行。可聚焦到选中对象，再恢复全工件视图。跨通用 App Mode 面板的自动联动不作为本批前置要求，不为此新建全局选择总线。

结果至少区分：量值和单位、测量方法、几何有效性及原因、实测/模型估计性质、质量指标。无效值不显示 0。未经产品限值评价不显示产品合格或不合格。报告数值只能用于独立对照，不能回填结果。

S2 方法明确为“部分实测圆弧估计直径”。F4 删除角块的稳定性诊断未通过，保留在本工件配方说明和验收记录中；该诊断不是每次 Run 的证据，不向当前结果伪造“已执行稳定性检查”字段。只有将来真正产生同输入、同配方的验证证据，才显示相应验收状态。无相应数据时不推断“稳定”。

## 5. 按节点分批实施

### U0：真实页面基线

1. 隔离启动已有后端/前端及必要执行器，加载当前正式节点包；先处理该隔离环境的明确启动错误，不绕过 manifest/发布准入。不改业务环境配置或管理界面设计。
2. 使用既有完整 PLY 与 F4 配方建立本轮真实输入和当前 Run，不用 297 点等合成工件替代视觉验收。小型独立真值仍用于组件/算法测试。
3. 截图记录 ROI、拟面/坐标系、H/Z、包络 L/W、S1、S2、结果详情七个操作点。每个页面记录当前输入、参数、结果来源；没有显示成功的步骤记为阻断，不记为通过。
4. 核对 1366×768 与 1920×1080 浏览器视口，检查键盘焦点、弹窗关闭及长 ID。这个步骤只建立 UI 基线，不调整操作系统显示设置，不重跑长稳或 P99。

### U1：结果含义、来源和参数防错

- 修改三维 Summary 与节点表单：几何状态明确命名；原始 reason 保留并提供直白中文；选中高亮不使用“成功”语义。
- 为有长度/面积/角度意义的参数显示实际单位；向量显示 X/Y/Z 或 U/V，矩阵放高级区域。角度读写如提供度数视图，仍保存现有弧度契约，未经编辑不反复转换/舍入。
- 来源选择展示现有节点/端口与 frame/unit，不改变显式选择规则；无 Preview、计算中、失败、过期、无可用来源分别呈现。
- 沿现有配方检查定位到字段；局部草稿问题、连线引用问题、运行时动态输入问题分别呈现。禁止在浏览器另写几何可用性或公差算法。
- 量值显示格式复用项目现有格式约定；若无法满足三维量值，先确认显示小数策略。保留原始精度用于导出/证据，不把显示位数当作质量阈值。
- 验证：中英文/单位/空值，两个同名来源，换节点/Run 的失效引用，模式切换清理非活动字段，部分弧显示与孔径参数一致；所有数值/算法配置往返不变。

### U2：ROI、基准和 H/Z 同屏配置

- 在原 RoiEditor 中复用 ROI 图与并集依赖，提供成员列表、高亮、显示开关和聚焦。并集不是可直接拖动的包围盒，编辑实际成员，不改五窗联合支持。
- 在原 TransformControls/overlay 中增加盒面、圆柱半径/长度的显式尺寸编辑；直接写入既有 center/size/radius/length/rotation 等字段。不能保留 Three.js 临时 scale 作为另一份测量参数，禁止反转或非正尺寸。
- fit-plane/build-frame 复用 CloudViewer 显示输入支持、正法向、基准轴和当前拟面证据；已存在的支持/剔除和残差着色保留。平面外框是显示范围，不冒充连续实测支持区域。
- height-query/measure-step 内嵌已有拟面表单，显示本次 pose/U/V、方向、两交点、真实支持及基准延伸距离/上限。切换来源清除候选，不自动延长被测面。
- 验证：拖动与数字输入等价；旋转盒/倾斜平面独立真值；并集改名/删除依赖；取消不改参数；修改草稿不显示为已重算；显式 Preview 后数值与冻结配方一致。

### U3：包络、拟线/拟圆和尺寸证据

- visible-envelope：沿当前评价面显示有限栅格范围、种子窗、前景归属、真实观测/空格、四侧剖面、插值点与格边估计；显示格距、格数和覆盖/缺口指标。编辑格距不能自动改变目标分区距离或闭运算参数。
- fit-line/measure-edge-pair：真实有限段、缺口、正方向和查询线同屏；区分模型延长线与实际支持，域外无效不变。
- extract-boundary/fit-circle：为既有环带、起始角、扫角提供可视手柄；未选候选、选中片段、残差内外点、缺弧、拟合曲线分别表示。环带选择使用配方参考中心，拟合覆盖使用拟合圆心，两者不能混画为同一角域。
- 补实际稳健权重及径向残差的有界显示，连到角区计数与缺口表。禁止从屏幕采样重新计算权重、残差或全部覆盖率；只消费后端同观测的真实证据。现有证据不足时在原预览契约内明确补充并同批更新读取方，不新建点云服务。
- measure-extents/measure-hole：直接消费已有特征，方法、统计端点、支持来源、圆心和直径线联动。拟合补全用虚线，缺弧不连成实测线。
- 验证：有界显示点与原始/生成来源映射，组/段选择，跨 0 角域、反向和缺弧，估计/实测线型，保存读取、导出和当前 Run 一致。全部结果仍由原算法产生，显示层不能“修好”S2。

### U4：全工件与真实发布验收

1. 先走 A_top_L 的 ROI → 基准 → H/Z → 动态等高 → 包络 → L/W，再走 S1 完整弧和 S2 部分弧；逐步截图和核对参数，不只导入后运行一次。
2. 用当前 F4 全对象配方核对全部 50 项、测量 ID、方法和单位；无效/失败用独立案例验证，不覆盖真实工件结果为“方便显示”的假值。
3. 保存、读取、正式发布、WorkflowAppRuntime、App Mode 查看采用现有链路。历史结果只读，没有保存原云时不能假装可以重新测量。
4. Windows 与 WSL Ubuntu 原生数据目录分别检查服务端证据和保存恢复；浏览器在支持的前端环境验收，不把 WSL 服务通过算作 Ubuntu 桌面 GUI 已验收。

### 8.2 I1：环带与扫角手柄

**编辑对象必须明确。** 三类角域分别处理：

| 对象 | 参数/来源 | 操作含义 |
| --- | --- | --- |
| 提取目标环带 | `targets[].arc.center/radius_range/start_angle/sweep` | 按评价面 UV 选择实际边界点；中心不是拟合结果圆心 |
| 拟圆均衡角区 | `robust.center/start_angle/sweep/sector_count` | 控制现有权重角区；不是提取环带，不能修改上游选点 |
| 拟合结果支持弧 | 当前 CircleFeature 的实际支持区间与拟合圆心 | 只读证据；不能拖动结果来反写参数或补全缺弧 |

`fit-circle.radius_range` 是求解半径范围，不冒充选点环带；`max_overlap_angle`、`max_arc_step` 和质量规则均保持数值编辑及原校验，不由手柄自动放宽。

实施步骤：

1. 在 `BoundarySettingsEditor.vue` 现有目标/方法区域选择正在编辑的角域，沿 `EvaluationEditor` 使用配置面、当前继承特征或 pose 的真实解析面。圆心 UV 到世界坐标只使用该面原点和轴，不按源 XY 或显示点云质心推测。
2. 复用 CloudViewer/geometry-overlay 的控件生命周期，增加中心平移、内外半径、起始角和结束角手柄。起始角拖动保持扫角；结束角拖动改变评价面内从 +U 朝 +V 的正向扫角，并跟踪跨零点操作。完整一周仍为一周，不能规范化成零。
3. 数字输入与手柄调用同一草稿更新函数。角度界面采用度数，存储仍为原弧度；未修改字段保持原数值，不在打开/关闭时重新舍入。非法内外半径、零扫角、反转或非有限输入明确拒绝，不自动交换端点或取绝对值。
4. 使用当前成功 Run、观测、节点/端口、目标 ID、frame/unit 和评价面来源共同核对可编辑性。仅有背景云、过期/失效来源或不能唯一确定评价面时显示只读证据；数字草稿继续遵循既有局部编辑规则，不强行补引用。
5. 拖动只改草稿。取消恢复进入编辑前的参数；换节点、目标、Run、来源和关闭弹窗中止拖动并隔离晚回调。应用后沿原 Preview 显式重算，不在 pointermove 中提交算法。

验证与出口：倾斜评价面、非零原点、跨 0°、完整 360°、窄扫角、正方向、内外半径退化、无效来源、取消和晚回调；通过独立 UV/世界坐标真值检查拖动和数字输入等价。真实 S1/S2 页面确认选点环带、均衡角区和拟合支持弧不混用；未改变参数时发布结果与原配方相同。

隐藏正在拖动的叶或包含该叶的父项时，先结束原 TransformControls 手势并恢复该手势起点，再解除控件和应用可见性。保留手势前已经完成的数值修改；不恢复整个弹窗初始草稿，不提交拖到一半的位置。复用现有角域的代次/活动对象判定方式，在原 ROI 控件内补局部恢复，不新建撤销栈。换 Run/对象后只销毁旧控件，不把旧手势恢复值写入新对象。

无活动手势时，显示切换前后草稿 JSON 必须完全相等；有活动手势时，对照的是该手势开始时的草稿。取消与应用仍由现有编辑器处理。

纯显示切换沿现有 overlay 中的 ROI 对象映射切换 `visible` 并调度一帧绘制，不调用整体 geometry update 重建 I2 格网/曲线，不重新解码显示正文，不重建空间索引。仅补必要的叶 ID/裁切路径关联；原几何参数改变仍走原更新路径。

聚焦仅计算可见叶在当前裁切路径下的边界。隐藏不承诺立即释放已缓存的几何，但不能重复分配；关闭/换来源继续由原 owner 销毁 CPU/GPU 缓冲、监听器和控件。空间/图合法性校验仍针对完整依赖图，不能因为隐藏而跳过。

### 11.2 I4 的具体设计

**界面组织**：宽布局保持当前参数和三维同屏；空间不足时切换为“参数 / 三维 / 证据”，按实际容器可用宽高而不是设备名称判断。复用现有对话框及五类编辑器，最多提取一个三维包内的布局组件来消除重复，不改全平台 ConfirmDialog 或应用页面。当前对象、单位/坐标、来源状态和应用/取消始终可达；无证据、未选 Preview 和来源失效分别表达，不填充空表。

**隐藏与恢复**：首次尚未显示三维区域时可以延迟创建场景；已经创建后，切换到参数/证据仅暂停视口绘制、拾取与控件，保留受预算计量的缓冲、相机、目标和 I2 证据。隐藏前取消尚未完成的 ROI/角域手势并恢复该手势起点，不丢失先前完成的草稿修改；复用 I1/I3 的取消函数，不新增撤销栈。零尺寸期间不重新适配相机、不触发视口错误；恢复到合法尺寸后沿原计量入口调整画布并绘制一帧，不自动 fit 或重新下载/解码。换 Run/来源、关闭和 WebGL 丢失仍走原释放路径，不因隐藏缓存绕过回收。

**证据页签**：在同一个 CloudViewer 内安排视口区与证据区的呈现模式，复用现有 GeometrySummary、BoundarySummary、MeasurementSummary、BoundaryDebugSummary。行选择仍更新同一份选中对象；到三维页签后保持高亮，显式聚焦，不悄悄移动相机。切页签不得触发整体 overlay update 重建 I2 几何；真正修改参数或证据选择时仍使用既有更新路径。

**键盘与防错**：页签实现 roving tabindex、方向键和 Home/End，隐藏面板不进入 Tab 顺序；Escape 优先取消活动手势，其次按原对话框规则处理。使用既有图标、tooltip 和菜单收紧工具栏，数字字段仍是等价操作入口。隐藏、取消、应用、修改草稿和显式 Preview 的含义保持分离；App Mode 继续只读。中英文长 ID、单位、空值和焦点回到触发按钮均纳入验收，不添加前端质量算法。

### 12.3 第二项：S2 与长宽可靠性，沿 F4 原计划推进

**S2：** 冻结现有 733 点、真实段、源行号、评价面和质量参数。复用 I2 的候选/角区/残差证据、`circle_weighting.py` 与 `boundary_fitting.py`，先做同一输入上的影响分析和独立扫描线交点对照；不从 1,474 万点整图反复重跑每个局部实验。记录各角块真实支持、权重贡献、删除后的圆心/半径联动和对全部原候选的残差，区分候选几何偏差、权重适用性和支持不足。

现有角区均衡算法和独立标量目标已一致，不再把它当尚未查明的求解器 bug。若支持按实际弧长赋权等新方法，先定数学目标、真实拓扑贡献、退化/缺口规则及证据，并单独确认，再接现有求解入口；不自动回退、不删除不利片段、不以报告值选参数。解析圆、非均匀/缺弧/噪声/离群数据验证后，再对 S1、S2 和保存读取回归。若当前观测仍不能满足稳定性要求，明确所缺角域及补采条件，不能无限调参直到单样本通过。

**长宽：** 复用既有 A_top_L 格距/相位审计，锁定相同实测目标归属、pose 和高度，逐侧确认剩余变化是否与栅格边界估计一致。结合分辨率和独立连续几何真值报告方法适用范围；若实际精度要求更高，再设计基于真实边点的显式估计方法，不对多相位结果取平均掩盖变化。方法变更时核对全部十二片，不把新值与旧方法值强行要求相等。

出口分别是算法错误修复、可验证的方法修正，或有证据的采样/精度限制；三者必须明确区分。S2 的稳定性方法变更在实施前确认，产品公差不由本样本推导。

### 12.4 第三项：实际热点优化与有限节拍验收

复用 `tests/integration/metrology3d/compute_profile.py` 和原节点执行记录，不新增监控服务或常驻原云缓存。先固定完整输入、方法、线程配置和正式数值输出，默认关闭 I2 调试捕获；建立当前 F4 数值图的计算墙钟与分项，读取/传输、显示构建、诊断开销单列。

代码中的候选开销包括 `plane_coverage` 对同一平面支持的计数/收集遍历、原支持质量检查，以及 S1/S2 投影、曲面构建和求交。它们是需要计时验证的候选，不凭静态循环宣布为当前最大瓶颈。按实测占比只改一个热点：优先复用现有 Run/不可变来源内的精确查询和中间结果，包含索引构建成本、取消、预算及释放；不重复实现已完成的单遍 ROI 和支持摘要缓存，不用显示 LOD 代替计算支持，也不引入等待队列。

每项优化先验证数值、方法、质量、源行号和平局规则，再继续下一项。最后按原 F6 计划，在 Windows 与 WSL 原生文件系统各执行首次一次及同一常驻 Runtime 的五次独立 Run，记录逐次计算耗时、RSS、线程、Scope/租约和停止回收。六次样本不推算 P99，不增加长期 soak。具体秒数上限实施验收前确认，180 秒安全超时不是节拍目标；没有新秒数授权时先报告真实数据，不编造通过线。

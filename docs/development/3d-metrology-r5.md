### 3.1 高度定义差异

手工 `plane_height_at_xy` 在同一**源坐标** `(x,y)` 分别求局部平面上的 `z_top`、`z_body`，再计算台面有符号距离。因此 `H_report = n_D.z * (z_top-z_body)`。两个点连线沿源 Z，不一定沿台面法向 `n_D`。

R4 方向测距则对 `q + t*a` 与两平面求交，返回 `t_target-t_reference`；`a` 是显式单位方向。R5 已确认正式高度取 `a=n_D`，查询点在同一已定义的台面 U/V 位置。倾斜或翘曲时两种算法不能标成同一量；报告仅作参考，验收使用同一定义的独立计算，不调参数追求旧数字。

- `H`：钢片目标面相对其邻近基体面的中心位置高度差；仅基准可有限延伸。
- `Z`：钢片目标面相对载物台面高度；另一个基准和独立延伸距离限制，不复用 H 的上限。
- `t`：报告中的六个邻近基体 ROI 到台面的点高度中位数，不是钢片中心处的基体面高。`t+H` 不必等于 Z。
- `H_local`：height-query 的有限圆柱局部拟面结果，只作另一个明确命名的量。整片核心区拟面和局部拟面不要求相等；如用相同拟面特征/同一评价线经 measure-step 计算，应一致且不重复拟面。
- 十二片分别记录，不用六处左右片合并拟合结果替代单片值。两片间高差或六个 t 若纳入交付，单列输出，不暗中扩充本轮验收范围。

候选 item_id 为 `A_top_L.H`、`A_top_L.Z`、`A_top_L.L`、`A_top_L.W`、`A_top_L.W_at_query`、`S1.D` 等，沿同一规则覆盖全部对象。不把“有效”显示成产品“合格”。多分支表可先按六组归并再汇总，复用现有 Merge Numeric Tables 的 1–64 表限制，不扩容或新建聚合器。

### 5.3 质量与数值待定项

复用既有严格参数和 quality_policy：平面支持数/二维跨度/法向分离/RMS/最大残差；高度双方覆盖/最近点/三角边/残差/方向；边界支持及长度；线方向可辨识性/跨度/残差；圆角覆盖/最大缺口/Jacobian 条件/残差/半径约束。

待确认数值包括：实际三维 ROI 和真实边段窗口、固定查询 U/V、各基准延伸上限、局部搜索/支持半径、表面 alpha/边长/高度跳变、求解参数和各项质量限值。方向来源、坐标定义和等高取法已由 Q5/Q6 确认，不再列作待定。除 Q5 明确采用的数值外，报告已有值只能作为标注清楚的复现配置，不自动填进新定义。Open3D 与报告算法不同，不能承诺随机支持行完全一致；应比较合法支持、质量和数值范围，不强制逐位相同。

质量门禁不是产品公差，也不是算法数值容差。阈值敏感性、ROI 扰动和采样缺失分析用于说明方法适用性，不能从“刚好通过本工件”的值倒推生产限值。拟合失败不扩大残差、不切换算法重试，不把少点/歧义结果补零。

### 5.4 五 ROI 联合支持设计

实现位置是现有 `Roi3d → CropCloudParameters → RoiMaskPlan/roi_mask → crop_roi → CloudRuntime.register_subset`，不是新的点云合并节点。Q3 授权的是联合支持语义；以下设计已在 A 批次落地。

| 部分 | 设计 |
| --- | --- |
| 参数形状 | 在同一 roi3d.v1 中增加 `kind=union`，`geometry.roi_ids` 显式引用成员；成员正文仍放同一 ROI 依赖集合。当前 schema 已接受，列表非空、唯一，最多 8192 个成员；节点来源仍为参数/输入互斥 |
| 有限性 | 并集非空、成员唯一、引用存在、同 frame/单位；沿用现有配置规模限制。统一检查 union 成员与 section-band 的 bounds 依赖，拒绝环及缺失引用，不增加无限 ROI |
| 数据选择 | 对同一父云块分别计算成员掩码并逻辑 OR，闭边界沿用现有定义；重叠窗不重复加权，成员顺序不改变选中父行。五个不同父云不在此自动合并 |
| 所有权 | 沿现有两遍扫描：计数、预留索引、填入递增父逻辑行，再 register_subset。保持 source_indices/source_point_count；不复制五份属性数组、不建立第二套 owner |
| 预算与取消 | 合并掩码、成员工作数组和依赖求值都计入现有 max_working_bytes；逐块且逐成员检查取消，不创建整云×ROI 数量的布尔矩阵。原生拟合另按原预算准入 |
| 来源和保存 | CropCloudMethod 记录完整已校验参数及摘要；资产重读走同一严格类型。成员顺序改变可改变参数摘要，不要求不同配置的摘要相同；输出支持集合须一致 |
| 前端 | 扩展原 RoiEditor 的形状选择及成员勾选，复用现有子 ROI 编辑/拾取。并集显示实际子区域，不显示一个虚假的大包围盒；被引用成员禁止删除，重命名同步引用。未选成员仍留在草稿但不画入目标区域；显式选中编辑时单独显示 |
| 其他使用方 | 原边界 region/target、截面有限边界、资产方法读取和 geometry-overlay 同批支持或明确拒绝未支持输入，不能把 union 当 box。连续段选择仍按原规则，多个区域不意味着允许跨缺口连线 |

普通 crop 明确清除拓扑；R3 边界选择保持拓扑。联合裁剪不能替代 R3，不能把无序支持误当有序轮廓。实现时复用成员几何计算而不是复制三套 box/cylinder/section 算法；依赖检查也不能分成前端后端互不相同的规则。

三维数据契约继续使用当前开发期 v1，不新建 v2/v3 或旧算法兼容分支。实现时按既有规则递增受影响节点/包的实现版本，同批更新读取方和发布依赖身份；不改 Workflow 发布版本管理。原始数据不删除，生产 manifest 仍不创建。

验收必须覆盖：原始云与已有子集、同坐标不同采集行、重叠/相邻/分离窗、成员顺序、空结果、缺失成员和循环、frame/单位错误、参数/输入两种来源、分配/第二遍扫描取消、Scope 关闭、保存重读和前端取消/切节点。独立集合真值逐行比较，不只比点数。

五窗报告支持约 209 万点，不能把此前小窗口 RANSAC 的内存情况直接套用。当前 `_ransac_support` 按 `count*128 + iterations*(sample_size*8 + 64 + count*16)` 估算工作数据；正式验收先用确认参数核对预算，再执行原生调用。不能为通过预算静默抽成报告的 50,000 点、缩小五窗或取消原门禁。

### 5.6 台面坐标与动态来源接线

**设计选择：源云、拟合特征和 ROI 保持源坐标；本次 pose 只解析评价几何。** 这保留已有来源、精度和所有权，避免为获得法向而重复变换全云、重拟基准或新增特征变换服务。局部求解仍使用现有 float64 数值内核。

build-frame 沿用现有 anchor-projection 模式：anchor=[0,0,0]、x_axis.direction=[1,0,0]、positive_z=[0,0,1]，均为 Q6 指定的本配方设置。各方向质量条件仍显式配置；投影轴退化或方向不确定必须返回原失败状态。设其既有矩阵满足 `p_D = R*p_S + t`，则：

- 台面原点 `O = -R^T*t`，源坐标中 U/V/N 分别为 R 的第 1/2/3 行转置；不是矩阵列直接照抄。
- 固定查询 `(u,v)` 的源坐标点 `q = O + u*U + v*V`，测量方向 N。H/Z 共用 q、N；基体/台面参考各执行自己的有限延伸策略。
- 截面高度 h 对应评价面 `origin=O+h*N`、`rotation=[U V N]`，`frame_id` 仍为源 frame，单位不变。
- 来源是当前 pose，不是历史报告矩阵；失败时没有有效 R/t，不能填单位矩阵、+Z 或上一运行结果。

| 已有节点 | 接线扩展及进度 | 当前算法保持 |
| --- | --- | --- |
| height-query / measure-step 的方向测距模式 | B 已实现：显式选择“配置几何”或“本次 pose + 固定 U/V”；后者连接 pose3d.v1，解析 q/N | R4 交点、覆盖、有限延伸、质量与局部拟面；不改统计模式语义 |
| extract-boundary | 增加可选 pose 和 measurement-evidence3d.v1 输入；features 接受多个来源并按唯一 ID 选择 D/B/T。等高来源显式为固定 h 或有效方向测量的交点比例 | 原有限表面、求交、来源、共面和连续段规则 |
| fit-line / fit-circle | 评价面显式选配置或已选 BoundaryFeature 的本次解析结果；正方向可显式取其 U/V 轴 | TLS、几何圆拟合、面外偏差与全部质量；不重新提边界 |
| measure-extents / measure-edge-pair / measure-hole | 特征来源模式继承选定特征的评价面；边对另核对两线评价空间，查询以该面 U/V 表达，方向显式选面内轴 | 有限跨度、支持区间求交、CircleFeature 直径；不重拟合 |

来源选择必须在 schema、Catalog、handler 和编辑器中一致，必需连接由所选模式决定；不允许“端口没值就用静态值”。原显式几何模式是仍有用途的配置方式，不是旧实现兼容分支。这里只补有类型的几何来源，不改平台通用参数绑定器，也不提供任意嵌套路径或脚本表达式。

`NodeParameterInputBinding` 当前只接受顶层属性及普通 value 端口；Numeric Table To Value 虽保留 null/valid，但不足以证明几何来源。本链不用普通 value 覆盖整个 settings，也不让 Trigger 输入改变 quality_policy、延伸上限或已发布的解算条件。原绑定能力保持原职责。

### 5.7 等高值、证据和下游评价面

钢片选择本次 `<object>.H` 的有效方向测量证据，端点顺序沿既有契约为基体 B、目标 T。设 `p_B/p_T` 为这两个交点，D 的法向按本次 pose 定向，则：

```text
p_cut = (1-r)*p_B + r*p_T
h = N dot (p_cut-O)
r = 0.5  # 仅本工件配方
截面：N dot (p-O) = h
S1/S2：h = 0.25 mm  # 仅本工件配方
```

这是**同一评价位置确定的一张平面**，不是在每个 XY 位置变化的两面中间曲面，也不是沿源 Z 取旧报告中点。不重新拟面或再求一次 H；比例参数的通用合法范围为 `0<r<1`，不允许以比例外推。H 的目标必须在真实支持内，基体延伸已经由 H 的独立门禁审核；D/pose 无效或 H 无效则截面来源不可用。对本工件正向凸起，还须显式验证目标位于基体上方，反向或重合不能生成一条看似成功的边界。

**评价面必须随 h 一起解析。** 当前 fit-line/fit-circle 以 `parameters.evaluation` 计算 `plane_max_residual` 并还原三维线/圆；若等高边界在 h 处、评价面却仍在 D，实际高度会被误当面外偏差，放宽门禁也会把线/圆投回错误平面。R5 设计将 extract-boundary 的已解析评价面设在 `O+h*N`，下游继承这张面。W/L 仍为 U/V 跨度；平行面沿法向平移不改变跨度。边间距查询位置也必须在该截面，不能沿用 D 上的 q。

本次 H 证据是几何来源，不是执行权限。其公开结构有 observation_id、frame、单位，没有 run_id；不能仅凭 item_id 或历史 JSON 宣称属于当前运行。接入时同时核对当前 pose/live features 的 run_id、观测、坐标、单位、D 身份、B/T 特征 ID、方法摘要及实际支持内容摘要，并匹配 H 的两个平面快照和方向。复用现有支持摘要/借用机制，不增加全云复制或第二套来源系统。错对象、错运行、重复 ID 或不匹配为输入错误，不能降级成一个普通无效尺寸。

保存和追溯按以下设计同批完成：

| 内容 | 记录/约束 |
| --- | --- |
| 配方选择 | 来源模式、pose/feature/item 稳定 ID、固定 U/V、比例或固定高度；原 quality_policy 不可被输入覆盖 |
| 解析结果 | q/N、实际 h、实际评价面、所用两交点、本次来源证据及摘要；进入已有 method/证据，不只记录编辑器草稿 |
| 未解析状态 | 上游无效保留阶段与原因，解析几何为空；不得伪填 h=0、默认原点或旧 params 来凑合法结构 |
| 运行身份 | live pose/features 用当前 Scope；测量证据和持久快照不保存租约、数组地址或有效的历史访问引用 |
| 边界资产 | 既有 save-cloud/read-cloud 保存/恢复真实边界、方法和本次解析来源快照。恢复后可按已冻结截面拟线/拟圆，但不是用旧 pose 对新原云自动重测 |
| 历史查看 | 展示实际 h、来源、支持与失败；要重新适应新输入必须重新运行 D/B/T/H 链，不从历史证据补出当前结果 |

快照只保存实际选中的 D/pose 和一个方向测量项的必要证据，不把整包 MeasurementEvidence3d、全部输出表或 CloudReference 递归塞进 BoundaryMethod。当前总证据类型已包含尺寸项，尺寸项又引用边界方法；直接整体互嵌会形成循环结构。应复用并整理现有非递归的平面、方向测距及方法值对象，形成严格的有界来源快照，不复制第二套质量模型或新建通用证据仓库。

配置参数与解析参数不能混为一套静态值。实现时在现有 v1 方法和证据中严格区分来源配置、成功解析结果和未解析失败，同批调整验证器；不把新的字段标成“可选所以可以忽略”。同批更新范围包括三维参数/方法契约、Catalog/handler、BoundaryCloudMethod 与资产重读、measurement/dimension evidence、Preview/overlay、Vue 编辑器/只读结果、SDK 中实际解析或示例使用这些结构的部分，以及发布依赖身份。其余二维协议、资产目录/数据库、Workflow 发布系统不重建。

### 5.8 代表分支的具体接线与完整性

```text
read-cloud -> normalize-units -> filter-valid = C
C -> crop(D1..D5 union) -> fit-plane(D) -> build-frame = P
C -> crop(B.A_top)     -> fit-plane(B)
C -> crop(T.A_top_L)   -> fit-plane(T)
B + T + P -> measure-step(A_top_L.H)
D + T + P -> measure-step(A_top_L.Z)
C + D/B/T + P + H.evidence -> extract-boundary(A_top_L.outline, r=0.5)
outline -> measure-extents(axis-spans: U->W, V->L)
同一输入另设 sides 诊断分支 -> extract-boundary(A_top_L.sides, r=0.5)
sides -> fit-line(side.left/right) -> measure-edge-pair(W_at_query)
C + D + P -> extract-boundary(S1, h=0.25 mm)
S1.boundary -> fit-circle -> measure-hole(open-arc)
numeric tables -> 既有 Merge Numeric Tables -> App 输出
cloud/features/pose/evidence -> 既有 Cloud Preview
```

图中需要的接线扩展已随 A–C 实现，正式运行仍须 D 冻结实际窗口及质量配置。H 与 Z 共用 T 和同一查询线，不用 H_local 冒充整块顶面拟合；t 暂不纳入首条配方。所有测量仍消费完整输入产生的有限实测支持，不读显示抽样。

完整性验收先要求钢片外轮廓能够被明确选择并证明覆盖所报告的两轴极值。代表分支先验证闭合实测外轮廓；如果实际断开，保留缺口并定位原因，不能用剩余跨度声称完整 L/W。现有 measure-extents 的合同是“有限可见支持包络”，不是实体完整性检测器；残余跨度可作为另名诊断项，不能冒用正式 item_id。若确需由开段证明完整极值，须先给出可验证的支持判据再设计，不暗中添加补全算法。

用于 L/W 的整体轮廓和左右直边是不同选段需求。当前 extract-boundary 禁止多个 target 重复使用同一顶点，不能在同一次提取中既选择完整闭环又选择重叠的两侧段。R5 先将有限边距作为单列诊断分支，用现有提取内核和独立 target 配置验证；如需减少重复表面求解，再基于实测成本评审复用既有边界选择能力，不先增加缓存或节点。两种输出不得互相冒名顶替。

S1/S2 不要求闭合整圆；多个连续弧段的拟合仍必须通过原角覆盖、缺口、可辨识性及残差门禁。任何项都允许得到有依据的无效结果，但不能以“正确返回无效”宣称该工件全部尺寸已可测；软件行为验收与实际有效量值覆盖率分别记录。

### 7.1 独立真值与反例

- 高度：已知倾斜台面与两非平行面，在指定台面位置解析求交；与固定源 XY 的报告算法作明确非等价反例。高度搜索区含多层、目标有孔、参考有覆盖但质量失败、延伸等于/超过上限均覆盖。
- ROI：按已确认的并集验证重叠父行不重复、相邻闭边界、窗顺序不影响支持、空窗、跨 frame/单位拒绝、取消及保存恢复；保留同坐标不同采集行，不新增另一种原始行号语义。
- 长宽：已知矩形和圆角轮廓，固定 U/V 与最小矩形分别验证；极值附近缺测不能用残余跨度冒充完整尺寸。轴向跨度是有限所选支持的量，不自带完整性证明。
- 直边：两条有限平行/非平行边的指定方向交点；端点、缺口、外推、短段和错平面；明确方向宽与报告平均偏航修正宽的区别。
- 圆弧：已知半径的整段/多段/短弧；保留类似 S2 缺口的拓扑，检验角覆盖、整周 max_gap、半径碰界、非单调和退化。不得因 RMS 小就忽略角支持。
- 保存：原云/子集字段和 source_indices 不变；生成顶点保存源边/面及插值来源；边界 cloud+features 重读后沿同一选择拟合。最终数值证据持久化不含有效的旧运行租约。

新增接线必须单独验证，不由完整样本的一次成功替代：

| 验证对象 | 独立真值或反例 | 必须通过的条件 |
| --- | --- | --- |
| pose 解析 | 用已知刚体矩阵解析 q/U/V/N，构造行列转置错误、倾斜基准及 U 轴退化 | 同一测量线；源云不变更 frame/数组；无效 pose 不生成默认几何 |
| 动态截面 | 已知两非平行面、固定 U/V，独立求端点中点；换输入后重算 | h 随本次几何变化；不等于源 Z 中点算法，不拿上次有效 h 继续执行 |
| 评价面传递 | 已知非零 h 的圆/直线，在截面与底部台面分别拟合 | 正确截面满足面外门禁；错误底面不能靠放宽门禁通过；尺寸端点位于实际截面 |
| 来源准入 | 相同 item_id 但不同观测/支持/方法/运行；统计差而非方向测距；接线缺失 | 配置/身份错误与正常上游无效分开；历史无租约证据不能直接驱动新输入 |
| 无效与故障 | D/B/T/H 依次无效，参数解析取消、预算不足、native 异常 | 正常缺测保留已配置输出和原因；故障沿执行错误，取消不包装成测量成功 |
| 资产与方法 | 保存实际 h 和来源，重读后继承评价面；删除/篡改来源字段 | 同定义结果与独立值一致；不完整证据拒绝，不静默用默认 h/评价面 |
| 页面生命周期 | 改模式、改来源、断线、切对象、晚返回、取消/重开、卸载 | 参数与连接一致，无旧高度/旧选区冒充本次值，无订阅残留 |

测试配置至少列出：代表窗口、固定 U/V、拟合及方向条件、各延伸限值、覆盖半径与质量、表面求解参数、边界/线/圆质量、原生工作预算、显示容量和超时。未确认项留空会阻止真实运行验收，不以文档建议悄悄赋默认值。生产启用仍是独立步骤。

### 7.2 真实样本逐项记录

每个量记录输入文件/数组摘要、提交和包版本、发布版本、稳定 item_id、测量定义、实际 ROI/评价线、算法参数和质量策略摘要、支持行/生成来源、量值或 null、失败阶段/原因、关键质量、延伸或圆弧缺口、有界显示证据。

对照分三层：相同支持/公式的独立数值验证；不同提取方法的敏感性分析；实体标准件/量具的准确度验证。只有第一层允许给“同定义差值”结论；手工估计与严格边界不同的项标记不可直接比较，不能改名后当通过。源样本只说明这一份数据，不代表重复性、相机标定或真实公差。

表面/轮廓失败按 `input → ROI → datum/target fit → surface → intersection → target selection → feature fit → measurement quality → display/output` 定位；先查中间数据再决定改实现。区分产品定义不适用、真实缺测、参数错误、资源/执行异常与代码缺陷，不统一叫“算法失败”。

### 7.3 真实运行与清理

Windows 优先，WSL Ubuntu 的数据库、LocalBuffer、资产和运行目录使用原生文件系统；源码/只读样本可位于 Windows 挂载盘。Windows .NET bytes/fill、Ubuntu 支持的同机协议分别验收，不把 Ubuntu 协议成功写成 Windows 专用 SDK 成功。

复用现有真实发布生命周期用例，覆盖运行中切版拒绝、停止后换版、旧路由、客户端异常退出、执行中停止、恢复、预算拒绝；确认资源归零而非只看停止返回 True。新增多分支重点核对共享云没有十四份全量副本、取消时全部借用/派生索引释放。仅开展与本次变更有关的资源检查，不重做无关压力循环。

#### 参数、来源与失败

| 位置 | 严格字段及含义 |
| --- | --- |
| height-query.settings.query；measure-step.settings.mode.query | 二选一的 MeasurementQuery，不再在方向配置顶层混放 query_position/direction |
| 配置来源 | `{kind: configured, query_position: [x,y,z], direction: [nx,ny,nz]}`；源坐标、明确单位方向；禁止额外 pose 连线 |
| 本次基准来源 | `{kind: pose-uv, pose_id, target_frame_id, uv: [u,v]}`；必须连接一个本次 pose，目标 frame 与源 frame 不同；不包含隐藏的静态 XYZ/方向 |
| 实际解析 | QueryResolution.line 为源坐标 q/N；QueryResolution.pose 为无租约的位姿快照，包含观测、源/目标 frame、单位、状态、原因、实际方法、质量和变换 |
| 方向测量证据 | HeightMethod/方向 StepMethod 必须保存 query_resolution；统计 StepMethod 必须为 null，不改变统计投影语义 |

解析使用 `q=R^T*([u,v,0]-t)`、`N=R[2,:]`，原云、ROI 和平面仍在源 frame。参数和本次解算分别保存，禁止回写配方中的固定 U/V。持久读取重新核对来源身份、矩阵、质量及 q/N，不只检查 JSON 字段存在。

`require_pose` 从 transform-cloud 的既有校验提取后共用：核对当前运行、观测、坐标、单位，实际借用当前支持，重验质量与父支持内容摘要；没有新缓存、权限或资源系统。相同 ID 的过期 revision、跨运行或错误连接是输入错误。合法但失败的位姿产生 `query_pose_unavailable`，量值/端点/查询线为空，保存定位失败原因；不拟合伪造的目标，不回退源 +Z、单位矩阵或旧值。既有覆盖及有限延伸规则不变，被测面仍要求真实支持。

前端显式选择来源，切换清除另一来源字段；显示固定 U/V、位姿/坐标身份、本次源 XYZ/N 和失败原因。拾取只更新候选：pose 模式仅接受当前预览的匹配位姿，将源 XYZ 转成 U/V，实际数值仍须 Preview 重算。切对象、切运行或来源变更清除候选，晚返回/卸载不写回旧输入。配方检查核对 pose 连接与 build-frame 的 ID；没有通用脚本绑定器或隐式端口回退。

#### 真实点云显示

用户确认显示要覆盖完整真实工件和细节，允许有界采样和交互降采样；算法始终读取完整原始输入。此前 A 页面 297 点合成云仅验证 ROI 并集，不能代表真实工件外观。本轮改用第 2 节的完整 ASCII PLY 生成 1,000,000 点显示证据，显示页明确标注 `显示 1000000 / 输入 14745099`，不宣称已向浏览器传输全部原始点。

## 8. 本轮审计结论

R4 可作为 R5 基点，无证据要求重复实现延伸、资源或发布管理。**A–C 必要接线已内部实现，下一步为 D 的 A_top_L/S1 实际窗口审核与同定义配方。** C 的两种显式顺序、实际截面继承、来源准入和持久读取见[实施记录](3d-metrology-r5-c.md)。工件 XYZ/U/V、质量数值和验收配置仍需审核；本轮完整样本的局部截线返回 target_ambiguous，不能声称钢片/半圆正式尺寸通过。

源码核对特别排除了三种错误设计：用普通数值替代完整几何来源、把底部台面误作等高线拟合评价面、在同次提取中让全轮廓与其子边重复占用顶点。对应解决路径见 5.6–5.8，均为设计审计发现的接线风险，不是已实测复现的新运行故障。没有证据说明需要推翻当前高度/拟合数值内核。

下一步进入代表窗口审核，不再重复实现 A–C 或重新确认六项定义。**尚不满足全部对象有效量值验收条件**：先用审核冻结的显式配置验证 A_top_L/S1。窗口无法无歧义表达或质量规则缺乏依据时先确认，不临场改定义或放宽门禁。[2026-10-26 审计](3d-metrology-audit-20261026.md)已核查 21 区实际支持，确认候选外包框/预算不能直接作为正式配方；静态 iframe 无项目代码也复现原异常，另发现手动旋转后视图标签过时。D/E 仍需真实业务页验收。

当前实现基点为 B 提交 `9040bc0a`，本轮 C 同步入口/进度文档。隔离测试包含完整云和真实发布调用，不代表生产启用。后续按第 7 节顺序验证；R5 完成不替代 M3.4 公开三态、M3.5 最终交付、生产发行与工业准确度验收。

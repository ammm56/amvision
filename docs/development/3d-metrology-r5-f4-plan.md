## 2. 剩余问题与代码证据

### 2.1 S2 不是缺少一个孔径节点

[extract_boundary.py](../../custom_nodes/metrology3d_nodes/shared/extract_boundary.py) 对一个目标找到第二段即返回 `target_ambiguous`。这符合旧的“一个目标只能对应一个连续段”契约，但无法表达同一半圆上的多个真实断段。

[boundary_runtime.py](../../custom_nodes/metrology3d_nodes/shared/boundary_runtime.py) 的 `select_boundary` 已能选择多个明确段 ID；[boundary_fitting.py](../../custom_nodes/metrology3d_nodes/shared/boundary_fitting.py) 已保留各段角区间，但拟圆仍固定 `loss="linear"`、等权。`max_gap` 目前是整周最大角缺口，不等于指定目标弧域内的缺口。[measure_hole.py](../../custom_nodes/metrology3d_nodes/shared/measure_hole.py) 已正确直接消费 CircleFeature，不应重复拟合。

因此缺口是目标组选择、明确的稳健/权重方法及对应支持质量，不是重做拟圆或 Measure Hole。手工报告的栅格等高线、角区代表点和原始扫描线复核属于对照依据，不能把其数值直接当平台输出。

### 2.2 两项 Z 是配方适用范围拒绝

| 项目 | 当前原因 | F3 距离与限值 |
| --- | --- | --- |
| A_top_R.Z | reference_extension_limit_exceeded | 最近投影支持约 11.2392 mm，大于 10 mm |
| A_bottom_L.Z | reference_extension_limit_exceeded | 最近投影支持约 34.9828 mm，大于 30 mm |

[measurement_reference.py](../../custom_nodes/metrology3d_nodes/shared/measurement_reference.py) 已实现有限基准延伸、最近实际支持追溯和原始行号平局规则。这两项不能归因为求交失败，也不能通过把限值调到刚高于失败距离来宣布修复。需要证明五窗台面在有限工件区域内的参考适用性，被测顶面仍须有真实支持。

### 2.3 L/W 有效，但准确度仍有实质限制

A_top_L 名义 W=6.876303 mm；改为 0.06 mm 格时约 7.011007 mm，0.03 mm 半格相位时约 6.966305 mm。独立逐点参考复现该变化，因此不能归因于显示采样或 float32；也不能仅凭独立实现一致就声称物理准确。

已知变化发生于格聚合/分区/剖面测量链路，但尚未逐侧、逐阶段量化哪部分主导约 0.135/0.090 mm 差异。当前需要完成该项受控分解，区分实现错误、方法离散化和采样本身的限制，不调参贴合旧报告。

## 3. F4 A：目标片段集合与 S2

### A1 收口选择、来源与质量契约

在现有 `BoundaryTarget`/`BoundarySelection` 内扩展显式选择方式，保留原有单连续段的严格语义；它与目标片段集合是两种主动选择的方法，不是旧实现兼容或失败后降级。

| 内容 | 设计要求 |
| --- | --- |
| 配方目标身份 | 使用稳定目标组 ID；运行时生成该组实际片段 ID 列表。下游引用目标组，不要求工程师预知碎片数量 |
| 选区 | 当前评价面中的有限 ROI，以及明确的环带/角区；坐标系、单位、中心、正方向及跨零角区规则显式校验 |
| 段与来源 | 只选择既有顶点，沿原拓扑截为连续段；不跨 ROI、原拓扑缺口拼线，不新增虚假的连接端点 |
| 冲突 | 空组无效；重复归属、环带内多个无法区分的物理目标不得静默合并或取最长段 |
| 支持指标 | 全部候选、选中段、独立顶点数、逐段长度、角区占用、目标弧域缺口与整周缺口分别保存 |
| 资产和身份 | 沿 CloudRuntime/Scope 保存有序来源和组到段映射；保存重读保持方法、拓扑、质量，只重绑定本次运行身份 |

字段名在现有契约中统一落地，三维格式保持 v1，同批更新所有实际读取方；不新增 group 资源服务。开工前按调用点检查参数模型、handler、方法摘要、features、资产验证、显示、Catalog、前端控件和 SDK 暴露类型。

**验证出口：** 独立构造断弧、跨零角区、ROI 截断、两个物理圆、重叠选择、单点碎片和重复源点；逐项核对选中行号及断点。同一输入置换段顺序，归属与拟合量值必须保持一致；预算失败、取消和 Scope 关闭不留数组。A1 单独通过后才接求解。

### A2 在既有拟圆入口增加明确稳健方法

1. 保留等权几何最小二乘；在同一 SciPy 求解入口增加显式稳健模式、损失尺度、角区权重与有界迭代参数，不复制求解器到 handler 或 Measure Hole。
2. 角区必须在本次评价面定义，注明参考中心、角起点/范围和分箱方式。预选/加权的角区与拟合圆心下的实际覆盖分别记录，不能将初始中心的覆盖当成最终圆的覆盖。权重只调整已有观测贡献，不制造“真实中位点”；若采用角区代表点，须单独定义其生成来源，不能伪造源点行号。
3. 冻结权重与稳健损失的数学顺序、尺度单位和归一方式。不能先乘权重后无意中改变不同角区的物理残差门槛；独立目标函数与数值导数核对后使用。
4. 拒绝半径压边、未收敛、短弧病态及支持不足。稳健降权不等于自动删除；如使用显式外点筛选，记录全部候选、每次剔除、最终支持和有界轮数。
5. 同时报告全候选及实际支持残差、降权/剔除比例、真实弧覆盖、角区占用、目标域内缺口、整周缺口与可辨识性。不得只以剔除后的低 RMS 放行。
6. CircleFeature 保存实际方法与支持；Measure Hole 仍只读取圆心、半径和质量。当前四侧 `visible-envelope` 剖面不等于圆弧等高线，不能简单删除 `fit_boundary` 的拒绝检查来接圆。

首先使用现有 0.25 mm 实测截线的分段候选验证 S2，S1 保留原配方作回归。若仍缺足够实测支持，应定位是候选生成、选择还是拟合适用性；不得自动切换为栅格边缘、四侧剖面或报告值。需要新增高度场等高方法时，单独收口成熟算法、格来源与误差定义后显式接入，不自行编写等高解析器，不引入 Matplotlib 绘图执行链。

**验证出口：** 解析圆/半圆/倾斜圆、非均匀采样、已知外点、缺弧、极短弧、共线退化及半径边界；独立真值不用待测拟合器。S2 对照原始扫描线相邻实测点的交点，不跨缺扫插值；保留与报告的定义差异。S1、所有既有有效尺寸、保存重读及错误传播回归。不能把“错误成功传递”作为 S2 已完成。

### A3 前端与实际操作

- 沿已有 Extract Boundary / Fit Circle 参数编辑器提供单段/片段组选择；环带、角区及目标组均可数值编辑和三维预览，不要求手填运行段 ID。
- 三维同时显示选中真实片段、未选候选、缺口、稳健降权或剔除支持及拟合圆；拟合补全部分使用区别于实测线的样式。
- 结果表点击 S1/S2 定位同一组，详情展示方法、直径、覆盖、缺口、残差和无效原因；切换只改变显示，修改参数仍显式 Preview 重算。
- 覆盖任务切换、Preview 晚返回、运行停止、组件卸载与旧观测拾取。保存/恢复/发布消费同一来源，不引入常驻原云查询会话。

## 4. F4 B：两项 Z 的有限应用范围

1. 固定当前台面五个支持 ROI、坐标约定、全部查询 U/V 和被测顶面，不以自动换 ROI 取得有效值。
2. 联合拟面与五次留一 ROI 拟面分别计算全部查询点的参考高度、法向差、残差及最近支持距离；同时展示分离支持的空间分布。留一对照是敏感性证据，不是测量不确定度证明。
3. 以完整工件的有限查询区域核定工程应用范围，记录区域最远投影支持距离及留一变化。使用既有显式距离参数表达可行范围，不只取两个失败距离加微小余量。
4. 由既有工程参数授权形成此工件的配方值与依据，不设为通用节点默认、不取消距离限制、不降低原拟面或顶面支持质量规则。
5. 如仅靠距离确实不能表达预期范围，再单独设计显式应用域并确认测量定义；不暗中把“有拟合平面”当作无限有效基准。

**验证出口：** 倾斜面解析真值，范围内/边界/范围外查询，基准质量失败和被测面缺失；两项 Z、其余十项 Z 与 H 全部复核。前端显示当前查询、参考支持、实际距离、应用上限及参考/被测面各自状态。保存重读保留依据。

## 5. F4 C：长宽敏感性审计

只针对 A_top_L 和必要的稳定对照片进行有限实验，不每个因素重跑整张图。预先固定本次 pose、ROI、动态高度和原始点集合，复用一次完整读取后的测试输入；不把这种测试复用改成生产跨 Run 原云缓存。

1. 对原格、半格相位、双倍步长的既有差异，逐侧记录格计数/中位高度、种子区域、形态学前后归属、真实支持、缺邻类型及分位端点参与者。
2. 分别锁住区域归属与测量支持，定位变化来自 U/V 投影、分箱相位、分区连接、剖面邻格还是分位统计。定位实验结果不得冒充正式测量输出。
3. 区分实现错误与方法限制：错误按共享算法修复并保持独立真值；方法问题须给出可解释的方法修正或适用范围，不对多个相位取平均/选最接近报告者来隐藏差异。
4. 验证倾斜、圆角、缺口、分层、飞点及采样密度变化；源坐标平移与网格一同变换应满足约定不变性。仅网格相位改变属于敏感性实验，不能假定天然不变。
5. 若改方法，所有十二片重新形成同定义结果矩阵及来源/保存/显示回归。独立计算一致、标准件准确度、重复扫描稳定性分别报告。

**验证出口：** 给出逐侧、逐阶段的差值原因及修正后的相同实验结果，不能只写“网格敏感”。尚无可溯源实体尺寸/允许误差，不能发布物理精度认证结论；此缺口不阻止完善算法和公开已验证节点。

## 6. 计算优化与 F6 验收

先完成 S2 方法和支持定义，再冻结同方法输入作性能比较。优化一次只改一个实际热点，确认数值、来源和质量不变后继续下一项。

1. 沿既有节点计时将 S1/S2 的投影、曲面构建、求交、排序及筛选拆开；将高差中的摘要、邻域、最近支持和求交分开。只增加诊断能力，不默认开启重型跟踪。
2. 优先评估共享台面支持上的成熟空间索引/批量查询，复用现有 Run 作用域、缓存与预算。查询距离必须仍在正确切平面上；精确条件复核、等距原始行号选择、取消与失败释放不变。记录构建成本，不能只报查询时间。
3. 多 ROI 预筛、严格曲面处理中间结果按不可变云身份、评价面和参数复用；不重做已完成的单遍 ROI、包围盒摘要缓存。缓存只在本次 Run 内有效，pose/来源变化不得命中。
4. 若改用另一种边界方法，应按新方法单独验证，不把计算工作量变化宣传成同算法加速。ASCII 解码优化排在纯计算之后，不能关闭坏文件校验换速度。
5. 复用已有 worker 算子线程设置，记录实际生效的 NumPy/SciPy/Open3D/进程配置，不新增线程管理器或无约束并行。

冻结候选后执行一组有界验收：Windows 与 WSL 各一次首次执行、五次复用同一常驻 Runtime 的独立 Run，报告每次时间及范围，不以六次样本估算 P99。同机数组纯数值与开启显示分别统计；输入传输、读取、显示构建单列。记录进程峰值 RSS、线程、Broker 租约/映射与 Scope 归零，再覆盖停止/恢复及异常客户端的受影响路径。具体测试次数是本轮验证计划，不是生产并发或队列配置。

当前没有确认正式计算上限是 2、5 还是 10 秒，不填写虚构通过线。先提交优化后的真实分项，再按明确秒数完成节拍验收；180 秒安全超时不能用作秒级目标。1 GiB 活跃数组、4 GiB 工作预算、百万显示点和 2 秒停止宽限保持已确认本机配置，不扩大到所有客户机。

## 7. F5、三态与发行缺口

### 7.1 完整工件与现场界面

- 用既有十八节点完成 50 主项，再核对手工报告另有的六处基体 t、十二直边拟合宽、整体包络和台面轴跨度，逐项标清定义与是否属于交付范围。直边宽不是当前可见包络 W，不能复用同一标签冒充。
- 从空白画布手工配置一条代表性完整测量链；完整工件沿现有模板/导入及重复配置方式完成，不要求为验证而机械手连 106 个节点。
- 全部对象结果行定位、缺测详情、显示开关、参数修改后 Preview、保存重读、发布、现场 App 文件/数组输入逐项核对。
- 发布更新沿现有指纹校验、审核重发、版本切换与回滚，不建立三维专用发布版本系统。保持二维资源和模型流程不受影响。

### 7.2 M3.4 产品三态仍未交付

[现有 Check Limits](../../backend/nodes/core_nodes/support/measurement.py) 逐项已有 valid/passed/reason，但汇总 state 仍只有 ok/ng；缺必检与真实超差不能在汇总层区分为 INVALID/NG。该行为是已有实现边界，不是 F3 引入的新回归。

在原规则与 Result Record 上按基线升级，并同步实际使用汇总状态的前端、SDK、文件/HTTP/数据库/PLC 结果映射与 SPC；不新增三维判定器。公共协议变更必须沿项目规则显式处理，不因为三维格式 v1 就忽略非三维公开消费者。公差值需要图纸/工艺依据，不能从本样本有效量值倒推。三态未完成前，数值可用不等于自动分选规则可交付。

### 7.3 发行与容量

- 开发态 Windows/WSL 通过不等于 bundled Python 离线发行通过；需沿既有 assembler/profile 携带受控 I/O、几何库、前端和显式容量，验证 Ubuntu 系统库与原生运行目录。

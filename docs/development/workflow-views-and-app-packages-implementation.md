# 运行界面与 App 应用包实施基线

## 1. 状态、职责与阅读规则

状态：设计已接受，新增能力待实现。依据 [ADR-0012](../decisions/ADR-0012-workflow-views-and-app-packages.md)，本文是运行界面、Workflow JSON 导入导出、完整 App 下载上传恢复及语言模型生成界面的唯一详细实施基线。本文写入不代表完成代码、数据迁移、浏览器验收或现场认证。

当前代码仍是已实现行为的事实来源。以下资源名、包目录和消息字段是设计草案，不是已经注册的公开 endpoint 或完整 JSON Schema。实施时必须同步冻结版本化契约、迁移和测试，不能把示意直接当成可调用接口。

本文同时作为设计器与生产显示的共同约束：第 3 节定义资源归属，第 5 节定义页面操作与状态转换，第 6 节定义显示快照、接口草案和权限，第 13 节定义对应验收。页面操作语义和职责边界已经确定；字段、路由、容量和错误码的最终形式仍须按第 14 节完成实现前核对。

优先级：长期稳定和结果正确优先，其次是高性能；实现保持简单、明确、通用，不增加隐藏执行、隐式默认值、业务重试或同步等待队列。

### 当前能力与新增缺口

| 范围 | 已有基础 | 本基线待实现部分 |
| --- | --- | --- |

| 依赖 | 发布快照、节点包身份、直接稳定资源引用清单 | 完整交付依赖解析、资产携带和目标环境映射 |

## 2. 已确认的不变量

1. 采用方案 A：运行界面绑定 App 公开输入输出，不绑定内部节点参数、节点位置或 Preview 私有数据。
2. 一个页面只连接一个 Runtime；多个浏览器可查看同一 Runtime，但不导致多次执行。页面不组合多个 Runtime 的业务结果。
3. 内部节点参数、连线和业务算法只在 Workflow 编辑画布修改，随后按既有发布、选版规则生效。
4. 界面仅选择现有 App Entry 输入。`request_json` 字段由表单组成，不因此新增公开 binding 或修改 Workflow。
5. 可选输入保持可选；缺省、null、false、0、空字符串、空数组、空对象不能相互替换。
6. 界面只承担输入、调用、展示和显示格式化；数据组合、ROI/模型结果关联、规则判定及业务统计留在 Workflow。
7. 界面、主题及组件资产独立版本管理，不进入 Workflow 内容指纹；仅修改外观不重启 Runtime、不修改 Trigger。
8. 打包固定独立版本的交付组合，不要求 App、界面和所有组件使用相同版本号。
9. 页面打开、刷新、重连、设计预览和暂停显示不执行 Workflow，也不启停 Runtime/Trigger。
10. 显示从统一 Runtime 结果边界获取，不依赖调用协议或 Trigger 回传字段；现有 SDK/Trigger 响应结构不变。
11. 显示采集显式启用，不自动开启 full record 或全节点 trace；不改变原有同步 admission、异步任务和 Trigger 合并语义。
12. 模型只参与界面创作；生成进入草稿并经校验、预览、确认后发布。已发布界面可在模型离线时运行。
13. Workflow JSON 与完整 App 包共用现有文档语义；完整包不是数据库备份、进程检查点或平台发行包。
14. 导入不自动执行节点、安装代码、启动 Runtime、启用 Trigger 或回放历史事件。
15. 任何容量默认值、性能结论或稳定性认证必须来自实测，不以架构解耦替代验证。
16. 保存草稿、发布界面、应用到运行入口、启用显示交付是不同动作，不能互相隐式触发。
17. 设计预览不执行；试运行复用正常 Runtime 调用，真实节点副作用、资源占用和调用规则不变。
18. 本次手动调用结果按执行 ID 固定，不能被外部 Trigger 的最新结果覆盖；暂停显示不暂停业务执行。

## 3. 资源关系与独立版本

```text
Workflow App Draft --发布--> App Version --选版--> Runtime <--调用-- Trigger
                                │                   │
                           公开输入输出契约       公开执行结果
                                │                   │
运行界面草稿 --独立发布--> 界面版本 --显式应用--> 运行入口 --加载--> 运行页面
                                │
                             组件/主题资产

运行入口固定界面版本与一个 Runtime；显示交付配置归属 Runtime，不归属浏览器。
App 包 manifest：固定上述所选文档、版本、配置、依赖及现场映射关系。
```

### 3.1 界面资源草案

运行界面保存稳定 ID、名称、Project、所属 Workflow App、草稿、独立发布版本、输入输出绑定、组件布局、主题与资源引用。运行入口保存所选界面版本与一个 Runtime 的明确对应，不在每个控件中硬编码 Runtime，也不把 Worker 对象写入界面文档。入口是配置资源，不是新的 Runtime、执行器或常驻进程。

同一 App 可有不同界面版本或外观方案；一个界面模板可通过不同入口用于该 App 契约兼容的不同 Runtime，但一次页面会话只能选定一个 Runtime。Runtime 的选择是运行上下文，不增加页面跨实例编排能力。入口有稳定访问地址，鉴权后返回同一入口；地址不包含凭据。

界面版本不可变；修改生成新版本，明确发布与回退。设计草稿修改不改变已打开的生产界面；页面切换界面版本必须整体更新，不能混用新布局与旧绑定。已有输入草稿不得因后台发布自动丢失或提交。

### 3.2 契约兼容

- 设计以明确选择的已发布 App Version 契约为依据，不要求 Runtime 已启动。生产运行使用 Runtime 当前激活版本的公开 contract，不使用最新草稿或仅凭最新发布序号判断。
- 停止态入口配置可按 Runtime 已选择的目标版本预检，但必须标为待启动核对；desired version 不能当成已经激活的版本。
- 按界面实际使用的 binding、方向、payload type、Schema 和字段路径校验；不拿完整 Workflow 内容指纹相等当作界面兼容条件。
- 内部节点替换且所用契约兼容，界面可继续使用；新增未使用输出不应直接导致整个界面失效。
- 删除所用输出、改变类型或收紧输入规则时明确报告；不自动修复 binding、不替换同名字段、不切 Runtime 版本。
- 任意 JSON 的深层字段若没有 Schema，发布时只能证明外层 binding 有效，不能伪造深层类型保证。执行时字段不存在或类型不符，显示绑定错误，不填 0 或成功状态。
- Runtime 切版、generation 改变或页面重连后校验并切换数据来源；旧结果不能覆盖新实例状态。
- 兼容信息应在加载、发布和实例切换时构建缓存，不在每次生产调用中扫描完整图、数据库或组件目录。

### 3.3 修改影响范围

| 变更 | 生效面 |
| --- | --- |
| 已有组件的标题、布局、颜色、主题 | 独立界面发布；不发布 Workflow、不重启 Worker |
| 展示已有公开结果的其他字段 | 修改界面绑定并校验；不修改节点实现 |
| 新 Vue 组件或外观变体代码 | 受控前端组件发布；不改变 Workflow 契约 |
| 新增目前未公开的业务结果或输入 | 在 Workflow 编辑器修改并发布，Runtime 显式选版 |
| 本次表单参数不同 | 作为本次请求输入，不持久化为内部节点参数 |
| 目标机器路径、模型资源重映射导致图内容变化 | 创建导入派生版本，不原地改发布快照 |

### 3.4 最小持久资源与字段草案

以下是需要覆盖的信息，不是现有 ORM/API 声明。资源只新增界面、界面版本、运行入口三类，再为既有 Runtime 增加显示交付配置；不新增试运行任务系统或永久浏览器会话记录。

| 资源 | 字段草案 | 归属与约束 |
| --- | --- | --- |
| WorkflowView | `workflow_view_id`、`project_id`、`application_id`、`display_name`、`description`、`draft_revision`、`draft_document`、`draft_fingerprint`、创建/修改时间与主体 | 可修改草稿；所属 App 的内部节点不在此修改 |
| WorkflowViewVersion | `workflow_view_version_id`、`workflow_view_id`、`version_number`、`source_draft_revision`、`document`、`document_fingerprint`、`binding_requirements`、`dependency_manifest`、创建时间与主体 | 不可变；所用契约需求和依赖由服务端从文档推导，不相信客户端自报兼容 |
| WorkflowViewEntry | `workflow_view_entry_id`、`project_id`、`application_id`、`display_name`、`workflow_view_version_id`、`workflow_runtime_id`、`interaction_mode`、`config_revision`、`display_options` | 一个入口对应一个发布界面版本与一个 Runtime；配置修改使用修订号检查 |
| Runtime 显示交付配置 | `enabled`、`config_revision`、`output_binding_ids`、图片交付选项、快照/资源数量与字节及生命周期限制 | 每个 Runtime 一份；不为各页面重复生成同一显示资源，默认值实测后冻结 |

`draft_document` 包含 `format_id`、`basis_app_version_id`、`components`、`layout`、`theme`、`assets`。组件声明稳定 `component_id`、类型/版本、属性及明确的输入输出绑定。设计依据、发布文档和 Runtime 实际版本的关系按第 3.2 节校验，不要求版本 ID 相同才兼容。

`interaction_mode` 首版限定为 `monitor` 与 `interactive`：前者不提供页面调用操作，后者可提供公开输入及执行操作。模式不是权限凭据，服务端仍按主体与目标 Runtime 校验调用权限。`display_options` 只保存语言、全屏等显示选择，不隐藏业务参数或启停动作。

界面 `version_number`、草稿 `draft_revision`、入口/显示配置 `config_revision` 和 Runtime generation 各司其职，不共用计数器。最近结果、访问令牌、现场表单、选中组件、暂停状态和 Worker 句柄不写入发布文档。

## 4. 输入与输出绑定

### 4.1 只使用 App Entry 公开输入

`request_*` 是默认 binding 名称，控件应按契约中的 binding ID、payload 和 transport 能力配置，不硬编码名称猜类型。现有默认输入与控件对应如下：

| 输入 | 控件 | 提交边界 |
| --- | --- | --- |
| request_image_ref | 图片选择/上传 | 经既有上传或 multipart 接口得到有效引用，不提交浏览器本机路径 |
| request_image_base64 | 图片选择/上传 | 明确使用现有 Base64 binding，不隐式改写为其他输入 |
| request_json | JSON 编辑器或结构化表单 | 组装同一 value 输入，服从 request_schema |
| request_text | 单行/多行文本 | 保持原始文本，不自动解析 JSON |
| request_file | 单文件选择 | 现有文件上传及引用接口 |
| request_files | 多文件选择 | 保留明确的文件顺序和多文件协议 |

普通页面通过 HTTP Runtime 调用支持所有已公开类型，不为浏览器实现本机 mmap 或 ZeroMQ。高性能 Trigger 仍只使用既有 image-ref/JSON/text 能力，不因界面增加文件或 Base64 transport。

### 4.2 request_json 表单

多个控件可分别绑定 `request_json` 中的 `recipe`、`station`、`batch_id`，提交时组装一份 JSON 对象。这些是本次输入字段，不是新 App Entry binding，不改内部节点参数。

- 采用明确字段路径，复用项目路径语义；不能按控件排列顺序关联。
- 同一字段多写入者、父对象与子字段冲突在设计校验中拒绝。JSON 原文编辑与结构化表单同一时刻只有一个写入来源。
- 缺省字段按缺省提交；不因为页面存在控件就提交 null、空图片、空文件或虚构默认值。
- 可选控件明确区分“本次未提供”和“提供空值”；例如未提供 request_text 与提交空字符串、未提供 station 与提交 0 不等价。图片只提交明确选择的 binding，不为另一种图片输入补空 payload。
- 显式预填值可作为界面配置展示，由实际表单提交；不隐藏注入或反向修改 Workflow default。
- 可选字段仍可省略；未消费的可选输入不要求补齐，消费节点的既有错误语义保持不变。
- 提交构造层与后端现有输入校验复用同一公开契约；前端校验不替代后端权威校验。
- 一次输入不会改变外部 Trigger 下次提交的参数。暂停显示、重连和重试资源读取不重发业务调用。

### 4.3 输出

每个显示组件使用公开输出 binding ID、可选字段路径和显示配置。控件 ID 用于界面文档身份，移动控件、修改标题或节点位置不改变绑定。数组下标仅在明确数据路径中具有语义，不用节点/控件位置隐式配对数组。

允许单位、精度、文字、图标和颜色映射；合格判定、跨字段计算、ROI 与推理结果配对、业务累计和数据合并必须在 Workflow 中完成。图片叠加展示若支持原图与几何分离，必须使用同一结果中的显式来源和坐标契约，不重新推断关联。

Save Image 的 image-ref/saved_output 与 Save JSON 的保存回执不是相同类型。界面不因节点叫 Save 就自动读取其内部输入或磁盘内容；所需图片、文件或 JSON 必须成为明确公开输出，再按相应资源契约显示。现有 Preview body 可按公开类型适配，但不能访问 Preview 私有缓存。

## 5. 界面文档、组件和编辑器

### 5.1 一个文档，多个创作入口

文档包含格式版本、稳定组件 ID、组件类型/版本、布局、输入输出绑定、显示属性、主题引用、本地资源引用和允许操作。运行上下文、表单现场值、访问令牌、最近结果和 Worker 句柄不混入发布文档。

人工可视化编辑、模板创建、模型生成使用同一解析器、校验器、文档和 Vue 渲染器。必须支持 AI → 人工 → AI → 导出 → 恢复的往返，不维护生成式页面和手工页面两套格式。

第一阶段不建立任意 HTML/JavaScript、页面表达式执行器或第二套流程图。界面文档不支持任意 API 数据源、多 Runtime 联合处理、页面定时任务或控件业务事件链。

### 5.2 组件目录

| 类别 | 首批能力 |
| --- | --- |
| 输入 | 文本、数字、枚举、布尔、JSON、图片、文件、多文件 |
| 图片 | 适应窗口、缩放、平移、原图查看；几何与缩略图坐标关系明确 |
| 结构化结果 | JSON 折叠/复制、明确列绑定的表格；大列表有界渲染 |
| 标量 | 文本、数值/单位/精度、明确值映射的状态 |
| 文件 | 已授权文件的名称、长度、下载 |
| 说明与布局 | 标题、说明、网格、分组、标签页 |
| 操作 | 按权限调用既有 Runtime 接口；不绕过公开输入契约 |

组件注册至少声明类型、版本、接受的数据类型、属性 Schema、允许动作、空值/加载/错误状态和资源依赖。复用已有 Vue 图片、JSON、表格基础组件，先审计生命周期，不复制 Preview Run 状态管理。

首版导航建议为“运行界面”，包含列表、设计、版本及可全屏运行页。设计器左侧为组件/公开契约，中间为布局，右侧为绑定/属性；首版提供网格、尺寸、排序、分组、标签页及主题，不先建设通用网站平台。

设计预览使用明确标记的示例数据或只读快照，不调用 Workflow。手动“执行一次”是独立显式动作，仍遵守 Runtime admission，失败不自动等待或重试。

### 5.3 主题和扩展

- 主题层负责颜色、字体、间距、背景、边框、阴影及可关闭动效；组件外观变体负责不同呈现；新交互由受控组件源码实现。
- 现代简约、科幻 HUD、像素风等均不改变 binding、错误含义或执行协议。动态背景和动效不得成为运行依赖。
- 主题作用域限制在运行界面容器，不污染平台导航、管理页和节点编辑器。
- 使用现有中文、英文、日语、韩语切换机制；固定系统状态和控件文案本地化，业务原文不自动翻译，主题不复制四套业务实现。
- 首先覆盖桌面工作站、工控机和全屏模式。窄屏按现有前端原则支持查看，移动端验收单独标注，不能由桌面测试推断。
- 字体、图片等随资产本地分发，不依赖 CDN。扩展组件经过开发审查、测试、版本发布及安装信任校验；不接受配置中任意注入脚本。

### 5.4 页面操作与副作用

“运行界面”管理入口提供设计、试运行和版本管理；生产运行页使用独立地址。Workflow 编辑画布修改执行逻辑，界面设计画布只修改显示文档。各页面共用受控组件和渲染器，不共用草稿编辑状态。

| 操作 | 修改对象 | 执行 Workflow | 对生产页或 Runtime 的影响 |
| --- | --- | --- | --- |
| 编辑布局、绑定、主题 | 浏览器界面草稿 | 否 | 不改变已发布界面 |
| 保存 | 服务端界面草稿 | 否 | 不发布，不改变运行入口 |
| 界面预览 | 无持久修改 | 否 | 只渲染示例或固定快照 |
| 试运行中的执行一次 | 一次正常 Runtime 调用 | 是 | 真实节点副作用和资源占用不变；不修改生产界面 |
| 发布 | 新不可变界面版本 | 否 | 不修改现场入口，不启用显示 |
| 应用到运行入口 | 入口的界面版本引用 | 否 | 新打开页面使用新版本；已有页面提示更新 |
| 打开生产页 | 当前浏览器显示状态 | 否 | 不启动 Runtime/Trigger，不启用显示交付 |
| 生产页执行一次 | 本次公开输入请求 | 是 | 遵守原有 Runtime 调用规则 |
| 暂停显示、退出 | 当前浏览器状态与资源 | 否 | 不暂停业务，不停止 Runtime/Trigger |

“界面预览”与 Workflow 编辑器 Preview Run 不是同一动作。试运行应显示明确目标并说明是真实调用；不以“预览”名称掩盖 Save、Cleanup 等副作用，也不要求每次正常调用额外确认。

### 5.5 设计页：创建、保存、校验与预览

创建时依次选择所属 App、作为依据的已发布 App Version，以及空白/模板/复制来源。没有发布契约时先完成 Workflow 发布。打开已有界面读取服务端草稿和修订号，不直接修改发布快照。

设计器沿用第 5.2 节布局：左侧组件及公开输入输出、中间布局、右侧绑定/属性、顶部保存/预览/试运行/发布和草稿状态。选中组件能够定位到“公开 binding → 字段路径 → 接受类型”，不能只显示无法追溯来源的字符串。

保存状态与校验状态分开表达：

- 保存：`已保存 → 已修改 → 保存中 → 已保存 / 保存失败`。
- 校验：`待校验 → 校验通过 / 存在问题`。
- 已有发布版本与草稿有修改可以同时成立，不用互斥的“已发布/编辑中”状态覆盖事实。

保存携带 `expected_draft_revision`；另一个标签页或主体先保存时报告冲突，不自动覆盖或合并布局。保存失败保留浏览器修改，不把本地内容标成已持久化；首版不引入多人实时协同。

预览使用明确标记的示例数据或人工选取的固定执行快照，不跟随实时结果。覆盖空结果、错误、长文本、大数组、图片缺失等状态。示例与试运行数据不随界面默认发布/打包，进入和退出预览不保存、不发布、不调用。

### 5.6 试运行：固定上下文与请求状态

先保存界面草稿，再明确选择 Runtime。展示其 App、实际运行版本、名称、状态及契约兼容结论；不自动选择首个 Runtime、不启动、不切版。停止态可查看界面但不能执行，提供前往既有 Runtime 管理页的入口。

点击执行固定界面草稿修订/指纹、Runtime ID、预期 Runtime revision 和实际提交输入，并将返回的 `workflow_run_id` 关联到此次请求。输入框后续修改不改变已提交内容；结果区区分当前表单与本次提交。试运行上下文不要求永久任务表。

状态区分：尚未调用、正在提交、等待结果、Workflow 成功、Workflow 失败、明确拒绝且未执行、连接中断且结果未确认。网络错误不能证明节点没有执行；未知结果不自动重发，退出页面不隐式取消或停止 Runtime。

表单读取版本与实际执行版本之间的竞态由第 6.6 节的可选 HTTP revision 前置条件处理。检查在既有调用边界执行，不增加等待队列或自动重试。

发布必需结构与绑定校验，但不强制每次标题/颜色修改后真实调用生产 Workflow。试运行验证结论只对应被验证的草稿指纹，修改后不能沿用为当前版本已验证。业务返回不合格不等于界面验证失败。

### 5.7 发布与入口应用

发布接受已保存的明确草稿修订：服务端核对修订、校验组件/绑定/资源、固定文档与所用契约/依赖、创建不可变版本并返回身份和指纹。失败不修改旧版本或现场入口；相同内容可复用既有版本，这是发布去重，不是业务调用去重。

不存在的公开 binding、方向错误、已知类型不兼容、JSON 写入冲突、未知组件/资源和非法动作阻止发布。缺少完整 Schema 的 JSON 深层路径按第 3.2 节报告静态验证限制，不能一概禁止使用或伪造保证。

“应用到运行入口”明确选择入口及发布界面版本，携带 `expected_config_revision`，按目标 Runtime 契约校验。停止态只做目标版本预检，启动后核对实际 active revision。不顺便更新显示输出选择、不启动 Runtime/Trigger；所需输出未交付时明确提示单独配置。

新打开页面使用入口当前指定版本；已打开页面固定原会话组合，提示更新，不热替换局部组件。明确重载后整体切换；未提交输入需明确处理，不能自动丢失或提交。入口重新配置 Runtime 时旧页面不静默转向其他实例；撤销调用权由后端授权处理，入口地址不是权限。

### 5.8 生产页：加载、状态与操作

生产页只保留现场名称、简洁连接/Runtime 状态、配置好的输入和结果区，以及执行一次、实时监视、暂停显示、全屏等必要操作。不展示组件选框、绑定编辑、节点目录或发布按钮；版本、执行 ID 和错误详情放入详情区域。系统文案使用既有四语言机制，业务原文不自动翻译。

打开顺序：鉴权 → 入口及固定界面版本 → Runtime 实际状态/契约 → 兼容与权限 → 最新显示快照 → 通知连接。该顺序不执行 Workflow；快照与通知之间的竞态按第 6 节收敛。显示未启用、Runtime 未启动、尚无结果分别表达，不留空白或自动启用。

各维度独立维护，不把全部情况塞进一个 `status`：

| 维度 | 状态示例 |
| --- | --- |
| 网络连接 | 连接中、已连接、断开、无权限 |
| Runtime | 停止、运行、故障 |
| 界面兼容 | 可用、不兼容、待核对 |
| 当前显示 | 无结果、实时、本次结果、已暂停 |
| 本次调用 | 待提交、等待、成功、失败、结果未确认 |
| 资源显示 | 可用、加载中、已失效 |

Workflow 执行成功不等于产品合格；合格状态绑定 Workflow 明确公开的业务字段，不根据 HTTP 200 或 succeeded 推断。Runtime 正常与浏览器断网可以同时成立；图片失效不改写业务终态。

显示有两种明确模式：实时监视跟随最新完成快照，本次结果固定当前页面发起的执行 ID。手动调用完成后展示本次结果，不被后续外部 Trigger 结果覆盖；明确切回实时监视才继续跟随。正在执行状态与上一条完成结果分开，不因新调用开始清空上一张图片。

暂停仅冻结当前画面；恢复读取最新快照，不补播全部中间结果。关闭释放订阅、图片对象和监听器；重连只读快照，不提交表单。登录过期沿用现有鉴权恢复，不自动重放结果未确认的业务请求。默认不承诺刷新后恢复上次手动结果，尤其不能在 none 模式下假设存在数据库记录。

## 6. 显示数据通道与稳定性

### 6.1 来源与通信

```text
HTTP 页面调用 / ZeroMQ / 本机共享内存 / 目录 Trigger
                         ↓
                  现有 Runtime 执行
                         ↓
                 统一公开输出处理边界
                         ↓
              backend 显示快照与资源交付
                         ↓
            REST 快照 / WebSocket 通知 / HTTP 图片
                         ↓
                    Vue 运行界面
```

显示选取必须在统一结果处理边界完成，不读取 SDK 包装层或 Trigger 回传结果作为唯一来源。Trigger 可不回传某个字段，页面仍可显示已明确允许交付的 App 输出；这是独立的显示交付，不扩大第三方业务响应。

复用现有版本化 REST/WebSocket 骨架、Project 可见性和权限。只读监视与手动调用分权，服务端校验动作权限；界面隐藏按钮不代替鉴权。远程浏览器访问 backend 地址，不连接 Worker、mmap 或服务端 file 路径。无需新增前端框架、Redis、MQ 或独立微服务。

具体 endpoint 和新消息 format_id 在实施阶段冻结；不把已有 Runtime 生命周期流当成已经提供生产结果快照。

### 6.2 配置与快照

- 运行显示交付显式启用；创建/打开界面不自动启用。未启用时沿用原生产调用路径，不采集全节点记录、不编码显示副本、不新增显示历史。
- 只交付声明的公开输出；配置可在 backend 控制面缓存，每次执行固定配置快照，不能由浏览器数量或动画状态改变图执行。
- 外观修改只更新界面版本，不改变采集内容或节点行为。选择其他已有公开输出只涉及显示绑定/交付配置，不修改图或发布快照。
- 快照字段按第 6.5 节定义。显示流 `stream_epoch` 与顺序号防止 backend 重启后的顺序误判；Runtime revision/generation 表示执行来源，Worker epoch 在后端沿用既有来源校验，两种 epoch 不混用。
- 图片、JSON、表格和状态按同一快照关联。迟到消息按实例身份及顺序处理，不依据不可靠的客户端到达时间覆写当前结果。
- 首次进入和重连读取快照，通知只触发刷新；快照与事件的竞态必须通过序号/重新读取收敛，不能漏掉连接期间最后一次更新。
- 缺少结果、运行失败、资源失效、连接断开、Runtime 停止和暂停显示分别表达。保留上次成功结果时必须明确标记其执行时间和旧状态。
- 首版提供执行生命周期和完成后的公开输出，不承诺逐节点实时进度；阶段进度若需要，另行定义公开事件契约，不采集任意内部节点数据或伪造百分比。

### 6.3 图片与文件生命周期

- JSON/文本使用有界结构化快照；大图和文件正文通过 HTTP 资源读取，不在 WebSocket 或数据库 JSON 中传输。
- 已保存图片可通过受控资源映射复用，避免重复保存；校验文件身份及访问权限，不将任意绝对路径开放为下载接口。
- LocalBuffer 或其他临时图像只能在租约有效时完成必要的物化/交付；不得先释放再异步尝试读取，也不得因慢浏览器无限延长 Worker 数据面租约。
- 显示图可降采样，原图独立读取；明确尺寸/缩放关系，不影响算法精度、结果值或空间关联。
- 文件已删除、身份变化、快照过期时返回明确不可用；不能自动读取同目录最新文件代替原引用。
- 最新快照、正在读取的资源和替换后的资源必须有确定的所有者、引用释放和容量上限。owned 显示资源的回收不能删除生产 Save 文件或其他 App 资产。
- Runtime 删除、显示停用、服务重启和异常中断均需回收或标明失效；资源文件恢复清理只处理专属范围，不恢复旧共享内存句柄。

### 6.4 性能边界

复用现有有界事件分发与慢客户端策略；慢显示可以错过中间显示更新，但不能丢弃、合并或抑制业务调用。多个页面不重复生成相同显示资源，不为每个客户端保留全历史。

默认最新结果，不依赖 full record；保留内存/文件的数量、字节和生命周期边界。页面卸载释放订阅、Object URL、观察器和事件监听。服务重启后无快照则显示尚无结果，不重跑业务。

显示资源转换失败不能改写业务成功/失败或破坏原响应；必须可诊断，不无限重试。图片编码和数据复制仍有必要成本，不能声称开启显示零开销，也不能把工作塞入无界后台队列来隐藏耗时。

容量默认值和可接受的时延变化须在阶段 0/4 实测后明确记录。无浏览器、多个浏览器、慢网络和启停显示均需进行相同输入的对照，不以短测声称长期工业认证。

### 6.5 有界快照与本次结果关联

采用“有界不可变快照集合 + latest 指针”，不只保留一个可变 latest 对象。这样手动调用 A 与外部 Trigger 调用 B 可以按执行 ID 分别关联；超过保留范围的 A 明确失效，不以 B 替代。固定查看不意味着无限保留资源或延长 LocalBuffer 租约，快照也不默认成为数据库永久执行历史。

| 字段草案 | 含义 |
| --- | --- |
| `format_id`、`snapshot_id` | 版本化快照格式与不可变快照身份 |
| `stream_epoch`、`sequence` | 显示流身份及该流内单调顺序；backend 重建显示流后更换 epoch，不能用新旧流的裸序号比较 |
| `workflow_runtime_id`、`workflow_runtime_revision_id`、`runtime_generation` | 实际 Runtime 执行来源 |
| `workflow_app_version_id`、`workflow_run_id` | 实际 App 发布版本与本次执行身份 |
| `completed_at`、`workflow_state` | 完成时间和 Workflow 终态，不代替业务合格字段 |
| `outputs` | 按公开 binding 交付的结果与受控资源引用 |
| `error`、`display_errors` | 业务执行错误与显示交付错误分开，显示失败不覆盖业务结果 |

实时显示以当前流中服务端确认发布的最新完成快照为准，不按客户端到达时间或文件名猜测顺序。图片、JSON、文本按同一快照切换；迟到的图片加载回调不能覆盖新快照。图片资源必须定位具体内容，不能使用会被覆盖的 `latest.jpg` 作为不可变身份。

手动 HTTP 结果与显示快照需要明确关联标识；快照标识通过可选响应元数据交付，采用响应头还是既有元数据扩展在实现阶段冻结，不为此改变 SDK 业务响应包装。没有显示快照或已经过期时明确显示不可用，不把 Runtime latest 当作本次请求结果。

none 模式下手动调用优先复用既有 HTTP 同步 invoke；浏览器异步等待 HTTP 不等于创建持久化异步 WorkflowRun。实时监视使用本节有界显示快照，不为了页面显示修改 none 为 minimal/full。长任务如需其他交互，必须明确选择既有异步能力及其保留语义，不默认依赖历史 Run 查询。

### 6.6 REST、显示流与执行接口草案

以下路径是待实现草案。界面管理路由统一使用 `/api/v1/workflows` 前缀，表中省略该前缀；不得据此宣称当前 OpenAPI 已提供这些接口。

| 方法与相对路径 | 职责 |
| --- | --- |
| `GET /views`、`POST /views` | 列表与创建界面草稿 |
| `GET /views/{id}` | 读取界面及草稿 |
| `PUT /views/{id}/draft` | 携带 `expected_draft_revision` 保存，冲突不自动覆盖 |
| `POST /views/{id}/validate` | 校验文档，不保存、不执行；结果关联被校验的修订/指纹 |
| `POST /views/{id}/publish` | 发布明确的已保存草稿修订，不应用到入口 |
| `GET /views/{id}/versions` | 分页列出界面版本 |
| `GET /views/{id}/versions/{version_id}` | 获取不可变界面版本 |
| `GET /view-entries`、`POST /view-entries` | 列表与创建运行入口 |
| `GET /view-entries/{id}`、`PUT /view-entries/{id}` | 读取或带 `expected_config_revision` 更新配置 |
| `GET /view-entries/{id}/context` | 只读运行上下文；不创建永久浏览器会话，不调用 Runtime |

校验问题至少包含 `code`、`severity`、`component_id`、`field_path`、`message`，用于定位组件而非仅显示笼统错误。运行上下文返回入口配置修订、固定界面版本、Runtime 身份/状态、兼容结论、显示交付状态和主体允许操作；前端不能以自己构造的 allowed actions 代替后端授权。

Runtime 显示接口分别负责读取/明确更新显示配置、读取 latest、按 `snapshot_id` 读取保留范围内的快照、受控资源下载和一条显示事件流。精确路径与返回 Schema 在实现阶段冻结；沿用 `/ws/v1` 骨架，一条连接订阅一个资源流，控制走 REST、大图不走 WebSocket，不新增连接内执行/启停/发布命令。

试运行与生产手动执行继续复用已经存在的：

- `POST /api/v1/workflows/app-runtimes/{id}/invoke`
- `POST /api/v1/workflows/app-runtimes/{id}/invoke/upload`

使用公开 `app-result`，不默认 debug，不引入界面专用执行引擎或新的结果包装层。当前 invoke 使用 `workflows:write`，操作员调用授权需要按第 6.7 节补齐，不能把当前权限粒度说成已满足隔离。

拟为上述 HTTP 调用增加可选 revision 前置条件，例如请求头 `X-AMVision-Expected-Runtime-Revision`。JSON 与 multipart 使用同一语义，在既有调用边界真正执行前核对；不一致返回明确冲突且不执行，一致正常调用，未提供则保持既有语义。不排队、不自动重试、不强制修改 ZeroMQ/共享内存协议。被拒绝请求产生的上传/临时资源仍按既有所有权清理。

该请求头尚未实现，最终名称与错误码待冻结。现有请求解析支持顶层公开输入，不能直接把未声明的控制字段塞进 JSON 顶层，否则可能被当成 binding；此行为在 JSON/multipart 与 SDK 回归中必须核对。

### 6.7 权限与配置边界

服务端至少区分以下能力，并结合 Project 和实际目标资源授权：

- 查看界面和结果。
- 调用指定 Runtime。
- 编辑、发布界面。
- 管理运行入口和显示交付配置。
- 修改 Workflow、管理 Runtime/Trigger。

具体 scope 名称与既有授权兼容方案在实现阶段冻结，不新增通用权限平台。只读入口、隐藏按钮和全屏模式都不是安全边界；不把管理 token 放入生产页面地址。实际调用仍校验 Runtime 权限，不因为某界面声明 interactive 就授予写权限。

## 7. 生产检测与监视维护组合

生产 App 可保持既有高性能调用和 Save 节点；目录 Trigger 调用另一个普通监视/维护 App，后者读取结果、清理文件并通过自己的公开输出供运行界面显示。每个页面仍连接一个 Runtime，不在页面合并两个 Runtime 的数据。

推荐读取一份在图片保存完成后发布的结果 JSON，由其中的执行/业务标识和图片引用定位同次结果。独立选择“最新图片”和“最新 JSON”不能证明同次执行。该组合使用通用保存、读取、JSON、绘制和维护节点，不新增场景专用节点。

目录 Trigger 的间隔、样本边界和重启语义沿用[现有实施基线](directory-watch-trigger-implementation.md)。它是变化通知，不保证每张图逐条处理；默认 3 秒触发带来相应显示延迟。监视 App 的执行状态不等于生产 App 的逐节点过程。独立 Worker 仍共享磁盘、CPU、内存等物理资源，需要竞争负载测试。

平台不新增 Save 目录与监控目录重叠判断，也不因 Runtime 忙而跳过正常目录触发。读取结果的入口是否使用 request_json 由 Workflow 决定，该输入仍可选。

## 8. Workflow JSON 导入导出

### 8.1 文档范围

导出单个 Workflow 的 Application、Template、公开 binding、节点参数、连线、图布局、分组、说明和依赖声明。复用当前文档格式，最外层交换容器若新增必须有明确 format_id；不复制另一套节点执行 Schema。

不默认导出 Preview 原始数据、临时上传文件、运行句柄或完整模型 bytes。示例输入若提供，必须明确选择、标记并单独处理敏感数据。公开默认值和内部节点参数属于 Workflow 文档，但凭据按敏感字段规则处理，不能因其位于参数中就明文导出。

### 8.2 编辑交互

- 工具栏提供导出/导入，支持文件选择和拖入 JSON。
- 区分导出当前编辑文档与指定发布版本，不以未保存草稿冒充运行态版本。
- 导入可创建新 App，或明确替换当前编辑草稿；脏草稿确认后处理，不覆盖已发布版本。
- 校验格式、版本、节点/端口、参数、binding、资源依赖；缺失节点不能静默删去或用同名节点替换。
- 导入不发布、不选择 Runtime 版本、不运行节点。缺失能力先给出诊断，不伪装为可运行。
- ComfyUI 风格指打开/拖入/导出体验，不等于原生 ComfyUI JSON 或节点可直接运行；转换器不属于首版。
- 图片中嵌入 Workflow 元数据可后续评估，首版 JSON 往返不依赖图片容器。

往返比较区分执行语义与编辑数据：参数的缺省/null/false/0、绑定键、边、说明和布局都必须保留；仅在明确“导入为新 App”时映射根资源身份。

## 9. 完整 App 包

### 9.1 包结构草案

```text
app-package.zip
├─ manifest.json
├─ workflow/          草稿及所选不可变发布快照
├─ runtimes/          各 Runtime 配置、显示交付配置、版本引用和角色映射
├─ triggers/          各 Trigger 协议配置和输入输出映射
├─ views/             界面文档、所选界面版本、运行入口、主题和静态资源
├─ dependencies/      依赖清单、模型文件、节点包、组件资产
└─ site-bindings.json 目标环境需要确认的目录、端口、地址、资源映射
```

路径只是草案，实施时定义大小写、规范化路径和 manifest 条目规则。包内使用包局部稳定引用标识关联资源，不把 runtime-01 这样的包内角色误作真实 Runtime ID。

manifest 至少定义包格式版本、包身份、来源 App/Project、导出选择范围、各资源引用及版本、文件长度/校验和、平台/组件要求、已包含资产、外部依赖和待填现场配置。明确区分包格式版本、Workflow 发布版本、界面版本和依赖实现版本。

### 9.2 一致导出范围

默认以一个 App 为根，包含选中的 Runtime、其绑定 Trigger、相关界面及必要依赖。提供完整当前配置的选择，不能通过不完整分页静默漏掉 Runtime 或 Trigger。

包固定当前草稿和所选 Runtime 实际引用的发布版本，不自动使用最新发布版。active/desired 版本不同的配置必须分别表达，不能在导出时悄悄选择或启动 desired。多个 Runtime 使用不同版本时包含其依赖并集；历史版本可以显式增加，不默认无限打包。

界面独立发布并由包固定所选版本，同时保存运行入口与 Runtime 的准确对应、显示交付配置和组件/主题资产依赖。运行中的采集结果、表单现场值和最近快照不变成发布依赖；浏览器暂停状态、选中组件、访问令牌和试运行临时快照不打包。

导出先在短事务/一致文档读取边界固定引用及草稿内容，然后复制不可变资产。并发编辑、选版、删除或界面发布不能产生混合文档；检测到选择范围变化时使用明确一致快照或失败重试提示，不长期锁住生产调用等待压缩完成。

### 9.3 依赖完整性

现有发布清单记录直接资源引用，不能据此宣称完整可迁移。需要按明确资源类型解析传递依赖：Workflow → 模型部署实例 → 模型产物/文件/标签与运行要求；界面 → 组件版本 → 主题/字体/图片。Custom Node 依赖也必须有受控声明，不能只扫描字段后缀、任意字符串或整个磁盘猜测依赖。

- 包内携带实际必需资产，或明确声明目标环境依赖；不完整包不能标成无需补充资源的完整离线包。
- 相同不可变模型文件可按校验信息去重；实例数量、资源角色和参数不可合并，尤其保持双实例同步推理配置。
- 模型文件、规则和模板图像可以纳入依赖；配置中的监控/输出目录不意味着该目录的全部生产数据都是资产。
- 共享依赖可匹配复用；不自动覆盖其他 App 使用的模型、节点包或组件包。
- 包不包含整个 SQLite 数据库、所有项目账号、系统 Python/conda、GPU 驱动或平台安装目录。平台/64-bit/运行库要求列入 manifest，沿用源码 conda 与同目录发行 Python 边界。
- 普通包不保存明文密钥、token、模型服务凭据，保留敏感引用和待补配置；密钥迁移若需要，须另行定义受控加密方案，不借本文自动实现。
- 自定义可执行节点/组件携带内容与允许安装是两件事；哈希只证明完整性，不证明信任。缺失代码不通过导入自动执行 pip、构建脚本或任意 JavaScript。
- TensorRT 等运行产物须校验目标平台、运行库和硬件兼容性；不得自动换后端、重转模型或将不匹配资产当作兼容。

### 9.4 不打包的执行状态

不打包 PID、Worker epoch、GPU 内存、mmap、LocalBuffer lease、锁、socket、待执行任务、重试队列、幂等缓存、未提交目录窗口或 Preview 缓存。历史运行记录、生产保存图片/JSON 默认不包含，需要历史数据迁移时另定范围，不混入应用恢复。

## 10. 上传恢复与迁移

### 10.1 统一步骤

1. 上传到本次操作的 staging，流式计算长度和 checksum。
2. 校验包格式、文件清单、路径、容量、依赖及平台兼容性；尚不运行包内代码。
3. 展示恢复计划：新建/复用/冲突/缺失资源、版本关系、现场映射、敏感待填项和部署实例数量。
4. 明确选择导入为新 App 或恢复原 App，确认目录、地址、端口、设备和资源映射。
5. 按依赖顺序写入资产与声明，经校验形成不可变版本，再创建停止态 Runtime、禁用态 Trigger、界面版本及其运行入口，恢复显示配置的对应关系。
6. 回读并核对引用、checksum、公开契约、入口/显示配置与 SDK 配置，输出完整或待补状态；不能把未完成恢复标记为可运行。入口可以打开显示配置状态，不能因为打开页面而启动或执行。
7. 用户明确启动、启用后才允许执行；测试调用也必须独立确认，不能因恢复验收自动执行删除或保存节点。

### 10.2 身份和版本

| 操作 | 处理 |
| --- | --- |
| 导入为新 App | 新 App/Graph 使用同一组 14 位时间标识；Runtime 由平台生成 UUID；按引用表映射 Trigger、界面和依赖 |
| 恢复原 App | 身份可用时保留 ID；冲突先报告，只有明确处理停止态目标后才允许替换 |
| 快照内容未改变 | 保留原不可变内容与来源校验信息，并校验目标实际依赖 |
| ID/路径/模型引用重映射改变文档 | 保留来源信息，创建导入派生版本和新指纹，不修改原快照冒充原版本 |
| Runtime 恢复 | 重建 Worker/通信身份，不复制原 PID、epoch 或活动 Run；同机替换遵守既有 generation 防迟到回调规则 |

只在明确声明的资源引用和路径字段上做映射。普通文本、任意 JSON、动态路径表达式不全局替换、不猜测。输出和监控目录原样保留或显式映射；不新增目录重叠防呆策略。

Trigger 命名沿用项目标准：`zeromq-<workflow-runtime-id>`、`local-shared-memory-<workflow-runtime-id>`；多个 directory-watch 使用其既有唯一命名规则，不强行合成一个 Trigger。端口/地址冲突报告后明确配置，不静默换端口。

恢复后 Runtime 停止、Trigger 禁用。目录 Trigger 启用后重新建立当前观察基线，不回放恢复前事件、不为了处理旧文件额外触发一次 Workflow。

### 10.3 SDK 配置

按目标环境实际 Runtime、Trigger 和调用地址重新生成，不沿用来源机器 endpoint。单 Runtime 使用 `config_<app-id>.json`；多个 Runtime 使用 `config_<app-id>_runtime-01.json` 等，已有 01–08 示例不是新增数量限制。

包内保存 Runtime 角色与配置文件的明确对应，恢复不能按新 UUID 排序交换编号和目标。SDK 仍按 HTTP 与高性能 Trigger 各自能力支持输入，接口和响应包装不因恢复改变。账号凭据在目标环境配置，不明文嵌入包。

### 10.4 原子性、安全和容量

- 上传、哈希、压缩、解压和模型资产复制采用流式处理；不能整个 ZIP 或模型加载为 bytes。
- 校验绝对路径、路径穿越、链接/重解析点、重复条目、大小写冲突及解压后容量/文件数量；文件只能落在验证后的本次 staging/正式资源范围。
- 使用现有 Repository/Unit of Work、短事务和可恢复操作记录组织数据库与文件；恢复中断不能留下已经启用的半成品。
- 重试同一导入操作不得重复创建资源。失败只回收本次新建且无其他引用的资源，不删除预先存在的共享依赖。
- 更新同名共享扩展须显式说明受影响 App，不自动安装、升级或降级；不匹配时保持诊断状态。
- 导入授权按 Project 与资源写权限校验，包中原作者/账号只作来源，不恢复来源系统权限。
- 取消、磁盘不足、进程中断和并发导入需可诊断、可清理；清理只操作确认无任务使用的精确临时目录。

## 11. 语言模型生成界面

### 11.1 创作期输入与输出

生成上下文默认只包含公开输入输出契约、组件目录及 Schema、主题/布局规则、当前界面文档、用户提示和经确认的示例数据。模型 provider 可本地或远程，接口在创作服务边界封装；不要求在现场运行节点图中新增模型调用。

默认不发送 Workflow 内部图、生产图片、密钥、完整执行日志或其他 App 数据。远程模型和额外示例数据的使用必须明确；未配置模型时人工编辑与已发布运行页保持可用。

模型输出完整界面文档或对固定草稿版本的修改。生成开始固定草稿版本/指纹；返回时发生人工编辑则报告冲突，不能覆盖新草稿。保留稳定组件身份以便审查差异，不把整页重建当作无差别补丁。

### 11.2 校验和发布

依次校验文档格式、组件存在性/版本、属性类型、公开绑定、JSON 写入冲突、动作权限、静态资源、节点数量和布局嵌套边界。未知组件或虚构数据字段直接提示，不能静默替换。Schema 合法不代表业务显示正确，必须提供预览和差异确认。

生成只更新草稿；不自动发布、不运行测试、不修改 Workflow、不更换 Runtime、不启用 Trigger，也不扩大公开输入。生成服务失败或超时不影响生产执行。

主题调整、布局和既有组件组合可通过文档完成。全新交互组件允许开发者用 AI 辅助生成源码，但仍走代码审查、测试、静态构建和组件注册，不在运行浏览器执行未经审核的生成代码。

### 11.3 恢复与复现

包保存最终发布文档、资源、组件版本及必要来源信息。提示词、provider、模型标识等仅作可选来源记录，不代替产物，不保存密钥或无界生成日志。恢复不重新调用模型，不要求来源模型账号或网络可用。

受组件目录约束的 Generative UI 是参考方向，不是已选第三方库。依赖是否采用须验证 Vue 3、离线、绑定边界、文档往返、资源控制和维护成本，不整体引入任意 action、watcher 或计算表达式能力。

## 12. 模块、迁移与实施阶段

### 模块分工

- contracts：界面文档/版本/入口、组件声明、显示配置/快照、Workflow 交换容器和 App manifest 的版本化 Schema。
- application：界面草稿/发布/入口应用/兼容校验、统一结果交付、依赖解析、导出/恢复计划、生成草稿服务；职责拆分但仍属于模块化单体。
- infrastructure：ObjectStore streaming、owned 资源回收、包 staging、受控扩展资产及数据库持久化；不把 OS 细节写入领域模型。
- API：REST CRUD/发布/上传下载/恢复计划，WebSocket 增量通知；权限及错误由服务端统一定义。
- frontend：独立运行页、文档渲染、组件 registry、设计器、导入导出/恢复向导及模型生成入口，沿用 Vue 3。
- SDK：恢复后的配置生成及既有调用回归，不创建专属界面调用协议。

这些是职责规划，不要求每项新建一个进程或微服务。正式目录与 endpoint 在对应阶段确定，复用现有边界优先。

### 数据迁移

新增界面、界面版本、运行入口、显示配置、导入操作及资源关联等持久结构时附带 Alembic 和 Repository 实现，验证 SQLite、MySQL/PostgreSQL 兼容性。草稿/入口修订与 Runtime generation 分离，显示快照不默认转为永久执行历史。默认记录模式和已有 App/Runtime/Trigger 数据保持原状，不自动创建界面、启用显示或改写历史快照。

格式版本未知或无法迁移时明确拒绝；需要转换的旧文档通过显式转换生成新内容，保留来源，不在热路径长期维护隐藏双读。现有已发布 App 的公开输入输出、Runtime/Trigger ID 及调用方式不因增加界面强制改变。

### 阶段门禁

| 阶段 | 实现内容 | 完成后核对与放行条件 |
| --- | --- | --- |
| 0 | 现有契约/依赖/图片释放审计，冻结新增文档 Schema、恢复模式和显示容量预算 | 明确当前缺口；用同数据建立耗时、内存、句柄基线；不提前标记功能完成 |
| 1 | Workflow JSON 导入导出 | 图、binding、值语义和编辑数据往返一致；不修改运行中发布版本 |
| 2 | App manifest、一致导出、依赖解析、上传预检及恢复 | 双实例、多 Runtime/Trigger、版本映射、失败回收、SDK 配置正确；默认停止态恢复 |
| 3 | 界面资源独立版本、运行入口、契约绑定、基础 Vue 渲染 | 保存/发布/入口应用分离；修订冲突明确；只公开输入输出；外观发布不改变 Workflow 指纹或 Runtime generation |
| 4 | 统一显示交付、REST/WS、图片生命周期、调用授权及可选 HTTP revision 前置条件 | none 保持不变；本次结果不串线；过期请求拒绝；流重建/迟到/断线/慢端/资源过期验证通过 |
| 5 | 有限布局设计器、预览/试运行/生产页、主题和组件变体，界面与入口纳入完整 App 包 | 第 5 节操作表和状态转换逐项验收；不同外观共用相同协议；包在隔离环境恢复界面、入口、显示配置和资源 |
| 6 | 模型生成同一界面草稿 | AI/人工往返、虚构字段拒绝、草稿冲突、预览确认、模型离线和包恢复验证 |
| 7 | 源码与同目录发行环境端到端及长时间负载 | 实际图片/JSON/文件、模型推理、Runtime/Trigger/SDK、包恢复、前端状态和资源曲线核对 |

阶段 2 先支持已存在的应用资源，并预留界面依赖类型；阶段 5 未完成前，不能声称“含运行界面的完整应用包”已经验收。每阶段先检查实现与本基线，再执行最小验证和链路审计；有偏差先处理，不以串联功能数量代替正确性。

## 13. 验收矩阵

| 范围 | 必测项目 |
| --- | --- |
| 公开输入 | 仅图片、图片+JSON、纯 JSON/text、file/files 组合；可选省略；null/false/0/空值；未知 binding；字段冲突；权限与类型不匹配 |

| 试运行 | 固定草稿/输入/Runtime revision/run；不自动启动或切版；真实副作用明确；网络结果未知不重发；外观修改不强制真实执行 |

实际数据验证采用“生产检测保存结果 → 目录 Trigger → 监视维护 App → 公开输出 → 运行页”，以及直接观测选定 Runtime 的对照。测试资源应独立创建或经明确选择，不能为验证而隐式运行真实目录清理。

同步双模型部署在既有合理双分支负载下保持正确，不新增业务排队补偿。性能对比用相同输入和受控环境，区分模型、输入、编码、传输和渲染成本；记录结果正确率与完整性，不能仅比较平均耗时。长测未完成或资源增长未归因时明确保留限制，不宣称工业认证。

本任务阶段测试缓存统一位于 `.tmp/<task-name>`；确认本次进程停止后清理精确目录，不删除其他任务使用的 `.tmp` 内容。长期结论进入稳定专题或可重复测试，不把临时证据目录作为文档交付。

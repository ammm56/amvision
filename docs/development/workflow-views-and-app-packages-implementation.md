# amvar app 应用、运行界面与打包恢复实施基线

## 1. 状态、职责与阅读规则

状态：设计已接受，新增能力待实现。依据 [ADR-0012](../decisions/ADR-0012-workflow-views-and-app-packages.md)，本文是 amvar app 应用组成、运行界面、Workflow JSON 导入导出、应用下载上传恢复及语言模型生成界面的唯一详细实施基线。本文写入不代表完成代码、数据迁移、浏览器验收或现场认证。

当前代码仍是已实现行为的事实来源。以下资源名、包目录和消息字段是设计草案，不是已经注册的公开 endpoint 或完整 JSON Schema。实施时必须同步冻结版本化契约、迁移和测试，不能把示意直接当成可调用接口。

本文同时作为设计器与生产显示的共同约束：第 3 节定稿应用组成清单、命名数据源、运行入口映射三个模型的语义，第 5 节定义页面操作与状态转换，第 6 节定义显示快照、接口草案和权限，第 13 节定义对应验收。模型关系和页面操作边界已经确定；字段的完整 Schema、路由、容量和错误码仍须按第 14 节完成实现前核对。

优先级：长期稳定和结果正确优先，其次是高性能；实现保持简单、明确、通用，不增加隐藏执行、隐式默认值、业务重试或同步等待队列。

## 2. 已确认的不变量

1. 采用方案 A：运行界面绑定 Workflow App 公开输入输出，不绑定内部节点参数、节点位置或 Preview 私有数据。
2. amvar app 是多个 Workflow/Runtime/Trigger 与运行界面的组成资源；一个页面允许显示多个命名 Runtime 数据源。组成和显示不是新的执行引擎，也不要求将独立 Workflow 合成一个图。
3. 内部节点参数、连线和业务算法只在 Workflow 编辑画布修改，随后按既有发布、选版规则生效。
4. 界面仅选择现有 App Entry 输入。`request_json` 字段由表单组成，不因此新增公开 binding 或修改 Workflow。
5. 可选输入保持可选；缺省、null、false、0、空字符串、空数组、空对象不能相互替换。
6. 界面只承担输入、明确目标的调用、多来源展示和显示格式化；业务数据合并、ROI/模型结果关联、规则判定及业务统计留在 Workflow，不在页面隐藏编排。
7. 界面、主题及组件资产独立版本管理，不进入 Workflow 内容指纹；仅修改外观不重启 Runtime、不修改 Trigger。
8. 打包按明确选择的成员和依赖固定交付组合，不要求多个 Workflow、界面和所有组件使用相同版本号，不新增强制同步发布的应用总版本。
9. 页面打开、刷新、重连、设计预览和暂停显示不执行 Workflow，也不启停 Runtime/Trigger。
10. 显示从统一 Runtime 结果边界获取，不依赖调用协议或 Trigger 回传字段；现有 SDK/Trigger 响应结构不变。
11. 显示采集显式启用，不自动开启 full record 或全节点 trace；不改变原有同步 admission、异步任务和 Trigger 合并语义。
12. 模型只参与界面创作；生成进入草稿并经校验、预览、确认后发布。已发布界面可在模型离线时运行。
13. Workflow JSON 与完整 App 包共用现有文档语义；完整包不是数据库备份、进程检查点或平台发行包。
14. 导入不自动执行节点、安装代码、启动 Runtime、启用 Trigger 或回放历史事件。
15. 任何容量默认值、性能结论或稳定性认证必须来自实测，不以架构解耦替代验证。
16. 保存草稿、发布界面、应用到运行入口、启用显示交付是不同动作，不能互相隐式触发。
17. 设计预览不执行；试运行复用正常 Runtime 调用，真实节点副作用、资源占用和调用规则不变。
18. 本次手动调用结果按执行 ID 固定，不能被外部 Trigger 的最新结果覆盖；暂停显示不暂停业务执行。
19. 现有 Workflow App、Graph、Runtime、Trigger、API、SDK、变量和 ID 命名保持不变；仅前端系统文案把原 Workflow 的“应用”显示为“工作流”，新 amvar app 显示为“应用”。
20. 来源以稳定 `source_id`、公开 binding 和字段路径关联，运行入口将来源明确映射到 Runtime；同名字段、列表顺序、显示名称和更新时间不参与隐式关联。

## 3. 资源关系与独立版本

```text
amvar app（前端：应用）
├─ Workflow App A --发布--> App Version A --选版--> Runtime A <-- Trigger A
├─ Workflow App B --发布--> App Version B --选版--> Runtime B <-- Trigger B
└─ 运行界面草稿 --独立发布--> 界面版本（命名数据源、公开绑定、组件/主题）
                                  ↓ 显式应用
                            运行入口（source_id → Runtime）
                                  ↓ 加载
                            一个多来源生产运行页面

应用组成清单管理成员；各 Workflow、Runtime、Trigger 仍保持原有生命周期。
显示交付配置归属各 Runtime；应用包固定所选组成、文档、版本、配置和依赖。
```

### 3.1 命名与前端显示边界

完整应用统一称为 **amvar app**，前端导航和页面简称“应用”。既有 Workflow App 在前端系统文案中称为“工作流”，技术资源身份不改名。两者不是同一个 `application_id`，不能通过修改旧字段含义实现应用聚合。

| 现有前端文案/范围 | 中文目标 | 英文目标 | 日语目标 | 韩语目标 |
| --- | --- | --- | --- | --- |
| 图编辑导航 | 工作流编辑 | Workflow Editor | ワークフロー編集 | 워크플로 편집 |
| Workflow 新建操作 | 新建工作流 | New Workflow | ワークフローを新規作成 | 새 워크플로 |
| 原应用导航/标题 | 工作流 | Workflows | ワークフロー | 워크플로 |
| 原应用列表 | 工作流列表 | Workflow List | ワークフロー一覧 | 워크플로 목록 |
| 新 amvar app 导航/标题 | 应用 | Apps | アプリ | 앱 |
| 新 amvar app 新建/列表 | 新建应用 / 应用列表 | New App / App List | アプリを新規作成 / アプリ一覧 | 새 앱 / 앱 목록 |

沿用现有四语言切换，只修改指代 Workflow 的系统显示文案，包括标题、按钮、空状态、删除确认、版本/Runtime/Trigger 关联选择和说明。中文的“应用到入口”等动词、其他业务中的“应用”不全局替换；用户自定义名称、节点名称、原始业务结果和已有数据不改写。

`navigation.workflowGraph`、`navigation.workflowApps`、`workflowEditor.applications` 等翻译键、`WorkflowAppListPage` 等组件/变量、`/workflows/graph`、`/workflows/apps` 路径、公开 API、数据库、SDK 和资源 ID 均保持原状。新应用功能使用独立键、资源和管理入口，不占用旧 Workflow 路径。现有 App Entry 节点及发布版本仍是原概念；本次显示名称调整不造成数据迁移或重新发布。

新导航“应用”管理 amvar app；应用详情内管理组成、运行界面设计/版本、运行入口和下载恢复。首版围绕一个主生产页面，不额外建立与应用并列的另一套“运行界面”顶层资源入口。工作流编辑与界面设计仍是两个不同画布，不能在生产页修改任何画布。

运行界面和入口归属 amvar app，不再归属单个 Workflow App。一个界面版本声明多个命名数据源，入口将这些来源映射到实际 Runtime；控件不硬编码 Runtime，不保存 Worker 对象。一个界面可通过不同入口用于测试和现场映射，入口不是新的 Runtime、执行器或常驻进程。入口有稳定访问地址，鉴权后返回原入口；地址不包含凭据。

界面版本不可变；修改生成新版本，明确发布与回退。设计草稿修改不改变已打开的生产界面；页面切换界面版本必须整体更新，不能混用新布局与旧绑定。已有输入草稿不得因后台发布自动丢失或提交。

### 3.2 契约兼容

- 每个数据源以明确选择的 Workflow 及已发布 App Version 契约为依据，不要求 Runtime 已启动。生产运行逐来源使用映射 Runtime 当前激活版本的公开 contract，不使用最新草稿或仅凭最新发布序号判断。
- 停止态入口配置可按 Runtime 已选择的目标版本预检，但必须标为待启动核对；desired version 不能当成已经激活的版本。
- 按界面实际使用的 binding、方向、payload type、Schema 和字段路径校验；不拿完整 Workflow 内容指纹相等当作界面兼容条件。
- 内部节点替换且所用契约兼容，界面可继续使用；新增未使用输出不应直接导致整个界面失效。
- 删除所用输出、改变类型或收紧输入规则时明确报告；不自动修复 binding、不替换同名字段、不切 Runtime 版本。
- 任意 JSON 的深层字段若没有 Schema，发布时只能证明外层 binding 有效，不能伪造深层类型保证。执行时字段不存在或类型不符，显示绑定错误，不填 0 或成功状态。
- Runtime 切版、generation 改变或页面重连后校验并切换数据来源；旧结果不能覆盖新实例状态。
- 兼容信息应在加载、发布和实例切换时构建缓存，不在每次生产调用中扫描完整图、数据库或组件目录。
- 兼容报告按 `source_id` 定位受影响组件和动作；某来源停止、不兼容或失去权限不应使其他来源失效。页面可显示“部分不可用”，不能伪造一个所有 Runtime 共同的执行状态。

### 3.4 最小资源字段

以下语义作为三个模型的共同约束，完整字段类型和公开 Schema 在实现前核对。新增 amvar app、界面、界面版本、运行入口及组成关系，并为既有 Runtime 增加显示交付配置；不新增试运行任务系统、应用执行器或永久浏览器会话记录。

| 资源 | 字段草案 | 归属与约束 |
| --- | --- | --- |
| AmvarApp | `amvar_app_id`、`project_id`、`display_name`、`description`、`config_revision`、`composition`、可空的 `default_workflow_view_entry_id`、创建/修改时间与主体 | 完整应用组成；独立身份，旧 `application_id` 仍只指 Workflow App |
| WorkflowView | `workflow_view_id`、`project_id`、`amvar_app_id`、`display_name`、`description`、`draft_revision`、`draft_document`、`draft_fingerprint`、创建/修改时间与主体 | 可修改草稿；不在此修改成员 Workflow |
| WorkflowViewVersion | `workflow_view_version_id`、`workflow_view_id`、`version_number`、`source_draft_revision`、`document`、`document_fingerprint`、按来源组织的 `binding_requirements`、`dependency_manifest`、创建时间与主体 | 不可变；契约需求和依赖由服务端从文档推导，不相信客户端自报兼容 |
| WorkflowViewEntry | `workflow_view_entry_id`、`project_id`、`amvar_app_id`、`display_name`、`workflow_view_version_id`、`source_bindings`、`interaction_mode`、`config_revision`、`display_options` | 一个入口固定一个界面版本和多个命名 Runtime 映射；使用修订号检查 |
| Runtime 显示交付配置 | `enabled`、`config_revision`、`output_binding_ids`、图片交付选项、快照/资源数量与字节及生命周期限制 | 每个 Runtime 一份；不为各页面重复生成同一显示资源，默认值实测后冻结 |

`draft_document` 包含 `format_id`、`sources`、`components`、`actions`、`layout`、`theme`、`assets`。`sources` 按第 3.6 节声明每个来源的设计依据，不再有整页单一 `basis_app_version_id`。组件声明稳定 `component_id`、类型/版本、属性及明确绑定。设计依据与 Runtime 实际版本按第 3.2 节校验，不要求版本 ID 相同才兼容。

`interaction_mode` 首版限定为 `monitor` 与 `interactive`：前者不提供页面调用操作，后者可提供公开输入及执行操作。模式不是权限凭据，服务端仍按主体与目标 Runtime 校验调用权限。`display_options` 只保存语言、全屏等显示选择，不隐藏业务参数或启停动作。

界面 `version_number`、草稿 `draft_revision`、应用/入口/显示配置各自的 `config_revision` 和 Runtime generation 各司其职，不共用计数器。最近结果、访问令牌、现场表单、选中组件、暂停状态和 Worker 句柄不写入发布文档。

### 3.5 模型一：amvar app 组成清单

`composition` 明确列出 `workflow_application_ids`、`workflow_runtime_ids`、`trigger_source_ids` 三类成员集合。数组仅用于列举，不以数组位置表示角色、调用顺序或归属关系。界面和入口通过自身 `amvar_app_id` 关联，读取组成清单时一并列出，不额外保存两份可各自修改的界面/入口 ID 数组。

- 第一阶段成员属于同一 Project；完整应用不是新的租户或权限边界。创建完整应用可以从空组成开始，未配置主入口时显示未配置，不生成默认 Workflow 或 Runtime。
- Workflow、Runtime、Trigger 是引用成员，不是复制或独占所有权；同一既有资源可以被多个应用选择。加入/移除不隐式创建、删除、停止或启用资源。
- Runtime 的所属 Workflow、Trigger 的目标 Runtime 以原资源的真实引用为准，不在应用清单重复维护可冲突的归属字段。添加成员时列出所需成员，由明确选择或确认补齐，不静默导入整个 Project。
- 有效组成中 Runtime 的 Workflow 必须在清单中，Trigger 的目标 Runtime 必须在清单中；移除成员前核对界面来源、入口映射及其他成员引用，不能留下悬空引用。变更前报告依赖，明确修改引用后再提交；新应用关系不进入每次 Runtime 调用的热路径查询。
- 一个 Runtime 可以绑定多个 Trigger；成员 Runtime 不必都配置页面数据源，例如纯后台生产链路可以只进入交付包。页面也不因有 Trigger 成员而自动配置其结果为来源。
- 默认运行入口必须属于同一 amvar app；首版“打开运行页”使用这一明确入口，不从入口列表选择第一项。未指定时要求配置，不猜测。
- `config_revision` 用于组成配置的并发更新检查，不是 Workflow 发布版本。应用不新增总运行进程、总调用队列、全成员事务或强制共同发布版本。
- 删除应用不级联删除成员 Workflow、Runtime、Trigger 或共享依赖；自身界面/入口存在时先明确处理其引用，再删除空的应用资源。成员的既有独立版本和启停能力不改变。

新资源使用独立 `amvar_app_id`；其 ID 生成格式在实现阶段冻结，不能套用或复用既有 `workflow-app-*` 身份。导出选择是一次操作的选择范围，不自动改写应用日常组成。

### 3.6 模型二：命名数据源

数据源是界面文档内的声明，不是独立服务或数据库数据接入器。`sources` 是以稳定 `source_id` 为键的映射；例如 `inspection`、`maintenance` 只是可配置的通用标识，不预置行业角色。

| 来源字段 | 语义 |
| --- | --- |
| `source_id` | 即 `sources` 的键，界面内唯一；不使用翻译后的名称作为引用 |
| `display_name` | 界面中便于理解的名称，不参与绑定 |
| `application_id` | 该来源所依据的既有 Workflow App ID，必须是应用成员 |
| `basis_app_version_id` | 该 Workflow 的明确已发布契约依据，不取最新草稿 |

输入、输出和状态组件统一使用 `source_id`；公开数据绑定再包含 `binding_id`、方向和可选 `field_path`。所需契约由服务端从组件/动作推导，按来源生成 `binding_requirements`，避免维护两份独立可修改的契约。

- `inspection.request_json` 与 `maintenance.request_json` 属于不同输入空间；同名 binding 不合并，不自动广播。
- 来源与实际 Runtime 解耦；同一 Workflow 的两个 Runtime 可声明两个来源。来源名不等于 Workflow 名，也不强制等于 Runtime ID。
- 来源键在绑定后保持稳定；修改显示名称、移动控件、排序或翻译不改变关联。确需更换来源键时必须显式更新全部组件、动作及入口映射，不靠字符串全局替换。
- 一次执行动作包含稳定 `action_id` 和一个明确 `source_id`，只组装该来源允许的公开输入、调用该来源映射的 Runtime。共享控件需显式声明各动作的输入映射，不能选择一次值就调用全部来源。
- 首版不支持动作链、自动跨 Runtime 扇出、失败切备用来源、页面重试队列或任意 API 数据源。跨 Workflow 业务协作继续通过 Workflow 或既有集成协议完成。
- 无 Schema 的 JSON 字段沿用静态校验限制；命名来源不会使任意 JSON 自动获得类型保证。

### 3.7 模型三：运行入口映射

`WorkflowViewEntry` 固定一个发布界面版本和 `source_bindings` 映射。键与版本文档中的 `source_id` 完全一致，值包含既有 `workflow_runtime_id`。不将标量 Runtime ID 简单改成数组，不按 Runtime 列表顺序绑定。

以下仅示意引用结构，`<...>` 不是实际资源 ID：

```json
{
  "amvar_app_id": "<amvar-app-id>",
  "workflow_view_version_id": "<view-version-id>",
  "source_bindings": {
    "inspection": { "workflow_runtime_id": "<production-runtime-id>" },
    "maintenance": { "workflow_runtime_id": "<maintenance-runtime-id>" }
  }
}
```

- 入口与界面属于同一应用；映射 Runtime 是应用成员，所属 Workflow 必须匹配该来源的 `application_id`。不能仅因另一 Workflow 的字段同名就自动映射过去；复用界面到其他 Workflow 时显式修改来源并发布或通过导入映射生成派生版本。
- 创建/更新有效入口时校验来源键完整且没有多余键，全部 Runtime 身份明确；停止态允许配置并标记待启动核对。不配置隐藏默认 Runtime，不静默保留废弃来源映射。
- 应用界面新版本及完整映射在一次带 `expected_config_revision` 的配置更新中提交；只保证入口配置一致，不锁住或同时切换各 Runtime。
- 测试入口与生产入口可以映射到各自 Runtime；生产页不能随意换实例。设计试运行可以临时明确选择映射，但不能因此改写正式入口。
- 来源状态、契约、授权、显示快照及本次调用分别管理。某来源断开或不兼容时只影响相关组件与动作；其他来源继续使用，不实现“所有来源都就绪才运行”的屏障。
- 多个来源映射同一个 Runtime 时可复用网络订阅和资源缓存，但不合并来源身份、输入草稿或显式操作。两个动作分别点击仍是两次正常调用，不添加业务去重。
- 入口修改后旧页面固定原版本与映射并提示整体重载；不静默将正在进行的调用或未提交输入换到新 Runtime。身份和调用授权始终由后端校验。
- 入口仅保存映射，不保存 Runtime 当前版本副本、启动状态或执行数据作为权威；Runtime 切版仍由原资源流程管理，页面逐来源重新核对兼容性。

## 4. 输入与输出绑定

### 4.1 只使用 App Entry 公开输入

`request_*` 是默认 binding 名称，控件应按契约中的 binding ID、payload 和 transport 能力配置，不硬编码名称猜类型。现有默认输入与控件对应如下：

| 输入 | 控件 | 提交边界 |
| --- | --- | --- |
| request_image_ref | 图片选择/上传 | 经既有上传或 multipart 接口得到有效引用，不提交浏览器本机路径 |
| request_image_base64 | 图片选择/上传 | 明确使用现有 Base64 binding，不隐式改写为其他输入 |
| request_json | JSON 编辑器或结构化表单 | 组装同一 value 输入，服从 request_schema |
| request_text | 单行/多行文本 | 保持原始文本，不自动解析 JSON |
| request_file | 单文件选择 | 现有文件上传及引用接口 |
| request_files | 多文件选择 | 保留明确的文件顺序和多文件协议 |

普通页面通过 HTTP Runtime 调用支持所有已公开类型，不为浏览器实现本机 mmap 或 ZeroMQ。高性能 Trigger 仍只使用既有 image-ref/JSON/text 能力，不因界面增加文件或 Base64 transport。

### 4.2 request_json 表单

多个控件可分别绑定某个来源 `request_json` 中的 `recipe`、`station`、`batch_id`，提交时组装该来源的一份 JSON 对象。这些是本次输入字段，不是新 App Entry binding，不改内部节点参数。不同来源分别组装，不能因 binding 同名共用提交对象。

- 采用明确字段路径，复用项目路径语义；不能按控件排列顺序关联。
- 同一动作/来源中，同一字段多写入者、父对象与子字段冲突在设计校验中拒绝。JSON 原文编辑与结构化表单同一时刻只有一个写入来源；不同来源的同名字段不构成冲突。
- 缺省字段按缺省提交；不因为页面存在控件就提交 null、空图片、空文件或虚构默认值。
- 可选控件明确区分“本次未提供”和“提供空值”；例如未提供 request_text 与提交空字符串、未提供 station 与提交 0 不等价。图片只提交明确选择的 binding，不为另一种图片输入补空 payload。
- 显式预填值可作为界面配置展示，由实际表单提交；不隐藏注入或反向修改 Workflow default。
- 可选字段仍可省略；未消费的可选输入不要求补齐，消费节点的既有错误语义保持不变。
- 提交构造层与后端现有输入校验复用同一公开契约；前端校验不替代后端权威校验。
- 一次输入不会改变外部 Trigger 下次提交的参数。暂停显示、重连和重试资源读取不重发业务调用。

### 4.3 输出

每个显示组件使用 `source_id`、公开输出 binding ID、可选字段路径和显示配置。控件 ID 用于界面文档身份，移动控件、修改标题或节点位置不改变绑定。数组下标仅在明确数据路径中具有语义，不用节点/控件位置隐式配对数组。

允许单位、精度、文字、图标和颜色映射；合格判定、跨字段计算、ROI 与推理结果配对、业务累计和数据合并必须在 Workflow 中完成。图片叠加展示若支持原图与几何分离，必须使用同一结果中的显式来源和坐标契约，不重新推断关联。

Save Image 的 image-ref/saved_output 与 Save JSON 的保存回执不是相同类型。界面不因节点叫 Save 就自动读取其内部输入或磁盘内容；所需图片、文件或 JSON 必须成为明确公开输出，再按相应资源契约显示。现有 Preview body 可按公开类型适配，但不能访问 Preview 私有缓存。

多来源默认分区显示各自最新结果与时间，不宣称它们属于同一生产记录。生产 Workflow 与监视 Workflow 的 `workflow_run_id` 不同；需要表达同一记录时，公开输出必须显式传递原始生产执行 ID 或唯一记录键。不能按“两个最新结果”、接近的时间、文件名或可能重复的批次号猜测关联。首版不建立前端跨来源历史 join 缓存；严格联合判定或一致摘要由独立汇总 Workflow 输出，无需把所有原始 Workflow 合成一个图。

## 5. 界面文档、组件和编辑器

### 5.1 一个文档，多个创作入口

文档包含格式版本、稳定组件 ID、组件类型/版本、布局、输入输出绑定、显示属性、主题引用、本地资源引用和允许操作。运行上下文、表单现场值、访问令牌、最近结果和 Worker 句柄不混入发布文档。

人工可视化编辑、模板创建、模型生成使用同一解析器、校验器、文档和 Vue 渲染器。必须支持 AI → 人工 → AI → 导出 → 恢复的往返，不维护生成式页面和手工页面两套格式。

第一阶段不建立任意 HTML/JavaScript、页面表达式执行器或第二套流程图。界面文档支持多个命名 Runtime 来源的输入与显示，不支持任意 API 数据源、跨 Runtime 业务编排、页面定时任务或控件业务事件链。

### 5.2 组件目录

| 类别 | 首批能力 |
| --- | --- |
| 输入 | 文本、数字、枚举、布尔、JSON、图片、文件、多文件 |
| 图片 | 适应窗口、缩放、平移、原图查看；几何与缩略图坐标关系明确 |
| 结构化结果 | JSON 折叠/复制、明确列绑定的表格；大列表有界渲染 |
| 标量 | 文本、数值/单位/精度、明确值映射的状态 |
| 文件 | 已授权文件的名称、长度、下载 |
| 说明与布局 | 标题、说明、网格、分组、标签页 |
| 操作 | 按权限调用既有 Runtime 接口；不绕过公开输入契约 |

组件注册至少声明类型、版本、接受的数据类型、属性 Schema、允许动作、空值/加载/错误状态和资源依赖。复用已有 Vue 图片、JSON、表格基础组件，先审计生命周期，不复制 Preview Run 状态管理。

首版导航使用第 3.1 节的“应用”，在 amvar app 内进入界面设计、版本和可全屏运行页。设计器左侧为组件/按来源组织的公开契约，中间为布局，右侧为绑定/属性；首版提供网格、尺寸、排序、分组、标签页及主题，不先建设通用网站平台。

设计预览使用明确标记的示例数据或只读快照，不调用 Workflow。手动“执行一次”是独立显式动作，仍遵守 Runtime admission，失败不自动等待或重试。

### 5.3 主题和扩展

- 主题层负责颜色、字体、间距、背景、边框、阴影及可关闭动效；组件外观变体负责不同呈现；新交互由受控组件源码实现。
- 现代简约、科幻 HUD、像素风等均不改变 binding、错误含义或执行协议。动态背景和动效不得成为运行依赖。
- 主题作用域限制在运行界面容器，不污染平台导航、管理页和节点编辑器。
- 使用现有中文、英文、日语、韩语切换机制；固定系统状态和控件文案本地化，业务原文不自动翻译，主题不复制四套业务实现。
- 首先覆盖桌面工作站、工控机和全屏模式。窄屏按现有前端原则支持查看，移动端验收单独标注，不能由桌面测试推断。
- 字体、图片等随资产本地分发，不依赖 CDN。扩展组件经过开发审查、测试、版本发布及安装信任校验；不接受配置中任意注入脚本。

### 5.4 页面操作与副作用

“应用”详情中的运行界面管理提供设计、试运行和版本管理；生产运行页使用独立地址。工作流编辑画布修改执行逻辑，界面设计画布只修改显示文档。各页面共用受控组件和渲染器，不共用草稿编辑状态。

| 操作 | 修改对象 | 执行 Workflow | 对生产页或 Runtime 的影响 |
| --- | --- | --- | --- |
| 编辑布局、绑定、主题 | 浏览器界面草稿 | 否 | 不改变已发布界面 |
| 保存 | 服务端界面草稿 | 否 | 不发布，不改变运行入口 |
| 界面预览 | 无持久修改 | 否 | 只渲染示例或固定快照 |
| 试运行中的执行一次 | 一个动作指定来源的一次 Runtime 调用 | 是 | 真实节点副作用和资源占用不变；不执行其他来源，不修改生产界面 |
| 发布 | 新不可变界面版本 | 否 | 不修改现场入口，不启用显示 |
| 应用到运行入口 | 入口的界面版本引用与完整来源映射 | 否 | 新打开页面使用新组合；已有页面提示更新 |
| 打开生产页 | 当前浏览器显示状态 | 否 | 不启动 Runtime/Trigger，不启用显示交付 |
| 生产页执行一次 | 指定来源的本次公开输入请求 | 是 | 遵守原有 Runtime 调用规则；不广播给其他来源 |
| 暂停显示、退出 | 当前浏览器状态与资源 | 否 | 不暂停业务，不停止 Runtime/Trigger |

“界面预览”与 Workflow 编辑器 Preview Run 不是同一动作。试运行应显示明确目标并说明是真实调用；不以“预览”名称掩盖 Save、Cleanup 等副作用，也不要求每次正常调用额外确认。

### 5.5 设计页：创建、保存、校验与预览

先创建/选择 amvar app 并配置成员，再创建空白/模板/复制界面，逐个添加命名数据源，选择成员 Workflow 及其已发布 App Version。没有契约时可保存未完成布局，但不能伪造可绑定字段或发布无效来源；相应 Workflow 先按既有方式发布。打开已有界面读取服务端草稿和修订号，不直接修改发布快照。

设计器沿用第 5.2 节布局：左侧组件及按来源组织的公开输入输出、中间布局、右侧绑定/属性、顶部保存/预览/试运行/发布和草稿状态。选中组件能够定位到“来源 → Workflow 契约 → 公开 binding → 字段路径 → 接受类型”，不能只显示无法追溯来源的字符串。

保存状态与校验状态分开表达：

- 保存：`已保存 → 已修改 → 保存中 → 已保存 / 保存失败`。
- 校验：`待校验 → 校验通过 / 存在问题`。
- 已有发布版本与草稿有修改可以同时成立，不用互斥的“已发布/编辑中”状态覆盖事实。

保存携带 `expected_draft_revision`；另一个标签页或主体先保存时报告冲突，不自动覆盖或合并布局。保存失败保留浏览器修改，不把本地内容标成已持久化；首版不引入多人实时协同。

预览按来源使用明确标记的示例数据或人工选取的固定执行快照，不跟随实时结果。覆盖空结果、错误、长文本、大数组、图片缺失及一个来源不可用而其他来源正常等状态。示例与试运行数据不随界面默认发布/打包，进入和退出预览不保存、不发布、不调用。

### 5.6 试运行：固定上下文与请求状态

先保存界面草稿，再逐来源明确选择试运行 Runtime 映射。展示各来源的 Workflow、实际运行版本、名称、状态及契约兼容结论；不自动选择首个 Runtime、不启动、不切版。停止态来源可查看配置但不能执行，提供前往既有 Runtime 管理页的入口；不阻止其他可用来源试运行。

点击一个动作固定界面草稿修订/指纹、`action_id`、`source_id`、映射 Runtime ID、预期 Runtime revision 和实际提交输入，并将返回的 `workflow_run_id` 关联到此次请求。不自动执行所有来源；其他来源画面不算作本次调用的结果。输入框后续修改不改变已提交内容；结果区区分当前表单与本次提交。试运行上下文不要求永久任务表。

状态区分：尚未调用、正在提交、等待结果、Workflow 成功、Workflow 失败、明确拒绝且未执行、连接中断且结果未确认。网络错误不能证明节点没有执行；未知结果不自动重发，退出页面不隐式取消或停止 Runtime。

表单读取版本与实际执行版本之间的竞态由第 6.6 节的可选 HTTP revision 前置条件处理。检查在既有调用边界执行，不增加等待队列或自动重试。

发布必需结构与绑定校验，但不强制每次标题/颜色修改后真实调用生产 Workflow。试运行验证结论只对应被验证的草稿指纹，修改后不能沿用为当前版本已验证。业务返回不合格不等于界面验证失败。

### 5.7 发布与入口应用

发布接受已保存的明确草稿修订：服务端核对修订、校验组件/绑定/资源、固定文档与所用契约/依赖、创建不可变版本并返回身份和指纹。失败不修改旧版本或现场入口；相同内容可复用既有版本，这是发布去重，不是业务调用去重。

不存在的公开 binding、方向错误、已知类型不兼容、JSON 写入冲突、未知组件/资源和非法动作阻止发布。缺少完整 Schema 的 JSON 深层路径按第 3.2 节报告静态验证限制，不能一概禁止使用或伪造保证。

“应用到运行入口”明确选择入口、发布界面版本与完整 `source_bindings`，携带 `expected_config_revision`，按各目标 Runtime 契约分别校验。来源新增/删除必须显式补齐/移除映射，不继承未知键。停止态只做目标版本预检，启动后核对实际 active revision。不顺便更新显示输出选择、不启动 Runtime/Trigger；所需输出未交付时明确提示单独配置。

新打开页面使用入口当前指定版本；已打开页面固定原会话组合，提示更新，不热替换局部组件。明确重载后整体切换；未提交输入需明确处理，不能自动丢失或提交。入口重新配置 Runtime 时旧页面不静默转向其他实例；撤销调用权由后端授权处理，入口地址不是权限。

### 5.8 生产页：加载、状态与操作

生产页只保留现场名称、简洁连接/Runtime 状态、配置好的输入和结果区，以及执行一次、实时监视、暂停显示、全屏等必要操作。不展示组件选框、绑定编辑、节点目录或发布按钮；版本、执行 ID 和错误详情放入详情区域。系统文案使用既有四语言机制，业务原文不自动翻译。

打开顺序：鉴权 → 入口、固定界面版本及完整映射 → 分来源读取 Runtime 实际状态/契约 → 兼容与权限 → 各来源最新显示快照 → 对应通知连接。后续读取可独立并行，不等全部 Runtime 就绪才显示；该顺序不执行 Workflow。快照与通知之间的竞态按第 6 节收敛。显示未启用、Runtime 未启动、尚无结果分别表达，不留空白或自动启用。

以下维度按来源独立维护，不把全部情况塞进一个页面 `status`。整页仅汇总可用/部分不可用等显示提示，不能作为业务联合判定：

| 维度 | 状态示例 |
| --- | --- |
| 网络连接 | 连接中、已连接、断开、无权限 |
| Runtime | 停止、运行、故障 |
| 界面兼容 | 可用、不兼容、待核对 |
| 当前显示 | 无结果、实时、本次结果、已暂停 |
| 本次调用 | 待提交、等待、成功、失败、结果未确认 |
| 资源显示 | 可用、加载中、已失效 |

Workflow 执行成功不等于产品合格；合格状态绑定 Workflow 明确公开的业务字段，不根据 HTTP 200 或 succeeded 推断。Runtime 正常与浏览器断网可以同时成立；图片失效不改写业务终态。

每个来源有两种明确显示模式：实时监视跟随该来源最新完成快照，本次结果固定当前页面对该来源发起的执行 ID。手动调用完成后展示本次结果，不被该来源后续 Trigger 结果或其他来源更新覆盖；明确切回实时监视才继续跟随。正在执行状态与上一条完成结果分开，不因新调用开始清空上一张图片。

暂停仅冻结当前画面；恢复读取最新快照，不补播全部中间结果。关闭释放订阅、图片对象和监听器；重连只读快照，不提交表单。登录过期沿用现有鉴权恢复，不自动重放结果未确认的业务请求。默认不承诺刷新后恢复上次手动结果，尤其不能在 none 模式下假设存在数据库记录。

局部暂停只影响该来源显示；整页暂停只是同时冻结各来源视图，不暂停任何 Runtime。表单、手动调用和显示状态按来源隔离，默认不持久化为应用配置。

### 5.9 从工作流准备到现场交付的操作路径

以下是跨页面的使用顺序，不是后台自动执行链：

1. 在“工作流编辑/工作流”中创建、导入或选择 Workflow，编辑节点、公开输入输出并按既有方式验证和发布；准备对应 Runtime 与 Trigger。
2. 在“应用”中新建 amvar app，选择已有 Workflow/Runtime/Trigger 作为组成成员；加入成员不创建副本，也不改变其运行状态。
3. 在应用的界面设计中声明命名来源及契约依据，配置输入、显示组件和明确目标的动作；用示例或固定快照做不执行的界面预览。
4. 保存界面草稿，明确选择试运行映射，按需要点击指定动作验证；真实副作用沿用正常调用，不自动执行其他来源。
5. 发布界面，配置生产入口的界面版本和完整来源映射，并明确指定应用默认入口；逐 Runtime 单独配置需要的显示交付。
6. 根据现场需求显式启动所选 Runtime、启用所选 Trigger，再打开生产页。成员已经运行时不要求为页面重新启停；页面打开、关闭或重连不改变执行状态。
7. 交付时从应用选择范围、检查依赖并下载应用包；目标环境上传、预检、确认映射、恢复，再按第 10 节逐资源启用和验证。

| 所在页面 | 操作对象 | 不能混同的操作 |
| --- | --- | --- |
| 工作流编辑/工作流 | 单 Workflow 草稿、发布版本及 JSON 文件 | 导入工作流不是上传恢复整个应用；发布工作流不是发布界面 |
| 应用组成 | amvar app 成员引用与默认入口 | 保存组成不是发布所有成员，也不是启动应用进程 |
| 运行界面设计 | 界面草稿与独立界面版本 | 界面预览不是执行 Workflow；界面发布不更新生产入口 |
| 运行入口配置 | 界面版本与来源到 Runtime 的映射 | 配置映射不是切换 Runtime 的 Workflow 版本 |
| 生产运行页 | 公开输入请求和各来源结果显示 | 不编辑节点、界面文档或正式入口映射 |
| 应用下载/上传恢复 | 所选组成、准确版本、配置和依赖 | 不是平台发行包安装、数据库备份或历史执行恢复 |

## 6. 显示数据通道与稳定性

### 6.1 来源与通信

```text
HTTP 页面调用 / ZeroMQ / 本机共享内存 / 目录 Trigger
                         ↓
                  现有 Runtime 执行
                         ↓
                 统一公开输出处理边界
                         ↓
              backend 显示快照与资源交付
                         ↓
            REST 快照 / WebSocket 通知 / HTTP 图片
                         ↓
                    Vue 运行界面
```

显示选取必须在统一结果处理边界完成，不读取 SDK 包装层或 Trigger 回传结果作为唯一来源。Trigger 可不回传某个字段，页面仍可显示已明确允许交付的 App 输出；这是独立的显示交付，不扩大第三方业务响应。

复用现有版本化 REST/WebSocket 骨架、Project 可见性和权限。只读监视与手动调用分权，服务端校验动作权限；界面隐藏按钮不代替鉴权。远程浏览器访问 backend 地址，不连接 Worker、mmap 或服务端 file 路径。无需新增前端框架、Redis、MQ 或独立微服务。

具体 endpoint 和新消息 format_id 在实施阶段冻结；不把已有 Runtime 生命周期流当成已经提供生产结果快照。

多来源先复用各 Runtime 的流，浏览器对重复 Runtime 复用订阅和缓存。不增加应用专属 Broker，也不建立跨来源全局序号或原子结果承诺；`stream_epoch`、`sequence` 只在各 Runtime 流内比较。连接数量需要按来源数实测，确有瓶颈再单独评估通知聚合，不提前引入新协议。

### 6.2 配置与快照

- 运行显示交付显式启用；创建/打开界面不自动启用。未启用时沿用原生产调用路径，不采集全节点记录、不编码显示副本、不新增显示历史。
- 只交付声明的公开输出；配置可在 backend 控制面缓存，每次执行固定配置快照，不能由浏览器数量或动画状态改变图执行。
- 外观修改只更新界面版本，不改变采集内容或节点行为。选择其他已有公开输出只涉及显示绑定/交付配置，不修改图或发布快照。
- 快照字段按第 6.5 节定义。显示流 `stream_epoch` 与顺序号防止 backend 重启后的顺序误判；Runtime revision/generation 表示执行来源，Worker epoch 在后端沿用既有来源校验，两种 epoch 不混用。
- 图片、JSON、表格和状态按同一快照关联。迟到消息按实例身份及顺序处理，不依据不可靠的客户端到达时间覆写当前结果。
- 首次进入和重连读取快照，通知只触发刷新；快照与事件的竞态必须通过序号/重新读取收敛，不能漏掉连接期间最后一次更新。
- 缺少结果、运行失败、资源失效、连接断开、Runtime 停止和暂停显示分别表达。保留上次成功结果时必须明确标记其执行时间和旧状态。
- 首版提供执行生命周期和完成后的公开输出，不承诺逐节点实时进度；阶段进度若需要，另行定义公开事件契约，不采集任意内部节点数据或伪造百分比。

### 6.3 图片与文件生命周期

- JSON/文本使用有界结构化快照；大图和文件正文通过 HTTP 资源读取，不在 WebSocket 或数据库 JSON 中传输。
- 已保存图片可通过受控资源映射复用，避免重复保存；校验文件身份及访问权限，不将任意绝对路径开放为下载接口。
- LocalBuffer 或其他临时图像只能在租约有效时完成必要的物化/交付；不得先释放再异步尝试读取，也不得因慢浏览器无限延长 Worker 数据面租约。
- 显示图可降采样，原图独立读取；明确尺寸/缩放关系，不影响算法精度、结果值或空间关联。
- 文件已删除、身份变化、快照过期时返回明确不可用；不能自动读取同目录最新文件代替原引用。
- 最新快照、正在读取的资源和替换后的资源必须有确定的所有者、引用释放和容量上限。owned 显示资源的回收不能删除生产 Save 文件或其他 App 资产。
- Runtime 删除、显示停用、服务重启和异常中断均需回收或标明失效；资源文件恢复清理只处理专属范围，不恢复旧共享内存句柄。

### 6.4 性能边界

复用现有有界事件分发与慢客户端策略；慢显示可以错过中间显示更新，但不能丢弃、合并或抑制业务调用。多个页面不重复生成相同显示资源，不为每个客户端保留全历史。

默认最新结果，不依赖 full record；保留内存/文件的数量、字节和生命周期边界。页面卸载释放订阅、Object URL、观察器和事件监听。服务重启后无快照则显示尚无结果，不重跑业务。

显示资源转换失败不能改写业务成功/失败或破坏原响应；必须可诊断，不无限重试。图片编码和数据复制仍有必要成本，不能声称开启显示零开销，也不能把工作塞入无界后台队列来隐藏耗时。

容量默认值和可接受的时延变化须在阶段 0/4 实测后明确记录。无浏览器、多个浏览器、慢网络和启停显示均需进行相同输入的对照，不以短测声称长期工业认证。

### 6.5 有界快照与本次结果关联

采用“有界不可变快照集合 + latest 指针”，不只保留一个可变 latest 对象。这样手动调用 A 与外部 Trigger 调用 B 可以按执行 ID 分别关联；超过保留范围的 A 明确失效，不以 B 替代。固定查看不意味着无限保留资源或延长 LocalBuffer 租约，快照也不默认成为数据库永久执行历史。

| 字段草案 | 含义 |
| --- | --- |
| `format_id`、`snapshot_id` | 版本化快照格式与不可变快照身份 |
| `stream_epoch`、`sequence` | 显示流身份及该流内单调顺序；backend 重建显示流后更换 epoch，不能用新旧流的裸序号比较 |
| `workflow_runtime_id`、`workflow_runtime_revision_id`、`runtime_generation` | 实际 Runtime 执行来源 |
| `workflow_app_version_id`、`workflow_run_id` | 实际 App 发布版本与本次执行身份 |
| `completed_at`、`workflow_state` | 完成时间和 Workflow 终态，不代替业务合格字段 |
| `outputs` | 按公开 binding 交付的结果与受控资源引用 |
| `error`、`display_errors` | 业务执行错误与显示交付错误分开，显示失败不覆盖业务结果 |

实时显示以当前流中服务端确认发布的最新完成快照为准，不按客户端到达时间或文件名猜测顺序。图片、JSON、文本按同一快照切换；迟到的图片加载回调不能覆盖新快照。图片资源必须定位具体内容，不能使用会被覆盖的 `latest.jpg` 作为不可变身份。

手动 HTTP 结果与显示快照需要明确关联标识；快照标识通过可选响应元数据交付，采用响应头还是既有元数据扩展在实现阶段冻结，不为此改变 SDK 业务响应包装。没有显示快照或已经过期时明确显示不可用，不把 Runtime latest 当作本次请求结果。

none 模式下手动调用优先复用既有 HTTP 同步 invoke；浏览器异步等待 HTTP 不等于创建持久化异步 WorkflowRun。实时监视使用本节有界显示快照，不为了页面显示修改 none 为 minimal/full。长任务如需其他交互，必须明确选择既有异步能力及其保留语义，不默认依赖历史 Run 查询。

### 6.6 REST、显示流与执行接口草案

以下路径是待实现草案。新增应用管理使用独立 `/api/v1/amvar-apps` 前缀，不占用或改名已有 `/api/v1/workflows`；表中省略新前缀。应用内界面和入口子路径是否采用下列具体形式在实施时冻结，不得据此宣称当前 OpenAPI 已提供接口。

| 方法与相对路径 | 职责 |
| --- | --- |
| `GET /`、`POST /` | 列表与创建 amvar app，不创建任何执行资源 |
| `GET /{amvar_app_id}`、`PUT /{amvar_app_id}` | 读取组成/关联界面，带 `expected_config_revision` 更新应用配置 |
| `GET /{amvar_app_id}/views`、`POST /{amvar_app_id}/views` | 列表与创建界面草稿 |
| `GET /{amvar_app_id}/views/{id}` | 读取界面及草稿 |
| `PUT /{amvar_app_id}/views/{id}/draft` | 携带 `expected_draft_revision` 保存，冲突不自动覆盖 |
| `POST /{amvar_app_id}/views/{id}/validate` | 校验文档，不保存、不执行；结果关联被校验的修订/指纹 |
| `POST /{amvar_app_id}/views/{id}/publish` | 发布明确的已保存草稿修订，不应用到入口 |
| `GET /{amvar_app_id}/views/{id}/versions` | 分页列出界面版本 |
| `GET /{amvar_app_id}/views/{id}/versions/{version_id}` | 获取不可变界面版本 |
| `GET /{amvar_app_id}/view-entries`、`POST /{amvar_app_id}/view-entries` | 列表与创建运行入口 |
| `GET /{amvar_app_id}/view-entries/{id}`、`PUT /{amvar_app_id}/view-entries/{id}` | 读取或带 `expected_config_revision` 更新界面版本及完整映射 |
| `GET /{amvar_app_id}/view-entries/{id}/context` | 只读运行上下文；不创建永久浏览器会话，不调用 Runtime |

校验问题至少包含 `code`、`severity`、`source_id`、`component_id`/`action_id`、`field_path`、`message`，不涉及的定位字段可空。运行上下文返回应用/入口身份、入口配置修订、固定界面版本，以及按 `source_id` 组织的 Runtime 身份/状态、兼容结论、显示交付状态和主体允许操作；单来源失败形成局部诊断，不丢弃整个上下文。前端不能以自己构造的 allowed actions 代替后端授权。

Runtime 显示接口分别负责读取/明确更新显示配置、读取 latest、按 `snapshot_id` 读取保留范围内的快照、受控资源下载和一条显示事件流。精确路径与返回 Schema 在实现阶段冻结；沿用 `/ws/v1` 骨架，一条连接订阅一个资源流，控制走 REST、大图不走 WebSocket，不新增连接内执行/启停/发布命令。

试运行与生产手动执行继续复用已经存在的：

- `POST /api/v1/workflows/app-runtimes/{id}/invoke`
- `POST /api/v1/workflows/app-runtimes/{id}/invoke/upload`

使用公开 `app-result`，不默认 debug，不引入界面专用执行引擎或新的结果包装层。当前 invoke 使用 `workflows:write`，操作员调用授权需要按第 6.7 节补齐，不能把当前权限粒度说成已满足隔离。

页面从动作 `source_id` 解析目标 Runtime 后复用该目标的既有接口；`amvar_app_id`、来源映射和动作编辑配置不混入 Workflow 公开输入。新增应用不是另一个可统一执行全部成员的 invoke 端点。

拟为上述 HTTP 调用增加可选 revision 前置条件，例如请求头 `X-AMVision-Expected-Runtime-Revision`。JSON 与 multipart 使用同一语义，在既有调用边界真正执行前核对；不一致返回明确冲突且不执行，一致正常调用，未提供则保持既有语义。不排队、不自动重试、不强制修改 ZeroMQ/共享内存协议。被拒绝请求产生的上传/临时资源仍按既有所有权清理。

该请求头尚未实现，最终名称与错误码待冻结。现有请求解析支持顶层公开输入，不能直接把未声明的控制字段塞进 JSON 顶层，否则可能被当成 binding；此行为在 JSON/multipart 与 SDK 回归中必须核对。

### 6.7 权限与配置边界

服务端至少区分以下能力，并结合 Project 和实际目标资源授权：

- 查看界面和结果。
- 管理 amvar app 组成与默认入口；加入成员不自动获得成员调用或管理权限。
- 调用指定 Runtime。
- 编辑、发布界面。
- 管理运行入口和显示交付配置。
- 修改 Workflow、管理 Runtime/Trigger。

具体 scope 名称与既有授权兼容方案在实现阶段冻结，不新增通用权限平台。只读入口、隐藏按钮和全屏模式都不是安全边界；不把管理 token 放入生产页面地址。实际调用仍校验 Runtime 权限，不因为某界面声明 interactive 就授予写权限。无权限来源只返回允许的局部诊断，不借整个应用上下文泄露其结果、配置或凭据。

## 7. 生产检测与监视维护组合

生产 Workflow 可保持既有高性能调用和 Save 节点；目录 Trigger 调用另一个普通监视/维护 Workflow，后者读取结果、清理文件并通过自己的公开输出供运行界面显示。它们作为同一 amvar app 的独立成员，一个页面可分别显示生产状态、监视图片/JSON 和维护结果，不要求合并节点图。

生产来源可以只显示 Runtime 状态、保持图片交付关闭，由监视来源提供图片；选入组成清单不要求开启每个 Runtime 的显示采集。一个来源暂不可用时其他来源继续显示，各来源更新时间独立，不把读取监视结果当成重新执行生产 Workflow。

推荐读取一份在图片保存完成后发布的结果 JSON，由其中的执行/业务标识和图片引用定位同次结果。独立选择“最新图片”和“最新 JSON”不能证明同次执行。该组合使用通用保存、读取、JSON、绘制和维护节点，不新增场景专用节点。

目录 Trigger 的间隔、样本边界和重启语义沿用[现有实施基线](directory-watch-trigger-implementation.md)。它是变化通知，不保证每张图逐条处理；默认 3 秒触发带来相应显示延迟。监视 Workflow 的执行状态不等于生产 Workflow 的逐节点过程。独立 Worker 仍共享磁盘、CPU、内存等物理资源，需要竞争负载测试。

平台不新增 Save 目录与监控目录重叠判断，也不因 Runtime 忙而跳过正常目录触发。读取结果的入口是否使用 request_json 由 Workflow 决定，该输入仍可选。

## 8. Workflow JSON 导入导出

### 8.1 文档范围

导出单个 Workflow 的 Application、Template、公开 binding、节点参数、连线、图布局、分组、说明和依赖声明。复用当前文档格式，最外层交换容器若新增必须有明确 format_id；不复制另一套节点执行 Schema。

不默认导出 Preview 原始数据、临时上传文件、运行句柄或完整模型 bytes。示例输入若提供，必须明确选择、标记并单独处理敏感数据。公开默认值和内部节点参数属于 Workflow 文档，但凭据按敏感字段规则处理，不能因其位于参数中就明文导出。

### 8.2 编辑交互

- 工具栏提供导出/导入，支持文件选择和拖入 JSON。
- 区分导出当前编辑文档与指定发布版本，不以未保存草稿冒充运行态版本。
- 导入可创建新 Workflow App（前端“新建工作流”），或明确替换当前编辑草稿；脏草稿确认后处理，不覆盖已发布版本。单 Workflow JSON 不因此创建 amvar app、Runtime 或 Trigger。
- 校验格式、版本、节点/端口、参数、binding、资源依赖；缺失节点不能静默删去或用同名节点替换。
- 导入不发布、不选择 Runtime 版本、不运行节点。缺失能力先给出诊断，不伪装为可运行。
- ComfyUI 风格指打开/拖入/导出体验，不等于原生 ComfyUI JSON 或节点可直接运行；转换器不属于首版。
- 图片中嵌入 Workflow 元数据可后续评估，首版 JSON 往返不依赖图片容器。

往返比较区分执行语义与编辑数据：参数的缺省/null/false/0、绑定键、边、说明和布局都必须保留；仅在明确“导入为新工作流”时映射 Workflow 根资源身份。

## 9. amvar app 应用包

### 9.1 包结构草案

```text
app-package.zip
├─ manifest.json
├─ amvar-app.json     本次选择的应用组成和默认运行入口引用
├─ workflows/         多个 Workflow 草稿及所选不可变发布快照
├─ runtimes/          各 Runtime 配置、显示交付配置、版本引用和角色映射
├─ triggers/          各 Trigger 协议配置和输入输出映射
├─ views/             界面文档、所选界面版本、运行入口、主题和静态资源
├─ dependencies/      依赖清单、模型文件、节点包、组件资产
└─ site-bindings.json 目标环境需要确认的目录、端口、地址、资源映射
```

路径只是草案，实施时定义大小写、规范化路径和 manifest 条目规则。包内使用包局部稳定引用标识关联资源，不把 runtime-01 这样的包内角色误作真实 Runtime ID。

manifest 至少定义包格式版本、包身份、来源 amvar app/Project、导出选择范围、各资源引用及版本、文件长度/校验和、平台/组件要求、已包含资产、外部依赖和待填现场配置。`amvar-app.json` 表达可恢复的所选组成；manifest 表达交付事实与依赖，两者由同一个固定导出快照生成并交叉校验，不独立维护成员关系。明确区分包格式版本、应用配置修订、Workflow 发布版本、界面版本和依赖实现版本。

### 9.2 一致导出范围

以 amvar app 组成清单作为选择起点，允许明确选择多个 Workflow、各自的 Runtime/Trigger、界面版本和运行入口。提供“选择全部组成”及按资源选择，不默认打包整个 Project，也不限制为单个 Workflow 根。成员及选项完整分页加载，不能静默漏掉 Runtime 或 Trigger。

导出先展示“主动选择、依赖补齐、外部要求、未包含”四类范围。Trigger 依赖目标 Runtime，Runtime 依赖准确 Workflow 版本，入口依赖发布界面及所有来源映射。取消被依赖资源时只能明确一并取消依赖方、确认补齐，或声明目标环境必须提供的外部资源；不能静默丢掉映射后仍标为完整应用包。

部分导出不修改现场 amvar app 组成；包内清单准确表达本次选择，默认入口未包含时不另选第一项。含外部要求的包标记为需要补充配置/依赖，恢复前必须完成映射；不以“完整离线包”描述它。只有 Workflow 文件交换需求时走第 8 节，不强制打包界面。

包固定当前草稿和所选 Runtime 实际引用的发布版本，不自动使用最新发布版。active/desired 版本不同的配置必须分别表达，不能在导出时悄悄选择或启动 desired。多个 Runtime 使用不同版本时包含其依赖并集；历史版本可以显式增加，不默认无限打包。

界面独立发布并由包固定所选版本，同时保存运行入口逐来源的 Runtime 映射、各 Runtime 显示交付配置和组件/主题资产依赖。相同 Workflow 文件或共享资产可去重，不合并不同 Runtime、Trigger 或模型实例。运行中的采集结果、表单现场值和最近快照不变成发布依赖；浏览器暂停状态、选中组件、访问令牌和试运行临时快照不打包。

导出先在短事务/一致文档读取边界固定引用及草稿内容，然后复制不可变资产。并发编辑、选版、删除或界面发布不能产生混合文档；检测到选择范围变化时使用明确一致快照或失败重试提示，不长期锁住生产调用等待压缩完成。

### 9.3 依赖完整性

现有发布清单记录直接资源引用，不能据此宣称完整可迁移。需要按明确资源类型解析传递依赖：Workflow → 模型部署实例 → 模型产物/文件/标签与运行要求；界面 → 组件版本 → 主题/字体/图片。Custom Node 依赖也必须有受控声明，不能只扫描字段后缀、任意字符串或整个磁盘猜测依赖。

- 包内携带实际必需资产，或明确声明目标环境依赖；不完整包不能标成无需补充资源的完整离线包。
- 相同不可变模型文件可按校验信息去重；实例数量、资源角色和参数不可合并，尤其保持双实例同步推理配置。
- 模型文件、规则和模板图像可以纳入依赖；配置中的监控/输出目录不意味着该目录的全部生产数据都是资产。
- 共享依赖可匹配复用；不自动覆盖其他 App 使用的模型、节点包或组件包。
- 包不包含整个 SQLite 数据库、所有项目账号、系统 Python/conda、GPU 驱动或平台安装目录。平台/64-bit/运行库要求列入 manifest，沿用源码 conda 与同目录发行 Python 边界。
- 普通包不保存明文密钥、token、模型服务凭据，保留敏感引用和待补配置；密钥迁移若需要，须另行定义受控加密方案，不借本文自动实现。
- 自定义可执行节点/组件携带内容与允许安装是两件事；哈希只证明完整性，不证明信任。缺失代码不通过导入自动执行 pip、构建脚本或任意 JavaScript。
- TensorRT 等运行产物须校验目标平台、运行库和硬件兼容性；不得自动换后端、重转模型或将不匹配资产当作兼容。

### 9.4 不打包的执行状态

不打包 PID、Worker epoch、GPU 内存、mmap、LocalBuffer lease、锁、socket、待执行任务、重试队列、幂等缓存、未提交目录窗口或 Preview 缓存。历史运行记录、生产保存图片/JSON 默认不包含，需要历史数据迁移时另定范围，不混入应用恢复。

## 10. 上传恢复与迁移

### 10.1 统一步骤

1. 上传到本次操作的 staging，流式计算长度和 checksum。
2. 校验包格式、文件清单、路径、容量、依赖及平台兼容性；尚不运行包内代码。
3. 展示恢复计划：amvar app 组成，以及各成员的新建/复用/冲突/缺失、版本关系、来源映射、现场映射、敏感待填项和部署实例数量。
4. 明确选择导入为新应用或恢复原应用，逐成员确认身份策略及目录、地址、端口、设备和资源映射；复用资源须明确选择，不能因名称相同自动复用。
5. 按依赖顺序写入资产与声明，经校验形成不可变 Workflow 版本，再创建停止态 Runtime、禁用态 Trigger，恢复应用组成、界面版本、逐来源运行入口和显示配置。整个操作完成前不作为已完成应用交付。
6. 回读核对各 Workflow/Runtime/Trigger、来源契约、入口映射、checksum、跨 Workflow 的明确文件引用及 SDK 配置，输出完整或待补状态；不能把未完成恢复标记为可运行。入口可以打开显示配置状态，不能因为打开页面而启动或执行。
7. 用户明确选择启动/启用哪些资源后才允许执行，逐资源报告结果，不自动启动全部成员；测试调用也必须独立确认，不能因恢复验收自动执行删除或保存节点。

### 10.2 身份和版本

| 操作 | 处理 |
| --- | --- |
| 导入为新 amvar app | 生成独立 amvar_app_id；新建的每个 Workflow App/Graph 各自使用同一组 14 位时间标识，多个 Workflow 不能共用一组；Runtime 由平台生成 UUID；按引用表映射组成、Trigger、界面来源及入口 |
| 恢复原 amvar app | 身份可用时保留 ID；成员逐一检查，冲突先报告，只有明确处理停止态目标后才允许替换；不覆盖其他应用共用资源 |
| 快照内容未改变 | 保留原不可变内容与来源校验信息，并校验目标实际依赖 |
| ID/路径/模型引用重映射改变文档 | 保留来源信息，创建导入派生版本和新指纹，不修改原快照冒充原版本 |
| Runtime 恢复 | 重建 Worker/通信身份，不复制原 PID、epoch 或活动 Run；同机替换遵守既有 generation 防迟到回调规则 |

只在明确声明的资源引用和路径字段上做映射。普通文本、任意 JSON、动态路径表达式不全局替换、不猜测。多个 Workflow 的保存/读取以及目录 Trigger 的路径关联仅按明确现场映射维护，不从相同路径字符串自动推断业务关系；不新增目录重叠防呆策略。导入时 `source_id` 和 `component_id` 保持文档内稳定，映射所指的资源身份，不能按新 UUID 重新排列后配对。

Trigger 命名沿用项目标准：`zeromq-<workflow-runtime-id>`、`local-shared-memory-<workflow-runtime-id>`；多个 directory-watch 使用其既有唯一命名规则，不强行合成一个 Trigger。端口/地址冲突报告后明确配置，不静默换端口。

本次新建/替换的 Runtime 保持停止、Trigger 保持禁用；运行中资源不能被恢复操作直接覆盖。明确复用的既有资源保持原状态，不为了停止态恢复而擅自停止其他应用正在使用的资源；恢复计划必须区分新建/替换与外部复用。默认新建执行资源，需要全部停止的交付不能复用正在运行的实例。目录 Trigger 在后续显式启用时重新建立当前观察基线，不回放恢复前事件、不为了处理旧文件额外触发一次 Workflow。

### 10.3 SDK 配置

按目标环境实际 Runtime、Trigger 和调用地址重新生成，不沿用来源机器 endpoint。命名仍按每个既有 Workflow App 单独计算：单 Runtime 使用 `config_<workflow-app-id>.json`；多个 Runtime 使用 `config_<workflow-app-id>_runtime-01.json` 等，已有 01–08 示例不是新增数量限制。不能用 amvar_app_id 替换文件名中的 Workflow App ID，也不能把多个 Workflow 各自的单 Runtime 错算为同一个 Workflow 的多 Runtime。

包内按 Workflow 组织 SDK 配置，索引明确对应 Workflow ID、Runtime ID、Trigger ID 及配置文件；界面来源通过其 Runtime 映射关联，不依赖目录或编号猜测。恢复不能按新 UUID 排序交换编号和目标。SDK 仍按 HTTP 与高性能 Trigger 各自能力支持输入，接口和响应包装不因恢复改变。账号凭据在目标环境配置，不明文嵌入包。

### 10.4 原子性、安全和容量

- 上传、哈希、压缩、解压和模型资产复制采用流式处理；不能整个 ZIP 或模型加载为 bytes。
- 校验绝对路径、路径穿越、链接/重解析点、重复条目、大小写冲突及解压后容量/文件数量；文件只能落在验证后的本次 staging/正式资源范围。
- 使用现有 Repository/Unit of Work、短事务和可恢复操作记录组织数据库与文件；恢复中断不能留下已经启用的半成品。
- 重试同一导入操作不得重复创建资源。失败只回收本次新建且无其他引用的资源，不删除预先存在的共享依赖。
- 更新同名共享扩展须显式说明受影响 App，不自动安装、升级或降级；不匹配时保持诊断状态。
- 导入授权按 Project 与资源写权限校验，包中原作者/账号只作来源，不恢复来源系统权限。
- 取消、磁盘不足、进程中断和并发导入需可诊断、可清理；清理只操作确认无任务使用的精确临时目录。

## 11. 语言模型生成界面

### 11.1 创作期输入与输出

生成上下文默认只包含已选择的命名来源及其公开输入输出契约、组件目录及 Schema、主题/布局规则、当前界面文档、用户提示和经确认的示例数据。不因属于同一应用就发送全部成员数据。模型 provider 可本地或远程，接口在创作服务边界封装；不要求在现场运行节点图中新增模型调用。

默认不发送 Workflow 内部图、生产图片、密钥、完整执行日志或其他 App 数据。远程模型和额外示例数据的使用必须明确；未配置模型时人工编辑与已发布运行页保持可用。

模型输出完整界面文档或对固定草稿版本的修改。生成开始固定草稿版本/指纹；返回时发生人工编辑则报告冲突，不能覆盖新草稿。保留稳定组件身份以便审查差异，不把整页重建当作无差别补丁。

### 11.2 校验和发布

依次校验文档格式、组件存在性/版本、属性类型、公开绑定、JSON 写入冲突、动作权限、静态资源、节点数量和布局嵌套边界。未知组件或虚构数据字段直接提示，不能静默替换。Schema 合法不代表业务显示正确，必须提供预览和差异确认。

生成只更新草稿；不自动发布、不运行测试、不修改 Workflow、应用组成或生产入口映射、不更换 Runtime、不启用 Trigger，也不扩大公开输入。生成服务失败或超时不影响生产执行。

主题调整、布局和既有组件组合可通过文档完成。全新交互组件允许开发者用 AI 辅助生成源码，但仍走代码审查、测试、静态构建和组件注册，不在运行浏览器执行未经审核的生成代码。

### 11.3 恢复与复现

包保存最终发布文档、资源、组件版本及必要来源信息。提示词、provider、模型标识等仅作可选来源记录，不代替产物，不保存密钥或无界生成日志。恢复不重新调用模型，不要求来源模型账号或网络可用。

受组件目录约束的 Generative UI 是参考方向，不是已选第三方库。依赖是否采用须验证 Vue 3、离线、绑定边界、文档往返、资源控制和维护成本，不整体引入任意 action、watcher 或计算表达式能力。

## 12. 模块、迁移与实施阶段

### 模块分工

- contracts：amvar app 组成、命名来源、界面文档/版本/入口映射、组件声明、显示配置/快照、Workflow 交换容器和应用 manifest 的版本化 Schema。
- application：应用组成维护、界面草稿/发布/入口应用/逐来源兼容校验、统一结果交付、依赖解析、导出/恢复计划、生成草稿服务；职责拆分但仍属于模块化单体。
- infrastructure：ObjectStore streaming、owned 资源回收、包 staging、受控扩展资产及数据库持久化；不把 OS 细节写入领域模型。
- API：REST CRUD/发布/上传下载/恢复计划，WebSocket 增量通知；权限及错误由服务端统一定义。
- frontend：既有 Workflow 四语言显示名称调整、新应用管理、独立运行页、文档渲染、组件 registry、设计器、导入导出/恢复向导及模型生成入口，沿用 Vue 3；旧变量、路由和组件名称不变。
- SDK：恢复后的配置生成及既有调用回归，不创建专属界面调用协议。

这些是职责规划，不要求每项新建一个进程或微服务。正式目录与 endpoint 在对应阶段确定，复用现有边界优先。

### 前端显示名称调整的实施与核对

1. 依据第 3.1 节列出导航、工作流编辑/列表/详情、新建操作、空状态、确认框及 Runtime/Trigger 关联选择中的系统文案，逐项确认其确实指代既有 Workflow。
2. 在现有四语言消息中更新对应显示值，保留翻译键、插值参数、组件/变量名、路由及参数名；新 amvar app 使用独立文案键。不能全局替换 App、Application 或“应用”。
3. 核对页面仍调用相同服务、按相同 ID 查找资源；历史用户名称、模板、节点、保存文件、发布快照与 SDK 配置无需改写，不补做数据迁移。
4. 更新确实断言旧系统文案的前端测试预期；不得为保持旧显示文本而保留错误用词，也不得顺带重命名测试所使用的技术资源身份。
5. 对四语言导航、打开旧链接、新建/保存/发布工作流、Runtime/Trigger 选择及新应用入口分别验证；阶段尚未实现的新页面明确标记未测。真实副作用验证使用隔离资源，不为文案验收执行生产保存或清理任务。

### 数据迁移

新增 amvar app、组成关联、界面、界面版本、运行入口、显示配置和导入操作等持久结构时附带 Alembic 和 Repository 实现，验证 SQLite、MySQL/PostgreSQL 兼容性。应用/草稿/入口修订与 Runtime generation 分离，显示快照不默认转为永久执行历史。默认记录模式和已有 Workflow App/Runtime/Trigger 数据保持原状，不自动创建完整应用、界面、启用显示或改写历史快照。旧 UI 显示名称调整单独验证，不触发数据库迁移或重命名旧代码。

格式版本未知或无法迁移时明确拒绝；需要转换的旧文档通过显式转换生成新内容，保留来源，不在热路径长期维护隐藏双读。现有已发布 App 的公开输入输出、Runtime/Trigger ID 及调用方式不因增加界面强制改变。

### 阶段门禁

| 6 | 模型生成同一界面草稿 | AI/人工往返、虚构字段拒绝、草稿冲突、预览确认、模型离线和包恢复验证 |
| 7 | 源码与同目录发行环境端到端及长时间负载 | 实际图片/JSON/文件、模型推理、Runtime/Trigger/SDK、包恢复、前端状态和资源曲线核对 |

## 13. 验收矩阵

| 范围 | 必测项目 |
| --- | --- |

| 请求与权限 | 表单读取后 Runtime 切版拒绝旧 revision 请求；JSON/multipart 一致；未带前置条件的既有调用不变；只读/调用/编辑/管理授权分离 |

| 生命周期 | 断线重连、无页面、多页面、慢页面、暂停显示、Runtime 重启/切版、backend 显示流 epoch 变化、快照竞态、有界淘汰、迟到图片回调及 LocalBuffer 释放 |
| Workflow 文件 | 当前编辑文档/发布版本导出、拖入、新建/替换草稿、脏状态确认、缺节点报告、执行语义和布局往返 |
| App 依赖 | 自选多个 Workflow/Runtime/Trigger；选择与依赖补齐可见；取消依赖和部分包不冒充完整；双模型实例不合并；不同 Runtime 引用不同版本；多 directory-watch；共享模型/组件复用；缺失/不兼容报告 |
| 恢复 | 完整应用与各 Workflow 的同/新身份分别映射；目录/端口显式映射；派生版本指纹；SDK 按 Workflow 命名及编号角色；每个来源/入口/界面版本/Runtime/显示配置对应；原资源不被覆盖；停止/禁用；无旧事件回放 |
| 包可靠性 | 大文件 streaming、checksum、路径穿越/重复条目、磁盘不足、中断恢复、取消、重复提交、并发编辑/选版/导出与失败清理 |
| 生成 | 合法文档、虚构字段/组件、非法动作、过大结构、人工冲突、不自动调用/发布、模型不可用、只靠产物离线恢复 |
| 长期运行 | 基线/启用显示的 p50/p95/p99、吞吐、CPU、Private/Working Set、原生句柄、缓存项、LocalBuffer lease、磁盘曲线、浏览器内存及共享资源竞争 |

实际数据验证采用同一 amvar app 下“生产检测 Workflow 保存结果 → 目录 Trigger → 监视维护 Workflow → 公开输出”，在一个运行页同时显示这些独立来源，并与直接观测各 Runtime 对照。测试资源应独立创建或经明确选择，不能为验证而隐式运行真实目录清理。

同步双模型部署在既有合理双分支负载下保持正确，不新增业务排队补偿。性能对比用相同输入和受控环境，区分模型、输入、编码、传输和渲染成本；记录结果正确率与完整性，不能仅比较平均耗时。长测未完成或资源增长未归因时明确保留限制，不宣称工业认证。

本任务阶段测试缓存统一位于 `.tmp/<task-name>`；确认本次进程停止后清理精确目录，不删除其他任务使用的 `.tmp` 内容。长期结论进入稳定专题或可重复测试，不把临时证据目录作为文档交付。

## 14. 实施前需要冻结的细节与文档收敛

已确定的是 amvar app 命名、前端术语边界、组成清单/命名数据源/运行入口映射三个模型的语义，以及页面操作、状态分层和高性能边界。第 3.4–3.7、6.5、6.6 节的字段/路径不是已实现 API。以下细节仍需冻结：新 ID 生成格式与 format_id、字段类型/可空性/完整 Schema、REST/WS 精确路径、revision 请求头名称与错误码、快照标识的响应元数据位置、容量/TTL/字节限制、显示配置接口、权限 scope/兼容迁移、组件技术选型、包最终文件名及加密凭据迁移方案。

按对应阶段分别评审，不重新引入单页面单 Runtime 限制，也不引入内部参数编辑、跨 Runtime 页面业务编排、隐式执行或同步等待队列。具体默认值由最小实现与负载验证确定，不能以本文替代代码或工业长期认证。

当阶段实现并通过门禁后，将稳定规则分别合并到 Workflow/前端架构、API、节点扩展、部署运维和前端设计专题；本文件不再重复已稳定契约。全部阶段收敛后删除实施基线或将必要可重复门禁移入专门开发文档，保留 ADR 并更新全部索引。

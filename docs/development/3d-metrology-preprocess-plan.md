## 3. 依赖核对与算法选择

设计阶段只读核对 NumPy `2.4.4`、SciPy `1.18.0`、Open3D `0.20.0`；实施阶段沿用 Windows amvision 环境，在授权的 WSL 隔离目录准备同版依赖和受控 I/O wheel，未修改系统 Python 或生产环境。两平台原生算法与完整样本实际运行记录见专项记录，不再把设计时的“未执行”当作当前状态。

- 体素核心优先使用 Open3D `voxel_down_sample_and_trace`。已核对 0.20.0 源码：返回的成员列表记录完整输入索引；八列矩阵不是完整成员表；普通 voxel 方法会按输入边界确定格相位，并可能平均 normals/colors。平台只传坐标，以 trace 成员建立来源，固定显式格原点，不接收库的隐式属性聚合。[Open3D 0.20.0 PointCloud 源码](https://raw.githubusercontent.com/isl-org/Open3D/v0.20.0/cpp/open3d/geometry/PointCloud.cpp)
- 法向使用同一成熟局部 PCA 定义，计划复用 SciPy 精确邻域和 NumPy 对称矩阵特征分解。Open3D 0.20.0 的现成法向调用有旧法向参与符号和退化补方向行为；一致切平面定向还包含全局剖分，不能直接作为本项目“逐点质量有效且有界”的证明。[Open3D 0.20.0 法向源码](https://raw.githubusercontent.com/isl-org/Open3D/v0.20.0/cpp/open3d/geometry/EstimateNormals.cpp)
- `cKDTree.query/query_ball_point` 复用精确模式 `eps=0`、明确线程数及缺邻居标记；不新增近邻算法。`numpy.linalg.eigh` 用于对称协方差的最小特征向量，不自写特征求解器。[SciPy query](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.cKDTree.query.html)、[SciPy 半径查询](https://docs.scipy.org/doc/scipy-1.18.0/reference/generated/scipy.spatial.cKDTree.query_ball_point.html)、[NumPy 2.4 eigh](https://numpy.org/doc/2.4/reference/generated/numpy.linalg.eigh.html)

选型时 Open3D 网站 release 文档仍显示 0.19.0，不能拿该页面冒充 0.20.0 wheel 行为；以对应 tag 源码、本机绑定及本轮原生真值为依据。Open3D/trimesh 的几何职责、受控 PLY/PCD 和 NumPy XYZ 路径不改变。

## 4. B02：重采样节点

### 4.1 节点和方法

已注册节点 `custom.metrology3d.resample-cloud`，输入 `cloud: point-cloud-ref.v1`，输出 `cloud` 与有界 `summary: value.v1`。一个节点按显式 kind 分派，不设置自动降级或“任选一种能通过”的后备算法。

| 方法 | 明确算法 | 必须配置 | 输出性质 |
| --- | --- | --- | --- |
| `stride` 行间隔 | 从当前输入逻辑行选 `offset + j * every_k_points`，不随机、不按距离插点 | 正整数 every_k_points；`0 <= offset < every_k_points` | 只读子集，原字段/坐标位型完整保留；不是空间均匀分布保证 |
| `voxel-representative` 体素原点代表 | Open3D trace 分组；每格选离该格质心最近的真实输入点；距离相等按稳定身份排序 | 正格边长 voxel_size、grid_origin[3]、明确 frame_id/length_unit | 子集，不生成位置；最终按父逻辑行递增输出，不能拿库的哈希遍历顺序当行序 |
| `voxel-centroid` 体素质心 | 同一 trace 分组，格内所有实测输入行等权质心；不把各处理块质心再次等权平均 | voxel_size、grid_origin、frame/unit、max_position_error；属性策略明确为 positions-only | generated / estimated，体素键字典序，新的 vertex index 加完整原始成员来源 |

空间格为当前 frame 的轴对齐立方体，`key = floor((p - grid_origin) / voxel_size)`，半开边界 `[o+k*s, o+(k+1)*s)`，包括负坐标规则。需要旋转格时先显式 Transform Cloud，不另塞一个隐式 pose。grid_origin 必须来自配方，不以每次包围盒最小值重新定相位。

规则抽取和原点代表可对合法 source/generated 引用取子集，保留父生成来源但清除被抽样后不再成立的边界 topology。质心首批只接受 source 实测输入及其裁剪、去噪、变换视图；对已有生成边界/质心再次聚合明确拒绝，不伪造递归来源。此限制写入 UI/文档/测试，不留隐藏的回退分支。

### 4.2 字段、来源和数值

1. 原点路径：`source_indices` 始终是最初输入行号，`source_point_count` 始终是最初总点数；有序源视图先按当前逻辑行选择，不能重新当原始行序。多个逻辑行指向同一原始行时，质心路径拒绝重复计权；规则子集沿现有语义处理。
2. 质心路径：禁止产生假的 source_indices。来源使用新 `voxel-aggregate` kind，复用现有 lineage blob/Scope，保存体素键、CSR offsets、全部原始 source_rows、source_point_count、原始来源身份和实际方法摘要。每个输出的权重固定为 `1 / member_count`，无需保存一组全相同的浮点权重。
3. 拟定二进制布局：`voxel_keys[M,3]: int64`、`offsets[M+1]: uint64`、`source_rows[N_selected]: uint32/uint64`。源行宽度由原始总点数选择；offsets 记录成员总数，不能混用点数。键排序唯一，offsets 首0/末总成员数且每个非空格严格递增；成员不丢失、不跨格重复。重复坐标的不同原始行是不同实测记录，不能去掉。
4. Open3D trace 返回的是当前调用的局部索引，必须经父视图映射回最初行号。其 int32 范围和体素整数键范围先检查，不能溢出后转 uint64 掩盖。声明边界覆盖全部输入；不把库的 bounds 参数误当 ROI 裁剪。
5. 当前样本保持 float32 保存/传递；外部 float64 保留。原点路径逐位不变；质心局部 float64 累加，输出使用输入位置 dtype，并记录实际回写误差。减局部原点避免大平移下累加失稳；误差超显式数值限额时拒绝，不悄悄降精度。
6. 质心只生成 positions。颜色、强度、类别、大整数和旧 normals 不自动平均或借一个成员值；摘要列出未传播字段，UI 明示 positions-only。原云和原字段不修改，需要全部原属性的调用选原点代表或显式保存父云。将来属性聚合须按字段定义另行增加明确方法，不能当本轮暗含功能。
7. 质心的 estimated 身份不能被保存重读、归一、变换或去噪改成 measured。现有尺寸/边界的实测支持要求保留；没有公开支持生成点的消费者必须明确拒绝，不为了接线通过放宽质量。

### 4.3 有效性与失败

有效输入不隐式去噪/过滤；非有限位置和已有 validity 无效位沿 Filter Valid 边界明确拒绝。单位/坐标错误、失效引用、非法格距/相位、整数溢出、预算不足属于输入/执行错误；上游 unavailable 沿既有原因传递，不伪造空结果。真实空输入或规则未选到点可以产生合法零点子集，摘要计数为零，不是产品 OK。

summary 包含方法、输入/输出点数、保留率、源身份、实际格配置、成员计数范围、代表点偏移/质心量化误差及显式字段处理。格距是处理分辨率，不是测量精度。若配方要求最少输出点或最大偏移，复用现有逐项质量规则，不添加另一套判定器；不得由程序替客户填写该限值。

## 5. B03：法向估计节点

### 5.1 节点、参数和计算

已注册节点 `custom.metrology3d.estimate-normals`，节点参数以 `settings` 包装同一算法 DTO，输入 `cloud`，输出带计算法向的 `cloud` 与有界 `summary`。位置、行数、行序、原始字段与来源不改变；源点和带合法来源的生成点均可估计，但生成位置仍是 estimated/interpolated，不因此成为实测点。

| 参数组 | 规格 |
| --- | --- |
| 邻域 kind | `knn`、`radius`、`hybrid` 三种主动选择；不是运行失败后的回退顺序 |
| knn | 显式其他邻居数 k；可配置最大支持距离，必须明确有限范围或 unrestricted，不用隐含无穷大 |
| radius | 已确认单位中的正半径，取闭球内全部其他邻居；不能因性能静默截断数量 |
| hybrid | 正半径及 max_neighbors，在半径内按距离取至多指定数量；与 radius 的数学定义不同，摘要记录实际数量 |
| 质量 | 最少支持点、最小法向特征间隔、最大局部平面 RMS/表面变化率等由配方显式选规则及限值；数学退化硬条件始终执行 |
| 定向 | `unoriented` 无符号轴、`direction` 显式参考向量、`viewpoint` 显式观测点及 toward/away；禁止默认 +Z 或默认相机原点 |
| 方向条件 | direction 非零且 frame 一致；viewpoint 同 frame/unit；显式最小绝对对齐余弦，正交/点重合时不能随意翻向 |
| 已有字段 | `existing_normals=reject/replace` 明确二选一；replace 只替换声明的法向及其计算字段，父云不变，不能借旧法向决定新结果 |
| 输出精度 | 默认规则与 positions dtype 一致，局部计算 float64；若另选精度必须显式，不能让 float32 输入全云自动永久升成 float64 |

计算步骤：验证引用/字段/位置 → 复用精确空间索引 → 分块查询 → 按身份排除自身一次 → 查询点与所选其他邻居组成支持集 → 局部中心化协方差 → NumPy `eigh` → 最小特征向量 → 逐点质量 → 显式定向 → 注册不可变输出。

协方差采用总体归一 `C = sum((p-c)(p-c)^T) / n`。令升序特征值为 `λ0 <= λ1 <= λ2`，法向取 λ0 对应单位向量；RMS=`sqrt(λ0)`，surface_variation=`λ0/(λ0+λ1+λ2)`，normal_gap=`(λ1-λ0)/λ2`。后两者是无量纲局部描述，surface_variation 不命名为实体曲率或曲率半径。

至少三个不共线的支持位置才有可辨法平面。重复坐标不能伪造秩；λ2 为零、秩不足、最小特征空间不唯一、数值异常或配方质量不满足，记录具体无效原因，不填 +Z。数值舍入导致的微小负特征值只可在明确机器精度误差界内归零并测试；真正非半正定/求解失败不得吞掉。

邻域 tie 按距离和稳定输入身份定义；不能依赖 KDTree 对等距点的偶然返回顺序。若 k 截断落在等距壳层，需在预算内取得壳层候选再按稳定身份选取；不擅自减少 k。radius 先计数再分配，密集重复点超过工作容量明确拒绝，不创建无界 Python 列表。查询块始终使用同一个完整输入支持索引，不能独立分块建树造成块边界法向断层。

### 5.2 有效性、定向和字段来源

- 保持 `validity` 的位置语义。新增 `normal_valid`、`normal_oriented`、`normal_reason` 三个受契约约束的 uint8 scalar，normal_reason 使用固定编码及说明，不塞每点字符串。不通过把位置删掉来隐藏法向失败。
- `normal_valid=1` 表示无符号法向轴通过数学和配方质量；`normal_oriented=1` 还要求明确方向通过。方向歧义可以保留有效无符号轴，但面向需要有符号法向的消费者时必须拒绝，不能当定向成功。
- `normal_valid=0` 时 normals 使用有限零占位并强制状态伴随，绝不能被当单位法向。为避免零向量伪成功，字段/资产/预览校验和所有 normals 消费者同批核查；缺状态的“本节点计算法向”属于坏数据。外部导入的 normals 只声明为外部属性，不凭字段存在推断本节点质量通过。
- 可选逐点诊断字段包含邻居数、RMS、normal_gap、surface_variation，明确 dtype/unit；summary 只保留计数和有界分布，不把全量邻域放进 JSON。没有计算成功的诊断使用明确无效位，不用零当真实误差。
- 在现有引用与资产中携带专门的 `normal_info`：估计方法/参数摘要、支持输入身份、定向 frame 和定义、输出字段及状态编码、是否替换已有 normals。它是小型计算说明，不是新资源或第二个发布版本。后续 crop/stride 保留原估计说明，不声称法向已按裁剪后邻域重算。
- 对 generated 云，允许的是本次明确计算的 normals/状态及诊断，不是插值恢复颜色/强度等源属性。沿 `CloudReference`/资产字段白名单和 normal_info 联合校验，不能简单删除 positions-only 约束后任意放行。
- 刚体变换同步旋转 normals、方向向量并转换 viewpoint；RMS 在单位归一时换算，normal_gap/variation 不变；保留“曾在哪个输入上估计”的证据。不能只变 positions 而留下指向旧 frame 的定向声明。

本批不新增全局 MST 定向算法或隐式闭合曲面“朝外”判断。无方向、参考方向、观测点定向构成这次明确交付范围；跨缺口的全局一致传播属于另行选择的算法扩展，不以库默认全局剖分替代当前有界邻域定义。此边界必须在 B03 完成说明保留，不能宣传支持所有法向定向方法。

## 8. 容量、取消和释放

继续已批准的本机工程策略：活跃数组 1 GiB、工作预算 4 GiB、显示最多100万点、节点180秒/停止宽限2秒。数值不改为所有客户机默认；输入载荷1,000,000,000字节与算法运行内存上限是不同约束。新算法可能因字段、点数、邻域密度或输出来源量超预算而拒绝，不能暗中缩邻域、抽点、丢来源或提高上限。

| 方法 | 必须记入成本 | 有界路径 |
| --- | --- | --- |
| stride | 输出索引与父输入共存 | 分块构造递增索引，借用父字段，不复制整云 |
| voxel | 临时 double 坐标、原生哈希/成员表、trace 返回、规范排序/CSR、源映射、输出及父云共存 | 先验容量；必要分区须按同一全局格对齐，完整体素只属于一个分区。复用已有临时盘/Scope，不能直接用显示 KDTree 任意切开一个格 |
| normals | KDTree 坐标副本、查询索引/距离、局部协方差/特征结果、状态/诊断/输出、可选显示 | 复用完整精确索引，分块查询/eigh；radius 先计数，单点邻域也超预算则失败，不加等待 |
| 保存/显示 | 保存 data/lineage 时副本、原子临时文件、新旧代次、浏览器 CPU/GPU/glyph | 沿现有流写、索引和显示容量，禁止把全部 lineage 或邻域转 JSON |

有界体素调用仍使用同一 Open3D trace 算法；跨分区只合并已完整的格记录，不另造一套近似体素引擎。不按分块数平均格质心。工作集过大且尚无已验证的有界路径时明确容量失败，不能称该布局已支持。

原生建树/体素调用前后、查询块间、CSR 写入/保存间检查取消；不可协作中断的原生调用继续由已有进程组/timeout 强制终止。成功前所有输出归本次 Scope；异常、第二输出/注册失败、保存失败、客户端退出和停止后均清理本任务数组/映射/临时盘。无需修改 Outbox、ProcessGroup、恢复准入或重写 Broker。

## 10. 双平台验证矩阵

### 10.1 独立算法与契约真值

| 对象 | 数据与断言 |
| --- | --- |
| 行间隔 | offset=0/边界、k=1/大于点数、空云、父子集/有序源视图；选择完全等于手写期望行集合，uint64属性逐位不变 |

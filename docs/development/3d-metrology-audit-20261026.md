## 1. 结论

方向仍符合 [ADR-0015](../decisions/ADR-0015-3d-metrology.md) 和[实施基线](3d-metrology.md)：提供通用工业三维节点，复用 Workflow、发布、CloudRuntime、LocalBuffer、资源及 Vue/Three.js 查看器；没有把十二钢片和两半圆写进生产算法。本次样本名称/窗口只出现在审计测试和工件配方文档。

**通用内部实现不等于真实工件配方完成。** R4、R5 A/B/C 接线已有实现；D/E 正式支持区、参数和至少 50 个量的有效覆盖尚未验收。不能声称十八节点的所有真实使用分支、全部尺寸、生产准确度或工业长期运行都已通过。

本轮找到一个可复现的界面状态问题、两项具体配方/容量阻断和文档状态偏差。未发现本轮检查的逐行裁剪、浮点读取、正交拟面数值计算错误。这个结论不覆盖所有算法或未执行的完整业务发布路径。

## 4. 问题与根因

### 4.1 正式支持区不能直接抄报告外包框

证据：D 最大偏差点位于 `[34.272003,-22.320002,-20.264002]`；A_top_L 外包框最大偏差点位于 `[-29.868002,-22.350000,-16.234001]`。这些点确实由候选窗口选入，逐行真值通过，不是 crop 串行号。报告实际使用高度筛选、栅格内核和抽样/稳健拟合，不能用 XY 外包框 + 全高 SVD 冒充同一个支持定义。

根因是 **R5 D 工程支持尚未审核冻结**，而不是 float32 不够或 QR/SVD 算错。按已确认 Q4 应显式审核三维 ROI、排除区和原始支持；不能缩小窗口直到指标刚好通过，不能重建报告的隐藏侵蚀/补边算法。五区联合基准保留；需要稳健拟合时使用已有明确配置的 Open3D 路径，不静默切换方法。

### 4.2 现有小窗口验收不能证明实际配方容量可用

源码 [boundary_runtime](../../custom_nodes/metrology3d_nodes/shared/boundary_runtime.py) 在分配前按 `point_count * 12544` 检查完整局部工作集；512 MiB 只允许最多 42,799 点。本轮实际调用同一前置检查，确认十二片候选和两半圆搜索框均在物化前拒绝。数值是保守准入估算，**不是实测峰值 RSS**，也不是建议的生产配置。

根因是此前完整样本验证使用中间行附近的 0.3 mm 局部窗口，未覆盖正式 ROI 的规模；“读取完整 14.7M 点”掩盖不了下游局部计算规模缺口。不能简单提高门禁、抽稀测量支持、任取最长段或用细碎 ROI 改变全局拓扑。D 阶段须先把真实必要支持、工作集估算、实际峰值和节点时限一起核定。若固定预算内无法承载，应优化原内核的数据布局和释放时机，并用同样完整支持/拓扑证明等价后再用，不另建算法或关闭检查。

基准 RANSAC 还有独立预算公式 `N*128 + iterations*(sample_size*8 + 64 + N*16)`；本轮没有运行原生拟合，不用边界预算或报告 50,000 点抽样替代其容量验收。

### 4.3 视角标签落后于实际相机姿态

操作：正交顶视 +Z → 手动旋转。画布已明显倾斜，选择框仍显示“顶视 +Z”，见[截图](assets/r5-audit-20261026/view-label-after-orbit.png)。

根因： [CloudViewer](../../frontend/web-ui/src/workflows/workflow-editor/point-cloud/CloudViewer.vue) 的 axis 只随选择/复位改变；[renderer](../../frontend/web-ui/src/workflows/workflow-editor/point-cloud/renderer.ts) 的 OrbitControls change 只调度重绘，不反馈相机方向。影响现场阅读视角，不改变云坐标或测量值。

修正设计：保留现有相机和控件；从当前视线/上方向识别仍是预设视图还是自由视图，旋转后显示自由视图，缩放/平移不错误清掉正交视图标签。选择预设仍显式复位；重建控件、换云和卸载解除订阅。补旋转/平移/缩放/投影切换、重新选择同一预设及卸载回归。本轮只记录设计，未修改 UI。

### 4.4 入口文档与当前实现不一致

ADR 顶部仍称有限延伸未实现、边界方法 v2；R5 的 5.2 表仍称并集/pose/动态等高未实现。本轮更新当前状态，历史验证记录保留。无需重复实现 R4/A/B/C。

## 5. 显示与异常隔离

以完整原云生成 1,000,000 点有界显示，抽查首/中/末显示行对应原始点值。实际打开复用组件的测试页，验证顶视/正交、缩放、平移、旋转、390 px 容器换行及关闭释放；主页面控制台未出现 error/warn，关闭后 cpuBytes/gpuBytes 均为 0。[顶视](assets/r5-audit-20261026/real-top.png)、[窄容器](assets/r5-audit-20261026/real-narrow.png)、[释放](assets/r5-audit-20261026/released.png)。这不是完整手机浏览器或空白业务图发布验收。

显示保留全工件范围，不等于渲染全部原始点，也不把采样点用于计算。当前测试颜色取原始 Z 的有限范围，报告总图取台面高度；两者的色彩不能直接逐像素比较。不能通过删除异常深点来改善画面。后续配方须明确颜色标量及范围，长数字只做显示格式化，不回写数据。

上一轮 iframe 的 `MutationObserver.observe` 异常，本轮在 **无任何 JavaScript、Vue、Vite、Three.js 或项目导入** 的静态 HTML + iframe 同样复现；记录时间 `2026-10-26T08:01:54.885Z`，错误文本一致，仍无源 URL。见[静态对照](assets/r5-audit-20261026/plain-iframe.png)。项目代码不是该复现的必要条件，不能据此修改项目 DOM 生命周期；具体浏览器侧脚本归属仍未确认。

CloudCompare 已运行但窗口最小化，当前界面工具未取得有效窗口内容；本轮没有对其执行测量或宣称完成独立 CloudCompare 数值验收。独立数值对照来自上述协方差算法和原报告的定义核对。

## 6. 下一步实施顺序

逐批修改位置、参数审核、前端行为、失败定位和完成标准已细化到 [R5 D/E 详细实施计划](3d-metrology-r5-de-plan.md)，以下保留执行顺序摘要。

1. **D0 固定验收配置与环境。** 保留既有 Q1–Q6，不再重新讨论已确认定义。重建 Ubuntu 原生文件系统的隔离测试环境，登记解释器和锁定依赖身份；Windows/Ubuntu 使用相同输入、配置和用例。先完成视角标签小修复与回归，避免支持审核时误判视角。
2. **D1 冻结代表性实际支持。** 同一原云逐项显示 D 五窗、B.A_top、T.A_top_L、边界搜索及有名连续边段、S1 弧段；按源坐标和本次台面坐标双重记录。保存 ROI 参数、原始行摘要、点数、空间范围及排除依据；固定 U/V 由审核位置确定，不能自动取质心。支持无法表达时暂停确认最小必要扩展。
3. **D2 核定容量和质量依据。** 先计算每个实际 ROI 的现有准入估算，再测工作集和耗时；生产数字仍待确认。质量规则与产品公差分离，不能从“刚好通过当前样本”倒推阈值。必要优化只进原 crop/拟面/表面内核，保留原始支持、取消、所有权和分配前检查；先独立几何真值与资源回归，再验真实云。
4. **D3 跑通 A_top_L。** 真实节点输入 → 五区基准 → pose → B/T 平面 → 同一 U/V 法线 H/Z → 本次有效两端中间高度 0.5 → 边界 → L/W。边距与局部高度另列诊断项。每层保存实际支持、方法、残差/覆盖、来源和失败位置；与同定义独立计算比较，手工报告仅作参考。
5. **D4 跑通 S1。** 本次台面以上 0.25 mm → 有名连续弧 → fit-circle → measure-hole(open-arc)。不把半圆强制闭合，圆模型尺寸端点与真实弧端点区分。逐层检查真实缺口、角覆盖、最大空弧、可辨识性和残差；无效不得作为成功量值覆盖。
6. **E 扩展全部对象。** 对其余十一片和 S2 逐个审核，不复制第一片质量/窗口；输出十二片 H/Z/L/W 加两直径至少 50 项的有效覆盖矩阵。每项须有实值或准确失败原因，失败原因还需区分数据缺测、配方不完整与实现错误。
7. **真实业务与交付。** 冻结候选后从空白 Workflow 页面配置 → Preview → 发布 → WorkflowAppRuntime/Trigger/.NET → 保存恢复 → App Mode；覆盖文件/数组、取消/停止、版本切换和资源回收，Windows/WSL 各自支持范围明确。随后 M3.4 同批升级既有规则/记录/SDK/交付的 OK/NG/INVALID，不创建独立判定器，再完成 M3.5。

D1–D2 未通过前，不进入盲目十四对象批量“调参出值”。本轮没有把候选窗口、原报告阈值或测试容量转成生产默认。

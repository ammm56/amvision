# 数据集工作区实现与验证

日期：2026-11-05。依据：`docs/design/frontend/dataset-pages-design.md`、管理状态与完整工作区设计，以及 `generated/数据集/` 中已确认的图稿。

> 当前规则（2026-11-06）：下方首批实施记录中的自动创建版本、文件关联样本、外部标注交接已被后续用户确认取代。添加／删除保存到当前版本，显式创建版本才生成新 vN；以[样本管理](dataset-sample-management.md)和[最新设计对照验收](../design/frontend/verification/datasets-design-alignment-20261106/README.md)为准。

## 实施顺序

1. 数据集目录、版本和记录分页接口；名称与说明编辑、并发冲突保护。首页复用公共表格、主题、菜单与抽屉，拆为四个标签。
2. 固定版本工作区：分页样本、真实标注、分类与划分、受控文件结构、来源。图片大图及对象信息共用现有 ImageViewer。
3. 导入和导出分步页面、记录报告、权限与草稿保护；复用现有 worker 和格式能力。
4. 生命周期：导入记录与版本分离删除、外部引用阻止、导出产物清理与记录删除分离。
5. 质量检查、版本比较与衍生版本、外部标注交接；各类型依据实际后端能力展示，不虚构未支持的成功状态。
6. 自动化回归、真实开发环境导入—查看—导出闭环、亮暗与短屏核对。

## 不变边界

- 保留现有版本、模型训练引用和 Runtime/Trigger 数据面。
- 列表和样本查询分页，不在页面请求中加载整套图片和标注。
- 最新版本按实际创建时间确定，不能使用随机 ID 排序代替。
- 数据集信息独立于导入记录及版本；删除最后版本后保留名称和说明。
- 名称编辑不改变 dataset_id，不改写已发布版本内容。
- 普通悬停与输入焦点中性色，选中品牌绿；右侧抽屉覆盖全页面并有进出动画。普通提示无彩色竖条。
- 测试写入使用隔离资源；开发服务保持运行。

### 数据与调用边界

- 新增 `DatasetRecord`，以 project_id/dataset_id 作为身份，展示名称和说明采用 revision 条件更新；改名不改变旧资源 ID。新版本发布更新目录时间，但不覆盖名称/说明。
- 迁移 `b9e2d6f4a018` 为已有导入与版本补齐目录，增加样本查询索引。开发库已先备份，再运行迁移；备份留在 data 下，不纳入 Git。生产更新须先备份数据库、停止写入，再从同目录 Python 执行既有 Alembic 升级流程。
- 目录、版本、记录、样本均在数据库分页。普通查询上限 100 项；手工选择最多 1,000 个样本 ID，大范围选择传筛选条件。文件文本预览上限 256 KiB，文件路径只能在已授权版本根内解析。
- 缩略图和标注来自实际版本数据，不使用设计图中的演示框。图像切换取消旧请求并回收 Blob URL；刷新/切版采用请求代次，避免迟到响应覆盖新页面。
- 质量、派生、比较、回传通过现有 Task/Outbox/worker 执行，不在 HTTP 请求内执行全量检查。报告最多保留 200 条明细并提供截断标志。
- 新版本登记与任务成功通过同一事务提交；取消获胜时不发布版本。提交断线使用原 request_id 查询结果，未查到时复用同一 ID，不自动重复创建。
- 分组划分保持组内样本在同一 Split，缺少分组字段时明确拒绝。标注回传以稳定样本 ID 关联，未知/重复 ID、类别冲突及图像变化均需检查，不根据文件名猜测归属。
- 完成或失败任务正常保留报告；排队任务可取消。已有导入/导出执行器没有安全运行中取消能力时返回明确拒绝，不伪装成已取消。
- 新 consumer 加入现有 `dataset-export` worker profile。开发使用 conda amvision；发行使用同目录 Python 和该 profile，不新增外部服务、CDN、数据库或队列依赖。Runtime/Trigger 同步高性能链路未改写。

### API 增量

均位于 `/api/v1/datasets`，保留原导入/导出接口。

| 路径 | 用途 |
| --- | --- |
| `GET /catalog`、`GET /catalog/versions` | 指定项目的目录和版本分页 |
| `GET/PATCH /catalog/{dataset_id}` | 元数据读取/条件更新；PATCH 必须包含 revision |
| `GET /catalog/records/{imports\|exports}` | 指定项目的记录分页 |
| `GET /{dataset_id}/versions/{version_id}/workspace` | 固定版本的统计、类别和来源 |
| 同一版本下 `samples`、`samples/{sample_id}`、`samples/{sample_id}/image` | 样本分页、详情和受控图片读取 |
| 同一版本下 `category-statistics`、`import-report` | 类别统计与原始导入报告 |
| 同一版本下 `files`、`file-text`、`file-samples` | 目录分页、文本及精确样本关联 |
| `POST .../selection-summary` | 选择范围统计，不要求前端提交全量 ID |
| `POST/GET .../jobs`、`GET .../jobs/{task_id}` | 创建工作区任务、历史、结果 |
| `GET .../job-requests/{request_id}`、`POST .../jobs/{task_id}/cancel` | 提交恢复和取消 |

所有接口校验资源所属项目与读取/写入权限；跨项目不可见资源统一返回 404。编辑冲突返回 409。具体字段及约束由 Pydantic schema 和 OpenAPI 提供。

- `GET /api/v1/datasets/catalog/records/{kind}` 增加可选 `days=0|7|30`，以及导出 `file_state=ready|generating|not_generated|cleaned`；默认行为不变，非法枚举返回422。`q` 支持数据集名称/ID及已登记文件名；导入兼容旧记录的 package_path。筛选通过 ORM 在分页前执行，项目权限及准确总数保持不变。无需数据库迁移或新增运行依赖。
- 文件“可下载”表示记录已完成且未执行产物清理，允许首次下载时打包；不是对所有导出文件的实时磁盘完整性保证。下载服务继续校验实际文件并返回错误。列表不递归扫描磁盘。
- 导入详情保持执行时统计，不能拿后续增删样本后的版本计数覆盖历史报告。类别使用实际 class_map，不以数组序号伪造类别ID；结构化失败原因可见，没有报告时不显示“无错误”或“检查通过”。数据集名称查询失败不阻断历史记录及导出文件浏览。
- 导出文件浏览切换记录重置目录、分页和预览；目录使用公共按钮，叶文件没有展开箭头；原始报告和JSON预览换行，不产生水平滚动。验证范围与截图见根目录 design-qa.md。

## 数据集传输向导和详情（2026-11-10）

- 上传草稿：`POST /api/v1/datasets/upload-drafts` 接收 multipart 的 `package` 和 `project_id`，返回 `draft_id`、文件名、大小。草稿按项目及主体隔离，24 小时后过期，下次操作时清理。取消和换文件时用 `DELETE /api/v1/datasets/upload-drafts/{draft_id}?project_id=…` 释放。
- 提交导入：`POST /api/v1/datasets/imports` 接受原有的文件上传或一个 `draft_id`，二选一。提交成功消费草稿。创建版本时可通过三项同名 `split_ratios` 表单字段和 `split_seed` 请求可复现的 train、val、test 重新划分。当前版本追加沿用原接口。
- 导出：`POST /api/v1/datasets/exports` 可传 `included_splits`、`package_name` 和 `source_category_ids`。类别数组按目标 ID 从 0 连续排列，`category_names` 给出对应输出名称。对象检测、分割、关键点与旋转框允许排除类别；在所选划分内保留图像，仅输出勾选类别的标注。图像级任务保留完整类别集合。文件名仅控制下载名称。参数省略时采用原有语义。
- 详情使用执行时保存的类别和划分统计，已清理的导出保留顶层清单摘要及已生成 ZIP 的名称和大小。后端存储在已有元数据字段中。历史记录缺少快照时显示未保存或未知。
- ZIP 结构预览在本地 Web Worker 中读取，文件树最多展示 2,000 个条目，清单解码预算 16 MiB。未完整预查的项目交给正式导入 worker 校验。导出前文件树展示目标格式结构，完成后读取实际产物。

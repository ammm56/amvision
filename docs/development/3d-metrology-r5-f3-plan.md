## 3. F3 方法与参数设计

### 3.1 一次测量的数据路径

```text
完整原云 -> 已有粗 ROI/本目标有限 ROI
本次 pose + 台面 + H 测量及双方平面 -> 已有动态高度解析
局部全部观测 -> U/V 中位高度栅格 -> 显式目标分区
目标的真实占据格 -> 四侧有序剖面及缺测证据
四侧剖面 -> 稳健分位跨度 -> W/L + 质量 + 显示证据
```

钢片使用已确认的本次基体/顶面中间高度，比例 0.5、目标高于基体。任何上游无效、跨 Run、旧 pose、单位或身份不一致都不得回退到旧高度。输入仍为原始 float32；局部投影、聚合和统计按数值需要使用 float64，不扩大整份原云的保存精度。

通用方法正式标识为 `visible-envelope`，尺寸方法为 `robust-profile-spans`；沿 v1 联合类型扩展，Catalog 与读取方已同步。完整字段与来源布局见本轮实施文档。

| 参数组 | 必须表达的内容 | 本工件起始依据 |
| --- | --- | --- |
| 空间及高度 | 当前评价面、固定或测量比例来源、正法向、前景高于/低于截面 | 复用当前 pose 与 H 来源；正负方向不自动交换 |
| 栅格 | 显式 U/V 原点、物理步长、有限范围、聚合方式、每格有效计数要求 | 报告 0.03 mm 为主候选，0.06 mm 为敏感性对照；不做全局默认 |
| 分区 | 目标有限 ROI、种子窗口、连通规则、是否显式闭运算及结构元素 | 3×3、一次闭运算仅为报告对照候选；无自动最大区域选择 |
| 剖面 | 四侧角色、物理观测支持要求、有效站位数/覆盖、缺口统计 | 报告 0.30 mm 作为起始物理支持条件，明确指占据格数乘步长，不把中间空洞算成观测长度 |
| 边界位置 | 显式选择格边，或格中心阈值插值/格边组合估计 | 本工件采用报告定义的组合估计；每个点记录实际分支和缺测原因 |
| 稳健范围 | 四侧分位数、统计方法、输出 U/V 项 ID | 左/下 0.02、右/上 0.98，`linear`；U 对应 W、V 对应 L，不自动按大小交换 |
| 质量 | 各侧支持下限、缺口/估计比例/分层风险的适用规则、ROI 截断检查 | 根据原始采样、独立扰动和完整样本确定并记录依据，不反向贴合报告数值 |

工程参数由本工件的已有授权推进选择和验证，不再要求逐个外部填写。通用节点不写入钢片专用默认值。具体秒数上限尚未确定，不能擅自把 2 秒、5 秒或 timeout 当作验收线。

### 3.2 栅格与区域

1. 只处理本目标有限 ROI 内的全部原始支持，不以显示采样作为输入。投影高度相对解析后的截面；记录原基准中的实际高度，不能丢掉动态来源。
2. 复用现有 NumPy/SciPy。中位数、计数和分箱由成熟函数执行；显式固定网格原点、末端格归属和 NaN 规则。空格为缺测，不为零。[SciPy 分箱统计](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.binned_statistic_2d.html)
3. 观测占据掩码与分区掩码分开。闭运算只能影响目标归属，不能为测量制造高度、原始点或连续边缘；不把填孔格当作观测。[SciPy 闭运算](https://docs.scipy.org/doc/scipy/reference/generated/scipy.ndimage.binary_closing.html)
4. 种子窗口与目标 ROI 显式配置。窗口命中零个目标则未找到，命中多个则歧义；不得自动换成最大区域、最长段或上一帧目标。被形态学合并的候选仍需审查，分区连通本身不证明是同一工件。
5. 四侧剖面仅取属于选定目标的原始占据格。内部孔洞、缺失格、闭运算连接格分别统计。多个高度层重叠时不能宣称中位数能恢复正确顶层；保留格内高度分布和有限法向 ROI 的适用性检查。
6. 本批方法面向沿评价法向可表达的可见高度场。悬垂、多层遮挡等超出方法定义的输入必须明确拒绝或判为不适用，不增加隐式三角表面回退。

### 3.3 四侧剖面与跨度

每个符合支持条件的行/列产生对应两侧边界估计。若相邻观测格中心的高度确实包围阈值，则计算格中心之间的插值位置；否则采用已选择的方法规定的格边位置，并记录邻格缺测、不包围阈值等原因。这是预先声明的组合估计公式，不是严格等高算法失败后的兼容降级。

遇到 ROI 截断、上游无效、无合格剖面、目标歧义或质量拒绝，不允许继续用格边替代错误。格步长是分辨率证据，不直接宣称为完整测量不确定度或保证误差不超过半格。

四侧角色固定为 `u-min/u-max/v-min/v-max`。缺失站位必须断开；不把四组剖面强行闭成一个环。孤立有效站位可以作为明确的单点剖面证据参与统计并计入覆盖规则，显示为点，不伪装两点线段。现有连续截线的段数量/闭合校验不放宽；新增剖面布局在同一特征与资源契约中表达角色、站位和连接关系。

尺寸计算分别取左/下侧低分位、右/上侧高分位，再求 U/V 差。采用显式 `method="linear"`，保留排序中参与统计的两个位置及系数；不把结果当某个实测极值点。[NumPy 2.4 quantile](https://numpy.org/doc/2.4/reference/generated/numpy.quantile.html)

同一原始数据顺序变化、分块大小变化，不应改变目标归属或统计定义。相等值的来源顺序使用稳定的站位/原始行号规则；不依赖排序的偶然顺序。

### 3.4 质量与失败分类

- 输入错误：参数缺失/冲突、失效引用、错单位、错来源、预算不足等沿已有请求/资源错误处理，不伪装测量无效。
- 几何无效：目标未找到/歧义、四侧支持不足、目标被配方 ROI 裁断、不可接受的多层输入、质量拒绝等返回明确 `valid/reason`，不得输出看似正常的零值。
- 有限有效：方法允许的格边估计、非致命内部缺测必须保留比例、分辨率和原因，不能统称实测截线；是否满足工程用途由显式质量规则决定。
- 产品 OK/NG/INVALID 仍属于既有 M3.4 消费者计划。F3 不另建三态判定器，不把几何有效自动解释为产品合格。

只按“有无低侧邻点”否决全部可见包络不符合已经确认的方法。反之，允许可见包络也不意味着所有缺测、截断或歧义都可以接受。适用性与质量规则需按新测量定义独立验证，不修改旧截线质量条件。

## 4. 来源、保存与所有读取方

### 4.1 来源不能借用错误语义

沿现有 CloudRuntime、OwnedCloudArrays 和 ResourceScope 扩展一种显式格剖面来源，不增加资源服务。已有源边/三角面插值分支继续保持严格校验。

| 内容 | 需要保存/校验的证据 |
| --- | --- |
| 原输入 | 原始 `source_point_count`、父内容身份、单位/坐标/观测身份；源点视图继续保留原始 `source_indices` |
| 栅格定义 | 评价面与动态来源、原点/步长/范围、聚合/分区/边界方法及完整参数摘要 |
| 被剖面引用的格 | 格坐标、有效计数、聚合高度和质量统计；按格去重的原始行号分组，不为每个顶点重复保存整组支持 |
| 生成顶点 | 四侧角色、站位、格引用、插值系数或格边位置、实际估计方式及缺测原因；不填假的 source_index、源边或源面 |
| 分位端点 | 侧角色、完整剖面内容身份、样本数、分位数/统计方法、参与排序位置和系数；展示位置与统计值分别明确 |
| 特征/尺寸 | 稳定 target/feature/item ID、逐侧质量、覆盖/缺口、观测与估计占比、当前评价面与结果有效性 |

格聚合剖面的顶点属于**估计点**。即使在两个格中心之间插值，也不称为两个原始实测点间的截线。原始属性保持在原云；生成点不自动插值颜色、强度或法向。

数组布局在 F3.1 明确：格表、去重行号分组及偏移、逐顶点格引用/方式分开登记。先计算字节数、格数和索引溢出风险再分配；所有临时排序和库函数数组也纳入工作预算。仅保存参与结果追溯所需的格，不自动持久化整个局部高度场或完整原云。

1. Python 参数、引用、来源、边界/尺寸证据与显示契约；生成 Catalog 和执行身份同步更新。
2. CloudRuntime 的校验、借用、分块、关闭；取消/异常后没有未登记数组或半成品引用。
3. `save-cloud/read-cloud`、点云资产打包/导入及资源 API；保存边界 features 时完整恢复方法、剖面和质量，普通点数据保存不凭空生成它们。
4. PLY/PCD 作为显式点数据交换，不宣称能往返全部平台测量证据；平台资产承担完整追溯。历史显示证据不是重新计算所需的原云。
5. `measure-extents` 新方法读取；现有 `fit-line/fit-circle` 在未完成对应来源/质量语义前明确拒绝不支持的估计剖面，不将其自动当实测源边，F4 再按明确方法扩展。
6. 前端 `boundary-display.ts`、`dimension-display.ts`、CloudViewer、参数编辑器、资源预览、结果表与 App Mode。通用消息通道沿原机制传递，不新增二进制上传协议；SDK 若有对应强类型字段校验则同步，否则不因新增 JSON 证据重做整个 SDK。

保存后重读必须得到相同的剖面、统计数值、质量、来源和显示；损坏偏移、伪造行号、跨云/跨方法引用必须被拒绝。重读不能触发重新拟面或改换动态高度。

## 5. 前端使用路径

工程师在现有 Extract Boundary 的方法选择中选“可见包络（栅格剖面）”，连接当前 pose/基准/H 及双方平面；复用当前有限 ROI 编辑和三维定位。设置网格步长、目标种子窗口及剖面条件，Preview 后显示解析高度、选中目标和四侧边界。

- 普通区展示目标、网格和测量方向；质量与来源放在现有详细参数区。新方法不出现无关的 alpha radius、三角边长或闭合环要求。
- 三维点击仅填写候选位置，修改后仍通过 Preview 使用完整输入计算。不新增常驻完整云查询服务，也不在浏览器做最终拟合。
- Measure Extents 选择“稳健剖面跨度”，连接目标特征，继承当前评价面与四侧角色。配方明确 U/W、V/L 输出 ID；不手输本次碎片编号。
- 实测云、格中心估计、格边估计与尺寸标注用线型/符号和标签共同区分；缺口断开，孤立剖面显示为点。估计矩形只作尺寸示意，不能画成完整实测外缘。
- 结果行展示值/有效性/原因；工程详情列出网格、四侧支持、估计比例、缺口和来源。现场 App 不被大量来源数组淹没，必要追溯仍可查看。
- 切换方法清除不适用草稿字段；切换任务/对象、重复 Preview、关闭面板时不能显示晚返回的旧结果。复用已修复的前端生命周期，不再复制异步管理器。

参数、真实完整工件预览与页面保存发布已实测。程序构建的完整配方经正式 API 入库，不能冒称已从空白页面手工配置全部 106 个节点；该人工操作覆盖仍列入完整工件使用验收。

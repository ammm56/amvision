# 点云显示故障与资源释放验收

日期：2026-11-04。对应剩余清单 A08/A09，基点为 `01587765` 加前序未提交候选。范围仅为现有 CloudViewer、原始细节控制器、回归与隔离验收入口；没有修改测量算法、工件配方、质量门禁、输入队列、生产容量或进程停止机制。

## 本轮修复

### 细节错误引起重复请求

完整工件进入原始细节显示后，暂时移走隔离库的 `display-index/index.json`。真实块 API 返回 404，但页面不断回到“概览”，同一块重复请求，错误提示不能保持。

调用链为：块读取失败 → 错误消息和条件重试按钮出现 → 工具栏折行/高度变化 → ResizeObserver 通知视野变化 → detail-controller 清除错误并重新加载 → 再次失败。原控制器将错误后的布局变化与正常相机交互一律当作新加载，没有保留失败状态。

修复沿原组件和控制器完成：

- 重试按钮在存在资产细节入口时固定占位；正常或加载中禁用，失败后可用，不因错误反复增减工具栏高度。
- 控制器在失败后保持错误。后续缩放、尺寸变化及显隐开关不会自动请求；显式“重新加载资产细节”沿既有 `load()` 释放旧控制器并建立新控制器。
- 失败块集全部释放，只保留明确标为概览的显示，不冒充当前视野全分辨率。取消、晚返回、来源切换和卸载仍使用原 AbortController/代次/所有权边界。

修复后，真实页面一次失败后请求计数保持 14，末次请求起始时间保持 `80784.89999985695 ms`；三组放大/缩小没有新增块请求，错误原因保持可见。这不是通过重试退避、后台队列或静默降级掩盖失败。

### 故障文字在深色画布上不可读

真实 `WEBGL_lose_context` 触发后，原错误文字继承浅色主题的深色字，深灰画布上难以辨认。显示消息层显式使用 `#f3f5f7` 前景与 `#202326` 背景，计算对比度约 14.45:1。加载、空数据和故障提示共用该消息层；重开按钮继续使用现有主题样式，不改平台主题。

结束日志还确认，后端原始错误句子被送入 i18n，重复触发缺失键警告。查看器仅翻译已知本地错误码，其他内容按纯文本显示，不解析 HTML/插值，也不全局关闭翻译警告。此项最后补丁通过组件回归及类型检查；真实浏览器截图在该纯文本补丁前采集，显示内容相同，不称为最后补丁后重新运行了整套页面。

## 资源与影响审计

原始细节成功时应用账本为 CPU 45,728,352 B、GPU 19,342,008 B；索引失败后回到概览 CPU 14,933,336 B、GPU 6,144,144 B；上下文丢失和关闭时均为 0。画布像素预算随视口尺寸变化，因此不同截图的 GPU 账本不必相等。

这些是应用声明的缓冲预算，不是驱动实际显存。探针中的 `gpuMemoryBytes=null` 表示不可观测，不能写成零；JS heap 为浏览器采样值，受 GC、Vite 和测试代码影响，五轮观察不能作长稳或最低 RAM 结论。没有重新执行 1 GB、S2 稳定性、P99 或长稳。

测量、全量支持、数值精度、配方、公差与停止/恢复准入均未变。修复减少失败时无意义的 HTTP/解码/渲染工作，不宣称正常检测算法因此提速。代价是细节失败后需要显式重新加载；这符合原资产来源/代次重新校验边界，避免错误时静默反复尝试。

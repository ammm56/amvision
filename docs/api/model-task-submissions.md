# 训练与转换任务提交回执

创建训练任务和转换任务时，可通过 `X-Model-Submission-Id` 传入客户端生成的 UUID。每次新的提交使用新的 UUID；不传时沿用原有行为。任务和回执一起提交到数据库，同一项目、提交人和 UUID 只接受一次。重复提交或提交已被关闭时，服务返回 `409`，`error.details.submission_id` 为原 UUID。

提交后如果未收到明确结果，调用 `POST /api/v1/model-submissions/{submission_id}/resolve`，请求体为 `{"project_id":"<原提交所用项目>"}`。调用者需有 `tasks:write` 和项目访问权限；回执仅供原提交人查询。

| HTTP 200 响应 | 后续处理 |
| --- | --- |
| `{"status":"accepted","task_id":"task-…"}` | 使用原任务编号查看任务。这只确认任务已经创建，并不表示任务执行成功。 |
| `{"status":"not_created","task_id":null}` | 确认原提交未创建任务并关闭该 UUID。迟到的原请求将被拒绝，如需重新提交，使用新的 UUID。 |

没有拿到上述明确回执时，应保留原 UUID 并重试查询。不要依据任务列表是否可见来判断提交结果。任务删除后仍保留此前接受的回执，防止同一请求重新创建任务。

部署新版本时使用 Alembic `90ab3916f4cb` 建立回执表。该迁移不修改既有任务或产物。先迁移并更新所有 API 实例，再启用新前端；旧接口会忽略回执编号，不能用于新前端的断线恢复。回滚版本应先撤下依赖回执的新前端和接口；降级会移除回执表，旧提交结果将不再可查。

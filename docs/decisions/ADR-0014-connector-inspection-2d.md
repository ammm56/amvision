# ADR-0014：二维连接器检查与测量扩展

## 状态

设计提案，尚未实现；按当前需求整理，供后续实施核对。已经明确的需求是二维、节点化、复用现有 Workflow/Runtime/Trigger，以及通用基础节点与行业专用节点包隔离。下列节点名称、字段及资产接入方式为拟定方案，尚未成为公开运行时契约。

## 背景

连接器需要固定编号的 PIN 阵列、明确基准的尺寸量测和与图像联动的配置体验。当前项目已有 OpenCV 定位、边缘、几何、标定、通用检查和图编辑器，不需要新建一套运行平台。现有基础算子也不能直接证明已具备连接器计量准确度。

公开参考及证据边界见 [ViSCO 功能核对](../reference/vision/visco-connector-inspection.md)。唯一的详细实施基线见[二维连接器检查实施基线](../development/connector-inspection-2d.md)，不得再维护含义不同的平行方案。

## 决策提案

1. 通用二维采样、边缘、拟合、坐标变换仍归 `opencv.nodes` 及其共享算法函数；PIN 名义排列、身份关联和按 PIN/壳体特征展开的尺寸拟归 `connector.nodes`。通用规则、记录和显示保持 Core/既有包归属。行业包显式依赖通用包的受支持版本，禁止反向依赖、调用其他节点 handler 或嵌套执行 Workflow。
2. 首轮行业节点以 `Pin Array Locate` 与 `Connector Measure` 两类节点为目标，通过节点专属编辑器和 Workflow 模板使用。前者提供观测和特征，后者按特征计算行业尺寸；均不输出隐含的整件业务判定。不新增连接器业务页面、Metrology Runtime、独立调度器或业务数据库。
3. 工件姿态用于找到区域；测量基准用于定义尺寸。不得通过拟合待检查的 PIN 自动消除其偏移、伸缩或缺陷。物理量测先将几何证据映射到定义的物理空间再计算，除经验证的均匀比例模型外，不以像素测量值乘比例替代标定。
4. 测量值、有效性和业务判定分层。通用规则处理公差及整件结果；算法不得将失败写为零或默认 OK。存在性、设计留空、多余候选与尺寸条件分别显式接入必检集合，不从成功返回项临时推导整件已完成哪些检查。生产计数、图像保存和结果显示继续显式编排。
5. 标定、参考图和模板必须随 App 发布冻结内容与身份，并参与导入导出和删除引用检查。运行时不得读取一个可被随意覆盖、却仍被视为旧版本的测量资源。
6. 专属 UI 复用 Vue 3 图编辑器与图像组件。先实现受信任的本地构建注册，不建立任意脚本加载、在线依赖或另一套前端框架。
7. Preview 沿用现有临时内存结果和 WebSocket；Runtime/Trigger 沿用既有调用与资源生命周期，不增加生产排队或自动重试。测量使用原始像素，JPEG 仅用于显示。
8. 第一阶段不包含空间共面度、完整 GD&T、多相机拼接、硬件直连和以模型分数替代尺寸测量。
9. 型号、料号、针数、公差、NG 标签与保存路径是产品配置，不成为节点类型。行业包内部仍须跨型号复用；不得建立某个客户/工位专用包来复制通用算法。
10. 已有节点保持 ID、分类及含义。关闭连接器包不能影响已有流程；新增通用工具必须同时验证非连接器场景。详细归属表和准入条件只在实施基线维护。

## 与 ADR-0011 的关系

[ADR-0011](ADR-0011-industrial-vision-node-coverage.md) 对前一轮通用工业视觉扩展限定 Core/OpenCV 两类归属。本提案保留其通用算法、业务规则分离和节点粒度原则，拟为稳定的行业排列与检查配置增加一个扩展包；不将既有通用算子搬出 OpenCV，也不为每种连接器型号建包。提案被接受后补充 ADR-0011 的后续决策链接，不改写其历史状态。

## 未采用方案

| 方案 | 未采用原因 |
| --- | --- |
| 新建独立计量服务、运行时及连接器导航页面 | 重复现有执行、发布、监视和节点交互边界。 |
| 每个 PIN、每个尺寸都必须使用单独节点 | 图规模失控，编号、配置复用与诊断难保持一致。原子节点仍可用于调试。 |
| 单一黑盒 Connector Inspect 节点包办所有功能 | 基准、图像处理、判定和输出关系不可核对；先采用两个工具节点及透明 Workflow。 |
| 直接把 YOLO 框坐标用于精密尺寸放行 | 没有匹配的测量定义和误差证据；模型可参与定位或外观检查。 |
| 使用硬盘交换 Preview 中间结果 | 违反现有内存链路边界，增加延迟和清理负担。 |

## 影响

需要补齐测量契约、跨包算法接口、少量专属编辑器接口和测量资源发布边界。首轮对新功能采用独立模板验证；不自动修改已有 Workflow，不改变已有节点的测量语义或模型输入。旧节点如需语义修复，应单独说明影响、更新版本并回归，不能在共享函数抽取时暗中改变行为。适用的长期分类规则见[节点包边界](../architecture/workflows/node-taxonomy.md)，新包仅在完成实现和验收后进入运行时 Catalog。

验收分为算法数学正确性、真实计量准确度、交互正确性和平台性能/稳定性四部分；其中任一部分未通过，均不能以其他部分的成功替代。

# ADR-0012：资源删除与存储清理

## 状态

已接受并实现统一资源删除链路。本文保留设计决策；当前模块、存量清理限制和验收范围见[资源删除实现与验收边界](../development/resource-deletion-implementation.md)。

## 背景

平台同时管理数据库记录、本地 ObjectStore 文件、持久队列和独立运行进程。仅删除列表记录不能释放全部资源；仅删除输出目录又可能使保留的模型记录指向不存在的文件。

改造前不同删除路径的行为并不一致：导入、导出和转换只清理部分资源；评估只删除任务记录；YOLOX 登记模型后保留训练目录，而通用 YOLO 和 RF-DETR 没有同样的保护。ModelFile 登记的是输出 URI，并不自动复制成独立模型资产，因此需要统一归属和删除事务。

统一删除复用 Project 和 Workflow Runtime/Trigger 已有的目录暂存、启动恢复与生命周期互斥方式，补充严格物理清理、队列清理和独立持久清单。

## 决策

### 删除的含义

删除成功表示目标对象及其拥有的文件、数据库附属记录、已结束的队列消息和专属运行数据已清理。文件缺失可以视为已清理；权限不足、文件占用、路径归属不明和数据库失败不能被当成成功。

删除训练任务时，同时删除该任务产生且未被其他资源使用的 ModelVersion、ModelFile 和训练输出。存在转换、部署、其他训练或工作流的有效引用时，整个删除操作在修改数据前被阻止，并返回具体依赖。

导入记录、数据集版本、训练任务和部署实例是不同对象。删除一个对象不隐式删除整条业务链：导入记录不拥有规范化后的数据集版本；部署实例不拥有被多个实例共用的模型。数据集及其版本必须有独立删除入口，使这些资产可以实际清理。

### 文件归属与依赖

每类资源明确列出自身数据库记录、受管目录及依赖。文件路径来自服务端模型和固定目录规则，不能通过递归搜索任意 JSON 字符串推断删除范围。

仅清理平台拥有的对象。预置模型、外部路径、模型运行时、第三方软件目录及其他资源仍在使用的文件不属于当前对象的删除范围。历史来源信息与需要继续读取的文件引用应分别建模；不能把失效文件引用伪装成可用资源。

### 一致性和恢复

应用层负责资源归属、依赖检查和删除编排；Repository / Unit of Work 负责数据库事务；ObjectStore 负责安全路径、暂存和严格物理删除；QueueBackend 负责精确清理关联消息；Worker / daemon 负责执行停止和释放运行资源。

删除前必须阻止新执行、新引用和恢复任务与删除并发。目录暂存后才提交数据库删除；提交前失败恢复目录，提交后失败保留可重试的清理记录。清理记录必须保留到磁盘与队列都完成，不得先删恢复凭据再清理队列。

大目录清理复用现有任务和 Worker 架构，前端显示实际清理状态。数据库已提交但磁盘清理未完成时，不能显示“已全部删除”。不新增独立清理微服务。

### 存量数据和数据库体积

历史遗留数据通过受管路径和资源引用核对清理。不能按目录年龄直接删除训练输出、模型文件或整个数据根目录。

删除记录与回收数据库文件空闲页分别处理。数据库整理属于基础设施维护能力，不在业务应用层写数据库专用 SQL，也不在每次删除后重建数据库。

## 未采用方案

- 只删数据库记录：文件和持久消息仍会增长。
- 只删输出目录：可能留下失效的模型和部署引用。
- 默认递归删除所有下游资源：单个训练或数据集删除可能影响已经部署的工作流。
- 自动复制所有训练模型再删除任务：改变当前存储归属并增加磁盘占用，不符合已确认的一并删除未使用产物的边界。
- 永久回收站或无限保留清理日志：不能解决持续占用问题；恢复暂存仅服务于中断一致性，完成后清除。

## 影响

已补齐数据集/版本入口、统一任务产物删除、Outbox 与队列清理、后台重试及数据集无主目录维护。公开契约、Alembic 迁移、存量边界和验证入口见实现文档；后续新增资源继续遵循相同规则。

实施基于现有 Vue 3、FastAPI、SQLAlchemy、ObjectStore 和 Worker，适用于 conda 开发环境与同目录 Python 发行环境，不依赖云服务或额外中间件。

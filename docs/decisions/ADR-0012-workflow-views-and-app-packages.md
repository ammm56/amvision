# ADR-0012：amvar app 应用组成、独立运行界面与打包恢复

## 状态

已接受，待实现。本文固定 amvar app 应用组成、运行界面、Workflow 文件交换、应用下载恢复及语言模型生成界面的架构取舍，不表示相关页面、接口或恢复能力已经交付。唯一详细设计、实施顺序和验收门禁见[amvar app 统一实施基线](../development/workflow-views-and-app-packages-implementation.md)。

当前决策采用多 Workflow、多 Runtime 的应用组成及命名数据源，取代本 ADR 早期的“单页面只连接一个 Runtime”限制；独立界面、公开契约和既有执行边界不变。

最新收敛以已经实现的 Workflow/Runtime/Trigger 为核心，页面只辅助在线监视和一般调用，不要求硬实时或每次执行逐条显示。取代早期的 Runtime 显示启用配置、结果快照集合、latest 缓存、历史恢复、固定某次结果与暂停恢复设计；这些不再属于待实现范围。持久化的是界面配置，不是页面显示过的生产数据。

新结果流允许在单消息 64MB 范围内直接传输 Base64 输出图片，取代“首版只用已保存资源”“WebSocket 不传图片正文”的旧限制。第三方可按公开 HTTP/WS 和输入输出契约独立实现界面，不要求使用本项目设计器，也不改变核心执行与部署。

权限收敛为登录即全部操作权限，沿用当前默认全权限用户的永久调用 token，与 SDK 相同；不新增角色、分级 scope 或应用 ACL。执行出口、完整公开输出消息、手动调用的现有 `response_mode=run` 与分阶段验证要求已补齐，详见实施基线第 6、12–14 节。

## 背景

Workflow App 已有节点编排、公开输入输出、不可变发布版本、长期 Runtime 和多协议 Trigger。编辑器 Preview 用于开发调试，不等同于面向操作人员、持续接收外部调用结果的生产界面。

现场需要查看图片、JSON、文本、判定和维护结果，也需要通过公开输入手动调用。高性能检测与结果读取/维护可以属于不同 Workflow，由同一页面展示；不能为了界面组合而强制合并节点图。客户的布局、主题和组件定制不能要求修改节点逻辑、重新发布 Workflow 或重新配置 Trigger。另一方面，现场交付不能只复制图 JSON，必须按完整应用追溯多个 Workflow、Runtime、Trigger、界面、模型部署及文件依赖，并支持离线下载和上传恢复。

界面创作需要兼容可视化编辑、模板创建和未来的语言模型生成，不能维护互不兼容的手工页面与 AI 页面。

## 决策

### 1. amvar app 组织应用，界面使用命名数据源

完整应用命名为 **amvar app**，前端简称“应用”；既有 Workflow App 在前端称为“工作流”。原导航“图编辑”改为“工作流编辑”，“新建应用/应用/应用列表”等指代 Workflow 的系统文案改为“新建工作流/工作流/工作流列表”，沿用中文、英文、日语、韩语机制。只改显示，不重命名旧资源、代码变量、翻译键、API、路由、数据库、SDK 或 ID，也不修改用户自定义名称。

amvar app 是成员与交付关系，不是新的执行器。组成清单引用多个既有 Workflow/Runtime/Trigger；界面与入口归属 amvar app。成员引用不表示独占所有权，不因添加/移除/删除应用而复制、启停或级联删除共享执行资源，不新增强制共同发布的应用总版本。

采用方案 A：界面通过命名数据源绑定各 Workflow 的公开输入输出，不暴露内部节点或参数。Workflow 负责计算与编排，Runtime 负责执行，Trigger 负责调用，界面负责输入和多来源显示。来源有稳定 `source_id` 和明确的 Workflow 发布契约依据；同名 binding 不跨来源混用，运行入口将各来源映射到实际 Runtime。

一个页面可以同时显示生产、监视、维护等多个来源；每个显式执行动作只调用指定来源。页面不隐藏扇出、重试、故障切换或业务编排。多来源独立刷新，不将两个来源当前画面当作同一生产记录；严格业务关联及汇总由 Workflow 完成并公开结果，不在页面做历史 join，也不强迫合并所有原始 Workflow。

界面输入只能选择现有 App Entry 公开 binding。`request_json` 可以由多个控件按明确字段组装，这仍是一次调用输入，不修改草稿、已发布版本或 Runtime 参数。内部节点参数只能在节点编辑画布中修改并按原流程发布、选版。

App Entry 声明支持的输入不代表每次必须全部提交。图片、JSON、文本、文件等按实际调用选择，页面不补齐所谓必填输入，不注入空值或业务默认值；缺少实际需要的数据由消费节点执行报错，基本报文格式校验和既有错误语义仍保留。Runtime 增加未使用的公开输入不强迫页面增加控件，也不作为页面不兼容的理由。

界面输出按来源、公开 binding ID 和明确字段路径关联，不按节点位置、控件顺序、显示名称或内部节点缓存关联。界面可做数值格式化、状态文字和颜色映射，不承担推理、ROI 关联、规则判定或业务统计计算。

### 2. 界面独立版本管理，应用包固定交付组合

界面文档、发布版本和静态资源独立于 Workflow App Version。布局和主题改动不进入 Workflow 内容指纹，不修改 Runtime revision，不重启 Worker，也不修改 Trigger。

运行入口明确关联一个发布界面版本与完整 `source_id → Runtime` 映射，是配置资源而非执行服务。界面定义“需要哪些来源/契约”，入口定义“现场对应哪些实例”，控件不硬编码 Runtime。保存草稿、发布界面、应用到入口、打开页面订阅和手动调用分别操作；发布不自动改变现场入口或建立连接，不增加 Runtime 显示开关。设计预览使用标记的示例数据且不执行，试运行逐动作复用目标 Runtime 调用并保留真实副作用；生产页不共享设计编辑状态。

界面逐来源依据 Runtime 激活版本的公开契约校验所用字段；不能读取最新草稿代替实际运行版本，也不能因界面不兼容自动切版。仅内部节点变化且所用公开契约兼容时，界面无需被迫改版。来源停止、不兼容或显示失败局部表达，不清空其他来源或增加全部就绪的执行屏障；token 失效按现有认证反馈。

来源键修改只进入草稿及新界面版本，再显式更新目标入口映射，不改写旧发布文档。应用成员移除和原资源删除入口都需核对引用；配置操作的依赖检查不进入每次执行热路径。

导出时用应用包 manifest 固定所选多个 Workflow、Runtime、Trigger、界面及来源映射和依赖的准确组合。选择与依赖补齐明确展示，不静默丢弃引用或自动打包整个 Project。独立发布与统一打包不冲突；包不是新的执行单元，也不是要求所有部分同步递增版本的总版本。

### 3. 按在线订阅交付实时结果，不建设结果队列或缓存

显示结果来自统一 Runtime 公开输出处理边界，不分别在 HTTP、ZeroMQ、本机共享内存和目录 Trigger 内实现。显示不依赖 Trigger 的结果回传字段选择，不改变 SDK 或 Trigger 业务响应结构。

每个 Runtime 的结果连接发送完整公开 binding mapping，控件在客户端选取字段；不引入逐页面字段过滤。只使用 Runtime 状态的来源不订阅结果。新结果路由及 v1 消息语义在实施基线第 6.5 节固定，尚未实现；不依赖内置应用/界面身份，不支持历史 cursor 或连接内执行命令。

HTTP 沿用公开输入提交、上传、管理和受控图片/文件读取；WebSocket 直接交付公开 JSON、文本、Base64 图片及资源引用，不为每条 JSON 再查询服务端快照。单条完整 UTF-8 JSON 消息上限为产品所称 64MB，即 `64 * 1024 * 1024 = 67,108,864` 字节；包含所有 Base64 和消息结构，按未压缩消息计量，不是每张原始图片各 64MB。超限只影响显示，不截断业务数据或自动改用其他图片方式。限制细则以实施基线第 6.4 节为准，不改变其他现有接口限制。

Worker 不直接公开浏览器端口。本项目运行界面仍使用 Vue 3，不新建另一套受维护前端框架、消息中间件或独立执行服务；第三方独立页面可以自行选择技术栈，共用同一公开协议、权限和资源读取规则，不依赖内置界面文档、Preview 会话或设计器。异机部署按既有网络和授权边界配置，不以关闭鉴权换取独立访问。

后端通信层维护持有效 token 且明确订阅对应 Runtime 的连接；无订阅时不做新增的显示准备、保存或发送，存在订阅才交付当前完成结果。图中显式编码/保存节点无论页面是否连接都正常执行，不能把这些成本混称为显示成本。Runtime 不管理浏览器连接，页面状态不改变节点执行。关闭、刷新或断开页面不停止 Runtime，不重跑 Workflow，不抑制正常 Trigger 调用，不增加同步调用队列或自动重试。

不新增显示结果队列、latest 缓存、快照集合、持久历史、可靠投递、确认消费或断线补发。网络在途数据及协议栈缓冲不可避免，但不能扩展为应用级待发结果列表；同一连接仍在发送时跳过新显示交付，不取消旧在途消息、不排队，也不因下一条到来就断开。实际发送失败/超时才关闭连接。面向页面的序列化和发送不进入核心返回、执行锁或 Trigger ACK 等待链，不能以无界后台任务代替队列。页面不保证逐条显示，可靠保存由 Workflow 完成。

现有事件总线含订阅队列，不能原样套用后宣称无队列。复用鉴权、路由规范和连接管理，单独核对实时交付全链路无积压；已有任务、训练、Preview 和状态事件流不改动。同步、持久化异步以及 none + event-only 临时异步都须接入统一终态交接，不能遗漏成功、失败、超时或取消；执行身份取自接受调用时，资源清理完成后才交付，不先报成功。HTTP 与 Trigger 的 service 共用显示通信组件，不为显示改为 minimal/full，也不新增 HTTP revision 前置条件或修改 Trigger/SDK 业务协议。

交接容量必须在提交回调/后台任务之前约束，发送器不能保留下一条待发结果。`async send_json` 不等于序列化已隔离；共享 CPU/GIL、全局在途字节、连接数量、发送超时及浏览器接收/解码资源必须实测并公布限制，不由 64MB 单消息上限推导总内存稳定。

### 4. 只保留当前画面，明确内联图片与存储引用两条路径

可以复用图片查看、JSON、表格等组件及通用资源转换函数，但不能把 Preview 的事件记录、原始节点输入输出采集或临时 artifact 生命周期整体带入生产 Runtime。

首版允许已有 Image Base64 Encode 或 Image Body 的明确内联输出经 WS 发送，无需先保存图片。也支持已保存或已有受控网络读取能力的公开图片/文件引用经 HTTP 读取，不增加显示副本仓库。图片内容、格式、质量、尺寸和保存由 Workflow 明确决定；显示层不隐式缩图、转码或超限后落盘。页面不扫描目录或猜最新文件，不配对不同执行的图片与 JSON。引用被删除、替换或无法读取时明确不可用，不替换成其他文件；显示模块不删除生产保存数据。

可覆盖路径不等于内容身份；引用显示需要不可变资源或内容摘要核验，并在图片阶段验证同路径覆盖与读取竞争。当前文件接口不能被默认视为已具备这项保证；Workflow 可显式采用内联方式，显示层不自动复制文件、扩大公开路径或延长保存期限。

仅执行期 LocalBuffer 图片不能在执行资源释放后交给浏览器，也不能为了慢页面延长核心租约。内联路径由通用节点在资源有效时编码，显示交付使用已独立的 Base64 正文；不依赖失效内存引用，不建设后台转码体系。现有 Preview 主要通过 HTTP 结果返回图片，WS 通知状态；可复用图片格式和浏览器显示组件，但不复制其缩略图、隐式存储、脱敏记录与历史恢复机制。

浏览器只持有当前画面和在途读取资源，不保存历史结果数组。图片、JSON 和状态按同一 `workflow_run_id` 关联，旧连接及迟到图片回调不能覆盖新画面。首次打开、刷新和重连等待后续实时结果，不补读之前或错过交付点的结果；断开时保留旧画面须标明已断开及时间，不能冒充实时状态。

公开输出按 binding 类型适配，再按明确字段路径显示；JSON 保持类型，文本按原文，Base64 按图片媒体类型解码，不通过字段名或节点顺序猜测。新 WS 消息携带实际 Runtime/版本/执行身份，`outputs` 即使只有一个输出也保留 binding 键；现有 HTTP 单输出成功响应可能展平且不含执行 ID，不为页面改其包装。

内置页面手动 HTTP 调用显式使用已有 `response_mode=run`，取得实际 run ID、版本和状态；它不是 record_mode，不要求开启持久化或 debug。保留既有 HTTP/SDK 默认 app-result，第三方选择无执行身份的返回时不拿下一条 WS 猜测请求结果。在线画面继续更新，不用迟到 HTTP 响应覆盖较新的画面，不建设固定结果或历史回查；同 Runtime 可复用连接但不合并动作。手动 HTTP 与 WS 可能重复返回公开图片，需测量并及时释放，不另改核心协议省略正文。

结果读取型监视 Workflow 与生产 Workflow 可以分开部署，但仍使用普通 App/Runtime/Trigger。读取保存文件不能还原生产逐节点过程；目录事件样本也不是每条生产记录可靠投递队列。

### 5. 界面以统一文档为核心，生成发生在创作阶段

可视化编辑、模板和语言模型生成必须读写同一种版本化界面文档，使用同一个受控 Vue 组件目录和渲染器。组件、主题、资源、输入输出绑定及允许操作都有可校验结构。

语言模型仅生成或修改界面草稿，不能修改 Workflow、扩大公开输入、启用 Trigger、调用 Runtime 或自动发布。生成结果经过结构、组件、绑定、动作目标和资源校验，再预览并人工确认。生产显示使用已发布的确定文档，不在每次执行时调用模型重建页面。

包保存生成后的文档、组件依赖和资源，不以提示词替代实际产物。模型离线、未配置或不可用不影响已发布界面。需要新增组件代码时，走普通开发、审查、测试和前端发布，不直接执行模型生成的任意 JavaScript。

### 6. 文件交换与完整恢复采用两种入口、共用文档

Workflow JSON 用于分享和继续编辑，包含 Application、Template、公开输入输出、编辑布局和依赖声明；不包含运行进程或自动启动指令。体验参考 ComfyUI 的打开、拖入和导出，但不承诺原生 ComfyUI JSON/节点可直接执行。

amvar app 应用包使用 ZIP 容器和版本化 manifest，包含本次所选组成、多个 Workflow 快照、Runtime 部署配置、Trigger 配置、界面及必要依赖。部分导出不改写现场组成；外部依赖必须明确声明，不能将其标为无需补充资源的完整离线包。包内复用平台文档，不建立另一套图语义，不通过复制整个 SQLite 数据库迁移应用。

界面版本、默认运行入口、逐来源 Runtime 映射及其明确对应关系属于交付范围；包含界面来源明确引用的契约版本，不能因 Runtime 已换版就漏掉旧 basis 版本。不存在 Runtime 显示配置交付；浏览器现场表单、当前画面、实时连接、令牌和试运行结果不属于包或发布依赖。恢复后的入口可查看配置状态并等待后续结果，页面打开不会启用或执行后台资源。

包只处理配置、可追溯版本和资产，不恢复 PID、GPU 内存、mmap、连接、锁、待运行任务或历史目录事件。业务执行历史与生产保存数据默认不在范围内。

### 7. 恢复采用显式资源映射与停止态提交

导入为新 amvar app 时生成独立应用 ID，按明确成员策略生成或复用各 Workflow/Runtime/Trigger 身份，再映射界面来源和入口；恢复原应用时仅在身份可用或明确处理冲突后保留 ID。旧 Workflow App/Graph 的时间标识、Runtime UUID、Trigger 及按 Workflow 的 SDK 配置命名不变。不能全局替换文本、猜测路径、覆盖其他应用共用资源或自动合并重复模型实例。

同一模型文件可去重，但部署实例数量及绑定不可合并。环境不兼容、依赖缺失、目录或端口冲突必须出现在恢复计划中，不自动更换模型后端或升级共享节点包。

内容未改变时保留快照和来源校验信息；资源重映射改变内容时创建明确的导入派生版本，不能修改原快照后沿用原指纹。恢复新建/替换的 Runtime 停止、Trigger 禁用，核对后显式启动；明确复用的既有资源不由恢复操作擅自启停。SDK 配置基于目标环境和恢复后的真实映射重新生成。

### 8. 导出与恢复不扩大生产热路径

使用短事务固定资源引用、一致草稿读取和不可变资产复制，不为大文件打包长期持有生产调用锁。上传、哈希、压缩和解压采用流式、有界处理。

恢复使用 staging、清单校验和可恢复操作记录，不能把部分导入结果暴露为已启用应用。密钥不明文进入普通包；可执行扩展的完整性校验不能替代信任和受控安装。

### 9. 复用全权限用户与永久 token，不增加权限体系

登录用户具有全部操作权限；独立页面和 SDK 使用现有默认用户的永久调用 token。HTTP 及支持握手头的 WS 客户端使用 Bearer，标准浏览器 WS 使用既有 `access_token` 查询参数。内置页面复用现有登录态，登录 session 的期限不等同于永久 user-token；不新增角色、专用 scope、应用 ACL、票据交换或每个 Runtime 独立 token。

有效性校验仍存在，永久 token 可撤销。全权限不取消 Runtime 启停、发布契约、恢复冲突或公开文件路径规则；monitor/interactive 是页面布局配置，不是账号权限。token 不进入分享页面地址、发布文档或应用包，目标环境使用其已有凭据；现有 SDK 下载携带 token 的选项不因此改变。此决策不隐式重置账号、修改运行配置或删除既有认证接口。

## 未采用方案

- **以节点选择驱动的 App Mode 作为产品主边界**：适合单图快速使用，但与内部节点身份耦合；本项目已选择只公开 App Entry 和 App 输出，使客户界面定制不影响内部实现。可借鉴输入输出选择体验、复用基础显示组件，不将其转为内部参数编辑入口。
- **界面与 Workflow 共用发布版本**：主题或布局改动会被迫牵动 Workflow 发布和 Runtime 选版。
- **一个页面只能连接一个 Runtime**：不能满足生产与监视维护 Workflow 独立运行、同页呈现和统一交付；采用明确命名来源，保持执行逻辑分离。
- **通用低代码业务页面平台**：多个明确 Runtime 的输入与显示属于范围，任意脚本/API 数据源、跨 Runtime 业务编排和页面定时任务不属于范围。
- **另建显示结果处理系统**：不采用 Runtime 显示开关、结果队列、快照/latest 缓存、持久历史、断线补发、固定结果或暂停恢复；页面仅在线呈现，数据组织、可靠保存和读取由 Workflow 决定。
- **为页面新建分级授权**：不区分查看/调用/编辑/部署角色，不配置应用 ACL；直接复用现有全权限用户及 token，有效性校验与资源操作规则保持。
- **AI 在生产运行时生成页面或执行代码**：引入模型可用性、非确定结果和不可控代码执行依赖。
- **仅保存提示词后在恢复时重新生成**：无法恢复同一份经过验证的界面。
- **完整复制数据库或进程状态**：混入其他 App、主机身份、凭据和不可恢复的执行资源。
- **自动把包内所有引用替换成最新版本并启动**：破坏可追溯部署、显式选版和副作用边界。

## 影响

- 增加 amvar app 组成、独立界面、命名来源、入口映射、兼容校验、结果交付和应用包导入导出职责，但不增加新的 Workflow 执行引擎。
- 现有依赖清单需要从直接引用扩展到交付所需的完整依赖集合，包含模型产物和前端组件资产。
- 先验证单 Runtime 的 JSON/文本交付、无订阅/慢连接隔离、Base64 与已保存图片及 64MB 边界，再扩展多来源、公开输入和独立标准客户端，最后开发正式设计器、界面发布和完整打包恢复；不先建设大规模页面配置系统。
- 序列化、网络、资源读取和导出任务会消耗共享机器资源，必须实测。无页面不新增显示 I/O，有页面不拖住业务；短测不能以界面解耦宣称零开销或工业长期认证，既有 Preview 和双实例合理负载一并回归。
- 新增持久化资源须经 Repository/Unit of Work 和 Alembic 迁移；公开文档格式与接口必须显式版本化，不能把实施示意当作现有 API。
- 主方向、64MB 消息上限、结果流契约、全部终态交接、手动 run 响应及全权限 token 已确定，可以启动最小链路实现。机器可验证 Schema、管理接口/新资源结构、图片内容身份、组件及包格式、实测资源限制按实施基线各阶段交付后才能放行，不冒充已有能力。HTTP/WS 文档须足以让第三方无需阅读内置前端源码即可接入。

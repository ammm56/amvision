# ADR-0012：独立运行界面与 Workflow App 应用包

## 状态

已接受，待实现。本文固定运行界面、Workflow 文件交换、完整 App 下载恢复及语言模型生成界面的架构取舍，不表示相关页面、接口或恢复能力已经交付。唯一详细设计、实施顺序和验收门禁见[运行界面与 App 应用包实施基线](../development/workflow-views-and-app-packages-implementation.md)。

## 背景

Workflow App 已有节点编排、公开输入输出、不可变发布版本、长期 Runtime 和多协议 Trigger。编辑器 Preview 用于开发调试，不等同于面向操作人员、持续接收外部调用结果的生产界面。

现场需要查看图片、JSON、文本、判定和维护结果，也需要通过公开输入手动调用。客户的布局、主题和组件定制不能要求修改节点逻辑、重新发布 Workflow 或重新配置 Trigger。另一方面，现场交付不能只复制图 JSON，必须按 App 追溯 Runtime、Trigger、界面、模型部署及文件依赖，并支持离线下载和上传恢复。

界面创作需要兼容可视化编辑、模板创建和未来的语言模型生成，不能维护互不兼容的手工页面与 AI 页面。

## 决策

### 1. 采用公开输入输出驱动的独立运行界面

采用方案 A：界面绑定 App 公开输入输出，而不是把内部节点或节点参数直接暴露给操作人员。Workflow 负责计算与编排，Runtime 负责执行，Trigger 负责调用，运行界面负责输入和显示。

每个运行页面只连接一个 Runtime。多个浏览器可以查看同一 Runtime，但页面不负责多个 Runtime 的数据组合或业务编排；需要组合的业务逻辑在 Workflow 中完成。

界面输入只能选择现有 App Entry 公开 binding。`request_json` 可以由多个控件按明确字段组装，这仍是一次调用输入，不修改草稿、已发布版本或 Runtime 参数。内部节点参数只能在节点编辑画布中修改并按原流程发布、选版。

界面输出按公开 binding ID 和明确字段路径关联，不按节点位置、控件顺序、显示名称或内部节点缓存关联。界面可做数值格式化、状态文字和颜色映射，不承担推理、ROI 关联、规则判定或业务统计计算。

### 2. 界面独立版本管理，应用包固定交付组合

界面文档、发布版本和静态资源独立于 Workflow App Version。布局和主题改动不进入 Workflow 内容指纹，不修改 Runtime revision，不重启 Worker，也不修改 Trigger。

界面依据当前 Runtime 激活版本的公开契约校验所用字段；不能读取最新草稿代替实际运行版本，也不能因界面不兼容自动切版。仅内部节点变化且所用公开契约兼容时，界面无需被迫改版。

导出时用应用包 manifest 固定 Workflow、Runtime、Trigger、界面和依赖的准确组合。独立发布与统一打包不冲突；包不是新的执行单元，也不是要求所有部分同步递增版本的总版本。

### 3. 显示使用统一后端结果边界

显示结果来自统一 Runtime 公开输出处理边界，不分别在 HTTP、ZeroMQ、本机共享内存和目录 Trigger 内实现。显示不依赖 Trigger 的结果回传字段选择，不改变 SDK 或 Trigger 业务响应结构。

复用 REST 快照、WebSocket 增量通知、受控 HTTP 图片/文件资源接口及现有鉴权。Worker 不直接公开浏览器端口，WebSocket 不传输大图正文。运行界面仍属于现有 Vue 3 前端，不新建另一套前端框架、消息中间件或独立执行服务。

显示能力显式启用，保持有界资源；不依赖 `workflow_run_record_mode=full`。关闭、刷新或断开页面不停止 Runtime，不重跑 Workflow，不抑制正常 Trigger 调用，不增加同步调用队列或自动重试。

### 4. Preview 与生产显示共享基础能力，不共享临时生命周期

可以复用图片查看、JSON、表格等组件及通用资源转换函数，但不能把 Preview 的事件记录、原始节点输入输出采集或临时 artifact 生命周期整体带入生产 Runtime。

临时 LocalBuffer 图片必须在引用释放前完成明确的显示交付，不能让浏览器持有失效引用。已保存结果可以通过受控资源接口复用。图片、JSON 和状态按同一次执行快照关联；资源过期、显示失败与 Workflow 执行失败分别表达。

结果读取型监视 Workflow 与生产 Workflow 可以分开部署，但仍使用普通 App/Runtime/Trigger。读取保存文件不能还原生产逐节点过程；目录事件样本也不是每条生产记录可靠投递队列。

### 5. 界面以统一文档为核心，生成发生在创作阶段

可视化编辑、模板和语言模型生成必须读写同一种版本化界面文档，使用同一个受控 Vue 组件目录和渲染器。组件、主题、资源、输入输出绑定及允许操作都有可校验结构。

语言模型仅生成或修改界面草稿，不能修改 Workflow、扩大公开输入、启用 Trigger、调用 Runtime 或自动发布。生成结果经过结构、组件、绑定、权限和资源校验，再预览并人工确认。生产显示使用已发布的确定文档，不在每次执行时调用模型重建页面。

包保存生成后的文档、组件依赖和资源，不以提示词替代实际产物。模型离线、未配置或不可用不影响已发布界面。需要新增组件代码时，走普通开发、审查、测试和前端发布，不直接执行模型生成的任意 JavaScript。

### 6. 文件交换与完整恢复采用两种入口、共用文档

Workflow JSON 用于分享和继续编辑，包含 Application、Template、公开输入输出、编辑布局和依赖声明；不包含运行进程或自动启动指令。体验参考 ComfyUI 的打开、拖入和导出，但不承诺原生 ComfyUI JSON/节点可直接执行。

完整 App 包使用 ZIP 容器和版本化 manifest，包含所选 Workflow 快照、Runtime 部署配置、Trigger 配置、界面及必要依赖。包内复用平台文档，不建立另一套图语义，不通过复制整个 SQLite 数据库迁移 App。

包只处理配置、可追溯版本和资产，不恢复 PID、GPU 内存、mmap、连接、锁、待运行任务或历史目录事件。业务执行历史与生产保存数据默认不在范围内。

### 7. 恢复采用显式资源映射与停止态提交

导入为新 App 时生成新 ID 并按明确引用映射；恢复原 App 时仅在身份可用或明确处理冲突后保留 ID。不能全局替换文本、猜测路径、覆盖其他 App 共用资源或自动合并重复模型实例。

同一模型文件可去重，但部署实例数量及绑定不可合并。环境不兼容、依赖缺失、目录或端口冲突必须出现在恢复计划中，不自动更换模型后端或升级共享节点包。

内容未改变时保留快照和来源校验信息；资源重映射改变内容时创建明确的导入派生版本，不能修改原快照后沿用原指纹。恢复完成后 Runtime 停止、Trigger 禁用，核对后显式启动。SDK 配置基于目标环境和恢复后的真实映射重新生成。

### 8. 导出与恢复不扩大生产热路径

使用短事务固定资源引用、一致草稿读取和不可变资产复制，不为大文件打包长期持有生产调用锁。上传、哈希、压缩和解压采用流式、有界处理。

恢复使用 staging、清单校验和可恢复操作记录，不能把部分导入结果暴露为已启用应用。密钥不明文进入普通包；可执行扩展的完整性校验不能替代信任和受控安装。

## 未采用方案

- **以节点选择驱动的 App Mode 作为产品主边界**：适合单图快速使用，但与内部节点身份耦合；本项目已选择只公开 App Entry 和 App 输出，使客户界面定制不影响内部实现。可借鉴输入输出选择体验、复用基础显示组件，不将其转为内部参数编辑入口。
- **界面与 Workflow 共用发布版本**：主题或布局改动会被迫牵动 Workflow 发布和 Runtime 选版。
- **通用低代码业务页面平台**：任意脚本、数据源、跨 Runtime 编排和页面定时任务超出范围。
- **AI 在生产运行时生成页面或执行代码**：引入模型可用性、非确定结果和不可控代码执行依赖。
- **仅保存提示词后在恢复时重新生成**：无法恢复同一份经过验证的界面。
- **完整复制数据库或进程状态**：混入其他 App、主机身份、凭据和不可恢复的执行资源。
- **自动把包内所有引用替换成最新版本并启动**：破坏可追溯部署、显式选版和副作用边界。

## 影响

- 增加独立界面资源、兼容校验、结果交付和应用包导入导出职责，但不增加新的 Workflow 执行引擎。
- 现有依赖清单需要从直接引用扩展到交付所需的完整依赖集合，包含模型产物和前端组件资产。
- 显示编码、资源转换和导出任务会消耗共享机器资源，必须实测，不能以界面解耦宣称零开销或工业长期认证。
- 新增持久化资源须经 Repository/Unit of Work 和 Alembic 迁移；公开文档格式与接口必须显式版本化，不能把实施示意当作现有 API。
- 主方向已经确定；具体 Schema 字段、端点、组件依赖选型、容量默认值和错误码仍需按实施基线逐步验证并冻结。
